# 配额契约门禁的进程清理

`scripts/account-platform-auth-quota-lua-check.py` 为每次 Go/Lua 验证创建独立进程组。
Linux 的 `SIGKILL` 不保证所有组员在调用返回时都已经退出；只等待 Go 父进程，
会让仍在完成退出的 Lua 后代被误判为泄漏。#2267 的超时诊断回归曾因此失败，
当时尚未执行真正的配额契约，Go 预编译也已经成功。

清理先向本次 `Popen` 创建的进程组发送终止信号，再在原有十秒清理预算内，
等待直接父进程及同一进程组、同一会话中的活跃进程退出。僵尸已经不能执行，
由系统或容器 init 回收，不把它们当成存活后代。不会按名称选择其他任务的进程；
超出清理预算仍会失败。

Go 验证的 180 秒外层期限、90 秒包测试期限、12 个必需根测试、11 个实际 Lua
执行证明，以及超时后不能接受已输出的通过事件等规则均保持不变。
Windows 继续采用原有 `taskkill` 路径；不宣称它能清理父进程已经退出后脱离的后代。

回归通过真实进程故障注入，让父进程先退出、后代延迟退出，验证清理不会过早返回。
还覆盖了僵尸、其他会话及清理超限的负向边界。
