# 平台模型默认与显式会话选择

平台目录的 `DEPRECATED` 新会话宽限只供用户明确选择会话模型或创建替代分支，不能用来设置全局默认。全局默认仅接受当前目录中 `PUBLISHED` 且 `context_eligible=true` 的精确模型 ID；本地和自配第三方模型仍沿各自配置入口工作，不自动寻找或映射替代模型。

当前目录明确返回同一默认模型的 `DEPRECATED` 或 `REMOVED` 状态时，应用按默认引用及私有选择 revision 一起比较后退休该默认。并发重选同一模型、A→B→A、改选第三方模型和旧登录响应均不能覆盖新的选择。目录请求失败、缺项、无有效目录版本或未知状态不是退休证据。普通设置 patch 不能改写模型选择及其 revision。

GUI、Web 和远程任务共用的新会话记录创建入口，会把自动继承平台默认的来源 revision 与其精确引用保存在同一个 `_session_models.json` 对象内。已有字符串和 typed 对象缺少该字段时保留原解释，不推测其来源。显式绑定或重选（包括同一模型）清除本条来源；其它条目、保留策略清理和启动格式重写保全仍有效的来源。

首次模型准备复用原有的当前身份和最新目录请求。完整目录校验通过后，即使当前历史绑定或冻结计划模型已缺席，也先观察并按原授权及引用/revision 比较退休目录中明确失效的全局默认，然后保留原缺席拒绝及零派发。坏目录、HTTP 失败、未知状态、缺项和过期身份不形成退休依据。选中模型的协议、目录和能力校验通过后，仍带自动默认来源的会话只允许 `PUBLISHED` 且上下文合格的模型；弃用时记录现有模型重选信号并拒绝派发，同时精确退休当时的全局默认。完成一次合格的模型准备后，仅消费仍匹配的来源标记，随后维持既有固定会话的历史继续规则。失败准备或注销不消费该来源；计划任务冻结的 `scheduled_model_ref` 优先，不作为全局默认继承处理。

以上不代表离线客户端可知道尚未观察到的远端目录变化。离线或错误响应不清除本地默认，真正调用仍经过原有当前目录和 Gateway 准入；不新增目录缓存、后台轮询或同步阻塞网络。退休全局默认不改写历史会话，不取消原用量，不创建或释放资金，亦不改变平台既有对账策略。设置页按权威选择投影刷新模型状态，不静默选择替代项。

语音辅助准备与上述默认规则共用同一权威目录及退休 CAS。已有真实会话的语音只观察/确认该会话的来源；独立语音 scope 不改变普通聊天路由或活动代际。无会话草稿没有 SessionStore 记录：只有后端从同一 prefs 快照自动解析全局平台默认时，才附带不可序列化的内存来源 revision，并对该次调用执行默认专用 PUBLISHED/context 准入；显式 typed 草稿选择仍沿原显式宽限。两路均可观察并精确退休当前明确失效默认，不创建可见假会话，也不把交付 Drop 当用户取消。
