# RemoteProxy 归档失败与恢复

归档持久意图写入独立 anchor 后即不可撤销；SQLite 保存档案索引和完整请求墓碑。活动 JSON 清理失败时，归档仍已成功，命令返回 `cleaned=false`，不能因此重新打开原记录。

归档内部区分两类错误，对外保留现有错误映射：

- 可证明的意图前拒绝：输入校验失败、取得跨进程文件锁时的真实竞争，以及健康既有库中的明确身份或请求 ID 冲突。它们不永久禁用本进程的 RemoteProxy 变更；锁释放后可以重试。实际数据冲突仍会被永久归档保护拒绝。
- 持久结果未知：初始化、恢复、SQL、anchor 写入、文件身份或后置校验错误。写函数报错也可能已经发布新意图，必须保守禁用本进程后续受保护的远程变更。即使本次尚未写新意图，恢复旧意图发生过持久工作后也不放宽分类。

明确冲突只有在整个包装器完成后置校验且未做初始化或旧意图恢复写入时才保留可重试分类；后置异常优先。不会根据错误文本或泛化 I/O 类型推断“未写入”。 上述进程禁用针对归档 seal 返回结果未知：受保护归档读取的恢复失败会向调用者报错，但不设置该粘滞标志；离线历史读取可回落到内存展示，此回落不授予写入权限。后续受保护操作仍须逐次通过严格的恢复及身份校验。可重试竞争和隔离错误对外均映射为现有 unavailable，界面不区分两者。

未设置进程禁用标志不保证所有持久变更都可用：持久化会核对全部活动记录，仍在的档案身份或请求 ID 冲突可能使其它记录的写入也持续被拒绝。重启只按严格规则清理与档案完全一致的活动残留；发生真实内容或身份冲突时，重启后仍可能拒绝，不保证重启即可消除冲突。

依赖恢复后，受禁用的进程通过重启进入严格恢复：仅接受同一库 UUID、精确记录、完整双域墓碑及连续水位，完成或核验恰好一次归档。缺库、异库、旧备份、损坏意图或不完整墓碑继续拒绝；不得删除 bank、anchor、pending 或墓碑来恢复可用性。

本地 Chat/ACP 会话保持独立。只读展示及对精确当前绑定、已经持久跨过发送屏障的既有任务取消，仍遵循原有契约；后者是已有任务收口，不授予新任务或归档记录执行权。失效 lease、已归档记录和从未尝试的请求不因此获得取消权限。

回归入口为产品 `cargo test --locked --manifest-path pinvou3-app/src-tauri/Cargo.toml --no-default-features --lib remote_proxy -- --test-threads=1`；适用 Windows/Linux 原生门禁另按仓库工作流执行。测试使用真实 SessionStore、跨进程 fd-lock、SQLite 与原子写，受控测试钩子只固定交错或故障位置，不替换这些判断和副作用。

锁测试的父进程分别限制子进程就绪和退出等待（各 30 秒），异常或断言展开时终止子进程，并在独立的 5 秒清理预算内轮询回收进程和 stdout 线程。回归包含已经持锁却不报就绪、收到释放后拒绝退出的故障子进程；两者都必须有界失败并释放实际 fd-lock，再验证下一次正常子进程及环境隔离锁可用。外层 CI job 超时不是这些用例内收口的替代。
