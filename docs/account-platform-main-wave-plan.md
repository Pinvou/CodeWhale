## 分波原则与差异口径

每个端点选择完整原提交，不拆开跨职责提交，不修改其 SHA。历史中的文档、测试、部署、迁移和功能同属所属波，标题应披露同时携带的职责。功能边界优先于行数；原子提交较大时提供文件导览，不伪造小 PR。

集成分支拟为 `integration/account-platform-main-20261004`，从冻结 main 创建。波分支为 `review/account-platform-a01` 至 `a49`，PR 均以集成分支为目标。已核验计划名称无本地或 origin 同名分支；创建时再核对，不能覆盖已有分支。

表中“自身 / 累计提交”是排除冻结 main 后的原始提交数。自身只属于本波，累计包含 A01 至本波。49 个自身集合不重叠，恰好覆盖 925 个原提交。完整 SHA 和分配见 [机器清单](account-platform-main-wave-plan.json)。

“历史树差”仅用于估计原端点审核负担，包含源码、测试、契约和文档；不是合并最新 main、追加修复后的真实 PR 大小。含主线同步的波不能把旧 main 变动算作本波功能。实际波 head 尚不存在，本轮不虚构 PR 累计行数。

每波审核时，固定前波已审 head `P`、本波已审 head `H` 和集成目标 `I`，分别登记：

- 自身树差：`git diff P H`，A01 的 P 是冻结 main；另列本波原提交、继承修复和本波新增修复。
- 相对目标的实际累计树差：`git diff I...H`，记录 I 的 SHA，不能混用目标更新前后的统计。
- 本波原提交集合：`git rev-list E_i --not E_previous frozen_main`；原端点 E 与含修复的实际 head H 分别记录。

初始全部 PR 指向尚未推进的集成分支，GitHub Files changed 会显示累计差异。正文提供固定 SHA 的前波到本波 compare 及职责导览；前波按依赖顺序合入后，后波 PR 的累计差异才缩小。不能承诺创建时页面仅显示自身增量。
