# 被控端任务输出与本地对话的展示收敛

被控端的任务状态会累计同一任务的正文，而本地对话会在工具和推理之间拆分正文。
展示合并按任务的用户消息定位回合：优先使用 journal 的 taskId 和正式记录的原始
messageIndex，再使用按任务顺序匹配的提示词兜底。
接纳状态在 dispatch 前发布；live 用户消息从当前会话唯一活动受控任务复制身份与原始
位置。任务已终态、提示词不匹配或多个活动任务时不猜测身份。无原始位置的历史兜底
只匹配提示词和任务顺序，不将展示数组索引与原始 transcript 索引比较。
附件消息允许完整提示词后紧跟唯一的 `\n\n📎 <JSON 文件名数组>` 显示后缀，
数组必须非空且所有文件名均为非空字符串，不能带额外正文或使用宽松前缀匹配。
此规则同时用于 live 身份复制和历史兜底；普通文本、任务顺序、原始位置、
其他任务身份及 steer 边界仍须满足原有约束。仅有附件时，UI 仍使用原有的
attachmentOnlyPrompt 作为非空提示词。提示词保留协议允许的完整 64 KiB 范围，
不再将前 8192 字符相同误当成全文相同；超出范围的任务提示词不用于匹配。
附件后缀只作 UI 文本形态比较，不代替后端文件名校验、来源认证或派发授权。
没有 taskId / 原始位置时仍为顺序加文本的启发式兜底，不能证明迟到的同文本旧事件
属于当前任务；本次不新增端到端事件身份，也不声称消除这一既有歧义。

同一回合内按顺序拼接正式正文进行覆盖比较，工具卡、推理及 mid-turn steer 保持原位。
正式正文已覆盖任务累计正文时，移除任务副本；任务流领先时仅补未覆盖的尾部，
并放在下一轮用户消息前，已有失败消息前。正式记录到达后重新投影，尾部兜底自动退出。
提示词尚未到达时，将提示词及输出兜底放在自身 journal 事件或后续任务之前。
错误及取消等终态独立匹配和保留，不作为模型正文参加覆盖计算。
补充权限提示时保留原始诊断码；仅当正式消息缺少原码字段时补入，不覆盖已有证据。
任务兜底的身份、原始位置、时间和输出 lane 不复制到正式消息上。
缺失提示词按原始位置寻找后续边界时，只允许用户消息作锚点，不能使用 assistant 或工具事件。

覆盖判断只允许同一任务回合内的有序全文/前缀关系，不做跨回合 substring 去重。
无法证明覆盖关系的文字保留，避免删除真实输出。这里仅调整被控端的 UI 展示，
不修改 SessionStore、任务事件、远控协议或提交版本通知。
中段缺失或分叉无法证明覆盖关系时，会临时保留整段任务正文；正式记录补齐后收敛。
这不是任意子串去重，不能为消除副本而删除无法证明重复的正式输出。
流式尾部兜底沿用 ChatView 既有契约：无 html 且 streaming 为 true 时暂不渲染，
到任务终态后显示；本次不改变流式渲染器。

回归命令：`node --test pinvou3-app/tests/remote_chat_projection.test.mjs`。
使用合成数据覆盖工具分段、连续任务、重复提示词/答案、原始位置与展示位置差异、
流式领先/滞后、正式记录恢复、steer、失败/取消、missing prompt 和 session 隔离。
另覆盖附件实时事件、工具分段、重复提示词、仅附件发送、非法显示后缀与中段恢复。
补充覆盖非用户位置不作提示词锚点，以及权限提示与原码、正式身份和既有证据共同保全。
