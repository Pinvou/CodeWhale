# 被控端任务输出与本地对话的展示收敛

被控端的任务状态会累计同一任务的正文，而本地对话会在工具和推理之间拆分正文。
展示合并按任务的用户消息定位回合：优先使用 journal 的 taskId 和正式记录的原始
messageIndex，再使用按任务顺序匹配的提示词兜底。
接纳状态在 dispatch 前发布；live 用户消息从当前会话唯一活动受控任务复制身份与原始
位置。任务已终态、提示词不匹配或多个活动任务时不猜测身份。无原始位置的历史兜底
只匹配提示词和任务顺序，不将展示数组索引与原始 transcript 索引比较。

同一回合内按顺序拼接正式正文进行覆盖比较，工具卡、推理及 mid-turn steer 保持原位。
正式正文已覆盖任务累计正文时，移除任务副本；任务流领先时仅补未覆盖的尾部，
并放在下一轮用户消息前，已有失败消息前。正式记录到达后重新投影，尾部兜底自动退出。
提示词尚未到达时，将提示词及输出兜底放在自身 journal 事件或后续任务之前。
错误及取消等终态独立匹配和保留，不作为模型正文参加覆盖计算。

覆盖判断只允许同一任务回合内的有序全文/前缀关系，不做跨回合 substring 去重。
无法证明覆盖关系的文字保留，避免删除真实输出。这里仅调整被控端的 UI 展示，
不修改 SessionStore、任务事件、远控协议或提交版本通知。

回归命令：`node --test pinvou3-app/tests/remote_chat_projection.test.mjs`。
使用合成数据覆盖工具分段、连续任务、重复提示词/答案、原始位置与展示位置差异、
流式领先/滞后、正式记录恢复、steer、失败/取消、missing prompt 和 session 隔离。
