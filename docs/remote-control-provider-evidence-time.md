# 远控发布证明的时间合同

在线 `verifyProviderAttestation` 使用受信当前墙钟：签发不早于五分钟前、不晚于
当前时间三十秒。无效时钟拒绝。签名、nonce、role、policy、driver、key、证书链
及固定信任根仍全部验证。

发布 deep validator 将演练时序与发布资格分开：

- 证明签发时间必须在其绑定的演练开始、结束之间；不能把签发时间当作当前时间。
- 演练最长 120 分钟，与物理双 Windows evidence workflow 的总预算一致。
- 发布资格必须在演练结束后五分钟内验证，允许最多三十秒墙钟偏差。陈旧或未来
  演练拒绝；超期需要重新取得有效演练证据，不能改 JSON 日期延长资格。
- 证书链在签发时和本次资格验证时均须有效。所有原身份、签名、产物摘要与关联
  校验继续执行，长演练不错误套用在线签发的五分钟时限。

资格时钟来自验证进程的 `Date.now`，不从 evidence、命令行或环境读取。库测试可注入
受信的 `qualificationClock`；生产发布入口不开放覆盖。deep validator 在进入验证、
文件重新哈希后和返回资格之前重读时间，不能冻结入口时刻来延长有效期。
最终发布 gate 完成外部检查后再次执行 deep 文件验证，避免检查耗时或本地文件变化
使先前有效的证明、证书或摘要在放行时已失效。

单独运行 schema 或不读取 artifact 的结构检查不能获得发布许可；正式门禁必须
使用 `validateReleaseEvidenceFile` 重新读取/哈希/验证全部签名文件。
