# 账户平台 Web 界面恢复

个人中心提供“额度与用量”“订单记录”“账号设置”分区；组织身份具备相应读取权限时增加“我的组织”。管理后台恢复工作台、身份与组织、资金与计费、模型与 Token、治理与安全五组导航。桌面宿主继续使用现有桌面界面与原生认证流程。

## 交互与业务边界

- 点击导航写入页面地址，浏览器前进、后退和详情链接恢复相应页面。旧个人中心和管理后台地址映射到当前分区；显式指向无权限页面时显示拒绝访问。
- 用户和组织目录具有详情入口。组织详情按概要、成员、组织单元、生命周期分区；成员搜索和分页使用服务端查询。修改、创建及删除使用现有确认和权限检查。
- 充值、财务审批和组织操作沿用当前业务控制器。切换导航保留已访问且仍获授权的操作实例；同一会话的价格管理入口共享未决操作。弹窗只在所属页面可见，隐藏页面的延迟读取不弹出跨页窗口；结果未知时只能恢复原请求，不能因切换页面重新分配幂等键或自动执行写操作。
- 个人资料通过字段弹窗编辑；组织删除继续要求停用、最新阻断检查、名称确认及二次确认。界面恢复不放宽这些限制。
- 个人中心购买和提交使用绿色主按钮，查询、刷新和取消保持次级样式；注销和移除等操作使用红色警告样式。确认弹窗挂载在页面根节点之外，同样保留操作层级与键盘焦点提示。
- 财务四类运营概览恢复统计单位、快照或统计时段、纳入状态和相关记录跳转；只有确实应用了对应过滤条件的跳转才标记为筛选记录。钱包账目、应收、商品及支付复核目录的读取筛选使用现有服务契约。已退役的用量冻结管理读取接口没有恢复入口。
- 总览按服务独立加载，失败显示不可用；缺少字段不显示虚构的零值。金额以原有精确整数协议读取和显示。退款记录保留普通/强制退款两种操作身份。
- 模型菜单遵循会话返回的功能开关与当前权限。界面恢复不重新启用已退役的金融写接口，也不绕过审批和权限。
- 暂不提供开票功能，页面不展示开票入口。

## 个人中心信息与操作

- 侧栏显示当前个人或组织身份；组织名称来自现有组织目录读取，切换身份不修改个人资料。组织页分为概览、成员与部门、角色与权限、额度与账单、模型设置，入口遵循已有权限。
- 余额区分别展示可用与已预留积分，并解释预留含义。套餐显示人民币价格、到账积分、赠送积分、有效期与适用范围；缺少服务字段时显示“暂未提供”，低价不会自动标为促销价。只有服务明确标记测试收款时显示测试提示。
- 权益显示剩余、已用积分与到期时间，不从不完整数据推断使用百分比。订单分别显示创建时间与实际支付时间；未支付订单不使用创建时间冒充支付时间。编号可复制完整值，表格显示缩写。
- 用量以紧凑表格展示，Token 和完整编号放入明细。日期、模型与状态可筛选当前页；“期间消费统计”显式分页读取全部历史并应用相同条件，只有游标耗尽后显示完整期间的已确认消费。每批最多读取 20 页，大量记录可继续或取消；读取失败不提交本批小计，重试从上一完整检查点继续，未知扣费单独提示。旧接口按单次请求筛选，已合并记录不拆分估算。统计不替代账务快照，进行中记录结算后可重新统计。
- 个人资料只保留一组编辑行；注销区先显示实际状态和服务返回的阻断项，完整规则可展开，保留身份清理后无法恢复的提示和原有文字确认。
- 成员操作从具体成员行进入；确认显示所选成员及操作后果。原操作实例保持挂载，未知结果的重试不会因成员消失、分页或导航而更换参数或幂等键。
- 组织目录随授权版本和账号刷新失效，侧栏及组织标题不保留旧角色或名称。配额同 key 回放可接受成员生命周期推进后的当前 grant 版本，同时保留对象、金额和版本下界校验，确定回执后可继续下一次分配。
- Web 配额分配选择已加载成员和有效权益组件，服务端标识从选项派生。输入单位为积分，支持 4 位小数，以整数精确换算为微积分（1 积分 = 10,000 微积分），验证合计不超过所选可用额度。旧桌面表单协议与服务端权限、版本、幂等控制保留。

## 数据与发布

原界面恢复新增管理总览、用户详情和组织详情读取；本轮另补 Web 个人中心的组织订单历史，只允许当前付款人读取当前组织钱包下的订单，并采用游标分页。上述读取复用现有权限及 Portal 会话边界，组织订单历史需要 Billing、Token、Portal 配套版本。桌面入口不挂载这一新增历史区。它们不需要数据库迁移、数据重置或角色调整。新增 Token 总览代理继续使用现有管理查询来源签名；Billing 价格概览仅增加既有 GET 读取的精确转发。

部署时应核对实际运行版本及所需依赖，避免把与界面无关的服务升级或迁移混入发布。构建产物由 `npm --prefix pinvou3-app run build:account-portal` 生成并嵌入 Portal。

## 验证入口

`npm --prefix pinvou3-app run test:account-platform-restored-ui` 验证导航映射、真实组件入口的受控 HTTP 交互、失败恢复、三种语言、响应式布局及独立打包后的两个页面。受控 HTTP 用例不代替真实数据库或生产端到端验证。

Account 的 `TestRestoredAdminReadsWithPublicMigrationsAndRuntimeActor` 使用公开迁移和实际非超级用户运行角色验证读取结果，并检查读取不新增审计或事件；必须使用专用的隔离 PostgreSQL 实例。

发布前还应运行受影响的个人、组织、财务、审批、认证回归及架构、国际化检查，并按仓库流程完成独立审核。生产验收使用只读检查，真实支付、退款和账户注销不能作为自动冒烟动作。

构建后运行 `npm --prefix pinvou3-app run audit:compat -- --portal-only`，校验三个 Portal 入口、实际 JS/CSS、内联脚本和本地引用；默认完整兼容审计也包含 Portal。兼容下限沿用项目 Safari 14，带 CSS 变量的固定定位使用明确的物理边界。
