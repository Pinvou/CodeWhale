# 账户平台 Web 界面恢复

个人中心恢复“额度与用量”“订单与发票”“账号设置”分区；组织身份具备相应读取权限时增加“我的组织”。管理后台恢复工作台、身份与组织、资金与计费、模型与 Token、治理与安全五组导航。桌面宿主继续使用现有桌面界面与原生认证流程。

## 交互与业务边界

- 点击导航写入页面地址，浏览器前进、后退和详情链接恢复相应页面。旧个人中心和管理后台地址映射到当前分区；显式指向无权限页面时显示拒绝访问。
- 用户和组织目录具有详情入口。组织详情按概要、成员、组织单元、生命周期分区；成员搜索和分页使用服务端查询。修改、创建及删除使用现有确认和权限检查。
- 系统与安全嵌入管理后台时复用外层页面标题，不再重复标题；工作区独立使用时仍保留标题，工作台的紧凑健康摘要不受影响。
- 充值、财务审批和组织操作沿用当前业务控制器。切换导航保留已访问且仍获授权的操作实例；同一会话的价格管理入口共享未决操作。弹窗只在所属页面可见，隐藏页面的延迟读取不弹出跨页窗口；结果未知时只能恢复原请求，不能因切换页面重新分配幂等键或自动执行写操作。
- 个人资料通过字段弹窗编辑；组织删除继续要求停用、最新阻断检查、名称确认及二次确认。界面恢复不放宽这些限制。
- 管理员的组织操作在首次弹窗中展示组织名称及标识；单元操作同时展示单元名称及标识。无输入字段的操作不显示空字段框，删除单元和组织启停在首次弹窗与最终确认中保留影响说明。取消不发起写请求，结果未知时继续保留原幂等键与请求事实。
- 组织操作弹窗采用并排的取消和提交底栏；忙碌或结果未知时禁止取消已接受的请求，恢复原请求后仍可继续下一次操作。内联表单保持原有结构。
- 组织操作弹窗的字段组不叠加外框，字段按统一间距排列；保留原生字段组的禁用语义，输入控件自身边界不变。
- 后台组织操作使用一致的按钮层级：新增入口与普通提交使用主色，删除、移除、停用及所有权转让使用危险色；取消保持中性，最终确认按钮写明动作。个人中心与内联表单沿用原有样式。
- 组织改名入口和弹窗标题明确为“修改组织名称”，与单元改名区分；弹窗继续展示当前组织名称及标识。
- 成员行操作采用视口内的浮层菜单，展开不改变表格行高；关闭菜单保留操作实例，打开的确认或未知结果弹窗继续由原请求控制。菜单可通过 Escape 退出并返回触发项。
- 成员归属行显示单元名称或“未分配”，无归属范围的规则在列表表头集中说明一次。普通成员归属与单元管理员角色范围分别管理，显示简化不改变权限。
- 后台成员列表将名称、角色筛选和添加成员集中在表格上方的工具栏；筛选与新增沿用原权限和请求，窄屏按顺序排列。
- 审计日志的长操作代码在所属单元格内换行，操作列保留可读宽度，窄屏通过表内横向滚动查看其余列；保留完整原文及原记录详情入口，不覆盖相邻资源列。
- Token 账户详情使用独立的账户概览标题，模型详情继续使用模型概览；两类标题均提供中文、英文和日文。
- 财务指标与模型、账户事实网格的未满行区域使用中性底色，实际条目保持分隔；不补占位数据，不改变字段、指标和跳转。
- 注销申请目录区分加载中、当前页为空、读取失败和权限不足；读取重试不触发注销或修复，已有待恢复任务继续显示。
- 用户禁用动作和最终确认沿用管理台危险色，启用保持普通语义；确认列明目标账户、编码和 ID，当前登录账户不能禁用的原因直接可见。原权限、自禁用保护、确认和取消流程保持。
- 角色目录和授权管理的授予入口明确标为给用户授权，抽屉标题沿用同一含义；仍按原向导选择用户和已有角色。
- 平台授权的列表、详情和授权确认分别标明生效时间、到期时间；未设置到期时明确显示无到期时间，仍独立保留实际授权状态。输入日期的填写说明与只读时间标签分开。
- 后台注销目录以“账号注销申请”标识页签与标题，并说明用于跟踪处理阶段；个人端保留发起注销的原有措辞。
- 账务归属修复的金额以积分输入，并显示精确微积分记账值；1 积分等于 10,000 微积分，支持最多 4 位小数。非法金额使当前冻结事实失效；结果未确认时只恢复、重放原事实和请求键。冻结事实仍按服务端原始单位展示。
- 审批中心及复用审批组件的读取失败提示使用审批数据语境；实际财务页面的错误文案、权限拒绝和操作结果未确认提示保持原有含义。
- 个人中心沿用原版充值卡片、按钮层级和间距；注销入口及确认按钮使用红色警告样式，查询状态与取消保持普通样式。确认弹窗挂载在页面根节点之外，同样保留警告色与键盘焦点提示。
- 财务四类运营概览恢复统计单位、快照或统计时段、纳入状态和相关记录跳转；只有确实应用了对应过滤条件的跳转才标记为筛选记录。钱包账目、应收、商品及支付复核目录的读取筛选使用现有服务契约。已退役的用量冻结管理读取接口没有恢复入口。
- 总览按服务独立加载，失败显示不可用；缺少字段不显示虚构的零值。金额以原有精确整数协议读取和显示。退款记录保留普通/强制退款两种操作身份。
- 模型菜单遵循会话返回的功能开关与当前权限。界面恢复不重新启用已退役的金融写接口，也不绕过审批和权限。
- 在线开票仍显示当前服务尚未提供的说明。

## 数据与发布

新增服务接口仅恢复管理总览、用户详情和组织详情读取，复用现有读取权限及 Portal 会话边界。它们不需要数据库迁移、数据重置或角色调整。新增 Token 总览代理继续使用现有管理查询来源签名；Billing 价格概览仅增加既有 GET 读取的精确转发。

部署时应核对实际运行版本及所需依赖，避免把与界面无关的服务升级或迁移混入发布。构建产物由 `npm --prefix pinvou3-app run build:account-portal` 生成并嵌入 Portal。

## 验证入口

`npm --prefix pinvou3-app run test:account-platform-restored-ui` 验证导航映射、真实组件入口的受控 HTTP 交互、失败恢复、三种语言、响应式布局及独立打包后的两个页面。受控 HTTP 用例不代替真实数据库或生产端到端验证。

该回归脚本在监听服务和运行检查的同一退出边界关闭共享夹具作用域。浏览器关闭失败时仍尝试关闭服务器，保留业务失败与全部关闭失败；未确认全部关闭时不删除夹具文件。

浏览器夹具对已退出的进程同样要求观察到关闭确认；退出码、信号码、断开连接或关闭回调返回都不能单独授权删除配置目录。

成员菜单的行高回归继续比较真实 DOMRect 高度，以固定 0.01 CSS 像素误差处理亚像素测量舍入，并拒绝非有限或非正高度；增长和缩小超过该范围仍失败。页面动画和浮层场景保留，纯测试覆盖已记录的舍入数对及超限变化反例，原失败记录不改写。

Account 的 `TestRestoredAdminReadsWithPublicMigrationsAndRuntimeActor` 使用公开迁移和实际非超级用户运行角色验证读取结果，并检查读取不新增审计或事件；必须使用专用的隔离 PostgreSQL 实例。

发布前还应运行受影响的个人、组织、财务、审批、认证回归及架构、国际化检查，并按仓库流程完成独立审核。生产验收使用只读检查，真实支付、退款和账户注销不能作为自动冒烟动作。

构建后运行 `npm --prefix pinvou3-app run audit:compat -- --portal-only`，校验三个 Portal 入口、实际 JS/CSS、内联脚本和本地引用；默认完整兼容审计也包含 Portal。兼容下限沿用项目 Safari 14，带 CSS 变量的固定定位使用明确的物理边界。

用户目录将普通搜索、完整用户编码精确查询与刷新当前结果集中在同一工具区。普通搜索显式提交并更新 URL；刷新和重试使用已执行的查询种类及条件，不提交草稿。编辑完整编码仍清除旧精确结果，重新查询前不可刷新；非法编码或未找到不会回退普通搜索。分页继续使用已应用的目录查询，既有权限、用户状态确认与请求代次保护保持。

用户详情将所属组织的成员状态与角色分开显示，复用组织域三语枚举并保留未知值；组织名称使用统一详情链接样式，原权限门及组织 ID 不变。授权入口明确为查看该用户的平台授权，继续按详情用户 ID 打开平台授权列表，不表示组织角色被转换成平台权限。

用户详情的页头和面包屑按实际用户详情路由显示详情上下文；真实姓名继续由详情组件已读取的资料提供，不复制到全局状态。返回用户列表作为次操作与姓名保持独立间距，并继续保留原目录的查询条件和游标；列表及其他页面的通用标题和返回文案保持原语义。

管理后台窄屏底栏使用完整的个人中心导航链接与可收缩语言选择器，覆盖旧移动端 flex 与百分宽度的竞争；链接沿用主题色、原生焦点和触屏目标。原首页地址、语言选项及切换回调不变，不重置当前查询或未提交输入。

授权抽屉的步骤名称采用可读字号，当前步骤提供语义标记；第一步的下一步旁显示真实前提并关联按钮说明。现有手填路径仅校验用户 ID 格式，仍保留无需用户目录读取权限的流程，不将格式通过宣称为已查询或已验证用户；无效 ID 给出明确格式指引。

审批中心的状态选项、列表与详情使用当前语言的业务状态，选项显式保留规范状态码，其他财务入口保持原显示。执行视图的条件说明和选择器来自实际查询状态（包括原有的失败默认及不支持组合的回退），不改变接口筛选、默认值或分页；原始状态码仍在列表及详情辅助显示，未知值保留原文。

审批策略目录以已支持命令的业务名称及真实风险类别为主信息，原命令码、风险码和策略版本作为可核对的辅助信息保留。风险标签只表达类别，不另设严重等级；未知展示值保留原文，原有支持命令列表、策略顺序、版本与可申请判断均不改变。表格使用局部容器并取消其继承的负外边距，长码自然换行。

组织目录将名称、状态、查询及重置筛选集中在同一工具栏，创建组织沿用原权限和主动作样式并置于工具栏另一侧。重置只清目录名称、状态和目录分页，保留其他路由上下文；名称仍按原表单提交，状态仍按原规则即时应用。页内数量保留真实本页含义，不新增总数或分页接口。

组织详情头部左对齐当前详情中的名称、状态和完整组织 ID，刷新与有权限的修改名称集中于右侧，窄屏自然换行。概览仅去除重复名称和状态，仍保留真实版本及原有成员入口；返回保持原目录上下文，编辑权限、已删除状态限制与原改名表单、读取回执均不改变。

组织单元的新建入口置于列表上方工具栏，沿用现有主动作主题；三语创建按钮及原对话框采用明确一致的组织单元命名。原权限、读取失败和已删除组织限制、名称与父级字段、目标归属及创建回执流程均不改变。

组织单元以紧凑列表呈现名称、真实上级、状态和行内操作，完整保留已接受条目、顺序与单元 ID。上级名称仅由当前组织的真实父 ID 查得；缺少名称时保留完整父 ID，只有无父级时显示根层级。长名称和 ID 自然换行，成功空列表与读取错误分别显示，原对象操作及权限、对话框和写入规则不改变。

对账证据确认任务按真实执行效果命名：渠道有付款、内部无对应记录且退款证据符合条件时，经审批并执行成功后结案匹配差异及关联人工复核案件。页面区分申请与执行结果，以业务名称和效果说明为主，原命令及记账效果 NONE 保留为辅助代码；原金融风险类别、权限、冻结投影、输入、重放键和记账规则不改变。

### UI035 / S24-02：上海业务日期输入

对账证据确认以原始 YYYY-MM-DD 上海业务日期匹配对账运行，不通过浏览器时区转换。日期字段提供原生日期选择和可切换的手动输入，并保留原校验、冻结申请及旧年份 0000 的原始字符串；不支持日历表达的值以文本保留，不能因切换控件丢失或改写。此项没有新增案件入口预填或从当前时间猜测日期。

### UI036 / S01-01：系统页标题栏的刷新与检查时间

系统页继续复用布局的唯一标题，原刷新与同一 accepted 状态中的 checked_at 通过 React portal 放入该标题栏的局部 ref 插槽。checked_at 是聚合检查开始时刻，不称各服务完成时间或持续健康保证；缺失、读取中与未取得快照分别说明，不使用本地现在伪造检查时间。页面离开、权限或 owner 换代时移除标题栏控件，普通独立工作区保留行内入口；compact 概览入口不在本项扩展。没有新增状态请求、轮询、恢复或写入。旧注册宏保留单标题、真实 GET 次数/只读/诊断/换代断言，并以真实 header 刷新控件和固定服务端时间加强检查。

### UI037 / S01-02：系统检查快照与相关复核入口

完整系统页与概览健康条使用同一 accepted 响应，健康服务显示已返回服务集合中的健康数/总数，原精确计数与不可用值保持。三语主状态与原始状态码并列；检查时间、正在获取、未取得结果与不会自动刷新的快照说明不构造 TTL 或持续健康保证。延迟保留真实整毫秒值，并说明 0 可能为取整或未计时，不擅自改成 <1 ms。

停止自动核对统计源为用量请求，入口明确通向相关用量复核案件队列，并说明它包含其他案件。仅当前身份具备用量读取权限且真实目的页可用时提供入口；统一查询参数清掉旧详情、游标和无关筛选，限定真实 USAGE_RECONCILIATION_REVIEW 案件类型，不伪造停止项精确筛选。新版独立页与旧版 tokens 宿主均走原路由/客户端/服务端权限；旧版 retained 管理区同时接收 routeSearch，以免 URL 已变而仍停在上次子页。全部为读取导航，不新增恢复或资金操作。

### UI038 / S24-03：从真实差异案件核对支付证据

具备对账读取与财务修复申请权限的操作者可从实际差异案件打开证据确认表单，目标案件 ID 直接沿用该记录。原有独立手填入口继续保留，不要求仅有申请权限的用户额外取得案件读取权限。

案件来源读取使用受 platform.billing.reconciliation.read 保护的 Billing GET /admin/v1/reconciliation-cases/{case_id}/repair-context，经门户明确 GET 白名单转发。单次读取只按案件主键关联它的原始对账批次，展示原批次、供应商、渠道、业务日、版本和精确的渠道记录金额/币种；不把后来关联的观测批次当作原始账期。金额和案件版本采用十进制字符串，缺失或不能解析的来源金额单列说明，不补零。该读取有独立三秒服务端预算，不进行供应商调用、审批、结案或资金写入。

来源卡片只供核对。操作者仍指定支付证据，既有审批前校验逐项校验案件/证据/账期和其他真实条件；通过后以原冻结投影显示已确认的案件、原批次、证据、业务日、精确金额和渠道交易。该结果不等于审批或执行完成。原始输入/严格回显、金融风险类别、冻结事实、未知写同键恢复和执行时再校验保持。

来源读取只接受当前身份、会话、客户端、案件和输入修订版本；修改目标、刷新来源或身份换代时失效旧资格，迟到结果不能覆盖当前记录。冻结未知意图显示原事实且禁止来源更新。此项展示权威账期但尚未自动填入日期字段，UI039继续完成独立预填。

案件入口使用不可编辑的真实来源案件 ID 固定目标，并为该案件保留稳定独立的未确认操作记录；原手填入口的恢复身份不迁移、不改变。成功或重置后仍保留该案件目标，返回已访问的表单不会成为空白且不可编辑的死路。当前实际挂载树仅有一个手填宿主及一个 selected-case 宿主；若未来增加同案件并行宿主，需重新审查恢复记录归属。
