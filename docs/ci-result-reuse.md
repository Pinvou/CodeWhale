# 合并队列的逐测试结果复用

本机制沿用现有 `changes → ci-test-reuse.py lookup → job if → required-gate`
链路，不新增工作流、任务调度器或 Runner。仅复用同仓、同 PR 当前 head、24小时内
完整成功且有成功凭证的实际测试步骤；矩阵必须全部成功，资源退休步骤不能跳过。
缺失、过期、失败、取消、API/对象读取失败、未知队列形状均保留执行。

PR Check 的 schema 2 凭证按 job 记录输入摘要。消费者独立读取原 PR 测试提交，
核对其真实双亲和文件树，重新计算摘要；不能只信工件自报的“已通过”或摘要。
main 的提交号变化不再单独导致失效，相关源码、锁文件、工具链、子模块 gitlink、
文件模式/符号链接、有效配置、路由或差异选择输入变化仍重跑。
仅在作业或准备作业直接使用 `backflow_mode`，或通过间接表达式读取 `needs` 时，
摘要才纳入该模式。Windows Rust 的运行模式变化仍需重验，前端和版本等不读取该字段的作业可继续核对证据。
schema 1 旧凭证和另外两个凭证工作流继续使用原整树校验。

当前只收窄已核对的 Rust/CLI 测试组：桌面应用、CodeWhale、私有运行时、CLI、
知识库及 Relay 都计入输入；独立 Account/Hub/发布控制台服务目录不作为这些组的输入。
其余测试组保留整树输入，避免为追求复用率猜测跨产品契约的依赖范围。
根目录文件、全部共享脚本、工作流/本地 actions、文档、部署配置以及任何未分类目录
仍影响全部组；同一 job 的生产者配置和未知配置也保守保留。

复用校验器、输入契约和对应工作流必须与已合入的基线版本一致。修改这些规则的 PR
不能为自己的测试授权跳过。Runner 镜像/环境调整应同步更新既有
`PINVOU_CI_REUSE_EPOCH`；`PINVOU_CI_REUSE_FORCE_RUN=true` 仍可强制重跑。
队列查找日志使用固定原因码，区分受信策略变更、来源不符、凭证过期或缺失、
工件下载或解析失败、Git 对象不可读、作业输入变化及执行证据不全。下载或解析失败时，
查找在现有候选和时间上限内继续核对同一 head 的其他凭证。凭证仅保存配置摘要，
日志省略配置值和异常原文。缓存命中与测试结果复用是不同机制。
