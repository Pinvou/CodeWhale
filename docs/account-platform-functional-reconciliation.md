# F03 四方对账

F03 在已审核 F02 个人支付、整笔退款和原资金门禁之上增加供应商付款、供应商退款、内部交易、账本事实的对账。每个批次按上海业务日处理；每日 worker 仅在供应商声明支持账单 API 时运行，使用持久批次去重。手动获取和文件导入由 `platform.usage.reconcile.retry` 管理，读取由 `platform.usage.read` 管理。

供应商账单不含客户与 SKU 权威字段。未入账付款需真实供应商查单确认全部冻结事实后才进入原付款合并路径，不能从内部订单补造外部事实。无法确认的账单保留原证据和差异案件，不改写已入账付款或重复账本。退款和拒付只参与事实对比，不从账单直接发起金融修复。

后台对账页提供批次和差异分页、实际账单导入，以及认领、分配、处理方案、复核、忽略和重新打开。案件操作使用同一演员、同一事实和同一幂等键；丢失回执时保留原操作，错误资源或未知成功不会清掉该操作。批次列表采用所选上海业务日期至次日的半开区间。手动获取和导入没有幂等键契约，未知结果需刷新当前批次核实，不提示同键重试；案件操作仍保留同键重试。金额读取承接既有十进制字符串投影，导入写请求保留原 JSON int64 数字字节。中英日文由共享 i18n 提供。

`contracts/openapi/reconciliation.yaml` 登记有限实际接口。生产使用个人及资金部署覆盖后再应用 `compose.reconciliation.yaml`，同时绑定已审核 F03 Account、Billing 与 Portal 镜像，使 Account 阶段权限投影与对账接口一致；仍需私有供应商配置和原授权接线。内部运行接口保留独立工作身份权限 `internal.billing.reconciliation.run`，不对个人 UI 放行。F03 不安装新 SQL：实际所需对账存储已作为 F02 不可达共享存储随原 004、028、029、034、050 安装。

F03 不包含未来财务修复审批或 Token 使用量对账，不启用组织、赠送、模型及注销业务入口。初始构造使用明确登记的 F02 `DRAFT_INPUT`，该输入不是前序审批或 Git 传播；最终必须与真正审核固定的 F02 归并后核验实际组合。整个端到端验收按用户指令延期，不能用定向 PG、受控供应商或浏览器夹具代称真实供应商或整套验收通过。
