# F03 四方对账

F03 在已审核 F02 个人支付、整笔退款和原资金门禁之上增加供应商付款、供应商退款、内部交易、账本事实的对账。每个批次按上海业务日处理；worker 仅使用供应商明确声明的能力。金融对账读取使用 `platform.billing.reconciliation.read`，手动获取和文件导入使用 `platform.billing.reconciliation.run`，案件管理使用 `platform.billing.reconciliation.manage`。原 usage 权限保留其用途，不能代替金融权限。

供应商账单不含客户与 SKU 权威字段。未入账付款需真实供应商查单确认全部冻结事实后才进入原付款合并路径，不能从内部订单补造外部事实。无法确认的账单保留原证据和差异案件，不改写已入账付款或重复账本。退款和拒付只参与事实对比，不从账单直接发起金融修复。

后台对账页提供批次和差异分页、实际账单导入，以及认领、分配、处理方案、复核、忽略和重新打开。案件操作使用同一演员、同一事实和同一幂等键；丢失回执时保留原操作，错误资源或未知成功不会清掉该操作。批次列表采用所选上海业务日期至次日的半开区间。手动获取和导入没有幂等键契约，未知结果需刷新当前批次核实，不提示同键重试；案件操作仍保留同键重试。金额读取承接既有十进制字符串投影，导入写请求保留原 JSON int64 数字字节。中英日文由共享 i18n 提供。

`contracts/openapi/reconciliation.yaml` 登记有限实际接口。生产使用个人及资金部署覆盖后再应用 `compose.reconciliation.yaml`，同时绑定已审核 F03 Account、Billing 与 Portal 镜像，使 Account 阶段权限投影与对账接口一致；仍需供应商配置和原授权接线。内部运行接口保留独立工作身份权限 `internal.billing.reconciliation.run`，不对个人 UI 放行。审核修复通过 Account 092 增加独立权限及新版本审计策略，通过 Billing 900006 增加批次处理进度、稳定案件事实指纹和批次关联；原 004、028、029、034、050 和已发布策略不修改。Billing 部署沿用 F02 独立迁移/owner 身份与 runtime 权限收回。

F03 不包含未来财务修复审批或 Token 使用量对账，不启用组织、赠送、模型及注销业务入口。已通过普通 merge 承接 F02 已独立审核且当前 CI 通过的修复，保留双方原始提交。整个端到端验收按用户指令延期，不能用定向 PG、受控供应商或浏览器夹具代称真实供应商或整套验收通过。确认的非阻塞问题与支持边界记录在 [Issue #1570](https://github.com/Pinvou/pinvou3/issues/1570)。部分拒付缺少独立现金金额事实时需要人工核实，不能从撤销积分反推现金金额或执行自动资金处置。

导入公开条数上限为 100000，只有已认证且具备运行权限的专用导入路径接收最多 64 MiB JSON；普通接口保持原小请求限制。Portal 在读取大体前通过服务端 session 的 AccessToken 获取可信 Account 当前权限，Billing 再次执行实际授权。此预检增加一次最长三秒的 Account 只读依赖，授权服务暂不可用时拒绝读取和转发大体。非法 JSON 返回明确 400，超过预算返回 413，不以空 200 表示成功。默认财务操作员拥有读、运行和案件管理三项权限，财务审批员及审计员仅有读取权限，超级管理员拥有三项，模型/运维角色不会因为原 usage 权限获得金融权限。

完整批次输入先持久化，处理进度与每笔可信付款合并通过短事务一起提交；外部查单不持有金融事务。只有全部必需事实完成才返回原 200/201 COMPLETED 回执，超时或暂时失败以 503 和批次 ID 表达待核实，后续使用已存输入恢复。未完成批次的 `completed_at` 为 null，这是用户确认的接口调整，客户端不能把开始时间视作完成证据。

持久批次每分钟尝试恢复，临时失败有下一次重试时间并轮转，不能由最早失败批次永久阻塞后续批次。供应商账单每小时复查最近七个已完成的上海业务日；每个已支持 channel 最多七次观察调用，不因每分钟恢复而重复全量查账单。相同供应商账单仍核对当前内部财务事实及订单绑定；事实变化生成新批次，保留旧完成回执，事实未变才复用观察。Billing 900007 将输入唯一约束限定为文件导入，保留同一文件的稳定回执。更早的迟到事实通过显式手动重查处理，这一窗口是本轮有界恢复策略，不是对未定义 T+N 产品需求的宣称。仅支持文件导入的供应商仍可恢复持久批次，不调用未支持的账单 API。

账本核验检查分录金额、账目类型、钱包、积分批次及来源关系，现金分与积分微单位分别比较；合法的应收还款和后续消费不应造成误报。关闭差异案件必须重新取得可信供应商事实并核验当前内部差异已消除，处理说明不能代替事实；资金修复仍通过原受控路径进行。重复批次通过关联保留共同案件及原证据，不能仅以新批次 ID 制造同一问题的新案件。

审计观察及原始财务快照不可更新或删除，案件生成按每百条保存短事务进度。恢复取得批次锁后重新读取终态，已完成回执不重新处理。恢复前核对当前关键财务事实，事实变化时生成新观察并保留旧观察；批次当前案件读取使用活动观察，不能把旧观察静默覆盖为新证据。900007 新增可空 `source_bindings`，保存参与指纹的未入账订单绑定证据；历史空值不伪造回填。案件再次出现会保留历史并重新打开，已忽略案件只接受相同事实指纹，事实变化必须重新审查。

退款和拒付的本地处置时间不能代替供应商发生日期。当批账单按冻结供应商身份、版本、channel、订单和具体来源标识匹配跨日终态；已有可信成功 API 账单提供的实际日期用于报告归属，不改写退款或拒付的金融时间。无法取得可信发生日期时进入人工日期核实，不能据此宣称资金缺失；原资金处置门禁保持。
