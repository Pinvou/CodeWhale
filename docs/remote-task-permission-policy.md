# 远程任务的 B 端权限模式

远程任务不会继承 B 的普通聊天或代码页面默认权限。B 必须在本地 `settings.json` 明确配置每条远程任务通道；没有配置的通道拒绝创建和执行新任务。A 的请求不包含可升级权限的配置字段。

关闭 B 应用后，保留已有设置，在顶层加入下面的对象，然后重新启动 B：

```json
"remote_task_permissions": {
  "chat": "plan",
  "code": "plan"
}
```

可选值仅为 `plan` 和 `yolo`。省略对象、省略通道或使用 `null` 均不授权该通道；未知值只禁用对应远程通道，不回退到自动执行或重置其他本地偏好。配置失败会通过现有三语远程任务错误界面显示；诊断码 `task_permission_mode_required` 表示该通道未明确授权，`task_permission_mode_changed` 表示持久通道/模式证据缺失、失效或当前状态与登记不一致，`task_permission_mode_unsupported` 表示 adapter 能力、模式配置或返回值不符合契约。原始本地路径和 provider 错误不发送给 A。

- chat 的 `plan`/`yolo` 复用 CodeWhale 的 Plan/Agent 模式和既有工具权限规则。
- code 仅支持可识别的 `@agentclientprotocol/codex-acp` 1.6.2 包及其明确报告的模式选项。`plan` 映射到 `read-only`（readOnly 沙箱、关闭网络、on-request 审批）；`yolo` 映射到受限 `agent`（workspaceWrite 沙箱、关闭网络、on-request 审批），**不映射到** `agent-full-access`（never 审批、dangerFullAccess）。这些语义来自该版本的 AgentMode 契约，不能推用于其他 ACP provider、任意替代二进制或未知版本。
- code 的配置只作用于当前精确会话，不更新 B 的普通 ACP 全局默认。provider 不支持指定选项、配置失败或返回值不匹配时，不发送 prompt。
- provider 发出的权限请求继续由已有远程权限 owner 和 A 的批准/拒绝链处理；B 的显式模式不能替代 A 对这些请求的决定。on-request 并不表示每个读取或沙箱内操作都必须产生独立审批。

尚未选定通道的协商只创建共同会话记录，不读取 chat 或 code 策略。可信首次通道 claim 读取 B 对应配置，先在普通会话的物理目录 `sessions/<id>/remote-task-permission.json` 登记不可变的通道和权限模式，再严格持久化当前模式；只有 code 配置也可协商并选择 code，两条通道可以配置不同模式。登记复用私有目录锚点和不覆盖发布，两实例同时首次认领也不能互相覆盖。ACP 绑定失败时通道尚未发布，已完成两份持久写入的合法同通道重试可复用会话；配置变化或改选另一通道均拒绝，即使两条通道模式相同。既有登记不是重写当前模式的许可，后续 claim 只验证，不重置用户选择。

登记独立于内存协商、连接映射及有界任务 ledger；清映射、退出或任务修剪不撤销或改写它，普通会话删除时随会话目录清理。恢复或切换历史会话必须严格读取登记、B 当前通道配置、落盘当前模式和内存模式；读取失败不回退启动缓存。普通本地模式文件格式及原有容错读取 API 不变。B 本地 Unknown→Chat 也须通过同一校验，不能把已有 code 登记当作 chat。

本功能尚未发布，不猜测迁移旧远控会话：缺失、损坏、超限或不支持版本的登记均拒绝恢复执行，由 B 新建远控会话；只拥有旧模式或历史任务不足以补登记。登记成功而模式写入失败时，保留不可变登记并拒绝执行，不能删除登记后改选通道，也不自动补写模式或重新派发。原子不覆盖发布不是跨文件事务，亦未证明断电无损恢复；丢失证据仍拒绝执行。新路径缺失或会话记录已删除时不得凭旧目录句柄继续授权；本次不声称解决 SessionStore 既有的跨进程删除/执行竞态。

执行前模式必须仍与 B 配置一致，不能把已选定的旧会话静默提升到新模式。调整配置会拒绝后续不匹配的执行；要使用新模式，应建立新的远程会话，不要只在原会话中创建新任务。已经进入执行的合法回调、取消收尾和历史记录继续按原 owner 处理，不清除或重新派发旧代际任务。

chat 的远控适配器负责读取和核对冻结权限；通用 EnginePool 只接收明确的模式参数，不读取远控策略。校验仍发生在附件及模型异步准备之后、转交该回合 reservation 之前。code 配置时已退休的实例返回临时运行时不可用，不伪装为永久权限模式缺失；busy 拒绝保持原语义。任务结束不恢复覆盖会话模式或新实例，全局普通 ACP 默认不变；同一远程会话的后续任务仍需验证原冻结模式。

配置 RPC 失败保留其原始错误链，不把通信故障或原因未确认的 provider 拒绝归为永久模式不支持，也不接受旧配置快照作为本次成功回执。对 A 仍只返回已有的运行时不可用类诊断，不发送原始 provider 错误，不自动重试或重新派发任务。明确的能力缺失或成功配置后的不符回执仍返回模式不支持。

未认领会话的创建端口默认明确拒绝；实现必须显式支持不选择通道的共同会话创建，不能借用 chat 创建路径。当前桌面实现已有该独立路径，首个可信通道 claim 才读取并冻结对应策略。

此设置不授予新工作区访问权，不扩大 A/B 身份授权、能力清单或工具范围。修改其他权限或撤销设备仍遵循各自原有流程。
