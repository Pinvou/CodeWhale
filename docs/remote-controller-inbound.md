# A 控制端入站预算与失败收口

A 专用入站 inbox 在真实 transport 已完成角色、generation、协议和租约准入之后记账。它独立于出站队列及 B/Legacy Web v2，不替代消费侧 AEAD、重放和当前 owner 验证。

每连接最多持有 64 个控制帧、256 个业务帧，原始 String 分配容量总预算 8 MiB，其中业务最多使用 8 MiB−128 KiB，为控制保留至少两个最大 64 KiB 控制帧的空间。业务额度可容纳协议最大合法 wire frame。正在处理的帧继续持有项数/字节许可，直到两个现有串行消费者请求下一帧或 Port 销毁；握手移交 keeper 不提前归还。

该预算约束排队和当前消费者持有的原始缓冲。固定项数限制队列元数据；WebSocket 当前读帧、JSON Value、密码学临时副本及持久投影缓存另受各自约束，8 MiB 不是全进程峰值承诺。同步投影不能被队列调度强制抢占。

控制/业务各自 FIFO，控制优先。断线到达时暂停业务交付，以常量空间保存第一次待处理断线之前的有限控制前缀：前缀→Disconnected→后续控制。重复断线不后移此前缀、不刷新认证截止。与主线 transport 所有权投影一致，每个已接受的断线按到达顺序携带本地 owner 上下文逐条交付，供消费侧过滤旧 owner；待交付断线上限为 8，超限时淘汰最旧上下文，前缀记账与常量空间不变。已接受的断线先于随后出现的本地终态交付，其恢复尝试在已停止的 transport 上按既有契约失败关闭。保留的业务不会被交给恢复处理器当作无关帧丢弃；完整认证恢复且业务通道重新激活后，按原租约/密钥/序号继续消费，新业务仍排在旧业务之后。这样即使 B 随后静默，已经接收的最后一条 journal/terminal 仍可投影。恢复失败、明确断开或 owner 换代则按原契约结束该连接。

项数、字节耗尽或生产端关闭使用独立且不可丢失的首个终态，不占普通队列位置，不自动转成网络恢复。准入立即拒绝后续帧、丢弃本次连接积压，并请求停止捕获的 exact transport；不等待队列腾位，也不创建无限等待任务。消费者再次运行时，仅以原 operation 提交 Error、清业务并发布状态。旧消费者/队列销毁不清理新 owner。

本地固定诊断原因是 `inbound_item_capacity`、`inbound_byte_budget`、`inbound_closed`；对外复用既有 `endpoint_offline` 公共码，日志区分本地来源，不透传原始帧、远端错误文本或凭证。握手成功交接和返回前复核本地终态及已知断线，避免把已失效的 joined 结果遗忘为可用连接。

40 秒整体握手上限、原 30 秒认证证据/恢复冻结截止和 reader socket epoch 一次性授权保持。队列等待、重复断线和容量故障不延长它们；只有既有有效证据或完整认证恢复才可更新周期。

回归在真实产品 lib 的 `controlling_inbound::tests` 与 `controlling_service::inbound_tests`；Windows 正式 regression 的已链接 exe 执行两个精确非零筛选，Linux 仍按既有全 lib 门禁运行。发布仍须独立通过 #1428 的安全前置条件。
