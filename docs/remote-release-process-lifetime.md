# 发布子进程的有界收口

Windows 远控的本地校验和远程可信命令共用 `windows-e2e-process-guard.ps1` / `windows-owned-process.cs`。新进程挂起创建，先进入本次命令的独立 Job 再运行；标准输出和错误同时排空。默认命令期限十分钟，可显式设置 1 毫秒至一小时；期限也覆盖等待管道 EOF。取消令牌与超时均终止本次 Job，确认成员清空；清理与管道收口各有五秒上限，不以进程名、父 PID 或共享 Runner Job 清扫。

每个 Windows 输出流最多保留 16 Mi 个字符，超过时继续排空并拒绝结果，不将截断的 JSON 当作成功。非零退出保留退出码，公开输出收敛为 `e2e_process_nonzero_exit`，不回显原始输出、参数或环境。执行失败与清理失败分别保留，外层清理不替换已经发生的主失败。

成功的可信 `start-role` / `legacy-start` 命令可能创建本轮需要的长驻服务；其精确 Job 继续由本次 nonce 所属 staging/session 持有，而不是在命令返回时结束服务。原有角色停止及持久归属注册表检查继续执行，最终清理另外关闭全部本轮 Job 并确认清空。失败或取消的启动不交接；未知后代没有全局放行。Job 的 kill-on-close 还覆盖宿主进程退出。

Node 发布门禁通过 `release-process.mjs` 调用仓库现有 Python 进程所有权实现，使用 Windows 独立 Job / Linux subreaper；不修改 CI 夹具的门禁或失败规则。执行门禁需要现有开发/CI 工具 Python 3（Windows `python`、Linux `python3`；CI 可通过 `PINVOU_CI_PYTHON` 选择解释器），仅使用标准库。该监督实现支持 Windows 和 Linux；开关关闭仍不启动任何命令。Node 同时消费两条输出流，错误诊断仅保留有界控制回执；传给命令的环境仍为原用途白名单，解释器及监控不增加命令的敏感环境继承。

解释器验证使用具有标准输入输出的 Python 命令行程序；GUI Python 或自定义嵌入宿主的标准句柄行为未验证。Windows 原生输入用例同时检查 Win32 标准输入是字符设备及 CRT 读取立即 EOF，不仅依赖 Node 对输入句柄的处理。

Windows 还用同一探针验证普通 EOF 管道必须因设备类型而拒绝，避免只读 EOF 的检查替代 NUL 语义。支持的 Windows/Linux 完整 CI 测试要求既定十个原生场景实际完成，不能将它们全部跳过后仍通过；本地聚焦测试和未支持平台不冒称原生覆盖。

回执分类测试执行真实 Node 接收与结算逻辑，覆盖合法 `start_failed`/`execution_failed`、独立清退确认和已知主退出/本地取消/超时的优先级。结构合法但当前 Python 写方不产生的字段组合只作为读方兼容合同探针，不代表真实原生复现；没有退出证据时不制造退出码。

两条输出流的读取错误均请求同一私有停止通道，在原清退期限内结束，重复错误不重置期限；诊断为 `release_subgate_output_failed`。已知本地取消/超时或已观察到的非零主错误仍优先；Python 为停止命令而回传的取消不替换先发生的读取故障。清理是否确认独立记录，缺少有效回执仍为未知。回执的 `reason` 只接受 `null`、`timeout`、`cancelled`，清理字段只接受布尔值；坏类型不参与成功或取消判定。

超时/取消先通过私有输入控制管道通知监督器，等待精确清理回执；取消的额外等待上限二十秒，缺少回执始终失败，不当作已清理或允许重试。非预期的存活后代即使被收回，也不作为成功子门禁。原命令非零退出码、超时、取消、未知清理分别保留，原始错误文本不传播到公开异常。

选择的 Python 必须能在用途白名单环境中直接启动，不能依赖被过滤的动态库环境变量。Linux CI 沿用 runner 已有 Python，不让工具安装步骤替换全局 PATH；自托管 Windows 同样沿用预装解释器，只有 GitHub 托管的 Windows 执行 Python 安装步骤。没有有效回执时，异常只增加监督器的有限整数退出码与 `missing` / `invalid` 回执类别，仍明确 `cleanupConfirmed=false`，不回显解释器路径、环境、nonce 或原始 stderr，也不把启动失败混同为清退期限耗尽。

共享监督函数的可选 `exit_evidence` 只接受普通字典，记录命令是否创建及首次实际观察到的根进程退出码。默认 CI 调用不传该参数，原取消返回值、Job/subreaper、等待与清理判定均保持。发布调用另保存已经观察到的非零主退出码，晚到的超时或取消只影响后代收口，不覆盖该错误；原监督返回码同时作为独立证据保留。命令尚未创建时的启动失败可确认没有子进程；已创建却缺少退出/回收确认时仍报清理未知。
