# MegaCube 单机管理：最终决策与实现说明

本文记录 Pinvou、模型商店与 Cube Manage Software 的单机职责、已经确定的取舍及验收边界。操作入口见[单机管理](megacube-single-node.md)，商店版本合同见[当前部署选择](megacube-model-store-selection.md)。同仓 [`components/cmsd/docs/single-node-decisions.md`](../components/cmsd/docs/single-node-decisions.md) 记录后台领域决策，其 `/v1` 协议文档继续作为字段和错误行为的依据。

## 交付范围与依赖

本批交付同一台 Linux 主机、同一个非 root 账号、用户级服务下的桌面闭环：组件安装与恢复、独立后台商店、模型安装与启停、默认选择、开机偏好、资源准入、维护清理、MCP 及原会话换模接续。关闭桌面不终止已受理任务。无需 LLM 的设备和商店入口始终是救援路径。

可读名称统一为 **Cube Manage Software**，守护进程、命令与协议技术标识保留 `cmsd`（c = Cube、m = Manage、s = Software、d = daemon）。本单机组件尚未发布，不引入旧品牌别名、旧名称兼容入口或第二套命名规则。已有路径和协议标识是否保留，以各自合同为准，不由界面品牌替换推导迁移。

Pinvou 变更以模型商店 [PR #1995](https://github.com/Pinvou/pinvou3/pull/1995) 为堆叠依赖：检查更新、隔离下载与历史版本管理复用该实现，不另建版本系统；依赖合入后再将目标分支改为 main，并核对实际差异及受影响门禁。持续评审不因主线日常更新反复重放整批变更，合并集成由仓库既定流程验收。

原有 standalone system 模式保留独立管理用途。root 后台与桌面用户商店跨账号联动需要另外设计和验收权限隔离，本批不靠放宽数据库、卡片、socket 或锁的账号校验支持它。Windows/macOS 管理入口明确返回 unsupported；既有聊天功能继续使用对应平台适配。CodeWhale 提供工具循环、Session 和模型调用，本批不修改其 gitlink 或 fork 行为。

## 状态所有权与执行边界

| 对象 | 权威与执行者 | 选择理由 |
|---|---|---|
| 卡片、脚本、附属资源、权重路径、部署配置、current | Pinvou 模型商店与 SQLite 版本事务 | 保留 #1995 的完整手动回退，避免两套当前版本互相覆盖 |
| 标准安装、下载、部署与商店卸载 | 独立 model-store host | UI 或 LLM 退出后继续，所有入口使用同一执行器和互斥 |
| 模型生命周期、管理权、预算、默认网关、恢复意图 | cmsd | 停旧启新与补偿由持久程序推进，不能依赖被停掉的 LLM |
| cmsd 软件、用户服务登记及组件恢复 | Pinvou 独立维护 helper | 停止 daemon 后仍能完成更新或恢复；组件维护与模型任务互斥 |
| 已保存模型连接、用户参数、原会话绑定 | Pinvou 设置事务与会话引擎 | 路由事实可刷新，凭据、显式参数和用户手动选择有明确归属 |
| 实验成果与历史检查证据 | 独立工具私有记录 | 成果可保存和复查，登记本身不授予 cmsd 管理权 |

Linux 桌面从启动起就连接同一独立商店 host；首次安装 cmsd 后无需重启桌面或迁移进程内队列。host 入口在窗口、WebKit 和桌面单实例初始化前执行。后台使用运行身份、私有 socket、宿主锁及协议/版本检查；忙宿主继续完成原任务，空闲时才按受控交接升级。版本冲突明确拒绝，不同时启动第二个执行者。中断后先核实并清理属于原执行代际的孤儿脚本，再将未终结任务记为 interrupted，不自动重发可能已有副作用的部署。

## 组件维护：先证明对象，再变更登记

组件状态区分未安装、当前用户已绑定、只读/系统服务、失联和归属未知。显示“找到 cmsd”或 socket 可连接，不能替代已安装包、unit、配置、进程与 peer 的绑定证明。维护核对注册原件及摘要、文件归属、systemd MainPID、OS peer 和进程代际；正常进程切换造成观测跨代时，只在新鲜有效 MainPID 确已变化的条件下有限重验。稳定不匹配、外来 peer 和注册漂移继续拒绝。

离线包先检查清单、大小、SHA-256、ELF 平台和能力，再复制到私有摘要目录执行探针。包的自附摘要与 `--component-info` 只证明内容及兼容声明，不构成发布者签名或发行认证。使用显式选定的可信来源，不将“本地 hash 正确”扩大成来源可信。

cmsd 源码直接纳入同仓 `components/cmsd/`，保留独立 Rust crate、`0.1.x` 组件版本及既有进程边界。该目录从历史 CMS 提交 `80a7ebc` 导入，此后为唯一开发来源；历史仓库保留记录，不并行维护第二份源码，也不依赖其 Release。Linux x86_64 / arm64 的统一 `build` / `bundle` 从当前 Pinvou 提交编译并校验组件，自动放入 `runtime/cmsd/`，正式构建拒绝 `PINVOU3_CMSD_PACKAGE` 外包覆盖。CI 直接测试独立 crate，发布 workflow 与本地 OTA 脚本在正式 deb 上传前验证组件存在、清单、摘要、架构和 ABI。其他平台管理范围不扩大。

发现随包候选不安装、不启动，仍由用户确认后登记为同账号的 systemd 用户服务。桌面通过 Unix socket 调用它；独立商店 host 与组件维护 helper 由 Pinvou 提供。用户更新 Pinvou 后，已有后台仍须确认组件升级。源码构建身份与实际发版包、GUI 自动发现、服务安装分别验收，不能以 debug/no-bundle 或显式包路径的测试代替。

中断回执只封存已持久化的维护现场：首次安装在受理后、登记落盘前被硬杀时，回执之后没有可恢复的服务记录，重试安装不视为绕过恢复门；登记一旦落盘，恢复仍走 restore/rollback 等既有入口。

安装、更新、回退、恢复和解除维护均核对所需能力，包括当前部署选择、原生卡档位/预算、实例隔离和 `local-v1` 状态范围。更新前发现远程身份或计划授权格式时保留原件并拒绝，不删授权状态强行降级。软件回退只更换兼容二进制与登记，不回放旧授权、旧任务或旧恢复意图。

配置迁移、unit/drop-in 替换及 Pinvou 自有服务卸载使用耐久登记事务。reload 失败、helper 中断或候选启动失败后，依据原字节和绑定回执恢复原登记，再提供启动/恢复入口；外来改动不能被旧副本覆盖。没有事务回执的缺失单元不自动获得恢复授权。卸载服务保留模型、权重、配置、设备状态、任务及回退缓存；不等于清空设备，也不自动更改 linger。

## 当前部署、历史版本与管理权

“当前”由商店成功发布的 logical card → physical card、version_id、deployment_revision 决定，不是目录最新、远端最新或最后扫描到的权重。修订包含有效脚本、附属文件、引擎与实际配置。普通启动、默认选择和自动恢复只接受有效 current。历史、ready、失败暂存及已保留但未部署的权重不因文件仍存在而重新进入运行候选。

用户可以在商店手动完整切回已验证版本，恢复目标的本地卡片、脚本、附属资源、权重路径和部署配置，然后原子发布 current。cmsd 随新 current 解析物理对象；不自行选历史目录，也不重放归档运行意图。逻辑开机偏好跟随逻辑卡迁移，旧物理版本撤下自启。部署失败或保留权重卸载后的 current 可保留清理身份，不能取得启动或默认权限。

已有容器和原生模型必须核实真实部署。容器核对可信配方已建模的镜像、挂载 source、网络/端口、内存比例及声明参数；原生实例核对引擎 inode、账号、权重、unit/进程绑定、监听所属 PID、准确模型 ID 和受管运行参数。HTTP 健康、同名、同端口或同容器名称均不足以证明归属。未建模的任意脚本参数仍需人工核对，不能声称获得完整脚本配置证明。

仅发现或实验登记保持只读。`managed` 表示已有生命周期管理权，`can_adopt` 表示可在明确启用目标下申请接管，`can_reserve_uninstall` 只表示可以申请清理预留。健康与预算足够均不能替代管理准入：健康但未托管的可接管对象须先明确授权启用并重查；正常停止且可接管的完整部署可在授权后走标准 switch，由其内部 enable 经同一准入取得管理权；只读、未部署或未知对象不提供可直接执行的默认/换模建议。

容器首次创建使用 current 记录固定的 `models_root`，不使用后来变化的默认下载目录。字段未知、目录缺失、变成链接或无法核实时，在脚本前拒绝并保留卡片、权重和原部署。恢复应使用原登记目录/挂载或匹配的完整商店记录，不能猜路径、自动回填或通过重新下载掩盖身份缺失。已有容器与原生服务不因此重跑首建脚本。

## 恢复、预算、任务与清理

cmsd 托管对象的开机/崩溃恢复由持久意图驱动。Docker restart=no 与原生 Restart=no 用于阻止后端绕过 cmsd 的同一预算、维护门、生命周期互斥和身份检查；这与 `boot_enabled=true` 可以同时成立。外部只读对象的原策略不因发现而改变。显式停止先撤恢复意图，防止对账重新启动；失败、未知和熔断保留原因，重启 daemon 不清除重试历史。

启动、换模预检、自动恢复和容量展示共用同一保守需求函数。原生卡可声明预留，需求取有效声明、有效测量与权重加运行开销下限的较大值，再保留系统边际；配置变化使旧标定失效。MemAvailable 是系统可用量依据，不能把 SwapFree 或 CUDA 空闲量直接当成可分配预算。下载磁盘空间、运行内存、静态估计和实际峰值分别说明；单机成功不能证明任意模型、上下文或并发均能满载。

持久任务先落盘关联、原请求类型和身份，再向执行者发送。超时、断线、临时 not_found 或未知应答不能证明未受理，也不能释放排他后重新安装。标准失败恢复沿用原 run_id、download/install_local 语义、固定目录与审阅包摘要；只对具备幂等合同的重试关联退避重投。取消先保存意图再转发；cancelling 不是脚本已退出，完成与取消竞态仍可能成功。下载成功、部署成功、启用成功分别报告。

任务列表和事件页均有界，不能把第一页当全部历史。已接受的换模在最近 20 条任务索引之外时，仍按私有回执中的原 task ID 有限串行轮转查询；unknown 保留待核实，不当失败、不消耗成功接续机会。运行中恢复任务继续呈现正常可后台化进度，旧终态详情不重新弹出历史维护浮层。商店终态内存索引有保留期，原 ID 私有记录和失败恢复证明按合同继续可查。

模型卸载由商店和 cmsd 的持久维护事务共同执行，固定 logical/physical 对象和私有 owner。正常托管维护与只读清理预留分开：预留不授予外部资源停止权，带 owner 的 purge 只撤登记，文件删除由商店按用户选择执行。停止、脚本退出、后端无自启和路径归属都需核实，才可解除门。中断不重跑删除脚本，不删唯一恢复收据，不用旧脚本绕过失联的管理链路。权限、I/O、引用或身份不明时保留残留并说明具体错误。

未完成安装的失败回执支持用户「放弃」：放弃在回执上打 dismissed 标记（不物理删除回执——删除会让同卡更早的失败记录顶上来，也破坏预览/重试的内容校验链），此后该条不再出现在未完成面板、预览与重试一律拒绝；同卡之后新的失败照常出现，放弃只针对那一次尝试。放弃只撤提醒与重试凭据，不授予任何文件删除，不改耐久任务事实，也不影响其他卡。模型商店「下载」筛选集中展示进行中下载（活跃任务实例）与已中断安装（同一份回执数据、同一组动作），计数徽标承担主动提醒；它只是聚合展示，不新增管理权。

正常下载、本地安装、排队及取消收尾期间，仍由后台登记持有的同卡、同运行 ID、同任务类型的非终态回执不进入未完成安装列表，也不在商店弹出失败横幅。界面在任务与库快照刷新不同步时同样避开已确认活跃的非终态任务；真正失败、取消或失去运行归属且结果待核实的记录继续显示，不自动重试或删除文件。

models_dir 下无库记录的残留目录（取消/失败下载的半截权重）可由用户显式扫描与删除：扫描只读、显式触发、软链接与库记录目录与进行中下载的目标目录一律排除；进行中下载的目标目录按物化卡片元数据推导，推导失败时扫描如实声明列表可能不完整，删除则整题拒绝。删除在执行前当场复验路径（仅 models_dir 直接子目录、非软链）、库记录归属、进行中占用与安装器进程存活，任一不过即拒绝；删除同步等待完成并回报释放字节数。断点续传仍是默认行为：应用永不自动删除半截权重，清理永远逐条确认、不可恢复，已入库模型只能走模型库的卸载/删除。

残留扫描把普通下载登记的共享 `models_dir` 与卡片独占权重根区分开：共享根本身不屏蔽全部子目录，已有模型仍按实际资源目录、仓库名和模型名保护；深层隔离根及其一级祖先继续禁删。残留删除从归属核查到完成持有写入方共用的排他资源锁，并核查全量安装器进程。回执不可读或损坏时明确报告无法确认的活动并拒绝删除；已占用资源时保留文件，待其他操作结束后重试。

残留保护的共享根排除统一覆盖普通记录和旧运行目录回退，深层实际权重目录及其一级祖先仍受保护。扫描和删除接受空格及 UTF-8 目录名，非 UTF-8 名称不生成有损路径操作项，并如实提示列表不完整；读取失败或其他系统账号拥有的一级目录同样不列为可删除项，删除时复核属主。

安装重试使用新的运行 ID；放弃旧回执必须与任务受理串行，并获取同卡跨进程操作锁。其他窗口或服务实例仍在操作该卡时拒绝放弃，保持旧回执和重试内容校验依据不变。已受理但本地运行尚未物化的委托也保留排除；状态无法核实时不把它当空闲，受理与委托绑定保存完成后才释放放弃互斥。下载视图中等待脚本输入的任务只在高于弹窗遮罩的浮层呈现输入表单，中心保留等待状态而不复制应答或取消操作。

残留判断只依据当前账号/配置的库记录、已声明路径和卡片命名约定，无法证明自定义脚本路径或其他配置未使用同一目录。各账号及配置应使用独立权重目录；顶层属主检查不能证明同 UID 的其他配置没有引用。用户确认前仍须核对目录内容，不能把候选列表当作跨账号或任意自定义目录的完整资产清单。

## 路由、上下文与原会话接续

商店关联以稳定逻辑卡为来源，API 请求使用当前服务真实模型 ID。启用或重新部署成功后，即使地址/模型名未变，也刷新连接事实和 EnginePool，使下一轮重新探测当前上下文；不打断进行中的生成。已有凭据、显示名及用户显式参数保留，手动改接口解除商店关联。自动上下文跟随服务，用户固定上限继续参与预算；特定旧配置修复有独立、一次性的严格身份和探测条件，详见[模型商店更新](model-store-updates.md#上下文跟随当前部署)。

设备页或 MCP 普通 enable 成功也会非模态触发成功之后开始的商店事实读取。设备受理返回以及 MCP start/get_task 中已知的 enable ID 接入同一确认队列；即使被最近 20 条索引挤出，仍按原 ID 查询，不重新提交动作。首轮已有成功 enable 时，等旧扫描结束后合并读取一次当前事实基线，不重放历史操作、选择、通知或弹窗。目标按任务实际 logical/physical/current 关联确认；明确已被不同 current 版本、physical 或已确认修订替代的旧任务仅结束观察，无关停用卡不阻塞本目标。缺少确认时保留 pending，不把 unknown 当刷新成功。

host 将本 profile、当前管理端点的已确认健康部署与实际窗口事实带回桌面，桌面沿用关联模型的修订通知；部署与窗口分别保留最后确认值。已确认的新部署即使窗口暂未知，也使相同路由、原有绑定在下一轮重探测；单项 unknown 不擦除旧值；新部署窗口仍未确认时继续 pending，稍后即使确认相同数值，也推进该部署的窗口证明以重探可能采用的 fallback。同一部署已确认后的 unknown/相同值恢复不重复失效。查询失败、身份未确认或过渡态保留旧事实，不改变用户显式参数；忙会话沿用既有下一轮延期重建。

事实确认队列最多 50 项，单轮串行查询最多 8 个已知 ID 并轮转，成功项合并至一次 fresh library；同一 watcher 单并发，沿用现有 CMS/商店请求超时。未确认时完成一轮后按 3、6、12、24、30 秒退避，之后至多每 30 秒一轮；没有把总次数或期限耗尽改写为成功的规则。已观察 pending 不随公开索引淘汰；队列满的新句柄明确记为未跟踪并保留原任务结果，仍在索引中的项可后续纳入，不冒称已刷新。观察仅在当前 webview/profile 内存保存；重开桌面的引擎缓存重新建立，并读取当前事实基线。

MCP 换模接续绑定发起时的原会话、原模型绑定、任务、准确 logical/physical、版本和部署修订。后台完成后先等已开始的路由扫描结束，再读取一份在成功之后开始的新商店事实；同步失败继续保留待接续。接续重新验证目标健康、当前网关及准确模型身份，不把会话订阅到可能随以后默认变化的全局别名。

会话空闲后才提交自动选择，后端再次做 idle 检查及 expected-binding/expected-default CAS。用户在同一会话手动选择优先：手动先完成使旧期望失效，手动后进入则最终覆盖自动选择。全局默认面向新会话；已绑定会话不要求追溯改绑。全局默认写入与自动选择交叠时以既定期望检查点验收，不宣称所有偏好与会话对象跨存储 ACID。手动选择取消接续意图，不取消已经受理的设备任务。

恢复仍有明确界限：接续回执和后台历史有各自数量/时限，空闲等待和健康重试也有上限。超限保留可查询的任务与可手动选择的模型并报告原因，不承诺无限自动接续。

## 28 个 MCP 工具的事实与准入

工具复用同一管理、商店和独立下载接口。内置 MCP 目录每次启动在 bundle 版本相同的早退之前逐文件核对并更新，因此修复不依赖增加 bundle 版本；验收仍需核实实际释放内容。所有结果区分事实、估计、unknown、unsupported 与 partial；失败查询不投影为空列表或“未安装”，监听不等于上游健康，历史验证不等于当前在线。以下完整列出本批 28 个工具，参数以实际 schema 为准。

| 工具 | 职责与边界 |
|---|---|
| `cube_get_status`、`cube_list_models`、`cube_get_capacity`、`cube_get_logs`、`cube_get_task` | 读取设备、管理权、运行预算和有界任务/事件；只读观察不授予管理权 |
| `cube_plan_switch` | 计划同时核对真实管理准入、部署、健康与预算；计划不执行也不替用户授权 |
| `cube_start_model`、`cube_stop_model`、`cube_set_default_model`、`cube_switch_model` | 分别启用/接管、停用、只改默认、持久换模；都遵循实际管理权、维护门和用户授权范围 |
| `cube_list_store_models`、`cube_check_model_repo`、`cube_install_model` | 标准商店目录、模板兼容性及后台安装；标准路径不支持不等于模型不能独立安装 |
| `cube_list_incomplete_installs`、`cube_preview_install_retry`、`cube_retry_install` | 找回原安装、预览原语义/当前包、按审阅摘要重试；不以完整重装替代恢复 |
| `cube_cancel_task` | 按任务所属后端请求取消，保留已有成果并查询真实终态；不是所有生命周期操作的通用撤销 |
| `cube_search_models`、`cube_inspect_source`、`cube_inspect_environment` | 候选、来源和本地环境事实；不以下载量、架构标签或曾安装过同发布者证明质量/兼容性 |
| `cube_fetch_files`、`cube_fetch_repo`、`cube_resume_task` | 独立下载与恢复；不顺带安装依赖、启动服务或切默认，不依赖 cmsd 在线 |
| `cube_validate_artifact`、`cube_verify_artifacts` | 文件观察与后台摘要核验；不执行文件内容，不证明实际推理 |
| `cube_validate_runtime` | 对显式回环 OpenAI 兼容端点做小规模真实推理；耗尽输出预算可为 inconclusive，未测能力继续未知 |
| `cube_register_artifact` | 保存外部成果和真实检查引用；不取得管理权，当前运行状态仍 unknown |
| `cube_install_local_card` | 执行新本地标准卡的安装/下载/部署；不是已有运行服务的无副作用纳管，也不能重放已登记卡 |

驭光仅走对应模型的 H3C 官方商店适配卡，不把它当任意第三方权重的通用引擎。其他引擎保留基于硬件、格式和当前支持证据的开放安装。首次转实验路径说明新增风险并按用户授权继续；独立成果先保存下载、环境、启动方式和真实验证，再处理可选接入。可选纳管失败不抹掉成功成果，不从头重复安装；实验终端操作不能绕过已有托管卡的维护门。

## 下载的完整性、恢复依据与当前结果

独立下载固定可确定的来源版本，校验 Range 区间及远端版本标识，最后计算完整内容摘要。`expected_sha256` 表示匹配调用方给出的预期摘要，其可信度取决于摘要来源；`computed_only` 仅表示计算了本地内容摘要，不能称为来源认证、官方验证或发布签名。

已存在目标每次使用都重新计算 SHA-256，并与显式预期摘要或该原任务保留的完成摘要核对；名称、大小、修改时间、旧校验标记均不能替代重 hash。无法确认一致时保留原件并返回冲突。完整文件使用无覆盖的原子发布；并发写入者创建的目标不会被下载替换。

恢复依据与本轮结果分开保存：任务私有 `resume-artifacts.json` 回执保留先前完成文件的 path/hash，先持久化再重置当前轮次 artifacts，且在发布新目标前持久化新的正向摘要。恢复时该回执只允许重新读取文件并比对内容，不直接计入本轮完成。本轮 artifacts、已完成数量与进度只包含本轮实际重新核实的文件。排队、rehash 或发布/状态保存间中断后仍可接续；当前内容已变化则冲突拒绝。损坏的恢复依据明确报错并保留现场。

取消与失败保留完整文件、可用片段和错误；摘要不匹配不发布成完整产物，不凭失败状态自动删除已有文件。没有稳定版本标识或预期摘要时不盲拼片段。凭据只使用已有安全配置或环境变量引用，公开结果去除 URL 查询参数，私有请求记录不得粘贴进日志、文档或 PR。

## 验证入口与声明边界

验收记录必须固定 Pinvou 提交、同仓组件源码身份、测试实际输入、二进制/组件摘要、配置与测试种类。只有夹具变更且能够证明生产内容相同时，也应明确各项旧结果实际受测的源码，不将旧制品改标为新提交。正式文档描述可复现入口与边界；最终计数、制品对应关系及未通过项写入当次 PR 和本地验收记录。

| 层次 | 可复现入口与证明范围 |
|---|---|
| 静态与契约 | `python3 scripts/architecture-guard.py`、`./scripts/fork-guard.sh --fast`、版本/三语/差异检查；只证明对应静态约束 |
| Rust/Node | Pinvou Rust 库、bundle、Clippy/fmt 及 `npm --prefix pinvou3-app test`；覆盖逻辑和状态机，不等于真实桌面/推理 |
| MCP | `python3 -B -m unittest discover -s scripts/tests -p test_megacube_mcp.py`、`python3 scripts/mcp-server-contract-smoke.py`，以及 `pinvou3-app/tests/megacube_*_test.py` 对应回归；区分 JSON-RPC/夹具与真实服务 |
| 构建 | 统一 `npm --prefix pinvou3-app run build`；原生 debug/no-bundle 与正式安装包分别记录，跳过 ASR/知识宿主不构成完整发布包验收 |
| 单机真实进程 | `pinvou3-app/tests/real_component_*.py`、`real_model_maintenance.py` 等显式传入独立制品的驱动，以及 `components/cmsd/tests/real_*.py`；按驱动参数创建新配置/单元/socket，保存完整错误与恢复过程 |
| 真实推理 | 提供真实权重及引擎后执行模型调用，分别记录下载、部署、收编前后、重启后和会话路由；模拟响应或监听成功不能替代 |
| 完整评审 | 以最终实际差异做三 scope 完整独立审核，逐轮保留结论和来源提交；窄候选 peer 和旧提交的通过不作为最终版本的通过轮次，创建 PR 不等同于批准合并 |

真实验收只操作新的测试 profile、socket、端口、用户单元和测试模型；原服务和权重作为保护对象。失败的旧轮次与新成功结果分别保存，不覆写错误后宣称一次通过。批准候选、测试通过、构建成功、最终评审完成和已创建 PR 是不同状态，必须按实际进展报告。

已知范围外包括远程 TLS 配对、Plan/Grant/Operation、组事务、多设备治理、出厂初始化、独立历史维护页面、跨账号桌面联动、其他平台原生管理、物理整机重启/断电、GPU 满长上下文与并发峰值、多日稳定性和签名发行。网关监听事实尚未完整接入 Pinvou 本机状态卡。独立实验脚本不具有标准换模的自动补偿保证。这些均需独立实现或以对应制品另行验收。
