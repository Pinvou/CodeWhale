# 双端远程控制统计

远控沿用现有行为统计采集、授权、持久化 outbox 和删除机制，不增加采集地址，也不改变远控执行权限。

## 调用与主体

- 总调用 = 本地调用 + 去重后的远程调用。沿用现有任务口径：有明确执行终态的逻辑任务计一次，成功、失败、取消和中断分别统计；提交前拒绝和结果未知不作为已结束调用。
- A 发起、B 执行的任务归属 A。B 在共享会话主动发起的任务归属 B。模型来自哪一端不改变发起者归属。
- 两端只报告自己授权范围内的观测。任务标识使用随机任务 ID 的域隔离 SHA-256，不上传对端安装身份、配对码、地址、路径、提示词、文件名或凭证。模型只上报现有注册表分类。
- 服务端按匿名逻辑任务标识合并，事件 ID 按角色和阶段分别稳定生成。重连、重传、outbox 重试和 journal 重放不新增调用。真正创建新任务的重试使用新的逻辑标识。
- 只有 B 上报时，实际执行计入总调用，但标记为未归属，不将被动执行的 B 纳入用户活跃、激活、WSTA、WEVTA 或留存。A 的已认证结果接收可以在只有 A 上报时提供终态证据；没有证据时保留未知状态。
- 服务端删除某一端的数据后，从剩余授权事实重新计算，不从 B 的事件重建已删除的 A 身份。两端均未开启采集时没有统计记录。

## 事件与结果

在 `remote_control_event` 上增加可选的匿名任务关联、角色、模式、终态、耗时和注册表模型分类。旧的无关联远控事件保留为诊断，不反推历史调用数。

B 的任务 ledger 提供接纳和执行终态，通用引擎观察器提供开始、首输出和实际模型使用。执行结束不依赖 Relay 当前连接仍有效。工具调用沿用 B 的实际执行埋点，通过可选的 `execution_task_key` 关联逻辑任务并归属已授权的发起端；A 的镜像显示不再上报一次工具执行。

A 只有在已认证的 journal 或恢复快照结果成功投影到本地存储后报告接收，两个路径使用相同稳定标识去重；本地提交时保存原始采集授权，重启后继续沿用，关闭或删除统计会清除相关上下文。B 的执行上下文同样持久化，过期和损坏数据不会重建为新任务。上下文最多保留 30 天，发起与执行两类各最多 5,000 条；满额时按最初登记时间逐出最旧记录，不影响另一类记录，重传不会刷新原任务的保存期限。被逐出的旧任务不能再补充接收关联，新任务仍可登记。仅在本机存储，不上传原始任务 ID。删除本地统计或请求远端删除时立即清除这些上下文，即使设备离线也不保留原始任务和会话标识。

本地删除不是原子事务：已清除的部分不会因后续失败回滚。远控上下文、outbox 或任务尝试表的清理、锁或持久化失败会让 `delete_local_data` 返回“清理不完整”错误，不能将该结果解释为全部数据已经删除，应在排除存储故障后重试。此前仅 outbox 清理错误向调用方返回，现扩展到这些持久清理项；会话、工具调用等一般内存表仍沿用既有尽力清理方式，不因此新增全部内存清理成功的保证。

任务获得执行回合后显式绑定真实回合：聊天模式通过发送前登记的 submission 标识确认 TurnStarted，代码模式绑定已预留的 turn ID；同会话的其他本地回合不会认领远控上下文，也不会被吞掉本地遥测。重启恢复终态直接查询预先注入的持久账本，不依赖尚未注册完成的应用运行时。

已进入任务发送路径、且确定未越过发送屏障的提交失败报告为 `task_not_sent`，不进入提交数、等待终态或调用数；发送可能发生但结果未知的首次尝试报告为带 `unknown` 状态的提交，独立于等待中任务。后续实际接纳或终态可以解析该未知状态。B 在已认证入站请求被明确拒绝且未曾接纳时独立报告拒绝，A 关闭采集不影响 B 自己的拒绝诊断。B 本地提交同样查询持久账本，仅在确认未曾接纳时报告拒绝；接纳后安装或执行失败只报告执行终态。没有有效任务 ID 的拒绝保留为无关联诊断，不把空 ID 哈希为同一个任务。预留或本地参数校验等尚未进入发送路径的失败不据此推算提交数。本地委派后的未接纳诊断从 worker 委派开始计算延迟桶，仅用于提交失败诊断，不作为任务执行耗时；已接纳后的失败由账本终态报告，不再追加无关联提交错误。

任务执行成功率独立于连接、权限、传输成功率，不再用所有步骤的成功事件占比代替任务成功率。权限缺失、权限变化、权限拒绝、超时、能力失效和模型不可用使用固定错误类别，不采集原始错误文本。

附件及产物只在整个传输完成或出错时上报；中间分块不作为一次完成传输。传输事件使用基于传输标识派生的稳定事件 ID，防止最终分块重发被重复统计。一次失败后恢复成功的传输可以同时留下失败和成功观测，不能将两者相加解释为文件数。传输延迟分桶测量最终操作的往返时间，不代表整个文件的传输耗时。

## 看板与边界

统计页新增独立的“远程控制”大项，支持今日、7 日、30 日独立切换，展示双端角色安装数、去重调用、任务模式、模型来源、结果分布、首输出与执行耗时，以及连接、重连、权限和传输诊断。沿用小样本百分比隐藏规则与主报表的每日贡献上限。

“未观测到主控接收”表示 B 有明确执行终态而未见 A 的接收事件，可能是 A 未开启采集、离线或回传异常，不能直接视为结果丢失。B 本地发起的共享任务不纳入主控等待接收的分母。执行耗时来自 B 的本地时钟；主控等待结果耗时来自 A 的本地时钟，不直接相减两端时钟。未知耗时保持缺失，不补成零。

执行耗时只使用同一进程内可信的单调时钟差。重启恢复将未结束任务标记为 `process_restart` 中断时，旧接纳时间与新进程时间不可相减，因此省略执行耗时；已在同一进程内结束的持久终态在重启重传时仍保留原耗时。接纳事件本身不报告执行耗时。已知耗时最多上报 7 天（604,800,000 ms），与 schema 上限一致。修复不回填旧 outbox 或已经上报的历史数据：合法的同毫秒终态也可能为 0 ms，不能据此识别旧伪值。

`unknown` 结果接收仍表示已观测到主控接收，只是结论未知，可进入接收覆盖分子，不表示执行成功。设备表和使用趋势的调用量描述执行观测，与用户活跃的口径不同；被动执行不使 B 成为活跃用户。已持久化的主控归属可在重启后恢复，新登记缺少合法模式上下文时保守降级，不根据未知模式补推归属。

主控等待结果耗时按接收事件所属日期采样，并遵守原始事件的每日贡献上限；接收覆盖率则以周期内经过每日贡献裁剪的执行终态任务为分母，与总调用统计共用每主体、每日最多 100 次终态的额度（含本地调用）。执行终态数、已接收数、未观测到接收数均基于这批任务，接收证据仍查询完整保留历史，允许跨日接收；被裁掉任务的接收不进入覆盖率。接收耗时采样与覆盖率的时间口径及裁剪对象不同。未知、等待中与确定未发送的状态仅统计周期内经原始事件贡献裁剪后仍可见的任务；跨日状态解析仍参考完整保留历史。现有共享额度按本地事件在前、远控投影在后的顺序裁剪，本地调用耗尽当天 100 次终态额度时，远控调用与接收覆盖率不再追加额度。明确的主控终态接收可解析此前的未知接收，但不会覆盖 B 账本的执行结论。凭证自动续期时，仅将同一授权 generation 内的主控发起和被控执行上下文迁移到新采集周期并持久化；关闭统计、删除及重新同意产生的新授权不能接续旧任务。

归属判定使用完整保留事实，周期内每日贡献裁剪不会删除分组中的 B 本地提交证据。若提交证据确已超出保留范围或被删除，只有 B 的终态仍按未归属执行保守统计，不凭空认定为 B 本地任务，也不要求必须存在 A 的控制端事件才保留真实 B-only 执行。

发起者身份可关联时才进入用户活跃与留存。远控任务暂不推断场景、附件输入类型或用户显式价值行为；代理会话的复制、反馈、导出尚无完整绑定时，标记为显式价值不可关联，不进入 WEVTA 分母，避免把未观测误当作没有价值。

统计接口在同一组保留事实下复用安装身份过滤、双端任务关联及投影快照，并为内部不可变快照建立按事件类型的视图。自然日窗口按起止日期复用，每个不可变视图只保留一个结束日期、最多三个起始窗口，结束日期改变时清空；接收证据成熟、小时趋势和采集状态等最终指标仍按请求重新计算。新增事件、实际原始事件清理、主体删除和安装身份集合变化后重新构建，未删除任何事实的压缩不更换快照，避免不同看板请求重复全量分组，也避免删除后沿用旧归属。

缓存只保留当前事实快照，派生索引以弱引用键关联其生命周期；窗口数量有界，但保存的事件引用仍随保留事件数线性增长，并非固定内存上限。远控投影增加合成行和任务分组，较未提供该功能的 main 存在额外 CPU 和内存成本；按类型索引、日期窗口复用和单趟远控诊断聚合用于减少重复扫描，不表示新增功能没有成本。可用 `remote-control-relay/scripts/benchmark-behavior-views.mjs` 比较相同负载下的旧 PR、新实现和 main，区分热缓存、源快照替换及持续新增任务，并核对报表输出；main 的远控语义不同，不能当作远控报表的等价实现。

客户端继续同步持久化上下文，重连快照沿用 outbox 的至少一次投递和服务端稳定 ID 去重；这会产生本地写入及重放成本。本轮不新增延迟持久化或仅靠内存去重来省略快照写入，以免改变崩溃恢复、删除生效和最终投递的保证。

### 合成负载测量

2026-10-21 在 Windows、Node v26.0.0、无并发构建时运行上述基准。旧实现为 PR head `d704e5a594`，main 对照为 `6bb6cd0582`。两类负载均从 106,000 个事件、20,000 个任务、200 个安装开始；远控负载含 12,000 个双端任务，无远控负载只含本地事件。版本执行顺序轮换，预热两轮后取五轮中位数；持续新增模式每轮追加 100 个任务。绝对耗时只代表该机器和运行时，不作为 CI 阈值或生产 SLO。

远控负载耗时（ms）如下。六接口为行为概览、设备概览、设备表、工具、场景和模型；总耗时先按轮求和再取中位数。

| 场景 | 旧概览 | 新概览 | main 概览 | 旧六接口 | 新六接口 | main 六接口 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 热缓存 | 1906 | 789 | 557 | 3085 | 1036 | 1045 |
| 替换源快照 | 1889 | 949 | 628 | 2800 | 1243 | 1140 |
| 持续新增 | 1937 | 1100 | 640 | 2875 | 1388 | 1042 |

这将六接口耗时较旧实现降低约 52%–66%，但新概览仍比不提供远控统计的 main 高约 42%/51%/72%；六接口在后两种场景仍有约 9%/33% 净成本，不能声称全面快于 main。无远控负载的六接口旧/新/main 分别为热缓存 1765/885/1344 ms、替换快照 1153/727/1114 ms、持续新增 1429/715/1061 ms；不同模式分别采样，不据此比较模式间的绝对速度。所有场景每轮均断言旧/新完整 JSON 相等；无远控场景另去除 main 缺少的新增 `remote_control` 字段后，对六报表既有字段完整断言相等。

内存在每版本三个独立子进程中显式 GC 后取中位数，单位 MiB，测量 `heapUsed`，不是 RSS 或峰值；报表输出已丢弃。main 没有持久投影快照，因此其中间阶段为空操作。

| 远控负载 | 原始 store 就绪 | 投影后 | 六报表后 |
| --- | ---: | ---: | ---: |
| 旧实现 | 54.49 | 69.99 | 72.38 |
| 新实现 | 54.04 | 69.55 | 77.87 |
| main | 53.97 | 53.97 | 54.48 |

新实现总保留堆较旧实现增加 5.49 MiB；校正各自原始 store 起点后的净保留增量增加 5.94 MiB。投影阶段成本基本不变，索引和复用视图以更多保留引用换取重复扫描减少，内存回退并未消除。无远控负载的报表后堆为旧 39.18、新 41.63、main 37.26 MiB。事件数量或查询窗口变化时仍需重新评估资源占用。

## 发布顺序与验证

先发布包含新 schema、聚合模块和页面的 Relay，再发布客户端。未升级的客户端仍提供旧诊断；新客户端对旧 Relay 的扩展事件可能被拒收，不影响业务执行，不能据此推算零调用。

验证覆盖双端同时上报、单端上报、B 本地发起、终态冲突、结果未知、提交拒绝、真实新任务、重复事件、跨日归属、删除主体、模型使用、每日贡献上限、上下文重启与过期，以及页面权限、周期切换、错误保留和旧服务兼容。上线后仍需用两台升级后的设备验证真实聊天、代码任务和断连恢复。
