# 商店当前版本与 Cube Manage Software 选择契约

2026-10-20：普通商店及 MCP 启停操作只面向商店明确选中的当前部署。历史目录是归档，不参加普通发现、启动、默认切换或自启恢复。实验资源的既有显式授权和租约边界不变。

## 只读清单

`--cmsd-store-inventory` 保持 `format=pinvou-installed-models-v1`、`models`、`skipped`，新增：

- `selection_policy=latest-installed-v1`。
- `selections=[{logical_card,card,version_id}]`：同一 SQLite 只读事务中的权威当前选择，仅 `card_source=store/local`、成功下载且当前版本绑定一致的记录参与；有效的 downloaded/pending current 也保留身份，但不授予启动权。已有真实生命周期归属的当前实例仍保留安全停止入口，未托管实例不能借清理身份取得停止权。配置损坏、待重新部署、删除未完成或快照不一致时保留选择身份，禁止旧目录回落，但不输出有效 `models`。
- `archived_models=[{logical_card,card,version_id}]`：所有非当前版本，包括 history、ready、失败/中断的版本记录。当前下载在部署失败或保留权重卸载后仍保留 selections 身份，仅可申请清理预留，不归为历史。排除当前物理卡的重复快照，保留逻辑 ID，使“仅剩归档”的自然卡请求也能失败关闭。普通启动不能把 ready 当作 current；完成显式部署和原子发布后才可启动。
- `models[]` 仅含当前有效条目，增加 `version_id`、`deployment_revision`；`fingerprint` 同步采用该部署修订。修订包含当前脚本、附属文件、实际部署配置、引擎及 profile。相同 wire 模型名、端口或 active_version_id 不能证明实例版本一致。

已卸载而保留权重的 downloaded/pending current 行不进入 models；其 selections 身份和 current_not_deployed 跳过原因只允许清理预留。版本关系必须与 model_versions 的 current 一致，deleting、history、ready、缺失或错配均不取得清理权。整条卡片删除后，剩余版本记录继续只作为归档。首次真正旧 schema 无版本指针时允许明确的 legacy 当前绑定，其不透明 ID 为 `legacy-<当前固化配方摘要>`；有版本 ID 却缺 runtime、重复绑定、schema 损坏或清单读取失败均失败关闭，不猜目录名、不按时间或哈希大小推选最新。

读取器有界读取同账号元数据及小型交付文件，不迁移数据库，不读密钥表，不执行脚本，不访问网络，也不读取大权重。必要的权重、实际 PID、引擎及运行参数核实由 cmsd 准入和实例身份链路完成；本清单不代替这些检查。

首次隐式登记读取器时，Pinvou 将查询、登记和读取新清单统一限制在 12 秒内。只有确认登记成功后才等待新事实；仅对 `503/store_selection_unavailable` 重查，不重放模型生命周期请求。明确拒绝登记时仍可读取原事实，响应丢失或状态未核实时保留未知状态。卸载在取得版本资源独占锁前准备读取器，锁内继续重新核实权限与维护对象，避免等待清单的共享锁与自身独占锁相互阻塞。

商店配方及版本绑定的文本在从 SQLite 复制前累计核算，整份清单最多读取 32 MiB 元数据，超限以 `store_inventory_metadata_limit_exceeded` 失败关闭。旧导入快照中的虚拟环境和缓存按导入扫描规则排除后，再限制有效声明源文件最多 1024 项；固定入口和部署配置仍单独逐字摘要，每文件上限 256 KiB，输出总上限 1 MiB。路径先校验后过滤。原始配方继续完整参与修订摘要，不删改旧快照，也不改变当前版本和归档选择。

## 首建脚本的固定下载根目录

`models[].models_root` 原样来自同一只读事务的 `store_models.models_root`，已包含在配方及 `deployment_revision` 摘要中；缺失字段输出 null。成功下载及隔离版本保存实际使用的规范根路径，后来修改默认目录不改变该卡片或版本的 root。清单不从权重目录反推父级，也不从当前设置、配额预留表或旧纳管副本补写这个值。

仅当前 selection 的容器尚不存在、需要执行 `enable.sh` 首建时，cmsd 才使用该已核实 root 覆盖 `LMM_MODELS_DIR`；同时持有原有版本资源共享锁，并在脚本前复核当前配方和目录。原生启动与已有容器不重跑首建脚本；未登记到商店选择合同的独立外部卡继续使用显式 daemon 配置。

已知商店条目的 root 缺失/不合法时返回 `store_models_root_unknown`，路径缺失、已变成链接或不可核实时返回 `store_models_root_changed`，均保留卡片、权重和原部署，不执行首建、不猜新默认目录，也不触发下载。路径故障先恢复已登记的原目录或挂载后重试；字段缺失时，恢复包含该固定 root 及匹配配方的完整商店记录备份，或在商店明确选择已有完整目录记录的已验证版本，重新发布 current。没有可核实的匹配记录时继续拒绝首建，需人工核查，不以重新下载或自动回填充当修复。

## 发布与锁

隔离下载/检查使用共享 `model-store/version-operations.lock`。当前包替换、当前部署配置写入、版本发布及删除使用独占锁；cmsd 从选择解析到启动就绪持共享锁并核实预期修订。共享启动不能与配置写入交错。每逻辑卡操作锁继续防止多个商店执行者互相覆盖。

版本切换遵循商店 PR #1995：已验证的新版本和历史版本均可由用户手动切换。切换完整恢复目标版本的本地卡片、脚本、附属文件、权重路径和部署配置，再原子提交 current。新升级要求旧版权重完整以保留回退能力；当前权重损坏时，已保存的历史版本仍可作为显式恢复目标。cmsd 接受商店回切后发布的当前指针，不自行挑选历史目录。归档清理无法证明安全时保留残留并说明错误。

卸载在资源独占锁内核对数据库的当前 physical、设备事实的 logical/physical 及清理预留能力；本机管理已配置时，权威 current 不可见、物理不符或事实未知均拒绝回退旧脚本。未配置本机管理的独立商店行为保留。

已有维护事务持有固定 physical 对象和租约。带 owner 的 disable/purge 不重新解析逻辑别名，也不嵌套申请版本共享锁；保留停止核实和原有删除授权。版本切换只部署及发布，不持独占锁同步调用普通 cmsd enable。

## API 与对话接续

cmsd 的普通 models 行保留 physical runtime 作为 `card`，`store_bindings` 提供 logical→current 映射。任务接收回执提供 `requested_card`、实际 `card` 和 `selected_version`（version_id 字符串）。模型行附相同 `version_id`、`deployment_revision`。

Pinvou 捕获原请求和任务身份，按绑定解析当前 physical，复核 active_model、健康、版本及部署指纹。验证期间 current 指针或同 runtime 配方变化均不把原任务接到另一个部署。保存的商店来源与稳定注册 ID 用 logical；API wire ID 用当前实际模型 ID。泛化 cmsd/实验标签不自动获得商店来源。

MCP 换胎继续保留持久任务接续、会话空闲等待、原绑定 CAS 和用户手动选择优先。后台模型库对账更新已有关联配置，保留凭据与显式参数；商店页关闭时全局任务观察仍触发刷新。旧商店后台必须提供 `model.latest_installed.v1` 能力，否则新客户端拒绝委托变更，不启动第二个执行者。

## 安装接收端围栏

本地目录安装仅用于尚未登记的新卡（包括用户明确创建的首次实验安装）。一旦逻辑卡、当前 runtime 或任意保留版本已登记，普通 `/v1/install_local`、重试预览和最终执行均拒绝重放目录配方，要求使用商店当前部署/检查更新流程。最终执行在资源独占锁内再次核对，队列等待不能绕过登记变化；已接受的同 run_id 请求仍返回原任务，不重复安装。归档 physical ID 不能借新安装变成另一张 current。cmsd 委托端同时对已知商店来源使用新卡片包并拒绝历史 ID。

## cmsd 组件升级与软件回退

内置及离线候选组件在停止当前服务前必须报告 `store_selection:1` 与 `native_profile_from_card:1`。启动、重启、解除维护、自启启用及恢复/回退的候选也检查能力。保留软件回退入口，但不能退到会重新扫描归档目录或固定覆盖上下文的旧二进制。

新配置写入 `require_store_selection="v1"`。已有配置先做只读解析、归属和版本预检，在显式更新的维护事务中合并该哨兵，再捕获新的注册摘要；不更改其他配置值。文件在预检后变化或存在链接时拒绝写入。后续旧二进制不认识该哨兵，应在加载配置时失败。初次从不支持此策略的 cmsd 升级后，旧包也不能作为自动补偿目标；需要支持新策略的组件完成恢复，不删除状态标记或重放旧模型意图。

## 验证边界

本接口保留模型商店的完整手动回退、配额、取消和目录归属检查。实际源码版本、组件包摘要及构建验收结果在对应 PR 记录中提供。本机验收使用隔离配置，不操作用户原服务。

接口和范围见 [单机管理](megacube-single-node.md)。历史验收材料只证明其记录的源码和制品，不作为其他版本的直接通过声明。
