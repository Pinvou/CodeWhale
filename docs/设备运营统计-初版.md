# 设备运营统计初版

日期：2026-07-14

## 范围

初版只统计唯一设备、在线状态和匿名使用量，不建立用户、安装实例或进程管理模型。

- 不上传消息正文、session 标题、文件路径、工具参数或工具输出。
- `device_id` 是服务端签发的不透明 ID；硬件原始声明只用于服务端 HMAC 去重，不落盘。
- 每轮 `TurnComplete` 只记录 input/output token 和成功状态。
- 遥测服务故障不阻塞 Pinvou 启动、聊天或本地工具执行。

## 路径

```text
https://pinvou.com/pinvou3/stats
https://pinvou.com/pinvou3/telemetry/healthz
https://pinvou.com/pinvou3/telemetry/v1/register
https://pinvou.com/pinvou3/telemetry/v1/heartbeat
https://pinvou.com/pinvou3/telemetry/v1/events
```

远控继续使用 `/pinvou3/remote/*`，运营统计不放在远控子目录下。

## 客户端

实现位于 `pinvou3-app/src-tauri/src/telemetry.rs`。

运行时目录：

```text
~/.pinvou3/telemetry/identity.json
~/.pinvou3/telemetry/outbox.sqlite3
```

`identity.json` 同时保存每个安装随机生成的注册秘密。服务端只保存该秘密的 HMAC；同一硬件再次注册时必须证明持有该秘密，不能仅凭硬件声明重新取得设备凭证。

设备身份按以下优先级选取：

1. `PINVOU_TELEMETRY_DEVICE_CLAIM`（受管环境覆盖）。
2. Linux DMI product UUID / product serial / board serial。
3. Linux `/etc/machine-id`。
4. Windows `Win32_ComputerSystemProduct.UUID`。
5. 本地持久随机 ID；此时 `identity_quality=installation_only`，卸载并删除用户数据后无法跨重装去重。

环境变量：

```text
PINVOU_TELEMETRY_BASE_URL=https://pinvou.com/pinvou3/telemetry
PINVOU_TELEMETRY_DISABLED=1
PINVOU_TELEMETRY_DEVICE_CLAIM=<企业资产编号或测试覆盖>
```

客户端每 2 分钟发送心跳。在线设备口径是服务端最近 5 分钟收到心跳。看板登录后每 30 秒刷新一次。

用量事件先写 SQLite outbox，服务端返回 accepted/duplicates 后才删除。本地网络重试不会重复计数。outbox 最多保留 30 天、5000 条；超过任一上限会优先删除最旧事件，避免服务长期不可用时无限占用本地磁盘。

## 服务端

实现位于：

```text
remote-control-relay/telemetry-service.js
remote-control-relay/web/stats.html
```

初版复用 47.120.8.237 上已经受公网代理保护的 8787 HTTP 服务入口，但代码、路由、数据和管理员鉴权相互独立。

服务器数据：

```text
/var/lib/pinvou-telemetry/devices.json
/var/lib/pinvou-telemetry/usage-events.jsonl
/var/lib/pinvou-telemetry/ip2region_v4.xdb
/var/lib/pinvou-telemetry/ip2region_v6.xdb
```

密钥配置：

```text
/etc/pinvou-telemetry.env                         # root:root 0600
/etc/systemd/system/pinvou-remote-relay.service.d/20-telemetry.conf
/root/pinvou-stats-credentials.txt                # 看板管理员密码
```

容量和限流可通过环境变量调整：

```text
PINVOU_TELEMETRY_MAX_DEVICES=10000
PINVOU_TELEMETRY_MAX_EVENTS=100000
PINVOU_TELEMETRY_EVENT_RETENTION_DAYS=35
PINVOU_TELEMETRY_EVENT_RATE_PER_MINUTE=2000
PINVOU_TELEMETRY_EVENT_RATE_GLOBAL_PER_MINUTE=20000
PINVOU_TELEMETRY_REGISTER_RATE_PER_IP=10
PINVOU_TELEMETRY_REGISTER_RATE_GLOBAL=100
```

服务端只在最近 35 天、最多 10 万条事件的有界窗口内计算 7 日/30 日统计；达到事件上限后压缩到 90% 再继续接收。设备默认最多登记 1 万台，注册同时受单 IP 和全局分钟级限流。达到容量时服务端拒绝新设备，不影响已有设备心跳与补报。

公开 `/pinvou3/telemetry/healthz` 只返回 `{"ok":true}`。设备明细和汇总 API 需要看板登录后签发的 HttpOnly、Secure、SameSite=Strict cookie。

### 统计口径

所有日期按北京时间自然日计算。

- 当前在线：最近 5 分钟收到设备心跳。
- 今日活跃：今日产生过至少一条有效对话的唯一设备数。
- 近 7 日活跃：包含今日在内，近 7 个自然日产生过对话的唯一设备数。
- 近 30 日使用趋势：每个自然日产生过对话的唯一设备数和对话总次数。
- 活跃版本覆盖率：按近 7 日活跃设备的当前版本汇总。
- 设备明细：展示匿名设备 ID、在线状态、版本、系统、所在区域、首次登记、最后活跃和近 7 日对话。

### 新旧采集兼容

首页的指标名称、展示结构和北京时间口径保持不变，服务端同时兼容两代对话事件：

- 旧客户端继续从 `usage-events.jsonl` 的 TurnComplete 用量事件统计活跃设备和对话次数。
- 新客户端从 `behavior-events.jsonl` 的核心用户任务 `task_finished` 统计相同指标，成功、失败、取消和中断终态均计入对话次数；只包含 `initiator_type=user` 且 `mode` 为 `assistant`、`code` 或 `team` 的任务，排除 `scheduled`、`system` 和其他后台任务。
- 旧设备身份与新安装身份没有可证明的关联键，后台不尝试按时间、地区等特征猜测它们是同一设备。兼容聚合按已发布的客户端代际选择数据源：截至 0.8.3 的旧代使用 usage event，已登记 `hardware_source=installation_id` 的新代使用 behavior event。0.8.4 起旧 TurnComplete 接线已不再产生数据，不使用该中间代的硬件身份虚构活跃。
- `task_finished` 按行为安装身份和 `attempt_id` 去重；缺少 `attempt_id` 时依次使用 `turn_id`、`event_id`。仅 `hardware_source=installation_id` 的服务端签发身份可触发并参与新代统计。
- 设备明细与首页折线使用同一发布代际规则：展示旧代硬件身份和新代安装身份，隐藏不再产生旧 usage 的中间代及新代硬件身份。新安装身份的 `task_finished` 会回填现有 `last_active_at` 和 `turns_7d` 字段，不新增 API 字段。服务端从本版本起在新收到的 usage event 中固化接收时的 `app_version`，避免设备升级后改变该事件的代际归属；历史事件缺少该字段时才使用设备当前版本。
- 由于两套身份无法转换，客户端进入新代时会按安装身份重新建立新增设备基线；这是明确的口径分界，不对历史身份做不可验证的合并。

兼容聚合只改变后台数据来源，不改变首页 API 的 `counts`、`usage_trend`、`active_versions` 和设备列表字段。

所在区域由服务端根据可信反向代理传入的真实公网 IP，通过本地离线 `ip2region` 数据库解析到国家/省/市。服务端只保存粗粒度区域，不保存原始 IP；同一设备最多每 24 小时刷新一次区域。离线库不可用、IP 为内网地址或无法命中时显示“未知”，已有设备会在下一次心跳时补全。

## 公网反向代理

公网 Nginx 需要把两个独立子目录转发到 47.120.8.237:8787，并保留客户端 IP：
仓库中的可部署配置为 `remote-control-relay/nginx-telemetry-stats.conf`。

```nginx
location = /pinvou3/stats {
    proxy_pass http://47.120.8.237:8787;
    proxy_set_header Host 47.120.8.237;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}

location ^~ /pinvou3/stats/ {
    proxy_pass http://47.120.8.237:8787;
    proxy_set_header Host 47.120.8.237;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}

location ^~ /pinvou3/telemetry/ {
    proxy_pass http://47.120.8.237:8787;
    proxy_set_header Host 47.120.8.237;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

代理机必须是 `PINVOU_REMOTE_ALLOWED_PROXY_IPS` / `PINVOU_REMOTE_TRUSTED_PROXY_IPS` 中的受信地址。

## 发布与验证

部署继续使用：

```bash
./scripts/deploy-remote-relay.sh
```

脚本会一起部署 relay、遥测模块和看板，并验证远控公开入口及服务器环回遥测健康检查。部署失败会恢复同一份备份目录中的旧文件。

```bash
systemctl status pinvou-remote-relay.service
curl -fsS http://127.0.0.1:8787/pinvou3/telemetry/healthz
```

```bash
curl -fsS https://pinvou.com/pinvou3/stats | grep 'PINVOU · 设备运营中心'
```

## 初版限制

- JSON/JSONL 存储只用于当前小规模上线，已通过设备、事件、时间窗口和速率上限保证资源有界；需要扩大容量或保留长期明细时迁移 PostgreSQL。
- 没有可靠硬件身份的设备只能按持久随机 ID 去重，删除 `~/.pinvou3` 后会被视为新设备。
- 客户端公开的 enrollment token 不能证明客户端真实性；当前通过安装随机秘密防止仅凭硬件声明重取凭证，并用全局/单 IP 限流和总容量限制约束污染规模。需要确认真实设备身份时仍需 TPM/企业设备证书。
- 看板只做设备维度统计，不追踪用户身份。
