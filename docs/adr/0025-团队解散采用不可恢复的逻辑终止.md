# 团队解散采用不可恢复的逻辑终止

> 状态：已接受。

团队解散采用用户侧不可恢复的逻辑终止，而不是物理删除。只有团队负责人可在不存在未结束责任项时解散团队；解散立即使加入码、成员访问和工作写入失效，团队也不再出现在有效团队列表中。既有工作、动作和附件关系继续按服务端保留策略存在，但当前产品不提供已解散团队的恢复或只读档案入口。

物理删除会破坏接力动作的历史归属，并要求为任务、参与者、附件和已读状态设计级联清理；可恢复归档则会额外引入归档列表、恢复权限和恢复后加入码等产品状态。逻辑终止以保留历史完整性和控制首批修复复杂度为优先，代价是解散不会立即清除服务端历史数据，最终物理清理留给统一的数据保留策略处理。
