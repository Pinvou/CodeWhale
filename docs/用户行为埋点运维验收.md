# 用户行为埋点运维验收

> 适用口径：behavior schema v1 / metric `behavior-v1.2`
>
> 时区：Asia/Shanghai
> 本文覆盖 P0/P1；P2 商业事实与实验不在本轮范围。

## 1. 自动化门禁

| 门禁 | 实现与判定 | 执行命令 |

任一门禁失败均禁止扩大灰度。自动化通过不替代产品、数据、安全/隐私负责人的发布批准。

## 2. 删除协议与恢复顺序

1. 客户端用有效设备凭证调用 `POST /pinvou3/stats/api/behavior/deletion`，正文包含幂等 `request_id`。服务端返回 HTTP 202、`deletion_request_id`、`accepted_at`、状态和完成时间。
2. 30 天结果窗口内，相同凭证和 `request_id` 重试返回同一结果。删除完成后原设备凭证不能再访问事件、控制面或聚合接口。
3. 客户端或受支持工具使用原 Bearer 凭证调用 `GET /pinvou3/stats/api/behavior/deletion/status?deletion_request_id=...`。结果可查询 30 个自然日；超期返回 410，不存在或凭证不匹配返回 404。
4. 服务端墓碑只保存带服务端密钥的主体摘要、凭证摘要和删除状态，不保存设备 ID 或明文令牌。墓碑先于事实删除持久化；进程在中间状态崩溃时，重启会完成清理。
5. 恢复备份时不得用备份覆盖 `behavior-deletion-tombstones.json`。先恢复事实和设备文件，再放回当前删除墓碑，最后启动服务；构造存储时会先加载墓碑，再加载设备与事件，并原子重写被净化的文件。
6. 恢复后运行删除恢复测试，并确认目标主体不在 `devices.json`、`usage-events.jsonl`、`behavior-events.jsonl` 中；不得通过修改 pepper 绕过墓碑。

## 3. 权限、留存和展示审计

- 行为采集、周期控制和删除接口只接受设备 Bearer 凭证；客户端声明的 `device_id` 和 `account_subject_id` 均不作为可信身份事实。
- 行为看板 API 需要 HttpOnly、Secure、SameSite=Strict 会话。`PINVOU_BEHAVIOR_ANALYTICS_PASSWORD` 签发的 `behavior_analyst` 角色只能访问行为聚合；`PINVOU_STATS_ADMIN_PASSWORD` 签发的 `operations_admin` 才能访问设备运营明细。分析角色页面不请求且不显示设备视图；页面不提供逐事件、单安装、单账号或单会话查询，也不提供导出接口。
- 设备运营明细属于既有独立页面，不在行为分析结果中通过主体 ID 关联。行为聚合响应的契约测试禁止出现 `device_id`、`account_subject_id`、`session_id`、`turn_id`、`attempt_id`、`operation_id` 和 `event_id`。
- 原始事件、可逆贡献和管道事实的配置上限硬限制为 35 天，允许使用更短策略；本版本不生成 35 天以上聚合，因此 13 个月聚合开关不存在。
- 北京自然日内，活跃每维度最多贡献 1 次，任务及其他事件名最多 100 次，工具成功调用最多 500 次；小于 20 个安装的版本、工具、场景和模型分组不返回。
- 看板顶栏统一展示数据状态、主体、时区、周期、口径版本、口径切换日、最后事件时间和报表更新时间；“未启用”“暂无事件”“数据延迟”和正常状态分开显示。

## 4. 五分钟资源探针

在同一台最低支持硬件、同一版本、同一稳定工作负载下执行两次。第一次关闭行为采集并保存基线：

```powershell
node scripts/behavior-telemetry-resource-probe.mjs --pid <应用PID> --duration 300 --output telemetry-off.json
```

第二次只开启行为采集，重复相同工作负载并与基线比较：

```powershell
node scripts/behavior-telemetry-resource-probe.mjs --pid <应用PID> --duration 300 --baseline telemetry-off.json --output telemetry-on.json
```

脚本在 Windows、Linux 和 macOS 上采样目标进程，结果文件使用私有权限创建。比较失败时退出码为 1。验收记录须附两份 JSON、硬件配置、操作系统、应用版本、工作负载步骤和执行时间；不得只保存截图或手工结论。

## 5. 灰度与回滚

1. 先发布兼容 schema 的服务端，再发布客户端，最后启用依赖新口径的看板。
2. 首批灰度检查事件量、服务端拒绝率、终态完整率、贡献裁剪率、时钟偏差、入队延迟及资源探针。
3. P0 服务端拒绝率连续 15 分钟超过 1%，或接纳任务 24 小时后无终态比例超过 0.5%，立即停止扩量。
4. 回滚顺序与发布顺序相反。关闭采集会立即停止新事件并清空当前周期 outbox；遥测服务不可用、限流或回滚不得改变任务、工具、语音等业务结果。
5. 每次扩大字段、主体关联、保留时间、降低 20 安装阈值或放宽性能预算，都必须提升口径/配置版本并重新完成隐私与性能评审。
