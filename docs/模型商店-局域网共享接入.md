# 模型商店局域网共享

此候选基于已提交产品源码 `0c3810ff3`。本机品悟继续直接调用本机模型；用户主动开启某个模型的「局域网共享」后，同网段的其他设备才能通过认证代理调用它。

## 用户接入

1. 在 Linux 模型库中部署并启用一个提供 OpenAI 对话接口的模型，打开详情。
2. 为每个调用方生成一把此模型专用的 Key，妥善保存。界面显示掩码，可复制或单独撤销。
3. 在「局域网共享」选择本机的一个私网 IPv4 地址和未被占用的端口，点击开启。默认端口为 8090，可选 1024–65535。多模型共用同一监听地址和端口，各自决定是否共享。
4. 复制共享区域的模型 ID、Base URL 和 Key 到其他设备的客户端。模型 ID 为 `pinvou:<card_id>`，不随显示名、引擎模型名或推理端口变化。
5. OpenAI 客户端的 Base URL 使用 `http://<所选地址>:<端口>/v1`。完整对话 endpoint 为 `http://<所选地址>:<端口>/v1/chat/completions`，不要在 Base URL 后再重复 `/v1`。
6. 详情页提供可复制的 Bash/curl 调用示例。示例读取 `PINVOU_API_KEY` 环境变量，不嵌入真实 Key。请在调用设备上设置该变量；不要把 Key 加进 URL、共享日志或提交到代码库。

只在信任的局域网开启；当前为 HTTP，无 TLS 加密。仅开放所选接口，不监听 `0.0.0.0` 或 `::`，仅接受该接口子网内的私网 IPv4 调用方。未自动放开防火墙，也不配置路由器端口转发。同一 LAN 不同子网、访客 Wi-Fi 隔离或主机防火墙可能阻止连接，应由设备管理员确认具体接口/端口，不能全局关闭防护。

关闭某个模型的共享，立即拒绝该模型新请求并结束其流式连接；其他共享模型不受影响。最后一个模型关闭时释放监听端口。此操作不停止模型、容器或共用引擎。退出应用后共享关闭，重新启动不会按历史配置自动对外监听。地址/网卡/掩码变化后停止共享，需重新选择并开启。

## 协议及权限边界

| 能力 | 当前范围 |
| --- | --- |
| `GET /v1/models` | 必须携带 `Authorization: Bearer <Key>`，只返回该 Key 对应的已共享且就绪模型 |
| `POST /v1/chat/completions` | 使用稳定共享模型 ID；代理替换为当前引擎的真实模型 ID；其他参数直接交给该引擎 |
| SSE | 逐块传递，保持流式背压；客户端断开、撤销 Key、停用模型、关闭共享时释放上游响应 |
| 错误 | 无效/撤销/旧全局 Key 为 401，未共享为 403，模型 ID 不属该 Key 为 404，模型或隔离证据不足为 503；上游拒绝保留 HTTP 状态但不泄露其诊断正文 |
| 多 Key | 同一模型可有多 Key；单把撤销不改变其他 Key。每次请求读取同一 SQLite Key 库；长流也检查撤销及模型状态 |
| 历史 Key | 已绑定此卡片的 Key 继续可用，格式不变；未绑定卡片的旧全局 Key 保留可见与撤销能力，不能自动扩大成所有共享模型的授权，需新建模型专用 Key |
| 图像 / ComfyUI | 此入口不支持 `/generate`、ComfyUI `/queue`、工作流、WebSocket 或 OpenAI 图像生成；不把它们包装成对话模型 |
| Ollama | 仅在其 OpenAI 对话端点及模型身份/端口隔离验证通过时使用；不代理原生 `/api/*` |

代理不接收 URL 参数或浏览器跨源调用，不转发 LAN Key、Cookie、任意请求路径及客户端指定上游地址。流式正文透传，因此返回体中的 `model` 可以是引擎自己的模型名；发起请求及 `/v1/models` 始终使用稳定共享 ID。引擎自己的参数、工具调用及模型能力仍以其实际实现为准。

## 原始引擎端口必须隔离

开启及每次模型请求都会重新读取模型记录，限定 loopback HTTP 上游和 OpenAI 路径，检查 Linux `/proc/net/tcp{,6}` 的监听范围；有容器名时也检查容器真实运行状态和 Docker 发布映射。发现原端口绑定通配地址、私网/公网地址，或证据无法取得时拒绝共享。实际 `/v1/models` 必须返回记录指定的模型身份；停止、换端口及模型身份不匹配都会反映为不可用，不把数据库的 `running` 当作独立健康证据。

该检查不自动迁移既有部署、不停止外部实例、不改防火墙。旧版裸露上游需先由部署维护端改为 loopback，再验共享。检查是当前操作系统/容器配置的证据快照，不能阻止管理员另行创建网络转发或重新发布容器。

现场执行端已报告两个需协调的前置条件，未在本候选中修改：

- MiniMax 原生 ComfyUI 启动脚本会 `--listen 0.0.0.0`，协议为 `/queue`；观察时它未运行。此协议不在本次共享范围内，不据脚本推断当前已监听。
- 已运行的 SGLang 用户实例存在 IPv4/IPv6 通配发布。客户端候选应拒绝认证共享，须由唯一设备执行端协调迁移后再验；不能借「开启共享」擅停用户实例。

## 源码与集成

- `lan_gateway.rs`：模型级监听注册、认证/路由、OpenAI 健康身份核验、SSE/取消、网络变化停服。
- `lan_network.rs`：Linux 私网接口清单、loopback URL 规范化、真实监听和 Docker 映射证据；无部署/防火墙写入。
- `lan_store.rs`：既有数据库及有界 Docker 查询的适配；非 Linux 平台返回明确 unsupported。
- `api_keys.rs`：从 `db.rs` 移出的原有 Key CRUD/生成代码。`db::ApiKeyRecord` 和五个原公开接口、schema、Key 格式不变；没有第二套 Key 存储。
- UI 新增 `LanSharingPanel.jsx` / `lan-access.js`；详情原有本机接入不变，增加单把撤销及未知状态处理。界面文案完整提供中/英/日三语。
- 新增命令：`model_store_lan_status(cardId)`、`model_store_set_lan_sharing(cardId,enabled,address,port)`、`model_store_revoke_api_key(keyId)`。
- status 包含 `enabled/address/port/interfaces[{name,address,mask}]/model_id/base_url/endpoint/available/reason`。开关代表共享许可，`available` 代表当前模型可调用；共享已开但模型停止时仍显示不可用原因。
- 新增 axum 直接依赖，复用已有锁图 0.8.9；不引入新 HTTP 框架包或模型。Key不出现在网关访问日志、URL或样例中。

独立分支 `feat/model-store-lan-sharing`，工作树 `D:/pinvou3-lan-sharing-20261016`。没有应用 rootfix 四文件补丁；与其交集只有 `platform/linux/mod.rs` 的模块声明。与客户端缺陷候选的公共文件交集为 `service.rs`、各 `mod.rs`、commands/lib、model-store-api、ModelDetailDialog 和三语词典，均保留既定接口。`db.rs` 的 Key 代码提取已另行通知集成端。最终统一构建/合并由知行协调，禁止直接覆盖共享 PR1916。

## 验证与剩余条件

小型原生 harness 直接编译生产 `lan_gateway.rs`、`lan_network.rs`、`lan_store.rs` 和 `api_keys.rs`，启动真实 TCP/HTTP 服务、loopback 假引擎及临时 SQLite 数据库。Key SQL/随机生成是生产代码；仅数据库路径/连接、模型记录、managed service 和进程 helper 使用最小测试适配。Docker helper 只检查编译签名，不在 harness 中调用 Docker。此结果不等同完整 Tauri 应用 crate 编译。

```sh
cargo test --manifest-path tests/model-store-lan/Cargo.toml --offline
cd pinvou3-app
node --test tests/model_store_lan.test.mjs tests/model_store_dialog_safety.test.mjs tests/ui_language_coverage.test.mjs
```

harness 使用本机 WSL 虚拟私网的临时端口，无模型下载、设备 SSH 或防火墙变更；UDP connect 仅查本机路由，不发送数据包。覆盖：

1. 默认无共享监听、有效/错误/空/旧全局 Key、Key卡片范围、稳定模型ID及上游替换、多模型独立关闭、真实 SQLite 生成/撤销且其他 Key 存活。
2. SSE 首块、断开/撤销/关闭导致上游释放；关闭全部共享释放端口且假引擎仍存活。
3. 端口冲突、非私网绑定拒绝、接口消失、模型停止/错误身份/恢复、URL Key和Origin拒绝、上游错误正文不泄露。
4. IPv4/IPv6及Docker通配发布拒绝、真实 `/proc` loopback/通配监听证据、非loopback/非OpenAI目标拒绝。
5. UI 的显式地址选择、启用/复制精确地址模型ID和样例/关闭流程，以及三语初始/未知状态、错误下一步、IPC边界。

完整 Linux/Tauri、ARM64 包集成、真实 Docker 环境权限、现场同 LAN 两设备请求、实际引擎流式取消、网络/端口迁移及 firewall 可达性仍待统一集成和唯一设备执行端验收。本候选没有声称这些已经通过，也未发布或改现场。
