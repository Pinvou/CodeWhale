# 模型商店卡片更新与历史版本

模型列表和已安装模型的详情页提供「检查更新」和「历史版本」。普通「刷新」不替换本地卡片。检查会联网读取卡片；权重清单变化时，还会下载并校验清单，不执行脚本、不改动现有部署。

## 每次启动检查一次

仅在当前版本报告模型商店可用时，主界面呈现后再延迟 15 秒，后台顺序检查已安装的线上卡片。当前版本不可用、平台不支持或可用性查询失败时，不发起检查、不显示提醒。后端另有可用性保护。

自动检查只读取卡片元数据和缓存摘要，不复制整棵本地脚本树，不读取或校验大权重文件，也不下载脚本或执行部署。每张卡片请求最多等 5 秒，不重试；单轮有 30 秒预算，失败、下架或校验不完整的卡片跳过。手动检查更新仍可使用完整检查流程。

每个应用进程只进行一轮，失败结果也会缓存，页面重载或取消等待不会重新联网。没有周期轮询或云端推送。发现变化时，侧栏收起显示红点，展开则在模型商店标题右侧显示红色「有更新」。进入模型商店后清除侧栏提醒，返回其他页面也不重复提示同一版本；若检测结果在商店打开期间返回，同样视为已查看。已阅记录按「卡片 ID + 线上版本摘要」保存在 WebView 本地持久存储中，正常关闭、重启 App 或重载页面后仍保留；发现不同版本或另一张卡片的更新时会再次提醒。存储损坏、不可用或写入失败时，保留本次运行的内存行为，不阻塞商店操作。

店内每个模型的红色「有更新」标记和「查看更新」入口继续保留，直到应用更新、切换版本或删除模型后清除对应的过期提示。侧栏已查看状态与模型可用更新分开管理；不额外弹出悬浮通知。跨重启保留已阅记录不会跳过下次启动的更新检查。

## 如何判定能否复用

权重身份以经校验的 `weights.sha256` 文件清单为依据，不以模型名称、仓库标签或单个文件名作结论。清单会校验原始内容摘要，再规范化 SHA 大小写、条目顺序、换行、BOM、注释和 `./` 前缀；拒绝路径越界、重复路径、空清单、损坏摘要和无法确认的文件选择。

- 清单证明文件路径及内容一致：允许修正来源、量化标签或缺失的文件名，无需重新下载权重。
- 文件或摘要不同：明确显示新旧文件、摘要、体积等差异，进入新版下载流程，不覆盖旧权重。
- 证据缺失、损坏或旧版离线配方不完整：说明原因并保留现有部署；不把「无法确认」当作「权重肯定改变」。
- 设备拓扑变化：独立拦截，不因权重相同而静默改变设备要求。
- 两版都没有独立权重清单的历史卡片，仅在来源、文件名、量化和已知大小均未改变时保持旧有配置更新能力。

当前隔离升级要求新旧版本都有完整离线配方和单文件 SHA-256 清单，且新版支持原生隔离部署（包括 Qwen / Ornith 驭光卡片）。旧版可以采用 Shell 进程管理，不要求已经包含新版引入的 Python 控制器；切换前会核对旧版路径、文件和进程。多文件、缺少校验依据，或新版采用 Docker、双机布局时，不猜测存储方式，暂不开放隔离升级；其兼容性检查和已有配置更新能力保留。

检查更新弹窗的操作栏固定在底部。支持隔离升级时显示「下载新版并保留旧版」及后续切换步骤；无法升级时显示具体原因，并提供「检查更新」重试和「历史版本」管理入口。

## 部署方案默认值

`Qwen3.8-27B (NVFP4 + Native MTP)` 未保存过方案时默认选择 `production-sampling`，即 262144（256K）上下文及该方案已有的 FP8 E4M3 KV Cache、生产采样和监听配置；界面与直接部署命令使用同一后端策略，不依赖线上卡片顺序。已有有效选择继续沿用，用户显式选择优先。基准方案仍可手动选择，其交付值为 8192，但部署包装脚本会覆盖为 65536（64K）。界面用实际部署长度标注两套方案，不再把基准方案标成默认。内置卡片及其部署脚本的缺省方案同步为生产采样。

## 配置更新

权重身份一致时点「更新卡片」。运行中的模型可以检查，但必须先停用才能应用更新。客户端验证用户审阅的确切线上版本，完整下载并校验入口、方案及附属文件后，在一次数据库事务中替换。取消或校验失败保留原包；线上版本再次变化时要求重新检查。

更新后点「重新部署」，按需刷新引擎和运行配置，再启用模型。部署失败时保留待部署状态，可查看日志并重试。模型标识、权重、API Key 和接入地址不因配置更新而删除。配置更新本身不创建权重副本；历史版本用于下面的隔离权重升级。

## 下载新版、切换与回退

1. 检查发现真实权重变化时，点「下载新版并保留旧版」。需要额外磁盘空间；配额包含已保留的历史版本和失败下载。
2. 新版使用独立的权重目录和卡片运行目录，不替换当前部署，也不启动第二个模型进程。全部文件及权重 SHA-256 验证通过后，显示为「已验证，可切换」。
3. 停用当前模型，在「历史版本」中选择「切换到此版本」。客户端重新检查进程、文件归属和权重完整性，先部署目标，再原子切换卡片记录。成功后点「启用」。
4. 原部署进入历史列表，保留完整离线配方、权重路径、运行配置和引擎引用。需要回退时，停用当前模型，再切换到旧版并启用。更改默认权重目录不会改写已归档版本的路径。切换时还会重新确认当前版本的权重归属；若下载期间更改设置等操作使旧版路径无法确认，会拒绝切换并保留当前记录及已验证的新版。
5. 下载失败或取消，当前部署不变，失败下载可重试或清理。应用重启后，已失去操作锁的下载会标记为中断，重新提供重试和清理入口。目标部署或数据库提交失败，当前卡片记录不变。

模型对外的卡片 ID、模型标识和 API Key 保持稳定。各版本的本地包和权重独立管理；全局引擎允许共享。

## 清理旧版本

在「历史版本」查看版本、状态和占用，点「删除此版本」，确认范围后执行。删除意味着不能再回退到该版本。

- 当前版本、下载中的版本、仍有进程使用的版本不可清理。
- 运行目录、权重目录仍被其他卡片或版本引用时，拒绝清理；不以 PID 文件为停进程授权，也不发送停止信号。
- 独立版本目录须通过归属标记校验；发现符号链接、错误归属或无法确认的路径时保留数据。
- 迁移前的旧部署不独占整个默认权重根目录：只删除清单确认、内容再次校验通过的权重。其他文件和目录会列为剩余项，供用户核对。
- 共享及全局引擎不随历史版本清理卸载；历史版本仍引用的引擎也不能单独删除。
- 释放量只计算实际删除且没有其他硬链接的独占文件块，不按卡片登记大小虚报。中途失败保留可重试的清理记录；取消只在不可逆删除开始前生效，提交完成后按实际完成结果报告。

删除或卸载整张模型卡片之前，需要先清理其历史版本，避免留下无法从界面管理的权重。彻底删除当前隔离版本时，也会清理对应的专属目录。

当前隔离版本的彻底删除按同一组去重后的专属权重和运行目录，在清理前后统计独占文件块；目录外仍有硬链接的文件不计入释放量，稀疏文件只按实际分配块计算。清理前无法可靠测量时保留资源并拒绝操作；提交完成后无法确认剩余占用时，释放量保守报为 0 字节，并在日志和结果摘要说明。共享下载根仍只用于残留披露，不扩大测量或删除范围。旧式部署及保留权重的卸载沿用原有测量行为。

切换新版或回退时会沿用目标版本保存的有效部署方案；没有有效选择时使用该卡片的默认策略，并记录实际采用的方案。历史版本弹窗在任务状态变化后刷新，下载成功、失败或取消后可直接继续切换、重试或清理。清理隔离目录时最后才删除归属标记，以支持部分文件删除失败后的安全重试；缺少标记且仍有未知内容的目录继续保留。

卡片更新包拒绝带首尾空白或控制字符的附属文件路径，避免落盘规范化后覆盖入口或运行状态。多文件权重清单中，旧版明确选择的文件被新版清空时，不能按相同清单直接复用；需要发布方提供明确选择。

首次切换已下载的新版前，还会校验当前权重，避免把缺失或损坏的旧版标为可回退；回退至已有历史版本仍允许修复当前版本损坏的情况。清理旧版时，未部署、无法解析运行目录的其他卡片若仍有相同来源选择或匹配的权重清单，也会保守阻止删除；部署这些卡片、确认实际目录后可重新检查清理。

彻底删除当前隔离版本时，卡片卸载脚本只清理服务并保留权重；宿主在共享引用、进程和归属检查通过后统一删除版本目录，避免卸载脚本先删权重、随后才发现仍被其他卡片引用。

当前版本的彻底删除也会先登记可恢复的删除状态；中断后可再次点击删除，继续处理已经移除标记的空目录。删除尚未完成时拒绝重新部署、启用或切换，避免把已部分删除的版本重新投入使用。首次下载与按需获取脚本的降级路径均拒绝运行缓存资产，并应用相同的已知控制器修复。

旧部署方式的彻底删除同样检查其他卡片及历史版本的全局引用；没有可确认路径时，相同来源或权重证据会保守阻止删除。下载、部署等可并行持有资源读锁，切换和权重删除持有独占锁，防止引用检查后又并发创建共享引用；冲突时显示等待进度并支持取消。更改默认权重目录并回退后，卸载和强制移除仍按该版本固定的实际目录报告残留，不把新默认目录中的文件算入旧版。

前端接入和清理只操作明确关联到该卡片的模型配置；无关联的同名本地接口不会被覆盖或删除，旧配置由后端按精确、无歧义路由迁移。GUI 与 CLI 中手动修改接口会解除关联；显式接入只有与运行中卡片当前接口精确一致时才可建立关联。完整对象客户端回传旧卡片 ID 也不能绕过协议字段变化的解绑规则。只有明确请求重新接入（`model_store_link_requested`）或提交新的卡片关联，且接口与运行中卡片当前部署精确一致，才重新建立关联；未修改接口的普通编辑仍保留原关联，包括卡片停用期间。

手动解绑会跨重启保存，匹配历史接口也不会被后台重新关联；再次点击卡片接入可显式恢复关联。后台更新接口时，已打开的设置表单若只修改名称或参数，会保留提交时的最新接口；用户实际改动接口字段时仍执行解绑。

旧历史权重清理使用与切换相同的受限递归查找规则，支持子目录中的唯一匹配文件；存在链接、多个匹配或内容损坏时保留版本记录并拒绝清理。目录整体缺失或受限查找确认权重已不存在时，可正常清理历史记录，随后卸载卡片，无需修改数据库。损坏且仍存在的旧权重继续拒绝自动删除；确认没有其它卡片或版本共享后，可手动清理提示路径再重试。也可使用“强制移除记录”：显式确认后只移除本卡及历史版本记录和密钥，不删除任何文件，结果披露可能仍存在或无法检查的登记路径，供用户自行核实清理。

## 原生引擎启动凭据兼容修复

2026-10-19 确认线上 `native_engine_process.py` 的启动竞态：`Popen` 返回时 `/proc` 的新参数可能尚未就绪，脚本误判退出并漏存凭据，随后操作返回 70。

客户端只对原始 SHA-256 为 `5cb4539ce50c34948ac22bc720d2fce2f08e840e615a963860453f9e1c321bc7`、或已修复启动竞态的 `6b9968bf37c944d6a0ef6207000a88ebe36deb68bac400db206aafb39a55af24` 控制器应用已验证修复，结果摘要必须为 `868605374b0f609f676bf826f72f314a4a1cdb9939464778842c4797368c7d01`。先验证线上包，再按严格指纹修复本地副本；存储实际文件摘要，并使用已知来源映射比较线上版本，避免反复提示恢复有缺陷的脚本。已有离线配方和回退版本执行前也应用同一指纹修复，归档包本身保留。其他控制器不改写。

启动凭据修复最多等待两秒，只检查本次直接启动且尚未回收的子进程；无法确认时保留进程，不认领扫描发现的实例。

同时修复无关进程的超长命令行导致整次扫描失败的问题：命令行截断时，只在可执行文件路径和 inode 不同，或完整读取的权重参数明确不同时排除该进程；仍可能属于目标引擎的截断身份继续阻止启停，不据此认领或发送信号。已知修复版本在本地与线上比较时使用一致映射，发布方采纳修复后也不会反复提示相同改动。发布方仍应合入 `docs/patches/model-store-native-launch-receipt.patch` 并同步附属文件摘要。

带原生控制器的包在执行脚本前创建私有卡片目录和 `0700` 的 `.runtime`，不再依赖宿主 `umask`。首次失败仅留下健康检查日志、且卡片父目录已私有时，可补齐运行目录权限并保留日志；已有凭据、PID、锁、其他状态、符号链接或不明属主时拒绝自动修复，不把原先可由其他用户改写的凭据变成进程所有权依据。

该控制器的完整来源文件由卡片发布方提供，未随本仓库分发，因此下面的真实摘要链和进程行为检查是**人工验证，不属于 Cargo 或 CI 门禁覆盖**。首次引入兼容修复、修改 `native_card_compat.rs` 的任一来源/结果摘要或替换片段、修改补丁文件或此测试脚本，以及采纳发布方新控制器前，必须在 Linux 上重新运行，并在 PR 中记录输入来源、SHA-256 和运行结果；不能以 Rust 中的合成内容测试代替。

```sh
sha256sum /path/to/publisher-package/native_engine_process.py
python3 scripts/test-native-engine-launch-receipt.py /path/to/publisher-package/native_engine_process.py
```

脚本接受上述 `BROKEN`、`LAUNCH_FIXED` 或 `FIXED` 摘要的真实来源文件，先在临时目录内按 Rust 的替换片段生成修复副本，拒绝未知摘要且不改写输入文件，再验证完整 `BROKEN → LAUNCH_FIXED → FIXED` 摘要链。8 项测试覆盖延迟就绪、提前退出、身份超时、未知实例保护、超长命令行的相关/无关进程，以及保留完整系统进程发现流程的 200 次真实子进程启停。测试使用临时目录和 Python 进程，不加载模型或使用 GPU；原始发布脚本无须预先手工打补丁。

由 Cube 等外部设备管理软件启动的服务仍有独立配置，需在对应软件中同步部署。卡片更新保留用户自定义上下文窗口，但本次修复会定向纠正旧版错误下发的 32K（见下文）；调整后可核对服务 `/v1/models` 上报值和品悟模型设置。

界面文案：本次新增的前端界面文案提供简体中文、英文、日文三语。版本操作的后端消息（历史版本行的错误、任务日志中的进度与校验文案）当前仍为中文，其中下载失败的内容源自引擎/脚本自身输出、语言不定；强制移除的结果警告已改为结构化警告码，由前端按当前语言渲染，残留路径始终以路径列表单独展示。权重全量摘要校验与下载一致，按 `LMM_PROGRESS_BYTES=已读/总量` 协议行驱动任务卡进度条（该协议行不进入可见日志），日志中另有逐文件字节数的中文明细。

## 已接入模型的接口同步

“在 Pinvou 中使用”保存稳定卡片关联。每次启用成功后，后台在设置事务中同步已接入模型的实际接口地址和服务模型 ID，并通知桌面及已连接的 Web 界面刷新模型选项和当前有效配置。全局默认模型、会话模型绑定、显示名、凭据及用户显式参数不变，不为未接入卡片创建模型。正在生成的会话不打断，下一轮由 EnginePool 安全更新配置。

旧配置只按卡片当前或已归档版本中唯一匹配的本机接口与模型 ID 迁移；同名远程模型、其他端口的模型及有歧义的旧配置不自动改写。改动模型接口的手动编辑解除旧关联，其他编辑保留关联。接入查重、卸载和强制移除同样按卡片关联匹配，不复用或删除另一张卡片的同名接口。任务完成后切走商店仍会同步；启动和读取模型库时重试未完成的同步。同步失败显示具体错误，可刷新商店重试，服务启用状态如实保留。

尚无卡片关联的旧配置还须符合旧版一键接入的 Chat 路由来源：预设为 `openai_compatible`，提供方为空或 `custom`，未指定厂商及端点模式。地址和模型 ID 相同的 Responses、Messages、其他厂商或完整端点模式配置不自动认领，也不会因此取得卸载清理资格。已有明确卡片关联的配置继续按原有关联同步，显式接入和恢复跟随部署的权限不变。

## 历史导入卡片的运行缓存

旧的本地导入快照可能混入 `.cache` 或 `__pycache__` 中的 Docker / JIT 缓存。新包在抓取附属文件前拒绝这类路径，要求发布方修正清单；旧离线包执行时跳过这些缓存及 `.runtime`、`.deploy-env` 等运行状态，保留磁盘上的实际状态及权限，也不改写归档配方。普通源码、虚拟环境中的源码和名字相近的源码目录继续处理，非法路径仍由原有守卫拒绝。版本切换与回退继续使用目标快照的脚本和部署方案重新生成部署配置，不回放旧运行状态文件。

## 失败恢复与资源操作等待

重试失败版本沿用其已登记的权重目录，即使后来更改默认目录也不会丢失原目录管理记录。继续检查目录与归属标记；不匹配时保留资源并拒绝执行。配额持续计入已有候选的实际占用；本 PR 对所有未完成下载和失败重试额外预留完整声明容量，磁盘余量也按完整声明容量检查。下载仍由原脚本执行，保持原有续传及配置生成流程；但在紧配额或低余量时可能保守提前拒绝，需要清理确认归属的残块或调整容量后重试。新版隔离下载之间的配额检查及登记以跨进程短锁串行，进行中候选预留预计占用，失败或进程中断后恢复为实际占用；就绪、启用和归档后仍保留托管目录实际残块的计费，按资源路径去重并扣除当前记录已计入的占用。配额扫描遇到权限或 I/O 错误时保守拒绝新增下载，修复访问问题后可重试，不将未知占用当作零；普通首次下载也通过同一短锁发布预计占用；失败或中断后保留实际残块计量，成功登记时撤销计划并保留固定目录的实际占用跟踪，避免与新版下载并发超出启用的配额。

普通脚本可自定义权重子目录，计量会保守包含固定下载根内未被独立版本计费的文件。彻底删除成功后，旧下载根转为残留计量记录，不再决定下一次安装位置；重新安装使用当时配置的默认目录，旧根的缓存和未归属文件仍计入配额。删除结果会披露仍存在或无法确认缺失的完整登记下载根，后续对同一卡片使用“只移除记录”时也会披露这些残留路径。下载根可能包含缓存或其他模型，提示路径不代表独占归属；请逐项确认后清理对应文件，不要直接删除整个共享目录。共享根仅用于残留披露，不扩大删除范围，也不与原有候选子目录重复测算释放量。失败下载重试继续使用原登记目录。下载目标缺少可验证约定，因此普通下载和隔离版本均不从同名文件或 HF 片段取得续传抵扣；已有残块、不同根相互嵌套或普通根与旧式历史版本重叠时可能保守重复计量而提前拒绝下载，不会据此自动删除或认领这些文件。即使 Hugging Face 片段具有匹配的 metadata 文件名摘要和 etag，也不代表本次脚本会在同一目录复用它；精确抵扣待后续补齐宿主可验证的下载目标约定后提供。

普通首次下载在准入检查期间先登记完整预留及根目录实际占用；磁盘余量、配额或占用扫描失败，以及进入首个引擎探针前取消时，不将这个尚未开始脚本的新位置固定为重试目标。其根目录原子转为残留计量记录，已有缓存和其他文件继续保留并计入配额；用户改好存储设置后可在新目录重新下载。应用在此阶段中断也按同一规则恢复。旧版已登记的下载目标、已安装模型的固定目录，以及已经进入引擎探测、安装或下载脚本阶段的目标继续沿用原目录；不会为换目录移动或删除残块。无法提交恢复事务时保留原登记并拒绝改用新目标。

下载、排队、部署和启用全程持有共享资源锁，防止脚本运行期间新增共享引用后被另一任务删除；切换、清理和彻底删除等待这些操作释放资源。切换前重新核对托管目标的目录、归属标记与祖先权限，新升级还对当前版本做同样检查以保证可回退；回退历史版本仍允许恢复损坏的当前版本。等待期间显示进度并支持取消，取消不会执行后续资源变更，停用操作仍可执行。

清理与切换的进程引用检查完整读取命令行，超过 64KiB 的无关参数仍可正常排除；每个进程最多检查 8MiB，另读 1 字节判别超限，整轮检查继续共用 5 秒预算。超过上限或预算时保守拒绝操作，不把截断内容当作没有资源引用；中断的系统读取会在剩余预算内重试，其他进程退出期间的读取失败沿用现有处理。

显式接入卡片时，无论新建模型还是复用已有模型，若详情中的接口已经失效，保存都会在修改配置和凭据前返回错误；请刷新卡片后重试，不会静默保存成永久脱离同步的独立配置。显式接入意图只随本次请求传递，不写入设置。既有模型只修改选项时仍保留事务内最新接口及卡片关联；手动修改接口字段仍会解除关联。


聊天模型选择器调整思考深度时，只在设置事务内修改最新模型的该字段；后台更新的接口、关联、上下文、用户别名及其它参数均保留。若模型已被删除，迟到的档位操作报错，不重新创建模型。已有设置表单未编辑接口时，也保留事务内最新的接口与关联状态，包含用户刚解除关联或改接另一张卡片的结果。接口作为一组包含协议预设、提供方类型、厂商、端点模式、地址和模型 ID，避免将后来更改的 Responses 接口与旧 Chat 预设混合；GUI 或 CLI 中显式更改其中任一字段时按本次编辑保存并解除原关联。普通表单的其它参数仍按整行编辑保存，不提供跨编辑器逐字段合并。

完整对象客户端回传原 `model_store_card_id` 时，同样按这六个字段判断是否解除关联；仅地址和模型 ID 仍与运行中卡片相同，不会覆盖协议编辑的解绑意图。主动重新接入继续通过本次请求的显式接入信号校验当前部署；未修改接口的普通编辑仍可在卡片停用期间保留原关联。

商店关联模型若是其它主模型明确选择的图片分析模型，配置更新或重新启用后也会在下一轮重建依赖它的会话引擎，保留原视觉模型选择；不依赖它的会话继续复用。依赖检查使用实际模型快照及进程内更新记录，不检测没有通知、凭据元数据也不变的外部密钥值轮换。

### 上下文跟随当前部署

商店接入的模型默认不保存固定上下文上限（`context_window_tokens = null`），由会话引擎探测当前服务实际提供的窗口；探测值不得写回为用户声明，否则升级后可能永久受旧窗口限制。用户在设置中填写的固定上限继续参与与服务能力取较小值的预算计算。

模型详情逐条显示已关联配置的自动/固定状态，并提供“恢复跟随部署”：只清除所选模型的固定上下文上限，不改凭据、输出限制、全局选择或会话关联。写入在配置事务中核对当前卡片关联和实际接口，拒绝已解除关联、接口过期或未运行的部署。此入口供用户主动恢复自动，旧版错误下发的 32K 由下面的一次性修复直接纠正，不要求用户额外操作。

本次更新定向修复 Qwen3.8-27B（SGLang v0.5.19、驭光、Native MTP 生产采样）和 Ornith（35B-A3B、9B）已验证卡片的历史 `32768` 配置。更新并成功启用、应用启动后的后台同步或模型库刷新时，核对当前卡片关联、运行状态、部署脚本/版本及方案，并对本地 `/v1/models` 做限时探测。只有唯一匹配的实际模型明确上报 `262144` 时，才把对应已保存配置直接改为 `262144`；无需重新接入或手动恢复跟随。尚未重新部署、未运行、探测失败、旧服务仍上报 32K、Native MTP 基准方案均不修改，后续同步自动重试。

修复与逐模型的迁移记录在同一个设置事务中持久保存。其它长度和自动模式保留；修复完成后用户再主动设为 32K 也会保留，重启不重复迁移。网络探测不持有设置锁，提交前重新核对部署身份，普通设置保存不覆盖迁移记录。设置表单在打开期间后台完成修复时，仅修改别名等未编辑上下文字段的保存不会用打开时的旧快照覆盖修复值（保存载荷携带 `preserve_context_window_tokens`，后端保留库内最新值）；用户在表单中显式修改该字段（含改回 32K 或清空为自动）仍按表单值生效。每轮 HTTP 探测预算 3 秒、单请求最多 1 秒，只访问已关联的回环接口、不经代理或重定向；没有待修复配置时不发起请求。

新版本设置表单对明确编辑的上下文字段另传一次性的 `context_window_edit_requested`；CLI 新建时明确传入固定上限，或编辑时明确传入上下文选项，也会在同一设置事务记录用户选择。该记录独立于卡片关联，即使旧模型尚未完成关联，或首次能力探测正在等待响应，刚确认的 32K 也不会被修复覆盖。未编辑上下文、只调整聊天思考深度、未携带明确信号的旧客户端及机器默认构造不记录手选意图；未编辑保护与思考深度专用保存均优先于不一致的显式信号。信号字段不落盘、不随配置读取返回；删除模型同时清除记录，同 ID 重新新建不继承旧选择。无此新记录的历史 32K 继续按上述一次性核验规则修复。

每次成功启用模型后，即使接口地址与模型 ID 未变，也通知模型列表、有效配置和 EnginePool 刷新。后台刷新与用户选模或切换会话交错时，桌面和 Web 界面均保留较新的选择与有效配置，迟到的旧响应或错误不覆盖它们。下一轮对话重建会话引擎并重新探测，可随升级、回退或部署档位变化采用新窗口，不打断正在生成的轮次。普通模型库查询保持幂等，不反复重建会话。

后台刷新设置时也保留较新的设置状态：用户成功保存设置、搜索配置或专属设置事件发布后，迟到的旧设置响应及其错误不会覆盖它们。读取之间按后发者生效，读取不阻塞用户设置保存；保存失败仍保留原有失败返回及后续读取行为。

### 版本长操作的进度与完成结果

切换保留当前与目标权重的完整摘要校验，校验期间显示逐文件和字节进度并支持取消；不以文件大小或修改时间代替内容校验。长期版本操作完成后不自动替换用户打开的对话框。当前应用页面运行期间，版本操作结果保留在模型商店的非模态结果区，切走再返回仍可查看；并行操作分别展示，清理残留路径须逐项确认已阅，整页刷新或退出应用不保留此临时结果区。
