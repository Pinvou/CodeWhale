# F06 成员重试与组织单元资金边界

## 成员操作与分页

普通成员移除和平台管理员移除成员都必须显式提供原操作的幂等键（既有 `Idempotency-Key` 请求头或 `idempotency_key` 查询参数）。缺少键返回 400，不能从管理员登录会话推导新的移除意图。同一操作的重试保留原键；移除、重新加入后的再次移除是新的操作，使用新键。旧回执不被解释成对后来重新加入成员的新删除授权。

组织成员及额度成员列表返回 `items` 和 `next_cursor`，末页明确返回 `null`。默认每页 50 条，最多 200 条；游标绑定列表资源、组织及所选节点，不能跨范围复用。页面通过“加载更多”取得后续成员，不把第一页视为完整目录；切换组织、节点或失去权限后清除旧列表并拒绝晚到响应。

`ORG_MODEL_ADMIN` 的角色约束通过新的 Account 前向迁移扩展，既有迁移文件不改身份。回滚遇到不能由旧约束表达的已分配角色时拒绝，不删除角色绑定来强行回滚。目标用户被停用时不能继续替换其成员角色；授权检查先于越权调用方可观察的成员存在性查询。

## 完整批次幂等

Billing 在处理任何子项之前，先持久化父批次的组织、操作者及完整有序 `items`。相同父键必须使用相同事实；重排、增删子项、改变金额或操作者返回 409，且不进入子项拨款。每个子项继续使用原有 v1 子键及原数组序号，保留后端既有的合法重复条目语义，不新增表单重复成员能力。

207 的每个子项可能为 `SUCCEEDED`、`FAILED` 或 `UNKNOWN`。只有已知业务拒绝能判为 `FAILED`；没有可靠未提交证据的存储错误（包括提交回执丢失）返回 `UNKNOWN / MEMBER_QUOTA_ALLOCATION_UNKNOWN`。父事实提交结果不明返回 503 `MEMBER_QUOTA_BATCH_OUTCOME_UNKNOWN`。客户端保留原完整事实和父键，沿已有不确定结果流程手动重试整个原批次；不能改用新键或只重发未知、失败子集。已成功子项由原子键回放，不再次拨款。

新增 Billing 父批次表是不可变证据，运行身份不能更新、删除或截断，向下迁移明确拒绝移除这些证据。旧迁移及已有子项拨款记录保持原样。历史子键是单向摘要，无法从旧记录反推出原父键及完整顺序；新父表不声称追溯恢复旧批次。升级前需完成结果未明的旧批次核对；旧操作只能按已知的原始事实及原键恢复，不能借升级重用旧键改变事实。本轮不自动补造旧事实或调整资金。

## 组织单元删除

删除评估同时核查组织单元钱包的余额、预约、应收、剩余权益、未结用量、付款退款、拒付、强制退款、对账、损失评审及待审批调整。存在任一未结事项时保留原资金和生命周期状态并返回阻断；内部评估的 200 响应不等于公开删除成功，公开入口继续将阻断映射为 409。

终态转换与钱包创建使用相同的钱包所有者锁，并持有钱包行锁完成资金检查。成功写入 `DELETED` 时在同一事务将钱包置为 `CLOSED`；已删除单元不能重新启用、创建可用钱包或新增资金调整。新增待审批调整的状态检查和记录写入也在持有钱包行锁的同一事务中完成，防止在空余额检查之后插入未结事项。

`DELETION_PENDING` 保留原钱包状态和既有受控清理能力，不额外引入冻结、迁款或清余额策略。缺少生命周期投影的旧单元仍保留原有创建语义；已知 `DELETED` 则失败关闭。历史已删除单元存在旧资金时需人工核查，本轮不改写旧账本或以删除证据绕过阻断。
