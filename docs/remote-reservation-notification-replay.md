# 配对预约通知重放

Relay 对同一 socket、稳定 `claim_request_id`、公钥、连接码和能力集合的合法重试复用现有预约。外层 `request_id` 可以变化；Router 仍向主控 A 和被控 B 各发送一次 `controller_pairing_reserved`。当前应用主控不会自动重发已清除连接码的 claim，这里处理的是协议允许的通知重放。

两端首次接收仍按原信任根验签并绑定预约；A 首次响应仍须匹配原请求 ID。此后只有与当前已认证预约安装上下文完全相同的通知才忽略，比较时仅排除外层请求 ID。预约、配对、代际、Relay epoch、对端、双方公钥、连接身份、能力及签名期限均不得改变。无效签名或不同绑定沿原拒绝路径处理。签名密钥 ID 用于选择已配置的信任根并验签，不属于安装上下文的相等比较字段；可信密钥轮换也不能跳过验签或改变预约绑定。

忽略通知不生成新密钥或收据，不重发 commit、Finished 或 ack，不重设状态与期限。B 在处理前继续检查当前操作所有权和待决阶段；停止、刷新、超时或已建立连接不会因旧通知启动新的握手。不同预约没有全局去重记录，也不继承前一握手。

Windows 定向集成测试以真实 Relay 的 ReservationManager、LeaseManager、Ed25519 签名及 Router 生成并路由通知，接入真实 A worker 和 B 的 WebSocket reader、worker、管理器及租约安装。测试控制端点认证、配对存储和 A 的传输适配；不代表完整 Relay 部署、UI 自动重试或持久化验收。独立协议测试另覆盖改变可信签名绑定和无效签名的拒绝。
