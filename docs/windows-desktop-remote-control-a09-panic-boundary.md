## 异常与阻塞工作

受控提交的冻结预算和精确接纳序号跨越阻塞准备、异步执行、阻塞结算三个阶段。
真实执行器仍异步；磁盘持久化、成果扫描和资源清理不搬回异步线程。
工作线程不继承线程局部脱敏状态，每段受控工作显式进入自己的作用域。
内部 borrowed 路径与生产 worker 路径均捕获执行异常；异常收口再次 panic 时只返回固定错误，
不递归收口，不输出 panic 内容，不声称损坏持久化已成功写入终态。
所有失败收口先检查捕获的接纳序号，再操作取消令牌及终态；迟到旧失败不得误停新任务。

资源 hook 独立捕获异常，仅对失败且幂等的同一个 scope 再试一次。
成功 scope 和 journal 发布不重跑；永久失败最多两次且不阻断其他独立清理端口。
这不是永久故障资源已经释放的保证。原接纳 guard 与精确终态清理接口保留。
附件来源的 None 与 Some(empty) 仍分别表示 wire 回执与 B 本地附件，不合并语义。

## 进程 panic hook 注册

泛型函数中的 static 并不按单态化分裂，原审核的多把注册锁推论不成立。
真实问题是每次 take_hook 到 set_hook 之间暂时恢复默认诊断，会影响已经生效的受控脱敏。
统一分发器仅首次安装；登记返回后对应作用域才可启用，后续只发布不可变的处理器快照。
回调按后注册优先调用，调用前释放注册表锁；无消费者时仍链至原诊断。
测试用确定性交错在实际核心代码中暂停第二次登记，核对原实现失败、当前实现无默认窗口。
