# 团队基本生命周期修复计划

> 状态：已实施，随本轮团队基本生命周期修复维护。

## 目标

通过一个 PR 补齐团队负责人交接、普通成员主动离队、无效当前团队恢复和团队解散四项基本生命周期能力。四项能力共享有效成员关系和当前团队选择的校验边界；本轮不扩展成通用角色管理或完整团队治理系统。

## 范围

### 1. 转让团队负责人

- 产品只提供一个团队负责人，不增加多负责人或通用角色升降级入口。
- 当前负责人只能把身份原子转让给同一团队的有效普通成员。
- 被转让人必须是未禁用的有效普通成员；禁用账号不能成为团队唯一负责人。
- 转让只交换团队成员角色，不修改 `teams.created_by`，也不改变任何 WorkThread 的 owner、current actor 或其他任务角色。

### 2. 普通成员主动离队

- 普通成员可以主动结束当前团队的 Membership；团队负责人必须先转让或解散，不能直接离队。
- 成员存在未结束责任项时拒绝离队，并一次返回全部阻塞任务摘要。
- 离队成功后，在同一事务中撤销该成员创建的未使用邀请；如果团队加入码仍启用，再轮换加入码，使离队成员掌握的入队凭据立即失效。
- 离队不影响同一 Principal 在其他团队中的 Membership，也不等同于退出账号。

### 3. 恢复有效当前团队

- 已保存的当前团队仍有效时保持不变。
- 当前团队失效且仍有其他有效 Membership 时，选择最近加入的有效团队并立即持久化新的 `team_id`。
- 不再属于任何有效团队时清除本地 `team_id`，展示创建或加入团队入口。
- 外部移除、主动离队和团队解散都走同一恢复逻辑；客户端不得继续展示失效团队的缓存快照或因状态不一致禁用操作。

### 4. 解散团队

- 只有团队负责人可以解散团队。
- 团队存在任何未结束工作时拒绝解散，并一次返回全部阻塞任务摘要；解散操作本身不自动取消任务。
- 解散采用 [ADR-0023](../adr/0023-团队解散采用不可恢复的逻辑终止.md) 定义的逻辑终止：用户侧不可恢复，服务端保留历史。
- 解散与加入码失效在同一事务中完成。解散后所有成员都不能再通过旧 `team_id` 访问或修改团队数据。
- 当前产品不提供已解散团队列表、只读历史入口或恢复入口。

## 契约与数据

- 新增下一顺序迁移，为 Team 记录解散时间和执行解散的 Principal；迁移不得物理删除既有数据。
- 为负责人转让、主动离队和团队解散提供窄而明确的 Hub API，不开放任意 Membership 角色修改接口。
- 抽取共享的未结束责任项查询，覆盖 initiator、WorkThread owner、current actor、return target、final recipient、pending sender 和 pending recipient，并返回任务 ID、标题、状态及被阻塞成员的责任角色。
- Membership 变更与任务建立、Handoff、改派继续通过 Team 行锁串行化，避免校验后又产生新的未结束责任项。
- `GET /v1/teams`、Membership 校验、Bootstrap、SSE 和所有 Team 范围资源必须排除已解散团队。
- 同一 PR 同步修改 `protocol.md`、`openapi.yaml`、迁移说明和契约测试。

## 客户端闭环

- Rust Team Relay manager 暴露负责人转让、主动离队和团队解散命令，并负责成功后的配置持久化和有效团队恢复。
- Bridge 统一更新 Team Relay 快照与 `status.team_id`，避免操作成功后仍保留旧团队状态。
- Hub 已提交生命周期操作后，后续账户、团队或事件流刷新失败不把已成功的操作误报为失败；客户端保留可见的同步警告和重试入口，直到权威状态刷新成功。
- 团队界面只向符合权限的用户展示操作入口；危险操作使用明确确认，阻塞时展示完整任务摘要。
- 新增文案全部进入共享 i18n，并同时提供简体中文、英文和日文。

## 验收场景

1. 负责人可以把身份转让给未禁用的有效普通成员，即使原负责人仍有未结束责任项也不改变其工作责任；重复点击或并发请求不会产生零负责人状态。
2. 禁用账号不能接任负责人，团队不会出现唯一负责人无法登录的状态。
3. 无未结束责任项的普通成员可以离队，其创建的未使用邀请和已知旧加入码立即失效；有责任项时离队被拒绝。
4. 当前团队被外部移除、主动离队或解散后，客户端持久化最近加入的其他有效团队；没有候选团队时清空选择。
5. 零未结束工作的团队可由负责人解散；存在未结束工作时拒绝且不发生部分状态变更。
6. 解散后旧 Token 即使仍属于同一 Principal，也不能通过旧 `team_id` 读取成员、任务、附件、头像或 SSE，历史数据库记录仍然存在。
7. Membership 终止与并发派活或 Handoff 竞争时，不会产生引用无效成员的未结束线程。
8. 生命周期操作在 Hub 已提交后，即使客户端刷新失败也返回成功并清除失效当前团队，网络恢复后自动同步权威状态。
9. 邀请领取与成员离队、移除或团队解散并发时统一按 `Team → Invite` 取锁，不发生数据库死锁；生命周期操作先完成时，已撤销邀请稳定返回 `invite_expired`。

## 非目标

- 失联成员的负责人强制取消、强制改派或强制收尾。
- 多负责人、增加负责人或通用角色权限管理。
- 团队重命名、创建团队幂等和加入码复制反馈。
- 设备列表、其他设备撤销和退出账号时撤销 Token。
- 已解散团队恢复、只读档案和统一数据物理清理。
