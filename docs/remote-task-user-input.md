# 远程任务中的用户提问

桌面主控向被控发送原生 Engine 聊天任务时，模型可能调用
`request_user_input`。这属于用户选择或补充信息，不是工具权限批准。
主控会话现在显示同一任务的问题卡，支持单选、多选、自定义文字及取消；
等待期间显示“等待你的回答”。被控本地仍可回答或取消，双方竞争同一次决定。
不会自动代选，也不会因此授予工具权限。

## 行为与恢复

- 主控只读取当前任务的问题。卡片绑定连接租约、远程会话及任务，切换会话、
  更换租约或任务终结后撤下。能力目录刷新不会清空同一问题的未提交选择。
- 被控将问题绑定到实际执行的 Engine 回合、所属执行器与任务预算。
  主控得到的是一次性问题标识和选项序号，不取得本地工具标识。
- 回答被确认只代表进入原回合邮箱，不代表工具或任务完成。
  相同决定可安全重投；不同决定不能覆盖已经接收的决定。
- 回答结果未知时保留原决定，禁用编辑，使用“重试”查询/重投同一请求。
  不自动改选或创建另一份决定。读失败停止自动轮询，允许手动刷新。
- 被控本地取消、远程停止、中断、失败和原有回合预算到期继续沿用任务终态；
  终态后的迟到列表不能恢复卡片，旧问题的回答不能进入下一回合。
  不因等待提问或重试延长原有预算（默认 30 分钟）。

此功能要求两端及所用 controller-v1 协议校验器支持新增操作。
不新增握手能力名称，仍要求 `task_v1` 和 `permission_v1`。
旧端点会拒绝不支持的操作，主控显示暂不可用并停止自动读重试；
可在被控端本地作答或更新两端后重新发起任务。普通远程任务及权限批准的契约不变。
本次仅覆盖原生 Engine 的 `request_user_input`，不扩展第三方 ACP elicitation。

## 有界输入与保密

每回合最多保留 8 个待回答问题请求、128 个问题身份/决定收据；每请求最多
3 组问题，每组 2–4 个选项。问题投影最多 192 KiB，自定义答案最多 4096 个
Unicode 标量。无法按此契约表达的问题会被取消，不会伪造答案。
已消费请求释放原问题及投影，只保留该回合内防重复所需的摘要。
回合结束释放其注册；不会持久保存问题收据，也不承诺跨应用重启恢复答案草稿。
问题展示文本沿用现有清理器，原值仅由被控端映射回来。
不要将问题正文、答案或原始工具标识写入协议日志。

## 验证入口

共享协议向量位于
`remote-control-relay/test/fixtures/controller-user-input.json`。
Rust 原生问题生产器校验该投影；环境变量
`PINVOU_REMOTE_USER_INPUT_PROJECTION_FILE` 可将本次生产的完整 DTO 写入隔离路径，
供 `pinvou3-app/tests/remote_user_input_smoke.mjs` 直接消费。
浏览器测试挂载真实 ChatView、选择卡与桌面 bridge，原生调用边界受控。
Rust 任务入口测试使用真实租约管理器、任务账本和问题生产器，仅最终邮箱注入受控。
这些验证不冒充两台已安装桌面应用和真实模型的现场验收。
