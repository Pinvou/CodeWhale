# 任务失败诊断

本功能分为自动结构化故障证据与逐次授权的详细诊断包。业务成功率仍由原任务生命周期计算，诊断详情抽样、上传失败和管理员处理状态不改变任务终态。

## 数据与授权

诊断写入同时核对当前已接纳任务的 attempt、非空 turn、原采集租约及对应提交上下文，
持有任务与诊断锁直到写入完成。历史消息复制等观察不能替待接纳提交选择 turn；
仅匹配 attempt 的真实接纳事件建立或校正归属。旧缓存缺少私有 attempt 标记时仍可读取，
但不会凭显示 turn 建立任务归属。本次不改变原任务终态收口及准入顺序。

自动证据只包含登记错误码、组件、采集点、版本、模型/工具分类及有界阶段轨迹，不包含原始错误、提示词、工具参数、文件路径、响应正文或凭证。事件沿用统计开关、原始采集 generation/period、持久化 outbox、退避和删除协议。原始证据最多保留 35 天。

用户从故障列表选择一次失败，填写最小复现说明并选择附加材料，预览最终清理后的报告，显式确认后才排队发送。预览令牌绑定报告内容、原授权与有效期，编辑内容后必须重新预览；不自动上传完整会话、配置、日志或截图。详细报告最多保留 14 天，停止采集清除未发送报告，授权删除清理所有关联诊断。截图需用户逐次选择并确认，文字脱敏不能保证消除图片中的私人信息。

同一授权 generation 的凭证续期不修改已确认报告的任何字段。当前投递周期单独放在请求外层；事故事件的 `diagnostic_origin_period_id` 保留首次原周期，重绑只更新路由周期。服务端同时检查当前采集授权、设备归属和精确原事故周期，不按“附近周期”猜测。已入库报告丢失回执时，在当前授权仍有效的前提下按同一报告 ID 和完整事实返回原回执，不要求事故明细仍在。旧客户端已重绑的本地队列可由同 generation 的原事故快照和确认记录一致恢复原周期；证据冲突时失败关闭。旧服务器已丢失原周期、客户端也无一致证据时不能自动恢复。若事故已按错误的重写周期入库且缺原周期标识，同一事故重新预览仍不能恢复关联；报告保留明确的 `incident_period_mismatch` 拒收终态并停止自动重试，提示通过既有反馈渠道手工报告，或故障再次发生时选择新记录。旧版已拒收且缺原因的记录也不再承诺重新预览可恢复。本轮不自动改写历史授权、猜测关联或增加重新授权协议。

采集期结束是报告投递终态，界面明确显示未发送，不继续退避；重新开启采集后需重新预览确认。事故已在服务端存在但原周期明确不符时，同样终止无效重试，按前述无法恢复关联的终态提示处理，不能靠同一事故重新预览恢复；事故尚未送达时仍退避等待。预览过期、授权变化和队列已满分别给出操作提示。无待发送材料时报告 worker 等待唤醒，有队列时按每份报告的下次重试时间唤醒。

续期先在私有主状态写入新凭据、目标周期与绑定原 generation 的恢复点，再更新 outbox、任务与诊断 lease，全部成功后清除恢复点。启动在授权清理前重放未完成续期；未完成写盘时保全队列并暂停采集，控制 worker 独立于报告队列按有上限的指数退避重试恢复，包括没有待发报告的情况。运行期失败和启动恢复失败都会唤醒该调度；成功后恢复采集并唤醒事件、报告和工具安装终态投递。恢复点不适用于已撤销、已删除、不同代次或不同端点的授权，不改变原有清理规则。没有合法恢复点的失效报告进入授权变化终态，避免反复唤醒；确认后的报告内容和原事故周期始终不变。未完成恢复前不要降级到不识别恢复点的旧客户端。

服务端联合删除仅在某个原始事件流实际移除主体材料时同步重写该流，成功落盘后才提交内存过滤结果。后续存储清理失败仍保持 `processing`，重试不重复重写已清理的事件流；某个流写盘失败则仍保留待清理状态，不能误报完成。

删除回执的常规有效期不终止尚未完成的清理。`processing` 记录及原请求标识跨有效期压缩和重启保留；状态查询或相同请求仍会继续清理。完成后的过期回执才返回已过期，最小墓碑继续阻止旧凭证恢复主体。

### 详细文本的字段级脱敏

客户端和统计服务使用相同的 JSON / 完整键值记录语法与封闭技术词汇。HTTP 状态、登记错误码、阶段、工具分类、token 用量、重试间隔、退出码及布尔状态按类型和范围保留；不再因为 `input_tokens` 包含 token 字样而删除故障行。凭证、Cookie、提示词、正文、原始消息、堆栈及其整棵子树删除；未知结构化字段的值和原始字段名不回传。未知错误码使用报告内匿名值，新增可读技术词汇须同时更新 Rust、Relay 及行为测试，不能放开任意字符串。

请求、任务、会话等关联 ID 统一匿名化。同一份报告的说明和文本附件共享客户端私有随机 scope，scope 不上传；不同报告重新生成。服务端使用私有持久化随机密钥，以设备与报告 ID 的结构化组合派生 scope，再次匿名化所有输入 ID，包括客户端提供的合法匿名标记，避免旧客户端复用标记形成跨报告关联。服务端替换后的标记可能与本地预览不同，报告内关联关系仍保留，用户确认后的材料只会进一步收窄。密钥不出现在统计接口、报告详情、审计或错误信息中。

完整多行 JSON 先整体解析。对无法证明边界的正文、凭证、未知字段、类型非法值、Markdown/PEM 块、未闭合引号或格式错误记录，保守删除其余未定界内容，不在后续看似合法的字段恢复提取。深度、数组长度、字段数、输入及最终报告大小均有上限。简短的普通复现说明仍可保留；**这不是任意未标注个人信息、凭证或未知编码的通用识别器**，用户仍需在预览中检查并删除私人信息。图片中的可见内容也不属于文字脱敏范围。

旧服务端存量报告在加载时实际重写材料并持久化，保留旧摘要以兼容相同内容重试；旧算法仅用于旧摘要比较，不能用于新报告入库。迁移、私有密钥写入或存储校验失败时关闭报告读取与接收，返回存储不可用。清理、审计、处理状态更新、重启及采集周期续期都保留该密钥与幂等语义。

设备库存或删除账本读取、解析、结构校验失败时，统计服务拒绝启动，在报告迁移、剪除和事件重写前保全持久证据。设备库存缺失且已有事件、报告或账本文件也拒绝启动，不能将未知库存当成有效空清单。升级先持久化删除账本，再在设备库存写入 `deletion_ledger_required: true`；此标记存在而账本缺失时同样拒绝启动。旧版无标记安装仍可迁移：无法区分其从未创建账本与历史账本丢失，需结合备份核查。写入失败可恢复后重复迁移。运维应恢复有效库存和账本，不得通过写入空清单解除错误；有效空库存、显式删除及正常到期清理仍按既有规则执行。

## 排障工作流

运营统计页通过与“设备概览”“行为分析”“远程控制”同级的“故障诊断”页签进入。进入页签时加载分组，支持按版本、错误码、提供商、平台、运行模式和周期筛选；顶部刷新使用当前诊断筛选条件，独立请求诊断接口，不等待设备概览或其他行为分析接口。会话过期时清除证据和加载态；重新登录后，若仍停留在故障诊断页签，则按原筛选条件重新加载。30 秒定时刷新不重载故障列表，避免打断正在查看的证据。筛选栏、分组表格和样本详情复用统计页的卡片与控件样式，小屏下筛选项纵向排列。

统计角色只能查看达到 20 个独立统计主体的故障分组。运营管理员可以下钻具体证据、授权报告与时间线，并标记待定位、已复现、已修复和修复版本。详情读取与修改写入有界私有审计记录。指纹由登记组件、阶段和错误码派生，不包含用户内容，不将应用版本放入指纹，因此可跨版本比较同类故障。

程序未提供结构化原因或堆栈时保留 unknown，不猜测源码堆栈。异常退出恢复标记为 inferred，不据此断言崩溃或网络故障。工具失败后恢复、用户取消、远控未收到结果与权威执行失败分别保留，不将每次工具失败计为任务失败。底座通用错误协议改进优先回馈 CodeWhale，本功能不在 fork 内复制执行生命周期。

CLI 连接器、市场工具及技能的安装失败在返回错误前显式记录安装终态，包括同步安装失败和后台任务 join 失败。原始错误仍按既有接口返回调用方；自动证据只保留现有分类器生成的受控错误码和 HTTP 状态，不保存原始错误文本。只有未显式完成的安装守卫才使用 `internal_error` 兜底。市场工具的安装后校验失败仍先完成配置修订和在线会话刷新，再记录失败；成功、已安装及失败均只记录一次终态，继续遵守采集授权代次与续期边界。共享诊断写入在取得本地状态锁后再次复核原租约，使禁用清理与迟到观察者的本地写入保持同一授权边界。安装事件目前没有细分下载、解压等阶段，分类也不构成底层根因证明；历史记录中已丢失的原因无法补回。

工具失败事件接入 Engine 已有的 `ToolResult.metadata`，只投影登记的 `error_code`、整数 `http_status` 及 shell 的整数 `exit_code`、`TimedOut` 状态和 `sandbox_denied` 布尔值。明确错误码、shell 状态、HTTP 状态优先于既有文本分类；非零退出码归为 `process_failed`，超时归为 `request_timeout`，沙箱拒绝归为 `permission_denied`。分类优先级为登记的明确错误码、shell 原因、HTTP 状态、受控文本分类；shell 原因内部依次为沙箱拒绝、TimedOut、非零退出码。不上传 metadata 原文、命令、stdout/stderr 或未知错误码。小写 `bash` 与既有 `Bash` 一样归入 shell。默认小写 bash 的失败返回 `ToolError`，不携带 `ToolResult.metadata`；宿主因此在原事件回调中，从该会话既有 ShellManager 查询精确非空 session / turn / call、根 Agent、唯一且非 stale 的自然失败记录，只补有效非零退出码。不按命令或输出文本匹配，不消费完成回执，也不重绑采集租约。`Killed` 不能证明超时，快照没有沙箱拒绝标志，启动前失败或已回收记录可能没有可用事实；这些情况继续保留未知，不承诺所有 bash 故障均有退出码或结构化原因。退出码范围为 -2147483648 至 4294967295，兼容既有有符号退出码并完整保留 Windows DWORD/NTSTATUS，例如 3221225477（0xC0000005）；自动事件校验与两端文本脱敏使用同一范围。退出码先保存在内部 hint，仅实际创建诊断信封时投影；取消观测或迟到的旧 turn 不产生孤立诊断字段，仍保留基础工具终态。没有结构化事实时继续使用受控文本分类或 `tool_failed`；ACP 未提供相同元数据协议时不从显示文本臆造退出码。`diagnostic_retryable` 是分类提示，不表示任务最终是否恢复，也不是重试承诺。

诊断详情的时间线最多返回 32 条事件，按故障发生位置选择前后窗口，并保留同一生命周期中发生时间不早于故障的最近可用任务终态；更早的终态仍可作为窗口上下文，但不计为该故障的终态证据。关联限定在同一设备和采集周期。远控执行优先使用严格 64 位十六进制 execution_task_key / remote_task_key，只有被控端 controlled 的 task_terminal 和明确受控终态才作为权威终态；控制端派送、result_received、unknown 回执或跨设备 trace 不代替执行终态。普通任务使用 turn，其次 attempt，再其次 operation；同时存在的 attempt 不相同则排除。无关联标识时仅返回故障本身。返回 `timeline_context` 标明当前留存的相关事件总数、实际返回数、是否截断、是否包含故障及任务终态；总数不代表完整执行历史，已过期或未上报事件无法补回。页面只接受当前请求代的列表、样本、证据与授权错误；旧 401/403 不覆盖新查询，当前代授权失效仍即时清除证据。被新查询取代的手动刷新不报告成功或部分失败。页面展示截断情况和终态可用性，旧服务未提供该信息时明确提示未知。历史故障可使用新的窗口选择方式，但缺失的退出码等客户端事实无法追溯生成。

## 发布与验证

建议先升级统计服务，再发布客户端。旧服务拒绝新增诊断字段时，以相同事件 ID 重传基础事件，保留任务指标；旧服务缺少报告接口时队列退避重试。接口不依赖私有反馈接收服务。客户端、服务端、页面和三语文案必须一起验证；真实模型/网络故障及双机端到端场景仍须按实际环境验收。

现有公网 Nginx 必须同时应用 `remote-control-relay/nginx-telemetry-stats.conf` 新增的精确报告路由，验证 `nginx -t` 后 reload。Node 部署脚本不会自动更新代理配置。该接口上限为 2300 KiB，其他路由不扩大上限；默认 1 MiB 代理限制不能承载合法的多图报告。

自动故障身份与计数不抽样；扩展阶段详情按设备每日每类最多 5 条、总计最多 50 条抽样，`diagnostic_sampled` 明示详情是否被保留。客户端保留最近 50 条本地故障供报告，未发报告最多 4 份，每份独立退避，收到匹配回执后清除本地说明与附件。图片预览前解码重编码以移除隐藏元数据，限制 4096×4096 和 64 MiB 解码预算。

服务端详细材料全局配额 28 MiB，另预留 4 MiB 给最多 2000 条审计和 2000 个处理状态。材料满额只拒收新增报告，保留既有报告的审计读取和处理能力；报告仍可在本地限量队列退避重试。

服务端 `failure-diagnostic-metadata.json` 单独保存同步访问审计和处理状态，读取或标记问题不再重写材料快照。返回详细材料前必须成功持久化审计。材料新增和删除仍同步写入一次有界快照，不宣称完全消除大报告写盘停顿。旧单文件数据可迁移；快照标记 `metadata_version: 1` 后，元数据文件缺失、损坏或不安全时拒绝操作，不能回落旧内嵌审计。材料快照丢失而元数据残存同样拒绝作为新库启动；首次写入失败留下的残存文件须运维核查并保全，不能直接清空。备份与恢复应同时保留库存、删除账本、材料快照和元数据文件。启动对两类报告文件执行私有权限检查；报告请求体大小保持 2300 KiB，并增加 15 秒无数据超时。

本地轨迹缓存最多 128 项，淘汰最近最少使用的单项，不因无会话的普通观察事件清空进行中任务。环境分类只接收登记枚举及布尔值，旧缓存中的非法分类在使用前同样清除，不能让扩展诊断阻断基础任务终态。

请求大小校验包含设备、投递周期和报告的完整 JSON 外层；预览为允许的最长标识预留空间。远控 `result_unknown` 保留未知结果诊断和终态去重，但不推断为权威任务失败。脱敏的文本长度分别限制 UTF-16 单元和输出字节；Rust 与 Relay 的完整键值记录使用一致的 ASCII 空白边界。

脱敏对照方法和运行命令见 [评估工具说明](../remote-control-relay/eval/failure-redaction/README.md)。

与留存持久化功能合并后，删除完成门禁同时覆盖最小留存依据、原始事件、诊断材料清理及元数据一致持久化；访问审计仍沿既有 14 天保留规则，不随材料删除而全部抹除。留存写入失败沿本 PR 既有的多存储删除协议返回 `processing`，不报告 `completed`；同请求重试、状态查询或重启可继续清理。这与旧留存独立实现的首次抛出 503 不同，不把处理中当成功完成。库存缺失预检覆盖两类全部材料，带 `deletion_ledger_required: true` 的库存在线启动和离线回算都要求删除账本存在，不能用空账本替代。
