# 实时 D1 / D7 / D30 留存

留存按安装实例去重，以首次成功完成用户任务的北京时间日期为第 0 天；只包含用户发起的 assistant、code、team 任务。页面打开、仅提交、失败、系统任务和计划任务均不能激活或形成留存。首次具备采集资格的 `analytics_cohort_started` 继续用于激活漏斗，不再作为留存起点。

第 N 个自然日当天即进入 D<N> 分母；当天成功完成任务也可立即进入分子。看板标注“实时更新”和“今日观察”数量，观察日结束前数值仍可变化。已经在第 N 天达成的留存不要求今天继续活跃。观察日未到的安装不进入分母，成功发生在相邻日期也不能替代精确第 N 天。今日 / 7 日 / 30 日切换不改变此口径。样本少于 30 时隐藏百分比，继续显示分子、分母。

## 持久依据和删除

服务在数据目录的 `retention-facts.json` 保存版本、初始化时间，以及每个安装的首次成功日、从首次成功日到第 30 天之间的成功日期集合和历史完整性标志；`retention-facts.initialized` 标记它已成为持久依据，备份与恢复须保全这两个文件。每个安装最多保留 31 个日期，不保存对话、任务正文、模型、工具或原始事件内容。日期集合支持幂等重复和乱序上报；更早的成功到达时重算起点与各观察日。已初始化后依据文件缺失会拒绝启动，避免按截断的原始事件静默重建。

这些最小留存依据与原始事件的 35 天/容量清理独立，保留至对应安装的统计数据被删除。清理原始事件之前必须先成功保存留存依据；存储失败会阻止清理，查询返回不可用，不伪装成 0。已落盘的事件在留存依据写入失败时返回可重试，重试可幂等确认。初次启动也先从清理前的事件建立依据。文件损坏或未知版本拒绝启动，必须修复或恢复有效备份，不能删除文件后声称历史完整。

显式删除先持久化既有删除 tombstone，再清除留存依据和原始数据。启动和回算均排除已删除的安装；恢复旧留存文件不能复活已删除主体。未注册主体和非安装实例不进入回算。

## 历史迁移与核对

首次部署时，旧安装的原始事件可能已经截断。因此自动迁移和备份回算都将它们标为“历史可能不完整”，而不会把残存的第一条成功宣称为真正首次成功。新部署后新注册、且未出现注册前成功事件的安装从完整采集开始。历史不完整时，已知样本仍展示，但不声称可还原全部历史。

使用新代码目录中的脚本流式扫描现存文件及备份，默认只复算、不写文件，也不把备份事件恢复进在线原始事件日志：

```sh
node remote-control-relay/scripts/backfill-retention.mjs \
  --data-dir /path/to/telemetry \
  --source /path/to/backup/behavior-events.jsonl
```

已有删除 tombstone 时，运行环境必须具有与服务一致的 `PINVOU_TELEMETRY_DEVICE_PEPPER`，用于匹配已删除主体；不要将其作为命令行参数或打印。脚本只输出汇总数量，不输出安装身份。相同快照或事件重复输入不会重复计数。复算同时报告新口径结果和旧 cohort 起算公式结果；二者因起点不同可能变化，不能把任何预先找到的样本数作为验收目标。

先备份当前代码和数据，核对只读结果，再停止服务，在停止期间重新复算并应用：

```sh
node remote-control-relay/scripts/backfill-retention.mjs \
  --data-dir /path/to/telemetry \
  --source /path/to/backup/behavior-events.jsonl --apply --offline
```

`--offline` 是操作方对服务已停止、无其他写者的确认，脚本不代替进程管理。应用后重新启动，核对认证 API 与页面的分子、分母、实时及历史标识；重启和原始事件清理不得让已保存的留存消失。回滚须同时恢复匹配的代码与数据备份，并保全期间新增事件和删除 tombstone，不能用旧备份撤销用户删除。
