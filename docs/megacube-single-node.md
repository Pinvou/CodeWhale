# MegaCube 单机管理

本文提供使用与部署入口；完整职责、已定取舍、MCP 事实边界和验收层次见[最终决策与实现说明](megacube-single-node-decisions.md)。

本批在模型商店 PR #1995 的更新与版本管理基础上增加单机 Cube Manage Software（守护进程 `cmsd`）对接。商店更新不重复实现，标准安装始终由后台商店执行，cmsd 负责模型事实、管理权、资源准入和执行恢复。

## 用户闭环

聊天页不再展示本地模型服务的启动与恢复横幅，也不为该横幅周期性探测模型连接。无可用本地服务时，用户可从模型商店或设备管理检查、启动和恢复服务；云端模型缺少或无法读取 API Key 时，仍按当前聊天模型显示现有的模型接入提示。

设备页提供模型启停、设备默认选择、独立开机策略、资源和日志，以及无需 LLM 的 cmsd 安装、启动、修复和回退。后台任务在关闭 Pinvou 后继续，重开按原 ID 查询；失败记录可标为已阅并收进历史，详情和设备事实保留。原因或执行代际变化重新提醒，查询缺失不能当作恢复。

商店已完成任务在内存中保留七天，重启不会重置完成时间；更早的日志仍可按原任务 ID 从私有记录查询。失败安装恢复按卡片归并，待接续委托只统计尚未形成商店任务的记录，累计完成历史不会耗尽恢复额度。旧记录不自动重发，也不删除唯一的失败恢复证明。

会话 MCP 复用同一管理接口。换模由持久后台任务完成；模型暂时缺席时仍可接续，原会话的选择跟随真实终态和准确卡片身份，并保留用户手动选择、会话空闲及 CAS 边界。实验产物登记不授予生命周期权限。驭光只走模型商店中对应模型的 H3C 官方适配卡，其他有硬件与格式依据的引擎继续保留开放安装。

逻辑商店卡始终解析到当前成功部署，参见[当前部署选择](megacube-model-store-selection.md)。非当前的历史权重不成为普通启用、默认或自动恢复候选。用户在商店手动完整回退本地卡片后，cmsd 跟随商店重新发布的当前部署。查询失败、失联和管理关系不明时不绕过 cmsd 运行旧脚本。 商店当前选择的固定 `models_root` 仅用于缺失容器的首建脚本环境；缺少或无法核实该记录时保留资源并明确拒绝，按[当前部署选择中的恢复步骤](megacube-model-store-selection.md#首建脚本的固定下载根目录)恢复匹配记录/目录，不猜新默认目录或自动下载。已有容器和原生运行时继续核对其实际部署。

## 模块边界

- `features/megacube`：本机客户端、管理权、组件维护、只读硬件观测和 UI 状态。
- `features/model_store`：后台商店、安装委托、维护事务及当前部署清单。
- bundle `megacube-admin`：MCP 管理与安装工具、选型和排障技能；模型调用和工具循环复用 CodeWhale。
- `components/cmsd/`：Cube Manage Software 的唯一开发源码，保留独立 Rust crate 与组件版本；项目 npm 包装器在受支持的 Linux 构建中自动编译并打包。

Linux 桌面从启动起连接同一独立商店执行器，不依赖 cmsd 是否已安装。首次完成组件安装无需重启桌面即可委托商店任务；后台无法启动时明确报错，不另开进程内队列。

## cmsd 的分发、安装与运行

Cube Manage Software 源码在同仓 [`components/cmsd/`](../components/cmsd/)，从历史源码提交 `80a7ebc` 导入后以本目录作为唯一开发来源。Linux x86_64 / arm64 的项目 `build` 和 `bundle` 命令自动从当前 Pinvou 提交编译组件，校验源码身份、清单、大小、SHA-256、ELF 架构及 GLIBC ≤ 2.35，再将 `cmsd` 和 `manifest.json` 放入应用资源 `runtime/cmsd/`。组件版本独立于 Pinvou 版本，构建来源绑定 Pinvou 提交。

随包携带组件不等于已安装后台。设备页发现候选组件后，用户确认安装；Pinvou 将验证过的二进制复制到当前用户的私有版本目录，登记并启动 systemd 用户服务。Pinvou 通过本机 Unix socket 调用 cmsd。关闭桌面不停止该服务；开机未登录时能否启动还取决于用户服务的 linger 配置。模型商店执行器是另一个独立后台，由 Pinvou 提供，不包含在 cmsd 二进制中。

CI 打包与本地 Linux OTA 发版共用该源码构建入口；正式 deb 在上传前还检查包内组件是否齐全、摘要、架构和 ABI。缺失或不匹配即失败，不能发布一个声称带后台但没有组件的目标平台安装包。`PINVOU3_CMSD_PACKAGE` 不再允许覆盖正式构建来源；较新 Linux 构建宿主可用 `PINVOU3_CMSD_SYSROOT` 显式指定匹配架构的 Ubuntu 22.04 sysroot。开发 `dev`、纯 UI 和配置测试不编译组件，LoongArch / Windows / macOS 仍不提供本机 CMS 管理。用户仍可在设备页验证并导入可信的本地组件包。

随包分发不需要先发布独立 CMS Release，也不需要跨私有仓库下载权限。源码归仓和构建检查不代替实际安装包验收；验证时须分别记录真实包内容、GUI 随包发现、用户确认安装和用户服务运行，不能用显式传入包路径的夹具冒充 GUI 自动发现。

本批不包含远程 TLS 配对、Plan/Grant/Operation、独立历史维护页面、组事务、平台接入或出厂初始化器。单机硬件观测不读取初始化收据，也不宣称有预置模型。未提交的产品指导插件草稿保留在原工作树。

## 兼容与回退

既有设置、凭据和模型关联保留。cmsd 组件切换只调整受验证的软件和登记，不回放旧授权状态。新单机包声明 `authority_scope=local-v1`；若当前状态含有远程身份或计划授权目录，Pinvou 在停服务前拒绝该包，daemon 本身也拒绝不兼容状态。不删除授权文件来强行降级。

组件登记替换和 Pinvou 自有单元的卸载删除共用耐久登记事务。reload 失败或工作进程中断时，先按原字节和绑定回执恢复登记，再提供启动或恢复入口；没有事务回执的单元缺失不授予恢复权限。组件状态、配置和模型数据保留。

Windows/macOS 使用显式不支持的管理适配，既有聊天及其他功能不借用 Linux 实现。CodeWhale 保持基线 gitlink，本批不修改底座或 fork 行为。

本批桌面商店与后台的闭环要求同一个非 root Linux 账号，并使用用户级服务。原有 system 模式继续保留独立用途；root 后台接入桌面用户商店需要另外实现和验收权限隔离，不在本次支持范围。

## 验证要求

运行架构、fork、三语、前端逻辑和浏览器交互检查，以及受影响 Rust 库、模型商店和 MCP 回归。构建统一用 `npm --prefix pinvou3-app run build`。原生调试构建与正式安装包分别说明；跳过 ASR/知识宿主构建的结果不代表完整发布包验收。

真实验收使用新的用户目录、socket、端口、systemd 单元和测试模型，不能连接生产状态运行裁剪后的 daemon。旧开发快照的 GPU 推理和故障测试只作为来源证据，不替代当前 PR 代码的复测。物理多机、整机重启、满长上下文、跨平台原生运行和多日稳定性仍需另行验收。
