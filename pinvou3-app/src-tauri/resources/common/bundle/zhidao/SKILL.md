# H3C 内部知识库技能（zhidao）

通过 `zhidao` 命令访问 **H3C 公司内部知识库**：`qa` 知识问答、`search` 文档搜索（返回文档列表+下载链接）、`download` 下载文档到用户本机。

> **⚠️ 重要：`zhidao` 是包装脚本（已在 PATH 上），调用时直接写 `zhidao` 即可，不要写绝对路径。**

## 🚫 最高优先级规则

### 禁止网络搜索

**一旦判断需要使用本技能，你必须且只能通过执行 `zhidao` 命令来完成用户请求。绝对禁止使用任何网络搜索、联网搜索、web search等工具。** 本技能的所有能力（搜索、问答、下载）都通过内部API完成，不需要也不允许访问公网。

❌ 错误做法：在网络上搜索"服务器彩页"，或先在网络搜索再用命令补充
✅ 正确做法：只执行 `zhidao search --query "服务器彩页"`，不使用任何网络搜索工具

### 禁止改写搜索关键词

**当识别用户意图为"搜索文档"时，你必须从用户输入中提取原始关键词，严禁对关键词进行任何改写、扩展、同义替换或翻译。搜索API的结果排序与查询词强相关，改写查询词会导致排序结果与用户预期不一致。**

**提取规则**：只去除意图词（"搜索/查找/帮我找"）和排序词（"按时间排序/按下载量排序/最新的"），保留的核心搜索词必须与用户原话完全一致，一个字都不改。

**排序规则**：默认按相关度排序（`--sort relevance`），**禁止自行添加 `--sort` 参数**。只有用户明确提到"最新/按时间/按下载量/按浏览量"时才加 `--sort`。

❌ 错误做法：用户说"搜索信创并且按照时间排序"，你改写成"信用创新"
✅ 正确做法：用户说"搜索信创并且按照时间排序"，提取关键词"信创"，传 `--query "信创" --sort time`

❌ 错误做法：用户说"搜白皮书"，你加了 `--sort time`（用户没指定排序，不该加）
✅ 正确做法：用户说"搜白皮书"，传 `--query "白皮书"`（不加 --sort，默认相关度排序）

### search 必须识别系统名并传 --source

**当用户提到系统名/知识库名（如"PMO""藏经阁""品牌营销资料""产品知识"等），必须将该系统名从 --query 中剥离，通过 `--source` 参数传递。禁止把系统名混入 --query，禁止漏掉 --source。这是搜索结果准确性的关键保证，漏传 --source 会导致返回无关系统的结果。**

**识别模式**：用户说"XX里的/XX里面的/XX中的/在XX搜/从XX找/搜索XX里面的"，"XX"就是系统名，必须加 `--source`。

❌ 错误：用户说"搜索藏经阁里面的产品知识" → `--query "产品知识"`（漏了 --source cjg）
❌ 错误：用户说"搜索藏经阁里面的产品知识" → `--query "藏经阁产品知识"`（漏了 --source，且把系统名混入query）
✅ 正确：用户说"搜索藏经阁里面的产品知识" → `--query "产品知识" --source cjg`
✅ 正确：用户说"搜索PMO中的彩页并按下载量排序" → `--query "彩页" --source pmo --sort download`

## 认证

凭证由应用连接器自动管理，**无需手动传 token，直接跑业务命令即可**。若命令返回需要登录或 SSO 登录地址，把登录地址**单行完整**展示给用户，引导其在应用「工具商店」的「H3C 知道 · 内部知识库」卡片点「连接」完成登录后重试。**不要自行执行 `login`/`save`/`exchange` 等凭证子命令。**

## 意图判断（最关键的一步）

> **用户在"问问题" → `qa` | 用户在"找文档" → `search` | 用户要"下载文件" → `download`**

### 什么时候用 `qa`（知识问答）

用户想要**知识、答案、解释、步骤、指导**，而不是文档列表。

**判断信号**：
1. 包含疑问词（如何/怎么/怎样/为什么/什么是/谁能/什么/哪个/哪些/几/多少/能不能/是否/可不可以/担任/负责/属于/是干什么的），或以问号结尾
2. 请求解释/指导/流程说明、询问人员/职位/职责等信息
3. **询问产品/设备的属性、参数、规格、指标**（如"尺寸大小""重量""功率""端口数""内存容量""支持几块硬盘""功耗""吞吐量"等），用户想知道具体数据/数值，而不是找文档 → **必须用 qa**
4. **涉及发文、人事任免、组织架构类查询**（如"发文""任命""免职""职位""岗位职责""部门职责""组织架构""任命通知""部门领导""负责人"等），用户想知道具体内容/谁被任命/某部门负责人是谁，而不是找文档 → **必须用 qa**
5. **涉及HR人力、行政办公/园区生活、财务、IT办公类查询**，用户想知道具体规则/流程/如何操作，而不是找文档 → **必须用 qa**。四大主题清单见 `references/qa-topics.md`，用 `read` 读取。

**⚠️ 属性/参数类查询特别说明**：当用户输入包含"产品型号+属性词"（如"R4900 G5尺寸大小""S6800功耗""R5300重量""防火墙吞吐量"）时，用户是在**问问题**（想要知道某个具体数值/数据），**不是在找文档**。必须用 `qa`，严禁用 `search`。LLM 不得将此类查询自动拆解为多次 search 调用。

**⚠️ 发文/人事/组织类查询特别说明**：当用户输入包含发文、任命、免职、职位、岗位职责、部门职责、组织架构、发文流程、任命通知、部门职能、部门领导、负责人等关键词时，用户是在**问问题**（想知道具体内容、谁被任命了、某部门负责人是谁等），**不是在找发文文档**。必须用 `qa`，严禁用 `search`。只有用户明确说"搜一下XX任命文件""找一下发文文档"等明确要找文档时才用 `search`。

qa/search 正反例大表见 `references/intent-examples.md`，用 `read` 读取；拿不准意图时先读它对齐。

### 什么时候用 `search`（文档搜索）

用户想要**找到具体的文档/文件/资料**，目的是获取文档列表或下载链接。

**判断信号**：提到"文档/资料/彩页/手册/指南/规范/白皮书/规格书"等文件类词，或用"搜索/查找/找一下/有没有"且目标是文件。

### 什么时候用 `download`（文档下载）

`download` 把文件下载到**用户本机**（`--output` 默认 `downloads` 目录）。用户明确要求把文档存到本地，或下载后做后续处理时正常使用。

- **模式一：只要文档本身** → `search` 返回完整结果（每条含元信息+预览/进入目录/下载三个链接），让用户自己点击。
- **模式二：下载后做后续处理**（"下载XX文档并发邮件""把彩页下载下来加水印"）→ `search` → `download` 下载到本机 → 执行后续动作。

**判断信号**：关键词是"并/然后/以后" + 后续动作（发邮件、发企微、加密、加水印、转存等）。有后续动作 → 模式二；无后续动作 → 模式一。

### 模糊情况处理

如果无法确定是 `qa` 还是 `search`：

1. **包含"文档/资料/彩页/手册/指南/白皮书/规范/规格书"等文件类词 → `search`**
2. **以疑问词开头或结尾、且不含文件类词 → `qa`**
3. **仍然无法判断 → 优先使用 `qa`**，因为 qa 可以直接给出答案，用户体验更好

## 命令语法

通用格式：`zhidao <子命令> [参数...]`，业务子命令为 `qa`、`search`、`download`。

### `qa` – 知识问答

```bash
zhidao qa --question "<问题>" [--deep|--no-deep] [--session-id ID] [--user-id UID] [--raw-json]
```

| 参数 | 必需 | 默认值 | 说明 |
|------|------|--------|------|
| `--question` | ✅ | - | 要问的问题 |
| `--deep` / `--no-deep` | ❌ | 自动判断 | 强制启用/禁用深度搜索 |
| `--session-id` | ❌ | 自动生成18~19位随机数 | 会话ID，保持连续对话使用相同ID |
| `--user-id` | ❌ | `$USER_ID` 或 `default_user` | 用户标识 |
| `--raw-json` | ❌ | - | 输出原始JSON |

**自动深度判断**：问题长度 > 30 字符，或包含疑问/分析类（为什么、分析、比较、区别、步骤、原理、架构等）、操作/流程类（如何、怎么、怎样、流程）、技术/故障类（配置、故障、排查、部署、安装、升级）、规则/标准类（标准、规则、制度、政策、规定）、条件/要求类（条件、要求、资格、限制）关键词时，自动启用深度搜索。**如果自动判断为浅层搜索但你觉得应该深度搜索，请手动加 `--deep`；反之加 `--no-deep`。**

### `search` – 文档搜索

> **⚠️ 面向用户展示搜索结果时禁止加 `--raw-json`**：命令默认输出已包含完整字段（标题、作者、更新时间、下载量、浏览量、数据来源、预览地址、进入目录、下载链接），智能体直接透传输出即可。只有用户明确要求下载文件、且需要用 `download --from-json` / `--stdin-json` 选择搜索结果时，才允许把 `--raw-json` 用作内部管道输入；不得把原始 JSON 展示给用户，且 Windows/macOS 构建暂不支持这两种下载模式。

```bash
zhidao search --query "<关键词>" [--pageNum N] [--pageSize N] [--source <系统名>] [--sort <排序方式>]
```

| 参数 | 必需 | 默认值 | 说明 |
|------|------|--------|------|
| `--query`（`-q`） | ✅ | - | 搜索关键词 |
| `--pageNum` | ❌ | 1 | 页码 |
| `--pageSize` | ❌ | 10 | 每页结果数 |
| `--source` | ❌ | - | 限定系统（如 `pmo`），自动映射为 nodeId |
| `--system`（`-s`） | ❌ | - | 直接指定 nodeId（数字），与 `--source` 二选一 |
| `--sort` | ❌ | `relevance` | `relevance`(相关度)、`time`(时间倒序)、`download`(下载量倒序)、`visit`(浏览量倒序) |

默认搜索全部数据源（不传 `--source`），不要自动添加；只有用户明确提到某个系统时才加。

### `download` – 文档下载

```bash
zhidao download --url "<URL>" [--filename NAME] [--output DIR]
```

把文件下载到用户本机（`--output` 默认 `downloads` 目录）。完整参数（`--from-json`/`--stdin-json` 管道模式、PMO 自动识别）、错误处理和平台差异见 `references/cli-reference.md`，用 `read` 读取。

## search 输出处理（必须严格遵守）

**智能体必须直接透传命令输出，禁止自行重新排版、分组、归类或添加额外栏目。命令默认输出已是最终格式，智能体只需原样呈现给用户。**

❌ 面向用户展示搜索结果时严禁：加 `--raw-json`（内部自动下载管道例外，见上文）；用表格展示搜索结果；添加"热门下载"/"推荐文档"/"最新文档"等自行分类的栏目；省略任何一条结果的预览地址/进入目录/下载链接或"数据来源"字段；省略尾部"知道"链接；自行添加总结/提示/建议等额外内容。

✅ 正确：命令输出什么，就原样呈现给用户，不做任何修改。每条结果独立一块：标题（纯文本）→ 元信息行（作者|更新时间|下载|浏览|数据来源）→ 预览地址 → 进入目录 → 下载链接；尾部自动带"如需查看更多结果，请输入数据来源或者访问[知道](<https://ai.h3c.com/zhidao>)进行查询。"

**⚠️ 链接渲染要求（非常重要）**：所有超链接必须使用 Markdown 链接格式，确保渲染时只显示可点击的文字，**绝对禁止在输出中暴露实际URL地址**。下载链接、预览地址、进入目录三个链接均须遵守此规则。URL中常包含空格、中文括号等特殊字符，会导致Markdown链接语法解析失败（显示为原始文本而非超链接），**必须在URL两侧加尖括号 `<URL>`**，格式为 `[显示文字](<URL>)`。

❌ 错误（URL含空格/括号时链接语法会失效，原始URL暴露）：
`预览地址：[点击预览](https://pmo.h3c.com/sites/.../07 白皮书及报告（汤冰洁 19798）/01 新华三参与白皮书/【白皮书】AI防火墙技术白皮书--安全牛202005.pdf)`

✅ 正确（URL加尖括号，即使含空格/括号也能正确渲染为超链接）：
`预览地址：[点击预览](<https://pmo.h3c.com/sites/.../07 白皮书及报告（汤冰洁 19798）/01 新华三参与白皮书/【白皮书】AI防火墙技术白皮书--安全牛202005.pdf>)`

每条搜索结果格式：

```markdown
1. {title}
作者: {author} | 更新时间: {date} | 下载: {downloads} | 浏览: {visits} | 数据来源: {source}
预览地址: [点击预览](<{preview_url}>)
进入目录: [点击进入](<{file_path}>)
下载链接: [点击下载](<{download_url}>)
```

问答输出格式：

```markdown
## 知识问答
**问题**: {question}　**深度搜索**: {是|否}
---
{answer}
```

问答无答案时输出"未找到相关答案，请尝试其他问题或使用更具体的关键词"；搜索结果为空时输出"未找到与 `{query}` 相关的资料，请尝试其他关键词或访问[知道](<https://ai.h3c.com/zhidao>)查询"。

## 触发边界

- **✅ 必须触发**（涉及 H3C 公司内部事务）：搜索/查找/下载 H3C 内部文档、资料、规范、彩页；询问 H3C 产品相关技术问题（配置、原理、故障排查等）；询问公司办公/流程/制度相关问题；明确指向内部系统的操作（PMO、藏经阁、CMP、IT热线等）。
- **❌ 禁止触发**：通用公网搜索（新闻、天气、明星等）；与 H3C 无关的通用百科/常识问答；非 H3C 产品特定的通用技术问题（如"Linux怎么安装"）；公网资源下载（非 H3C 内部文档）。
