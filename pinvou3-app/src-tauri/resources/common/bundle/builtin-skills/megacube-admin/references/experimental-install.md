# 实验安装

当前模板的架构、量化、布局或体积条件只约束标准模板。用户坚持目标模型时，查引擎对格式、aarch64、GPU 和依赖版本的支持，给出一条可执行路径及证据；不要把“尚未验证”写成“肯定能用”。

驭光（Tachyon / tachyon-serve）不属于可自行安装的实验引擎：需要 H3C 官方逐模型适配，只能通过 Pinvou 模型商店的官方适配卡安装、更新或修复。目标模型在商店没有对应官方适配或适配无法确认时，选择有支持证据的其他引擎；不得自行下载/编译驭光、复用其他卡的驭光或编造本地卡来尝试加载该模型。开放安装仍适用于其他合适引擎和模型来源。

转实验路径前，说明具体变化，例如额外引擎/依赖、未知峰值内存、可能影响正在运行的服务、暂时不能纳管。用户明确同意后在该范围内完成下载、准备环境、调整配置和合理重试；不要每改一个参数就再问。

优先使用独立目录、虚拟环境或容器；如果隔离办法不可行，说明新增影响后再换路径。这些是默认实践，不是新的模型白名单。需要提权时走现有受支持的授权机制，不索取用户密码，不配置免密 sudo，也不绕过底座策略。Docker 用户组权限不能被描述成无 root 风险。

启动前重新检查实际内存与在跑服务。未知引擎不能使用“权重+3.5 GiB”或其他引擎的 mem-fraction 值保证安全；显式记录预算依据和不确定性。统一内存平台不能靠容器内存限制保证 GPU 分配受限，首次启动仍有整机内存风险。用户确认只授权尝试，不使不足的硬件变充足。

不能无授权停止已有服务或接管其进程。优先使用空闲端口、保留现有默认模型，准备好真实的停止/恢复方式再启动。助手本身依赖的模型需要让位时，先准备并验证持久执行方式和恢复记录；没有可跨中断执行的工具就如实说明这一具体限制。

标准换胎仍通过 cube_plan_switch → cube_switch_model 发起，由 cmsd 持久状态机在模型能力缺席期间推进并恢复；不要改成让当前 LLM 手工停掉自己后再继续。如果要换成暂不受管理的实验服务，需要先确认已有程序能持久执行整个步骤；不能借普通 shell 前台调用承诺跨中断恢复。

使用底座已有命令/文件/终端能力，不另写通用 Shell 执行服务。长任务记录会话或任务标识。修复按日志提出新假设，一次尽量只改相关参数；当新增操作超出原授权、条件确实不满足或没有新假设时暂停该步骤，交付已完成成果及具体阻碍。

不会自动回滚的操作不要宣称自动回滚。清理只针对本次创建且确认可删的内容；用户已有权重、依赖、配置和服务需保留或取得明确授权。
