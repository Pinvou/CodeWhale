# 审计导出运行接线

本功能使用既有 Account、Portal 和已授权管理身份，不增加服务或公共未认证入口。
未启用审计导出的既有部署可省略 `AUDIT_EXPORT_MASTER_KEY_BASE64`；Account 不构造导出 worker，也不注册导出路由（沿既有不可用 404 合同），其它账户功能与审计只读路由保留。启用审计导出时，Account 私有环境文件必须提供该值，且为恰好32字节密钥的严格标准Base64；显式提供但非法仍在启动时拒绝，不生成替代密钥。文件与部署密钥仅在受控站点供应，不写入仓库、命令日志或示例。原始密钥解码缓冲在构造后清除；保留同一密钥直到既有任务的文件和解密授权完成或到期，不能用换密钥宣称旧任务已恢复。

Account 启动接入真实工作进程。管理权限为 `platform.audit.read`、`platform.audit.export`；未脱敏导出的创建（含同键重放）、签发下载票据及实际下载，均重新核验真实、未过期的 `platform.audit.pii.export` 临时角色授权，不由默认超级管理员继承。状态 GET 与同用户重新登录恢复仍只要求原导出权限；PII 授权失效不阻止查看任务，但不能再签票或下载。绑定的期限和分配流程必须来自已交付的角色管理组件，不能通过直接数据库造授权。仅有导出权限的管理员可以导出，但不能读取只授予审计读取权限的日志列表；仅有 PII 权限不能导出。

032 是本波新增的迁移；其已提交 Up/Down SQL 身份保持不变，由 Account 包装器在实际升级及回滚入口固定校验。实际回滚事务先保护所有 PII 角色绑定（包括过期绑定），并拒绝执行 032 不完整的逆变换。010 曾默认授予超级管理员 PII 导出权限，但后续 034 明确撤销；无法证明旧数据库应恢复该权限，不能用无条件补授权修复回滚。此限制已取得用户决定，正常升级不受影响；禁止直接调用通用回滚或手工执行 SQL 绕过保护。既有 forward-only 与旧 append-only 回滚限制仍保留。

Portal只开放精确审计读取、创建、查询和下载端点。一次性下载仅允许GET；HEAD拒绝且不消耗票据或删除载荷。`X-Pinvou-Download-Token`只转发至该导出的GET下载端点，其他路由剥离。理由至少10个Unicode字符且不超过500个Unicode字符。导出的加密信封上限500MiB，普通API响应上限仍为32MiB。既有TLS、SSO、CSRF、网关隔离和会话身份由前序已交付配置负责，不使用F18延后补接线。

创建结果不明时，页面保留同一过滤条件、原因、PII选择和幂等键；已签发但回包遗失的单次票据不能再次签发，页面显示刷新核验与创建另一导出的明确恢复路径。解密密钥仅在当前页面展示供操作者安全保存，不写日志、URL或浏览器持久存储。授权拒绝不会自动重发创建或签票请求；已在内存中的原票据保留，权限恢复后须显式重试。真正的签票 UNKNOWN 仍先查原任务，不因后续拒绝而换键或自动重签。

使用既有统一 Compose 投放入口，在个人及已启用阶段的 overlays 之后追加 `compose.audit-export.yaml`。沿用个人配置的 Account 私有 `env_file` 提供上述密钥，并使用同源 F17 Account、迁移及带本次 canonical 静态资源的 Portal 镜像。启用本导出叠加部署须事先供应密钥；显式非法密钥拒绝启动，未供应则导出功能不启用，不影响既有账户服务；不要在公开环境变量、命令参数或日志中传入密钥。

当前为已审 F16 全父上的 F17 修复候选，尚未部署。格式为 `PINVOU_AUDIT_ENVELOPE_V1` 加密信封（`.pae`），内部 CSV 使用 AES-256-GCM 与 HMAC-SHA-256；不是 XLSX，也不是明文 CSV。操作者安全保存页面展示的密钥，按信封协议解密并校验完整性后读取 CSV；密钥遗失不能通过重发票据恢复。现有自动化验证覆盖协议解密往返，未运行外部电子表格或另造解密产品。

编译、受控 HTTP/浏览器、规范资源及有限 PostgreSQL 的实际结果，以本波固定提交的 PR 验证记录为准。CI 在独立临时 PostgreSQL 中显式执行审计导出租约和回滚保护用例；普通 Go 测试的条件跳过仍单独披露，不能算通过。完整 E2E、真实 IdP、集群和 TLS 投放未执行；本说明不构成部署或发布通过。

本地四个有限 PostgreSQL 用例可使用显式 `F17_TEST_DATABASE_PROFILE=local-owned`，与原默认和 GitHub Actions profile 分开。实例必须由测试操作者独立创建，专用协调身份为 `pinvou_audit_fixture`；`F17_TEST_OWNED_PORT` 必须与连接和服务器一致，`F17_TEST_OWNED_DATA_DIRECTORY` 必须是系统临时目录下 `pinvou-f17-audit-<规范非零UUID>/data` 且与服务器实际目录一致。仅允许本机无 TLS fallback 的 `postgres` 数据库；所有外部数据库、角色或会话都会阻止夹具写入，不复用部署实例、不终止外部会话。测试结束只在准确 owner、零会话及无外部依赖验证后清理自己创建的数据库和角色。该装配修复对应 #1731，不意味着部署或真实 IdP/NATS 验收通过。


公共 `accountschema.Up` 在验证原 032 Up/Down 字节、已应用校验和、原 owner/function/行触发器后，幂等补充 `audit_export_events` 的 statement `BEFORE TRUNCATE` 保护；新库和已应用 032 的再次 Up 均经过此 Go hardening。原 017 的 `audit_logs_security_no_truncate` 保持不变。032 不完整 Down 仍拒绝，原 SQL 身份、账务和历史事件不改。此为既有 append-only 合同的前向补齐，不表示防御持有 owner DDL 能力的恶意管理员。

OpenAPI 使用 Account `/admin/v1` 路径；Portal 服务基址 `/api/admin/account` 与该路径拼成客户端的实际 BFF URI。票据中的 `download_url` 保留为已弃用的 Account 相对提示，客户端不跟随它，也不向任意 URL 发送一次性 token。`requirePermission` 的存储不可用分支使用既有 503、明确拒绝使用 403，影响存量 admin 路由，本轮不再改变此分类。

500 MiB 限额同时检查 CSV 构造与最终 JSON/base64 信封，最终封装上限使有效 CSV 容量约 375 MiB（另含加密和 JSON 开销），不是 500 MiB 明文承诺。当前构造有多次全量缓冲，未实测生产峰值或声明整个进程固定内存上限。领取与清扫仍用应用时钟；票据签发、下载的锁后有效期校验使用数据库时钟。无新的时钟/配额/内存策略；现有部署 issuer/NATS、实际大导出和完整 E2E 验收仍按既有边界披露。
