# 企业短信接入

这个发送适配器连接已有 Account `http-generated` 通道和阿里云短信服务
`SendSms`。Account 仍生成、验证六位验证码。网关通过 HTTPS 请求参数向阿里云
提供收件手机号、验证码、已批准的企业签名和按用途挑选的模板。账户挑战 ID
仅用于内部去重。模板的数字变量名为 `code`。四个用途必须显式
配置。可以使用四条模板，也可重复填写同一条审核通过的通用模板。写有
“正在注册”的模板只用于注册。

## 部署和切换

1. 在阿里云确认签名报备和正式模板已经通过，用六位测试值核对实际到达。
   使用独立 RAM 身份并仅授予 `dysms:SendSms`。将凭据和独立的至少 32
   字节随机 Bearer token 按现有生产 Secret 流程分别投影为文件。不要在日志、
   命令参数或代码中记录这些值。
2. 使用标准 `account-platform/Dockerfile` 构建，服务名
   `enterprise-sms-gateway`。以 `compose.enterprise-sms.yaml` 为私有部署
   配置入口，提供网络和受信 TLS 证书，证书 SAN 须包含
   `enterprise-sms-gateway`。Account 和健康检查均必须保留验证 TLS。
   文件目录只对容器 UID 65532 开放读取，敏感文件为 0400 或 0600。
   持久目录使用支持硬链接、原子重命名和 fsync 的本地磁盘，属主
   65532:65532，模式 0700。生产运行单实例，重启保留同一挂载。
   HTTPS 接口仅在既有私网开放，不映射公网端口。确保网关能经站点批准的
   出口访问 `dysmsapi.aliyuncs.com:443`，并在 `ca-bundle.pem` 保留健康检查
   所需私有 CA 和阿里云 HTTPS 所需公共信任根。
3. 保留 Account 部署默认 `SMS_PROVIDER=aliyun-managed` 及其凭据，另外配置
   `SMS_HTTP_ENDPOINT=https://enterprise-sms-gateway:8443/v1/sms/send`、
   与适配器一致的 `SMS_HTTP_BEARER_TOKEN` 及 Account 原有验证 HMAC 密钥。
   如需补充其 CA 信任，提供包含原有信任根的完整 bundle。
   正式发布前，在[生产配置预检](../runbooks/production-render-preflight.md)的
   `overlays` 中加上 `enterprise-sms`，并在独立制品清单加入网关镜像摘要。
   受控启动网关和重启 Account，核对网关健康检查和后台通用 HTTP profile。
   就绪只表示配置有效。先在验收环境验证注册、验证码登录、换绑、重置
   密码的真实发信、送达和核验，再通过「平台设置 → 短信发送服务」保存一条
   新生效版本，选择「通用 HTTP 短信」。已有验证码仍以创建时的供应商核验。
4. 验证生产新挑战和回执。需要回滚时，使用后台当前修订号发布恢复旧通道的
   新版本，保留新通道凭据直至已发挑战过期。未确认保存结果按原幂等键查询
   或重试，勿另起保存请求。不要改历史版本或在有效期内轮换验证码 HMAC
   和网关 Bearer token。

## 发送结果

适配器在发信前持久化该挑战的发送占用。同一挑战的重试只能返回已知回执，
或返回结果未确认，即使适配器重启也不会再次调用阿里云。超时或未知结果
不宣称送达。持久记录只含请求指纹和回执，不记录手机号或验证码明文。
网关拒绝过期挑战，并在收到新发送请求时清理超过 24 小时的本地发送记录，
最多每小时清理一次。Account 和网关应
保持时钟同步。丢失发送回执时，注册、登录和重置密码沿用 Account 的发送失败
处理，用户可能需要等待后重新获取验证码。换绑流程可按现有机制用原挑战重试。
