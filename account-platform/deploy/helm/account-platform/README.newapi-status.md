# NewAPI TLS and the existing system status probe

This chart requires the operator to build the approved newapi-tls command, supply images.newApiTLS.repository and an immutable digest, and create newApi.tlsSecretName before rollout. The Secret contains tls.crt and tls.key; its leaf certificate SAN must cover newApi.serviceName used by both HTTPS callers. The public issuer chain is supplied separately in newApi.caConfigMap under ca.crt. No default certificate, private key, valid image digest, or credential is generated by this chart.

NewAPI backend 8080 stays inside the Pod behind two containers using the same TLS image and certificate: data on 8443 and status-only on 8444, both fixed to loopback 8080. The Service exposes only 8443/8444. Gateway and the credential portal use 8443; the ordinary Portal uses only 8444 GET /api/status, which tests the actual NewAPI success JSON. Neither an empty response nor the listener health is a provider-health result. The Portal receives only public CA material; it does not receive NewAPI private keys or provider access.

The public CA is mounted as a read-only regular single file via subPath, preserving the existing safe CA reader. The factories load it at startup; CA rotation requires a controlled rollout to rebind that file. The OIDC HTTPS endpoints and their trust remain independent of SystemProbe CA configuration.

Existing Account/Gateway/Portal internal HTTP service calls are retained. HA deployments must configure the existing external endpoints and their bounded IP CIDRs for Redis 6379, NATS 4222, workload JWKS 443, Portal OIDC 443, and HTTPS NATS monitoring 443. The built-in NATS monitor retains port 8222. These lists do not authorize arbitrary internet or expand restricted executor permissions. Existing migration prerequisite Ready runtime Secrets, bootstrap keys and pinned images remain operator responsibilities.

Validation of this component is local Helm rendering and policy/source contract checks, not cluster deployment, certificate issuance, DNS, live OIDC, Redis, NATS, or end-to-end acceptance. The final F18 full-parent selection remains pending.

`global.podLabels` may add ordinary custom labels, but must not contain the chart-owned selector/classification keys: `app.kubernetes.io/name`, `app.kubernetes.io/instance`, `app.kubernetes.io/component`, `pinvou.io/newapi-data-plane`, `pinvou.io/restricted-token-control`. The schema rejects these keys even when the value matches, so custom labels cannot create duplicate security selectors.

The fixed loopback target belongs to the TLS frontends. Backend `PORT=8080` does not establish its listener bind address; the Service exposes only 8443/8444 and the reviewed NetworkPolicy union rejects external Pod access to 8080.
