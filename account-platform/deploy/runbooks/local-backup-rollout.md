# 本机备份部署模式（本次上线的明确例外）

## 需求与风险边界

2026-09-08，部署负责人明确选择“先本机备份，快速部署上线”，负责人为其本人。
本次不采购异机存储，不再将异机不可变副本作为上线前置；这覆盖此前安全设施文档中
“等待数据库异机存储位置”的阻塞，不改变默认 [`recovery-policy.json`](../recovery-policy.json)。
其他环境不得默认继承本次风险接受。

本模式只能防范部分误操作、应用损坏和可回溯的数据错误。源库与备份同机，整机丢失、
磁盘损坏、宿主 root 被攻破可能同时破坏二者；不能保证这些场景的 RPO/RTO，不能标记为
异机、不可变、容灾完成或通用 `RESTORABLE`。业务数据库身份无备份目录访问权限；
数据库 OS 用户、备份操作者和宿主 root 仍在本机信任边界内，不能声称它们无法删除备份。

不豁免持续 WAL、每日增量、每周全量、迁移前备份、加密、实际恢复验证、业务数据保留
和现有业务安全门禁。同机可恢复故障的目标仍为资金 RPO 60 秒、配置 RPO 300 秒、
核心 RTO 60 分钟、非关键 RTO 4 小时。Redis 灾难恢复仍重建空缓存并使旧会话失效。
KMS 已有加密快照及保管人离线交接继续有效，不重新初始化、重签或要求重复交接。

## 设计

采用成熟 pgBackRest，固定工具版本/镜像摘要；基于已验证 PostgreSQL 17.11 镜像增加工具，
不升级数据库、不重建现有正式集群。独立本机加密仓库位于 PGDATA 和发布目录之外，
整个物理集群一次备份，覆盖 Account、Billing、Token、Keycloak 和 New API 五库及角色。
pgBackRest 原生 AES-256 仓库加密；随机密码只存单独受控秘密文件，另以已交接恢复公钥
加密保存恢复副本。明文密码不进入 argv、Compose 环境、源码、清单或日志，业务容器
不挂载仓库和备份秘密。这里的密钥分离是目录/访问身份分离，不是异机或独立安全域。

使用同步 WAL 归档及短于 60 秒的切段周期，为归档耗时留出余量；持续监测真实归档成功
和积压，不能用配置值证明达标。每日增量、每周全量和迁移前即时备份由受限定时任务
执行，禁止并发冲突，失败返回非零。保留每日 35 天、月度 13 个月目标不变；上线初期
不自动删除正式历史，明确配置 `expire-auto=n`，保持 `archive-check=y`，不配置会丢弃
WAL 的 `archive-push-queue-max`；后续保留清理须以完整备份依赖和明确策略执行，不因磁盘紧张静默
降低保留期限。现有空库体积不能推算生产容量可满足长期保留。沿用磁盘预警
20%/5 GiB、严重 10%/2 GiB、inode 10%；只输出本机状态/journal，未接外部通知不冒称送达。

NATS 使用官方快照或停止全部本项目写入方及 NATS 进程后的离线一致归档，不直接复制运行数据。
配置、镜像摘要、迁移清单和 New API 非数据库持久文件绑定恢复集；敏感配置必须加密。
不备份 Redis 长期会话。恢复在独立网络/目录执行，不访问真实商城、短信或模型 Provider，
不覆盖正式库、不恢复生产公网入口。恢复 PostgreSQL 不等于完整业务恢复。

## 分阶段验收与任务

| 任务 | 内容与完成条件 | 独立提交 |
|---|---|---|
| D3-L1 | 本文需求/设计/任务及显式本机证据入口；默认异机门禁不变，风险接受、环境/部署绑定、真实时间/测量值、五库覆盖及负例测试 | 文档与门禁 |
| D3-L2 | 固定 pgBackRest 制品与隔离真实加密备份/PITR 测试；正式集群原地接入、自动调度、容量状态；实际恢复后核对五库/角色/恢复点 | 工具配置及现场证据 |
| C3-C4 | 本机基础恢复通过后继续正式 Keycloak、七个服务身份、业务迁移和 New API；每次迁移前用新的真实备份证据，补齐迁移后领域审计和完整恢复集 | 沿用既定串行任务 |
| 05C | 完整本机恢复证据与业务端到端通过后切换公网、验收并清理确切旧测试资源；统一推送/部署 | 沿用既定发布任务 |

每项仍由原变更者实施、独立审核者审核，修复后再审，通过后签名提交；不新增开发并行。

机器入口必须显式选择 `--local-only --deployment-id <expected-id>`，证据自报本机模式
不能放宽默认门禁；部署 ID 必须与受控调用提供的预期目标一致。证据记录
部署标识、负责人及风险接受时间，并明确 `offsite=false`、`immutable=false`、
`host_loss_recoverable=false`；本地传输允许 `LOCAL_ONLY`，实际联网连接仍须 TLS 1.2+。
加密、访问分离、备份新鲜度、持续归档及容量检测均需实际证据。测量必须为非负有限数值，
完成时间不得在生成时间之后，不能用未来时间、负数、重复数据库项、缺失项或布尔值充当成功。

两种状态不能混用：

- `LOCAL_BOOTSTRAP_VERIFIED`：五库物理备份与恢复、角色及恢复点核对、WAL 可用、基础设施
  本机 RPO/恢复耗时已实测，仅允许继续私网身份初始化/迁移，不表示业务恢复或公网切换通过。
  空库不能生成领域审计通过或虚构季度/年度业务演练。
- `LOCAL_ONLY_RECOVERABLE`：另需迁移后审计 SQL、完整恢复集各持久域、关闭 Provider 副作用、
  实测核心/非关键 RTO 与保留扫描证据；只授权同机风险边界内的上线。不要求伪造整机丢失
  演练，不省略正常月度抽样/季度端到端恢复演练。新上线首次真实完整演练可作为初始证据，
  后续仍按原有 35/100 天时限更新。

调用示例（预期部署 ID 来自受控发布计划，不能从待验证证据直接提取）：

```sh
# 只允许后续私网引导，不放行公网
npm --prefix account-platform run check:production-recovery -- --local-only --deployment-id <expected-id> --bootstrap <evidence.json>
# 完整业务恢复验证；不能传 bootstrap 状态冒充通过
npm --prefix account-platform run check:production-recovery -- --local-only --deployment-id <expected-id> <evidence.json>
```

证据字段以 `scripts/account-platform-local-recovery-gate.mjs` 为机器合同，测试文件只有随机
隔离验收示例，不是现场事实。`cluster` 对应一个物理集群/备份 ID 和五库，`restore` 绑定
同一备份与 system identifier；`recovery_set` 绑定部署、数据库备份以及七类持久组件收据。
保管确认、数据目录、身份、连接或秘密不能从测试示例复制到生产证据。

制品/配置静态通过与现场完成分开记录；尚未完成的备份或恢复不得写成功证据。
L1 现已实现显式入口与两阶段检查，53 项相关合同/CLI 测试通过；独立审核者另跑新增
51 项全部通过、无跳过，代码及文档审核通过。收据摘要只是证据合同，仍须现场独立
采集/核验原始收据；24 小时内报告通过不能代替持续监测。

## D3-L2 接线执行细化

先交付候选制品与隔离验收，再对正式集群原地接入；不运行整项目 down、不删除/初始化
已有 PGDATA。基镜像保持已核验 PostgreSQL 17.11，使用其既有 PGDG 签名信任安装固定
`pgbackrest=2.59.1-1.pgdg12+1`（官方 Bookworm 包）。构建只访问公开软件仓库，不挂载正式
秘密/数据；记录候选 image ID，核验 PostgreSQL 版本未变、pgBackRest 版本正确。
包下载保留签名校验，不关闭 TLS 或使用不可信软件源；不因工具安装升级其他业务服务。
基础镜像没有系统 CA bundle，首轮构建因此被 HTTPS 校验拒绝。仅从 Debian 官方 HTTPS
下载固定 SHA-256 的 Bookworm CA 包引导公开信任根，再经原有签名软件源正常安装 CA 和
备份工具；不使用宿主私有 CA、不跳过证书验证、不改变业务的专用 CA 信任。

附加 Compose 文件仅覆盖 PostgreSQL 配置和增加两处受控绑定：加密仓库可写、备份秘密
目录只读；原有 TLS、只读根目录、999:999、私网、无宿主端口和资源限制保持。基础 Compose
不启用该模式；显式叠加时才使用包含原数据库配置的归档配置，`archive_timeout=30s`，
同步 `archive-push`，不设置允许丢 WAL 的队列上限。pgBackRest 日志仅错误等级且不写文件，
锁文件位于既有受限运行目录，单进程备份，命令与密码不出现在证据或普通日志。

备份秘密目录中配置仓库加密密码和独立 PGPASSFILE，仅数据库 OS 用户可读（0700/0600）；
备份命令使用文件认证，不调整 HBA 为 trust、不新增管理员 TCP 入口。正式加密密码只生成
一次，先用既有受信恢复公钥加密备份，再投递运行配置；不得覆盖已有包或通过聊天解密。
实际备份/检查通过有限命令入口调用 pgBackRest，不接受任意 shell、目标库、删除或 restore
参数；恢复只在隔离验证流程中执行。归档无需额外开放网络或传递业务数据库秘密。

隔离测试使用随机新集群/秘密/目录：验证全量与增量、真实 WAL 归档、选择早于后续写入的
恢复目标并核对五库恢复事实、错误加密密码拒绝、原集群不被修改。验收启动配置应与正式
候选一致，备份仓库不得以可写方式交给恢复实例，不能在恢复实例继续向原仓库归档。
仅清理本次随机 fixture 的确切容器/网络/目录；创建结果不确定时保留现场，不猜测删除。
错误密码的实际恢复可能被工具包装为“备份集不可用”，不能只据该退出码判定加密验证通过。
隔离验收同时要求同一仓库/备份集正确密码恢复成功、错误密码恢复零写入，再通过工具官方
`repo-get` 对固定元数据文件验证确切解密错误；输出仅内存捕获，不打印/保存其中内容。

正式原地接入前，先把现有集群逻辑备份经 age 流式加密保存为变更前保护副本，不能将其
冒充持续物理备份/PITR。核实集群标识、已有完成标记、镜像/数据挂载与受控目录后，只受控
替换 PostgreSQL 容器；保留原镜像与配置供受控回退评估，归档启用后不得回退为关闭归档
来消除失败，具体回退另审。启动后检查原集群标识不变、
原有五库/角色/连接仍正确，再建立 stanza、全量备份、实际隔离恢复和增量备份。
若归档失败，保留 WAL/失败状态，禁止删除 WAL、关闭归档或反复重建数据库来消除错误。

现场首轮成功后再启用每日增量/每周全量、每五分钟检查的 systemd 任务（单次有界、失败
非零、禁止并发），并提供迁移前单次备份调用。检查实际成功归档、备份新鲜度、任务失败、
磁盘/inode及状态时间，容量阈值沿用前文；暂不自动过期，不伪称已发送外部通知。
PG 子备份基础验证通过才继续正式身份和迁移；NATS/配置等完整恢复集在新业务与配置确定后
收集并验证，公网放行仍必须获得完整本机状态，不能使用 bootstrap 标记替代。
