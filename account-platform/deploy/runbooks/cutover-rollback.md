# production-new 切换与回滚

本流程只切换新系统入口。旧 New API 保持只读观察，不迁移、不双写旧账号、
余额或 Token。

## 切换前门禁

- G6 故障、安全、性能、恢复和可观测性有对应构建 SHA 与原始报告。
- G7 真实 New API 已验证逐请求 Usage、流式/取消、私网隔离和价格对账。
- G8 每个启用的真实支付渠道分别通过创建、回调、查询、退款、轮换和账单。
- 生产 Secret、域名、证书、KMS、OTLP 和 NetworkPolicy 已由双人复核；Helm
  渲染物无 Simulator、Mock、默认密码或本地 KEK。
- 支付尾单处理人、回滚负责人、监控窗口和用户公告已明确。

## 切换

1. 冻结 production-new 发布，保存 Helm release、镜像 digest、数据库版本、
   Dashboard 和告警静默状态。
2. 先开放内部/员工流量，验证注册、组织、充值、余额、Token 和 Trace。
3. 逐级调整 DNS/API Gateway 权重；每级至少观察错误率、p95、支付回调、
   Outbox、死信、Hold 和账实差异一个完整窗口。
4. 记录订单 ID/Usage Request ID 时只放入受控演练系统，不写公开聊天。

## 应用回滚

触发条件包括资金事实不确定、跨组织授权、重复模型调用、账本不平或无法解释
的 Usage 差异。立即停止新增流量和新支付创建，保留 Billing 回调、主动查询、
Outbox 与对账处理，使已经创建/支付的订单继续收敛。将入口权重切回旧系统，
但绝不把新订单、余额或 Token 双写到旧库。

Helm 回滚仅回滚到与当前 Schema 兼容的镜像。若数据库不兼容，部署前向兼容
修复或新实例恢复，不执行未经演练的 down migration。回滚后继续监控所有
production-new 尾单，直到 Pending、退款、Hold 和 Outbox 均收敛。

## 下线旧系统

仅在公告期结束、旧系统无新流量、财务/安全/支持签字且备份保留策略满足后，
才另行批准下线。该动作不属于普通应用发布或本 Runbook 的自动步骤。

## 工件验证限制

命令从仓库根目录执行；策略或字段格式通过、工件摘要绑定和真实演练/发布审批是不同结论。现有可信来源、全部原始工件和独立审批不可省略，详见 [运维证据](operational-evidence.md)。
