# 私有基础设施 TLS 离线生成

本工具只生成 PostgreSQL、Redis、NATS、Keycloak、New API 的独立私有 TLS 材料，不初始化或修改 KMS，不访问网络，不读取恢复私钥、口令、root token 或任何现有 CA。现有 `kms-pki` 行为不变。

在 `tools/kms-recovery` 模块中构建 `go build ./cmd/infrastructure-pki`。命令仅接受 `-config <绝对路径>`；配置仅包含 `recipient_file`（已校验的现有恢复公钥文件）、`recipient_sha256`（去除首尾空白后的公钥 SHA-256）和 `output_directory`（尚不存在的绝对目录）。不支持自定义 SAN、KMS 地址或秘密参数。

父目录必须预先建立并限制访问：Linux 仅当前保管人可访问；Windows 必须由保管人明确配置 ACL，仅允许保管人和 SYSTEM，不能依赖 POSIX mode。配置、公钥均为受保护普通文件，不能是符号链接。不要在仓库目录生成正式材料。

输出包括：

- `ca-private.age`：新建独立 CA 的 age 加密恢复包，目的标识为 `pinvou-platform-internal-ca`。CA 私钥不写明文文件。
- `ca.crt`：五年有效、不能签发中间 CA 的独立根证书。
- `postgres/`、`redis/`、`nats/`、`keycloak/`、`newapi/`：分别包含 `server.crt` 和明文 `server.key`，每项使用独立密钥、单个固定 DNS SAN、仅 serverAuth、90 天有效期。服务私钥须按角色投递，不能把整个包挂载进业务容器。
- `manifest.json`：上述 12 个文件的哈希和恢复公钥指纹。
- `READY`：最后写入，绑定清单哈希。它不代表已部署，也不能替代部署时的完整文件集合、哈希、证书、权限验证。

工具使用排他创建、写后校验与 Linux 文件/目录同步。失败时保留部分目录且禁止原地重试/覆盖；部分包不可部署，排查后使用新的输出目录。不要自动删除可能已持久化的加密 CA 材料。私钥缓冲尽力清零，Go 内部对象及系统内存不保证彻底擦除。

正常更新使用公钥生成全新独立 CA 和五张叶证书：先让所有相关客户端信任新旧两个公开根，再逐个替换服务证书、验证实际服务序列号和 TLS，最后移除旧根。提前 30 天告警、14 天阻断新部署；本工具不提供自动续期。若怀疑叶密钥或 CA 泄露，不得按正常流程长期双信任或回滚旧叶证书，应隔离流量并执行应急整体替换与旧信任撤除，允许受控停机；没有 CRL/OCSP 能力声明。现场投递、监控与更新验收属于 SECINF04C2D，不因本工具测试通过而视为完成。

仅由保管人离线保存 `ca-private.age`、公开 CA、清单与可信副本指纹，并与恢复口令分开。普通投递无需解密 CA；恢复包的真实性还须依赖独立保存的清单指纹，哈希清单本身不是签名。测试仅使用临时 age 身份和隔离本地 TLS 服务，绝不解密正式恢复包。
