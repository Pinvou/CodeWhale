# Dedicated PDF image: lxml resource pruning

Only `Dockerfile.evidence-validator-pdf` applies this transformation. The pinned lxml 6.1.3 wheel is first installed from the local wheelhouse with `--require-hashes`, then `prune_pdf_lxml.py` independently verifies the exact official wheel filename and SHA-256 for the target architecture, its RECORD, every installed lxml RECORD entry, and the two approved files' source and installed SHA-256. It rejects unsafe paths, symlinks, unrecorded files, modified files, wrong architecture, and unexpected installer entries before deleting either resource. Python bytecode generation is disabled. After deleting only those two resources, it rewrites and verifies the installed RECORD.

The resulting image is **not an unmodified official lxml wheel installation**. Its `/opt/pinvou/pdf/share/pinvou/lxml-pruning/` contains both original RECORDs, exact removed-file hashes and source-wheel SHA, a pruning NOTICE and a CycloneDX fragment describing only this modification; the fragment is not an image SBOM. The unchanged original wheel remains in the external audited wheel inventory and the intermediate build context, not in the runtime image, because it contains the removed files. Standard wheel licenses and metadata remain in the venv. The lxml `isoschematron` module no longer imports and must not be used by this dedicated validator. No other business image is changed by this transformation.

Before modifying installed files, the helper rejects an existing destination, symlinked or non-directory ancestors, and a destination where it cannot create and write a probe. It is not a transactional filesystem operation: interruption, later disk errors or an adversarial process with the same UID can still interrupt or race the transformation. A failed Docker build step must not be distributed.

The intermediate build runs five hash-pinned synthetic PDF smoke fixtures with the actual pruned runtime, but **neither Linux architecture has yet been built or executed**. Local cross-target wheel installation/RECORD tests do not execute Linux native libraries. The final image still requires independent dual-architecture build and runtime tests, original-byte and isolation validation, a complete image SBOM, and license/provenance review of lxml, its native dependencies, Pillow/libwebp and its upstream PATENTS, Python, OS packages and other components. In particular, source licensing and distribution obligations are not resolved by this technical pruning. Keep the candidate disabled until the separate release gates pass.

Sources: [lxml 6.1.3 LICENSES](https://github.com/lxml/lxml/blob/lxml-6.1.3/LICENSES.txt), [RNG XSL](https://github.com/lxml/lxml/blob/lxml-6.1.3/src/lxml/isoschematron/resources/xsl/RNG2Schtrn.xsl), [XSD XSL](https://github.com/lxml/lxml/blob/lxml-6.1.3/src/lxml/isoschematron/resources/xsl/XSD2Schtrn.xsl), [libwebp PATENTS](https://github.com/webmproject/libwebp/blob/v1.6.0/PATENTS).
