# PDF validator test gate

`run_pdf_gate.py --strict` checks the fixture hashes, runs the Python validator, gate, lxml-pruning and image-candidate test suites with machine-readable test counts, and requires the real PDF Go parent test and all five named subtests to run and pass with no skips or failures. Strict mode requires `EVIDENCE_PDF_AUDIT_DIR` containing `manifest.json` and all four locked packages for both x86_64 and aarch64. The producer also retains `lxml.lock` for the pruning tests. A missing wheel, incomplete audit or unavailable real symlink test fails. Without `--strict`, a missing local pikepdf/qpdf runtime or Go tool causes an explicit skip, and the separate pruning and image-candidate suites are not selected. The gate does not install anything during the tests.

The Linux CI step creates an isolated Python 3.12.14 virtual environment. Dependency installation and downloading the two complete target wheel sets **use the network** to reach the official PyPI index, use the checked-in hash lock, accept wheels only, disable dependency resolution, and run `pip check`. The audit producer checks the exact per-architecture filenames and digests and runs the image preflight for both targets before returning success. The setup-python action leaves the job-wide interpreter environment unchanged. Only the PDF step prepends the selected interpreter's library directory to its loader path before using the explicit interpreter path; later contracts keep the runner's original Python PATH. The test-only child launcher also supplies that interpreter's fixed library directory because the supervisor deliberately sanitizes the child's environment. Registry or dependency unavailability fails the CI step. This is separate from the PDF child at runtime, which does not download dependencies.

The CI test does not build or run the candidate container and does not validate Linux cgroups, production isolation, dependency provenance, or all PDF formats. Local Windows results do not establish Linux CI results.
