# PDF validator test gate

`run_pdf_gate.py --strict` checks the fixture hashes, runs the Python validator, gate and lxml-pruning test suites with machine-readable test counts, and requires the real PDF Go parent test and all five named subtests to run and pass with no skips or failures. Strict mode also requires `EVIDENCE_PDF_AUDIT_DIR` containing the locked x86_64 and aarch64 lxml wheels and requires that a real directory symlink test can run; a missing wheel or symlink capability fails. Without `--strict`, a missing local pikepdf/qpdf runtime or Go tool causes an explicit skip, and the separate pruning suite is not selected. The gate does not install anything during the tests.

The Linux CI step creates an isolated Python 3.12.14 virtual environment. Dependency installation and downloading the two target lxml wheels **use the network** to reach the official PyPI index, use the checked-in hash lock, accept wheels only, disable dependency resolution, and run `pip check`. The setup-python action does not update the job environment. Only the PDF step prepends the selected interpreter's library directory to LD_LIBRARY_PATH before using its explicit interpreter path; later contracts keep the runner's original Python PATH. A private test-only launcher restores only that fixed library directory after the production supervisor clears the child environment, and executes the same venv interpreter. Registry or dependency unavailability fails the CI step. This is separate from the PDF child at runtime, which does not download dependencies.

The CI test does not build or run the candidate container and does not validate Linux cgroups, production isolation, dependency provenance, or all PDF formats. Local Windows results do not establish Linux CI results.
