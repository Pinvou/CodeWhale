# HTTP 限流地址容量

每个 HTTP admission 桶最多保留 10,000 个来源键。普通流量、无效回调、已验证回调和回调令牌仍使用各自的桶及既有速率、突发额度、可信来源和主体分类规则。

地址表满时，新来源沿用 `429 RATE_LIMITED` 和 `Retry-After: 1`；现有来源继续按原额度补充和消费。不会驱逐活跃来源来给新地址重置额度，因此该上限不能保证容量耗尽时所有新合法来源都可用。

按最近触达顺序回收空闲至少 10 分钟的条目，每次请求最多回收 32 项，避免在全局锁中周期性扫描整个地址表。长时间空闲后的后续请求会继续分批回收。GET/HEAD 健康探针保持豁免，仍执行真实 readiness 检查。

本机回归验证容量、并发、分批回收及探针行为，不代表已经测得生产吞吐、内存字节上限或暂停时长。
