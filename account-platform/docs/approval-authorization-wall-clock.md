# 等待后的审批与组织节点授权

临时角色的自然到期不会修改数据库行，也不保证产生可串行化冲突。
审批的新写入以取得对象、用户、角色和授权版本锁之后的数据库当前时间判定权限；
外部 activation、snapshot 或 precheck 返回后，再进行最终授权复核。
申请到期、证明的新鲜度和有效期、近期认证及执行窗口沿用原阈值，
最终准入不使用事务开始时间，也不使用应用测试时钟代替数据库当前时间。

APPROVE 的专用 writer 仍只通过原 SECURITY DEFINER 函数取得授权元组。
新增迁移保留旧迁移字节、函数身份、owner、search_path 和运行角色 ACL。
函数在全部授权锁取得后选取仍有效的候选绑定；checkpoint、决定和执行准入
仍须匹配原绑定及授权版本，不能以另一个有效绑定自动挽救原已批准授权。

Begin 先按稳定用户顺序锁住双方用户，再锁角色，最后锁授权版本，
以同一个数据库时刻复核申请者、审批者和执行窗口。
普通 CreateUnit 和 MoveUnit 在对象锁后复用组织授权最终围栏；
移动同时复核原节点和目标父节点的作用域，无变化但新增回执也须通过。

精确既有回执和已开始执行的查询保留原只读恢复路径。
本修复不新增认证年龄、SLA、自动重试、补偿或资金策略；
也不把审批拒绝的本地验证当作部署或实际财务效果验收。
