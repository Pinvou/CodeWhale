# 跨钱包套餐到期扫描索引

对应 #1632 的套餐到期扫描条目。原 `wallet_id` 前导的 ACTIVE 部分索引用于单钱包分配，不能提供跨钱包的 `valid_until, credited_at, id` 全局顺序。Billing 900043 增加相同三列顺序的 ACTIVE 部分索引，并 INCLUDE 查询返回的 `wallet_id`。

本片保留 `expireOnePackage` 的完整候选 SQL、REVIEW 分配排除、钱包先于套餐围栏的锁顺序、实际过期入账和幂等合同；不更改到期日期、金额、冻结状态或扫描批量。

## 安装与恢复

使用完整 Billing 迁移载体、预置的专用 `billing_migrator` 登录和 `MIGRATION_ROLE=billing_service`，沿用受控 `DATABASE_URL` 与既有生产备份证据配置。从 `account-platform` 源码目录运行：

```powershell
$env:MIGRATION_ROLE = 'billing_service'
go run ./cmd/migrate --dir ./migrations/billing --direction up
```

新 SQL 的名称、版本和双向摘要在公开迁移入口钉定；旧 SQL、已应用账本和旧索引不变。Up 沿用既有 Billing 事务所有权/CREATE 借用及收回框架；运行服务不获得独立 owner 成员关系。普通建索引以及原框架的所有权调整会阻塞相应写入，应安排维护窗口并核对空间、积压和现场角色。

公开 Down 明确以 SQLSTATE 55000 拒绝，保留索引及迁移账本；不借性能回退降级财务 Schema。故障恢复沿用向前修复流程，应用回退须另核对实际安装历史的兼容性。其他未合入的补充迁移应先组装完整载体并实际验证，不以本片的单独安装证据代替。

## 验证边界

隔离用例覆盖首次安装及非空 900038 载体升级、真实 migrate CLI、运行账号拒绝、重复 Up 与前向 Down 拒绝、旧金融事实/账本/所有者/ACL 保全。规模历史为十万钱包及其受控合成套餐、lot 和 component，包含九万终态及一万未来 ACTIVE；它用于索引分布，不宣称每条都经过真实付款或具有完整历史入账证据。

规模用例的工作与清理等待分别限定为 3 分钟和 45 秒，普通夹具仍用原 60 秒和 10 秒。清理仍核对独占数据库身份，并等待数据库确认所有连接及后台维护退出后非强制删除；超时不视为已清理，也不靠重试改写失败记录。

另有四笔套餐由原付款合并写方生成，其中一笔由原强制退款写方冻结。真实到期 worker 必须只依次处理其余三笔，批量上限、原钱包金额、准确的过期分录、冻结保全及后续 tick 无重复效果分别验收。已有 REVIEW/成员额度到期场景作为独立真实资金回归，不能只凭状态索引推断 REVIEW 排除已证明。

自然 EXPLAIN/BUFFERS 的 SQL 从实际 `expireOnePackage` 源码提取；预期结果及顺序另行断言。在同一数据集、同一运行角色中，仅在未提交的专用迁移账号事务内临时移除新索引取得基线，探针结束即回滚恢复；此步骤不是公开 Down 或现场操作建议。保留全部重复样本，不把测试指纹、热缓存或某个单次耗时作为生产容量/SLA。

本文描述机制和验收口径，不代表远端 CI、完整 issue、合并或现场发布已经完成。
