# ADR-001：服务边界和数据库所有权

- 状态：Accepted
- 日期：2026-08-12

## 背景

用户身份、组织授权、供应商 Token 和资金账本的生命周期、安全等级与扩缩容特征不同。把它们全部写入 New API 会绑定第三方数据模型，也会形成跨领域直写。

## 决策

- Account Service 独占用户业务资料、组织、组织单元、成员、角色、会话上下文和授权审计。
- Billing Service 独占钱包、账本、商品、预占、支付、退款和对账。
- Token Gateway 独占 Token 账号、加密凭据、共享策略、路由和用量编排。
- Payment Simulator 独占模拟渠道订单，只用于开发和测试。
- Keycloak 独占密码、MFA、OIDC 会话和认证令牌。
- New API 是模型数据面，不拥有业务身份、组织和资金事实。
- 每个服务使用独立数据库和数据库角色；跨服务只通过版本化 API 或事件通信。

## 被拒绝方案

- 全部放入 New API：升级和数据边界不可控。
- Account 与 Billing 合并：权限数据和不可变财务数据相互污染。
- 共享数据库表：绕过领域规则，无法独立迁移和最小授权。

## 影响与回滚

跨服务操作需要幂等和最终一致设计。若部署规模需要收缩，可以把进程共同部署，但不得合并数据所有权或允许跨库直写。
