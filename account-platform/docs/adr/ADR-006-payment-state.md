# ADR-006：支付状态、迟到支付和退款

- 状态：Accepted
- 日期：2026-08-12

## 背景

扫码支付存在异步通知、主动查询、重复回调、订单过期后到账和退款等不可避免的乱序状态。

## 决策

渠道支付流水、积分履约、退款和订单摘要分离。回调、主动查询、受控账单和人工修复都先追加不可变证据，再由同一归并器确认支付；客户端轮询只展示结果。订单默认 15 分钟过期，过期后收到有效渠道付款事实时进入 `PAID_LATE` 并履约，不丢弃资金事实。

普通订单在72小时边界完成最后一次 Provider 查询；仍未收敛时停止高频任务并幂等创建唯一 P2 晚到支付案件。前7天每日、此后每周复核。无回调无账单 Provider 必须具有长期历史查询、有限支付/晚到窗口、权威未支付终态和足够证据保留期才可正式收款。未支付归档还要求期限后成功的权威查询且没有支付、冲突或未复核申诉；否则升级 `PROVIDER_BLIND` 并停用该 Provider 版本新单。

支付成功、账本入账、履约成功和 Outbox 在同一 Billing 数据库事务提交。普通退款必须精确指定一笔成功支付流水及其唯一权益包，金额由该流水派生；只有该包全部 BASE 和关联 BONUS 均未消费、未预占且不存在异常时，才允许原路执行一次整笔剩余退款。成功后撤销该包全部 BASE/关联 BONUS，但不覆盖支付成功事实。渠道强制退款作为独立证据和人工案件处理。

## 被拒绝方案

- 以前端“支付成功”入账：可伪造且页面关闭会丢失。
- 只轮询渠道：延迟大且易受故障影响。
- 把查询快照冒充渠道账单：无法证明 Provider 侧资金全集。
- 订单级按金额部分退款：无法稳定锁定多流水订单中的资金来源和应撤销权益。
- 修改历史分录实现退款：破坏审计链。

## 影响与回滚

任何渠道适配器都必须映射到统一状态机并声明版本化能力。状态迁移失败时保留渠道证据供重试，禁止人工直接改余额或标记已支付。写入晚到案件、退款预约或 Provider blind 控制后不回滚到旧订单级状态机，只允许前向修复。
