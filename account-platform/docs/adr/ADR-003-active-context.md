# ADR-003：活动上下文按用户全局保存

- 状态：Accepted（取代原“按会话保存”决策）
- 原日期：2026-08-12
- 变更日期：2026-08-22

## 背景

同一用户可加入多个组织并同时使用桌面与 Web。聊天与计费请求必须始终能唯一确定付款主体，同时两个入口需要展示并使用同一个活动上下文。组织管理目标属于资源授权参数，不应反向改变正在使用的聊天与计费主体。

## 决策

每个用户全局只有一个聊天和计费活动上下文：个人，或用户仍为有效成员的一个组织。所有 OIDC Session、桌面和 Web 都读取同一条用户级活动上下文记录及单调递增的 `context_version`。

切换时重新校验成员和组织状态，使用期望版本原子更新用户级记录并递增版本。所有已认证业务 API 返回当前版本；客户端发现更高版本、窗口重新聚焦或切换成功时清空旧额度、权限、路由和组织缓存。组织计费请求不得静默回退个人 Token 或个人钱包。

组织管理 API 使用显式 `target_organization_id` 和目标组织的 `authorization_version` 做授权，查看、编辑或购买组织资源不隐式切换聊天和计费活动上下文。平台后台权限完全不受该上下文影响。

切换前已经开始的模型调用保存上下文、钱包、授予和版本快照，始终按开始时快照结算。成员被移除或组织停用时，Account 自动把受影响用户切回个人并递增版本。平台后台权限不受活动上下文影响。

## 被拒绝方案

- 每会话独立活动组织：桌面与 Web 会显示不同余额和组织身份，不符合跨端自动同步要求。
- 每请求同时激活多个计费组织：付款主体无法唯一确定。

## 影响与回滚

Account 需要把现有 Session 上下文迁移为用户级记录。若同一用户存在多个不同旧上下文，选择最近一次成功切换记录；无法可靠判断时回到个人上下文。所有资源 API 必须返回可验证的上下文版本，涉及上下文的写请求使用期望版本或强制重读。若撤销组织权限，服务端立即切回个人并使旧授权缓存失效。
