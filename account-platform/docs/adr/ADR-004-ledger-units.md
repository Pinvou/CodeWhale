# ADR-004：积分单位和账本

- 状态：Accepted
- 日期：2026-08-12

## 背景

充值、模型消费和退款需要避免浮点误差，并能够从不可变事实重建任意钱包余额。

## 决策

- 法币以整数分 `amount_fen` 保存，只支持 CNY。
- `1 CNY = 100 展示积分 = 1,000,000 microcredits`。
- 所有积分运算使用有符号 64 位整数并做溢出检查，禁止浮点数。
- 每次变动写不可变平衡分录；钱包余额是可重建快照。
- 普通角色不能更新或删除已提交账本。
- 购买积分默认不失效，促销积分使用独立批次和明确有效期。
- 模型计量单位与账本单位分离：`INPUT_TOKEN`、`OUTPUT_TOKEN`、`IMAGE`、`REQUEST`、`DOCUMENT` 等只表示版本化用量维度，不能直接作为钱包余额。
- 协议预占公式先计算各计量单位数量，再使用请求固定的价格版本转换为整数 `microcredit`；账本和 Hold 只以转换后的整数金额入账，同时保存单位版本、数量、单价和公式版本作为证据。

## 被拒绝方案

- 直接更新余额：无法审计和可靠冲正。
- 用浮点数计费：产生舍入差异。
- 把 New API 额度作为余额事实：无法表达支付、预占和退款。

## 影响与回滚

所有历史费用绑定价格版本。兑换比例变化必须创建新商品和新价格版本，不能重算历史。
