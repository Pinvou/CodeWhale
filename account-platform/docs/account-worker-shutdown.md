# Account 后台任务退出

Account 在账户侧配置核验与任务登记完成后，统一启动已登记的定时后台任务：手机号留存、钱包开通、角色到期、账户注销、审批到期、审批分页清理及人工复核 SLA；审计导出、手机号资料变更、注册恢复和商户客户同步仍按各自配置启用。账户侧配置失败时不提前启动这些任务。随后 HTTP 初始化仍可能失败，返回错误时同样执行取消、等待及数据库关闭流程。

SIGINT/SIGTERM 的同一个上下文会通知 HTTP 监听器和全部 worker 停止。HTTP 与 metrics 沿用公共服务器的关闭流程；监听器返回后，Account 取消 worker 上下文并等待全部已启动任务退出，再关闭 repository。监听器异常返回也执行这一步。worker 等待共用一个 `SHUTDOWN_TIMEOUT` 预算（默认 10 秒），不会逐个叠加；这个预算是 worker 阶段预算，不是 HTTP、tracing 和 worker 各阶段合计的总退出时限。

若 worker 阶段耗尽预算，输出固定 `ACCOUNT_BACKGROUND_SHUTDOWN_TIMEOUT`，随后进入 repository 关闭阶段。既有 `pgxpool.Close` 本身没有截止时间，仍可能在预算耗尽后等待未归还连接；该日志不能证明进程已退出，也不能证明未完成的外部操作已取消或回滚。不要按超时日志删除 lease、清空任务或直接重做外部副作用。重启后仍由各任务现有的 lease、幂等键和结果核实机制恢复。退出期间的未知结果应按原操作编号核查。

本任务组仅覆盖上述已登记的定时 worker。HTTP 请求内另起的短信投递不在该组内，本次没有改变其既有投递或取消语义。

部署终止宽限期需要覆盖公共 HTTP drain、tracing 收尾及 worker 等待阶段，并保留正常调度余量。修改 `SHUTDOWN_TIMEOUT` 时应同时核对容器/编排器的实际宽限期；本说明不代替目标环境的信号及外部依赖演练。
