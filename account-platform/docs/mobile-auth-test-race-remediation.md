# APT-138-P2：移动认证测试替身并发同步

## 需求与根因

APT-138 的 Linux 全量 race 验收发现，既有 `mobile_auth_test.go` 在生产异步短信投递期间，无同步读写测试替身的 `challengeFailed`、`challengeSent` 和 `sentChallenge`。轮询加 sleep 不能建立 Go 的 happens-before 关系。问题归属测试替身，不改变生产反枚举异步投递语义。

必须保留原有注册、登录、密码重置的反枚举响应、权限拒绝、验证码校验及调用次数断言；不得通过修改生产、禁用 race、跳过用例或固定等待掩盖竞态。

## 设计

仅为测试替身的跨协程投递状态增加互斥保护和只读快照方法，所有相关写入与断言读取使用同一同步边界。预期异步投递的用例在启动前建立完成通知，仓储替身在成功/失败状态落定后发出一次性通知；测试使用有界 channel 等待后断言精确状态与提供者调用，不再轮询或 sleep。权限拒绝与未知账号沿原同步返回分支验证零投递，不人为启动异步工作。仅同步确实被异步访问的状态，不扩大到生产接口或业务行为。
