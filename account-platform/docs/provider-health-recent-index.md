# 支付提供方健康观测的全局时间索引

对应 #1632 的全局近五分钟观测发现查询。原 `payment_provider_health_window_idx` 以提供方/版本/动作/渠道/路由开头，继续服务分区内证据读取；Billing 900045 另增 `received_at` 前导索引，INCLUDE 全局 DISTINCT 返回的五个分区字段。

本片保留原五分钟下界、动作筛选和完整分区集合，没有增加 LIMIT、分页或截断。分区内的排序、样本量、独立订单数、业务拒绝排除、停损控制版本和不可变证据成员均由原实现处理。不新增提供方调用或资金动作，不自动恢复已停损提供方。

## 安装与恢复

使用完整 Billing 迁移载体、预置 `billing_migrator` 登录、`MIGRATION_ROLE=billing_service`、受控 `DATABASE_URL` 及既有生产备份证据配置。从 `account-platform` 目录执行：

```powershell
$env:MIGRATION_ROLE = 'billing_service'
go run ./cmd/migrate --dir ./migrations/billing --direction up
```

公开入口钉定新增版本/名称/双向 SQL 摘要，Up 沿用既有 Billing 事务所有权与 CREATE 借用/回收框架。运行服务不获得独立 owner 成员关系，旧索引、账本和观察行保留。普通建索引及原框架所有权调整会阻塞写入，须安排维护窗口并核对空间与积压。Down 以 SQLSTATE 55000 明确拒绝，恢复采用向前修复。

本独立载体的升级边界为实际非空 900038。已安装其他尚未合入的补充版本（例如 900039）时，须组装同时包含这些版本的完整 SQL、编译期注册及不可变清单，并验证组合；不得删除旧账本以迎合本独立载体。旧独立载体不能代替未来完整合并载体。

## 证据与保留范围

历史压力数据为十万条受控合成 attempt/observation，覆盖千个提供方分区且时间在九十天前，只用于分布和查询计划，不能冒充真实供应商调用。另由原付款合并写方创建五笔实际测试付款，再由原 begin/finish 观察写方产生旧停损、当前连续失败、20 次混合失败率样本、业务拒绝、不参与该发现的动作及精确五分钟边界样本；失败率分区额外的业务拒绝不得计入分母。外部提供方为受控夹具，没有真实收费。

原停损评估建立旧观察引用；升级及计划探针必须保留旧观察、成员、控制、付款数据、账本、所有者、ACL 与触发器。实际运行原发现/派生/评估链核验完整集合、连续失败与失败率阈值、原证据 ID、已停损状态不重开及下次评估不重复；不以一次 SQL 成功替代运营停损恢复验收。

基线在独占未提交的迁移账号事务中临时 DROP 新索引，再切原运行角色执行完整生产查询，结束即 ROLLBACK 恢复；这不是公开 Down 或现场操作建议。计划不强制 planner 选项，不把热缓存单次耗时视为生产 SLA。规模夹具工作/非强制清理预算为 3 分钟/45 秒，普通夹具保持 60 秒/10 秒，仍等待数据库确认无活动连接再清退。

本片没有 TTL、归档或删除操作，不清除案件、保全或业务引用。它只完成索引及保全验收，不完成整个 #1632 的观测保留策略；保留期限、备份及受控处置政策需独立确定。索引覆盖全历史意味着仍需按实际增长规划存储容量。
