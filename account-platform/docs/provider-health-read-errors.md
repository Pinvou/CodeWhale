# 健康观测读取失败与恢复

对应 #1632 审核发现的原有 P2。全局分区发现、最新五条观测、一分钟失败率样本的 `Next()` 循环结束后必须检查 `Rows.Err()`；SQL 已描述结果并开始执行后仍可能发生读取错误，不能只检查 `Query` 或 `Scan`。

三个阶段任一失败，`observationCandidates` 返回 `nil, error`，不交付部分候选。`EvaluateProviderStopLosses` 沿原错误出口返回，不进行该次停损写入。原分钟 worker 可记录既有有界错误码并在后续 tick 再评估；提供方结果回调原本不因聚合失败重发调用，本片不改变这一资金副作用边界。

不改 SQL、窗口、阈值、业务拒绝分母、控制版本、索引或保留期限。跨商品读取原本已返回 `rows.Err()`，继续保留。没有迁移及新的持久失败终态；故障期间不将未知读取解释为零风险。

隔离 PostgreSQL 用例通过专用迁移账号，在自己持有的 UUID 数据库中暂时建立同列故障视图，以 VOLATILE 函数模拟实际读行阶段的 PZ001 错误。三个命名场景必须全部执行：发现、最近五条、失败率。每个场景检查原错误身份、无部分候选、无停损/资金/证据写入；恢复原表和连接后，下一次评估按原20样本/10失败/5订单阈值正常停损。后续评估不重复应用控制；已禁用控制首次以新控制版本评估时，原逻辑仍可新增 action_applied=false 的评估、成员和 outbox 证据。用例在这次评估后保存快照，验证相同版本及观测集合的再一次评估不重复持久效果。故障视图不是生产配置或操作建议。

本独立修复不依赖尚未合入的039/040索引载体。未来合并须保留全部 required roots 并核实实际集合及CI；不以单独分支通过代替组合验证。本片不完成整个#1632的保留策略、其他恢复合同或现场发布验收。
