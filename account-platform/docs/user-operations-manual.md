# Pinvou 完整操作手册

> 校准日期：2026-09-30
>
> 适用范围：Pinvou 桌面客户端、Web 个人中心、管理后台，以及与这些页面直接相关的发布、审核和异常处置流程
>
> 事实依据：当前仓库前后端代码、OpenAPI、数据库迁移、`requirements.md`、Accepted ADR 和部署 Runbook
>
> 阅读对象：普通用户、组织管理员、平台运营、财务审核员、安全审计员和发布运维人员

本手册描述当前仓库构建中已经存在的操作能力，但不据此断言任一环境已经部署或激活这些能力。所有页面和操作均受账号状态、活动上下文、部署版本、环境能力声明、功能 Gate、命令治理状态、授权版本、角色和权限约束。看不到菜单通常表示当前环境未交付/未开启对应能力，或账号没有读取权限；按钮置灰或不出现，通常表示缺少动作权限、近期认证、审批条件、资源状态或治理开关。

## 0. 使用约定与安全边界

### 0.1 三类环境和操作

| 标记 | 含义 | 是否允许人为触发 |
|---|---|---|
| 正式操作 | 在生产环境处理真实用户、资金、用量和审核事项 | 只允许按页面和 Runbook 正常操作 |
| 生产异常 | 生产运行自然形成的待审核、待修复或结果未知记录 | 可以处理，不得为了测试主动制造 |
| 隔离验收触发 | 在 UAT、测试租户或本地环境用受控依赖和测试账号复现前置状态 | 可以，必须确保与生产数据、密钥、支付渠道隔离 |

以下做法在任何环境都不是受支持的业务操作：直接修改数据库状态、伪造账本分录、手改审计记录、复制生产密钥到测试环境、关闭生产供应商或网络以制造异常。需要异常样本时，优先使用本手册第 6 章列出的测试入口、模拟场景或受控依赖；生产环境没有造数入口的，以自然产生的记录为准。

### 0.2 操作前通用检查

1. 核对环境域名和页面标题，确认不是把测试操作做到了生产。
2. 核对当前登录账号、活动上下文（个人或组织）和目标对象编码。
3. 高风险操作前完成近期认证；页面要求填写原因时使用真实、可追踪的业务说明。
4. 保存请求 ID、订单号、用量请求号、命令引用或审批 ID；结果未知时用原引用查询，不生成新幂等键重提。
5. 涉及资金、凭据、删除、恢复、导出或注销时，先截图或导出脱敏证据，再执行操作。
6. 页面状态与本手册不一致时，以服务端返回和审计事实为准，并停止重复点击。

### 0.3 适用构建与环境能力确认

代码、契约测试和需求状态只能证明“仓库中存在该能力”，不能替代目标环境的部署、Gate、授权或激活证据。特别是模型与 Token 新信息架构、命令动作、恢复队列及财务修复审批，在实现状态中可能仍标记为 `NOT_DEPLOYED`、部分实现或命令 `INACTIVE`。

执行本手册中的管理操作前，应先完成以下确认：

1. 从发布记录核对 Portal、Account、Billing、Token 和桌面制品版本与本手册对应；不能用仓库 `HEAD` 推断线上版本。
2. 以当前会话返回的环境能力和 feature flags 为准确认页面 Gate；没有对应 Gate 的环境只使用其实际展示的旧版只读页面。
3. 核对读取权限、动作权限和授权版本均有效。页面能读取不代表命令可提交，菜单存在也不代表写能力已启用。
4. 模型与 Token 命令还要核对命令 readiness、治理状态和 epoch；审批或财务修复还要核对对应命令的激活状态、冻结事实和独立审批策略。
5. 环境未部署、Gate 关闭、readiness 不可用、命令未激活或仅有只读能力时，停止写操作并交由发布负责人按 Runbook 补齐；不得绕过页面直接调用接口。

本手册后续的“可操作”均以以上条件满足为前提。若实现状态与目标环境不一致，以目标环境的发布证据、服务端 readiness 和审计事实为准。

### 0.4 后台导航与职责

后台左侧导航按权限分组，顶部面包屑显示当前位置；浏览器刷新、前进和后退会保留可路由页面状态。

| 分组 | 页面 | 主要职责 |
|---|---|---|
| 工作台 | 平台总览 | 业务、资金、模型和系统健康摘要 |
| 身份与组织 | 用户管理、角色与权限、组织管理、我的组织 | 用户生命周期、授权、组织和成员 |
| 财务与支付 | 账户与计费、支付与对账、定价与商品 | 钱包、账本、支付、退款、商品 |
| 模型与 Token | 模型管理、Token 资源、运行与用量 | 模型目录、Token Account、路由、用量核对 |
| 治理与安全 | 运维配置、审批中心、审计与导出、系统与安全、偏好设置 | 运营策略、双人审批、审计、运行状态和短信配置 |

同一人员不应同时长期持有“发起高风险财务修复”和“审批本人申请”的能力；系统不允许自审。

## 1. 首次使用与入口

### 1.1 常用入口

| 场景 | 入口 |
|---|---|
| 桌面客户端账号/余额/充值 | Pinvou 桌面客户端右上角账号入口 |
| 桌面端平台模型 | 聊天输入框模型选择器，或“设置 > 模型” |
| Web 个人中心 | 浏览器打开账号平台站点根路径 `/`，或在桌面账号弹窗中选择打开个人中心 |
| 管理后台 | 浏览器打开账号平台站点 `/admin.html` |
| 登录/注册 | Web 未登录会跳转 `/auth/login`；桌面账号弹窗内可直接登录/注册 |

### 1.2 首次注册/登录

1. 打开桌面账号弹窗或 Web 登录页。
2. 选择注册：填写用户名、手机号、密码、确认密码。
3. 先把密码和确认密码填写完整，再选择“获取验证码”。系统会保留已经填写的用户名和手机号；密码为空、格式不合规或两次不一致时，会直接提示具体原因，不会清空表单。
4. 系统先做注册预检；通过后完成滑块验证并获取短信验证码。
5. 输入 6 位短信验证码后提交注册。
6. 注册完成后回到登录界面，使用用户名或手机号登录；也可切换为短信登录。首次自动登录未完成时，账号本身仍应可正常密码登录。
7. 首次登录后，个人钱包可能处于 `PROVISIONING`。该状态表示账号已建立但钱包仍在初始化；稍后刷新，充值和平台模型调用才会可用。超时未完成会进入运营修复队列。

用户名规则为字母开头，可使用字母、数字、点、下划线、短横线，长度 3–32。手机号使用中国大陆手机号。密码长度 8–128，必须包含字母和数字，首尾不能有空格。不要把验证码、密码或会话链接交给他人。

密码登录、注册和重置密码的每个密码框只显示一个由页面提供的明文/暗文切换按钮。浏览器自带的重复密码图标已被抑制；若仍看到两个图标，先强制刷新静态资源，仍存在时记录浏览器版本和截图交给前端排查。

### 1.3 忘记密码

1. 进入登录页，选择“忘记密码”。
2. 填写手机号，完成滑块验证并获取短信验证码。
3. 输入验证码、新密码和确认密码后提交。
4. 返回登录页使用新密码登录。

重置链接由账号平台自身生成，不应跳转到身份服务的“禁止重置凭证”页面。出现该页面通常表示仍在使用旧书签或旧静态资源，请从当前登录页重新点击“忘记密码”。

### 1.4 账号与上下文

- 个人上下文：使用个人钱包、个人权限和个人用量。
- 组织上下文：激活某个组织后，按组织角色访问组织钱包、权益、成员、节点和模型策略。
- 模型调用、账单、权益和审批入口都会跟随当前上下文。切换上下文后建议刷新页面。

## 2. 桌面客户端

### 2.1 账号弹窗

1. 登录后打开账号入口。
2. 查看登录账号、平台账号状态、可用积分和预占积分。
3. 选择“充值”进入充值面板。
4. 需要完整资料、订单、权益、组织管理时，选择打开 Web 个人中心；桌面已登录时浏览器会自动建立独立的个人中心会话，无需再次输入账号。若桌面登录已失效，浏览器会进入统一身份登录；临时网络或服务故障会保留明确错误，请恢复后重试。
5. 退出登录会清除当前客户端会话；进行中的模型请求可能被中断。

桌面打开 Web 个人中心时，账号平台会用一次性交接建立与桌面当前账号一致的浏览器会话。如果浏览器此前登录了其他账号，应切换为桌面账号；Web 退出登录后不应继续恢复旧账号。若账号不一致，先在 Web 明确退出，再从桌面重新打开，并保存交接请求 ID 供排查，禁止复制或分享一次性交接地址。

### 2.2 个人充值

1. 在账号弹窗选择“充值”。
2. 选择充值商品和支付渠道。
3. 提交后展示支付二维码，并进入待支付状态。
4. 完成支付后保持页面打开，系统会轮询订单并刷新余额。
5. 若二维码过期或未完成支付，可继续支付、刷新余额或返回。未支付订单也可稍后在 Web 个人中心继续支付。

积分展示按 `10,000 microcredits = 1 积分` 换算。桌面余额、Web 余额和权益余额均显示整数，直接舍去小数部分；Web“模型用量”保留两位小数，避免少量真实消耗显示为 0。可用余额不等于可调用金额；模型调用会先创建预占，结算后按实际用量扣减。

### 2.3 选择和使用平台模型

1. 确认已登录平台账号，且账号钱包不是 `PROVISIONING` 或 `REPAIR_REQUIRED`。
2. 在聊天输入框打开模型选择器。
3. 在“品悟平台模型”中选择模型；桌面会按会话记录模型绑定。
4. 新会话可直接选择平台默认模型；已有会话切换模型会绑定到该会话。
5. 需要设置默认平台模型时，进入“设置 > 模型”，登录后从平台目录选择并设为默认。
6. 发送请求前确认上下文、模型可见性和余额。调用失败且提示余额/预占不足时，先充值或释放/等待预占结算。

本地独立模型、第三方直连模型和平台托管模型是不同来源。平台模型按平台钱包计费；本地模型不经过平台钱包。

#### 没有可用模型时

当客户端没有任何可用模型时，首页显示全屏、不透明的欢迎页，而不是覆盖在会话上的半透明弹层：

1. 主按钮“登录”在当前窗口进入登录/注册界面；登录成功后返回应用并加载平台模型。
2. 次按钮“使用本地/第三方模型”进入“设置 > 模型”，可配置本地服务或第三方 API。
3. 配置完成且至少有一个可用模型后，欢迎页自动退出。

内置账号平台模型属于只读来源，不能删除。用户添加的模型均可删除，包括最后一个；删除最后一个用户模型时，会同时清除失效的默认模型和会话活动模型，随后重新进入无模型欢迎页。

#### 余额不足提示

- 个人钱包在首次预占时不足：会话显示“余额不足”和“立即充值”，点击后进入应用内个人充值页。
- 组织钱包不足且当前成员有购买权限：显示组织余额不足，并提供组织额度购买入口。
- 组织成员获授额度不足：显示成员额度不足，提示联系组织管理员，不错误地引导成员给个人钱包充值。
- 请求已经完成、追加预占才不足：已产生的回答保留并按已有证据结算，界面提示继续使用前充值；不会把已完成回答改成失败，也不会遗留无法释放的新增预占。

#### Windows 关闭与托盘

Windows 主窗口右上角“关闭”在托盘已就绪时隐藏主窗口而不退出进程。左键单击托盘图标或选择“显示主窗口”可恢复；选择“退出应用”才会完全退出。辅助窗口仍按普通窗口关闭。若托盘初始化失败，主窗口保持正常退出行为，避免应用隐藏后无法恢复。

## 3. Web 个人中心

访问账号平台根路径 `/`。Web 菜单包括：额度与用量、订单与发票、我的组织、账号设置。内容按当前身份和权限显示。`/admin.html` 仅用于管理后台，不是个人中心入口。

### 3.1 额度与用量

#### 查看余额、权益和用量

1. 打开“额度与用量”。
2. 查看当前上下文的可用余额、预占余额、权益包摘要和用量记录。
3. 用量记录支持上一页/下一页；记录号取 turn ID 前 6 位，缺失时回退为用量请求号前 6 位，不再固定显示 `pinvou-t`。
4. 每条记录显示模型、时间、输入/输出/缓存 Token、两位小数积分，以及执行和结算状态。实际扣费大于 0 时不会显示“未产生消费”；仍在核对且没有可靠金额时显示“—”，不会伪装成 0。
5. 个人上下文中，允许取消的未完成用量记录会显示“取消用量”。确认后系统发起取消，结果以服务端状态为准；按钮无响应时不要连续点击，保存用量请求号后刷新详情。

#### 充值

1. 在“额度与用量”选择充值商品。
2. 选择支付渠道并创建充值订单。
3. 打开支付二维码完成支付。
4. 支付完成后刷新余额；未支付订单可继续支付。

#### 查看权益包

1. 打开权益区域。
2. 查看权益包名称、有效状态、剩余额度和有效期。名称按当前商品目录和当前语言实时解析；历史快照只在商品已不存在时作为回退，因此商品改名或切换语言后会同步更新。
3. 选择“查看全部”或单个权益包查看明细。

### 3.2 订单与发票

1. 打开“订单与发票”。
2. 查看充值订单号、商品、金额、渠道、状态和创建/更新时间。
3. 选择订单查看订单详情和支付/履约追踪。订单描述优先按当前商品目录和当前语言展示；商品已删除或无法解析时使用购买快照，保证历史订单仍可读。
4. 待支付订单可继续支付；关闭、失败或过期订单不能继续支付。
5. 发票区域显示当前支付渠道是否支持开票。如暂不支持，请联系平台运营确认线下处理方式。

### 3.3 我的组织

仅当账号在组织上下文中且有组织读取权限时显示。

#### 查看组织

1. 打开“我的组织”。
2. 组织树单独占一整行，成员区域在下一整行显示；组织模型策略作为独立卡片，与上方卡片保留间距。
3. 查看组织资料、成员、节点、模型策略、组织钱包和权益。
4. 页面内容受当前组织/节点权限约束。

#### 购买组织权益

1. 进入组织权益区域。
2. 选择商品和支付渠道。
3. 提交后完成扫码支付。
4. 支付成功后权益进入组织权益包。

#### 给成员分配额度

1. 进入组织权益或额度分配区域。
2. 选择成员、权益包和可用组件。
3. 填写分配额度，确认后提交。
4. 在额度授权列表中跟踪已分配额度。

成员在组织上下文调用模型时，系统同时校验组织钱包、成员授权和权益组件容量。授权成功后成员可以消费该额度；若仍提示 `MEMBER_QUOTA_INSUFFICIENT`，先核对授权是否有效、组件是否匹配当前模型、剩余额度是否足够，再由组织管理员调整，不要给成员个人钱包补账来绕过组织额度。

#### 撤销或回收额度

- 撤销：对正常授权执行“撤销”，剩余额度按服务端规则处理。
- 回收：对已注销账号遗留的授权执行“回收”。
- 操作前确认成员和授权 ID；操作会写入审计。

#### 创建组织节点

1. 进入组织节点区域。
2. 选择父节点。
3. 填写节点名称。
4. 提交后节点出现在组织结构中。

#### 邀请成员

1. 进入成员区域，选择“邀请成员”。
2. 选择目标类型：用户名或手机号。
3. 填写目标账号和有效期。
4. 提交后把邀请信息告知被邀请人。

被邀请人在 Web 个人中心“账号设置”的邀请区域接受邀请。接受后会按组织规则获得成员身份和角色。

#### 管理组织模型策略

1. 打开组织模型策略。
2. 查看模型是否允许组织成员使用。
3. 有管理权限时勾选或取消模型。
4. 保存策略。保存后仅影响后续请求，不改变已开始调用的结算。

### 3.4 账号设置

#### 查看资料

打开“账号设置”，查看用户名、手机号、账号状态、组织列表和当前上下文。

#### 切换个人/组织上下文

1. 在账号设置或身份卡中选择“切换身份”。
2. 选择个人或组织。
3. 确认后刷新页面。后续调用按新上下文计费和鉴权。

#### 修改用户名

1. 在资料卡选择修改用户名。
2. 系统可能要求重新认证。
3. 填写新用户名并提交。
4. 用户名全局唯一；成功后旧用户名不再用于登录标识。

成功后 Web 侧栏、账号设置和桌面账号卡应刷新为新用户名。若仅某一端仍显示旧值，重新打开账号卡或刷新页面；持续不一致时记录用户编码和修改时间排查缓存，不要再次改名“覆盖”旧值。

#### 修改手机号

1. 在资料卡选择修改手机号。
2. 完成重新认证。
3. 填写新手机号并获取短信验证码。
4. 完成滑块验证后提交验证码。
5. 成功后使用新手机号接收后续验证码。

#### 接受组织邀请

1. 在账号设置打开邀请区域。
2. 查看待接受邀请的组织、有效期和状态。
3. 选择接受。
4. 接受成功后切换到该组织上下文即可使用组织功能。

#### 申请账号注销

1. 打开“账号设置 > 账号注销”。
2. 阅读注销影响：账号进入关闭流程后，登录、模型调用、钱包和资料功能会逐步受限。
3. 按页面要求输入确认文本，例如 `CLOSE_MY_ACCOUNT`。
4. 提交注销申请后，页面显示确认要求、当前阶段、服务时限（SLA）和阻断原因。
5. 系统进入静默、资金清理、身份清理等阶段。存在未结算用量、未完成支付/退款、拒付/对账异常、组织所有者职责或最后一个平台超级管理员身份时，流程会阻塞并提示原因。
6. 注销是不可恢复流程；如仅想停用或换号，先联系管理员确认。

有余额或属于组织不等于一定禁止提交；系统按当前可证明的资金、治理和身份事实决定阶段与阻断项。后台未收到申请时，保存页面错误和请求 ID，先核对账号服务健康，不要反复输入确认文本。

## 4. 管理后台

访问 `/admin.html`。后台菜单按权限显示；只有读取权限时页面会显示只读。跨用户、资金、模型、审批和导出操作均写入审计。危险操作必须填写原因，部分操作还要求近期认证或双人审批。

### 4.1 平台总览

1. 打开“平台总览”。
2. 查看用户/组织、钱包、模型 Token、用量和系统健康摘要。
3. 选择卡片上的“查看详情”进入对应管理页。

### 4.2 用户管理

1. 打开“用户管理”。
2. 使用永久用户编码或用户名搜索用户。
3. 点击用户名进入独立的用户详情下钻页；详情地址包含 `section=users&user_id=<内部 UUID>`，可刷新、复制内部链接并使用浏览器返回，不再从右侧弹出个人信息窗口。这里的 `user_id` 是内部 UUID，不是以 `USR-` 开头的永久用户编码；日常定位仍应优先保存和使用永久用户编码，不能手工把永久编码填入 URL。
4. 在详情页查看账号状态、组织角色、钱包准备状态、资料和生命周期信息。
5. 有权限时可执行：
   - 启用/禁用账号；
   - 处理注册修复；
   - 处理资料变更修复；
   - 查看账号注销请求；
   - 对阻塞的注销执行受控修复。
6. 禁用、修复和注销相关操作必须填写原因。删除或身份清理前先核对资金和治理阻塞项。

### 4.3 角色与权限

#### 查看角色

1. 打开“角色与权限”。
2. 按名称、代码、权限代码、作用域或授予方式筛选。
3. 查看角色说明、作用域、权限清单和授权记录。

#### 新增授权

1. 选择“新增授权”。
2. 搜索并选择用户。
3. 选择作用域：个人、组织或组织节点。
4. 选择角色、开始时间和到期时间。
5. 填写授权原因。
6. 预览用户、角色、作用域、权限数量和有效期。
7. 确认授权。高风险授权可能要求重新登录。

#### 撤销授权

1. 在授权记录中选择“撤销”。
2. 确认影响。
3. 系统刷新权限缓存；被授权人的新请求按撤销后权限执行。

敏感数据导出角色不是普通长期授权。必须说明至少 10 字原因，完成近期认证，并设置不超过 24 小时的有效期。

### 4.4 组织管理

1. 打开“组织管理”。
2. 搜索组织，查看资料、所有者、成员、节点和状态。
3. 可执行的组织操作包括：创建组织、修改资料、启用/禁用、管理成员、管理节点、转移所有者和删除组织。
4. 删除组织前必须先禁用；系统会检查账户、资金、用量和治理域阻塞项。
5. 所有者转移、删除和成员变更都需要原因并写入审计。

### 4.5 账户与计费

1. 打开“账户与计费”。
2. 查询钱包、账本、应收、手工调账和用量预占。
3. 使用钱包 ID、所有者、来源类型、时间范围等过滤条件查询。
4. 查看钱包余额、账本分录、应收明细、预占和结算状态。
5. 有权限时可：
   - 发起手工调账；页面只生成审批申请，不直接入账。
   - 在“账户与计费”的 Hold/用量预占页卡释放异常 Hold；确认后预占不能继续结算。该动作不属于“支付与对账”。
   - 对异常账务发起财务修复申请。
6. 所有资金操作以账本和审批结果为准，不要通过金额倒推业务事实。

### 4.6 支付与对账

1. 打开“支付与对账”。
2. 查看支付订单、退款、支付流水、迟付复核、支付异常和渠道控制。
3. 使用订单号、交易号、案件号、渠道、时间和状态过滤。点击订单号打开只读“支付订单明细”，读取详情不要求账务写权限；明细包含付款/受益主体、支付、退款、拒付、关注状态、交易、权益和证据。
4. 常用处理：
   - 同步支付订单；
   - 对异常订单申请订单修复；
   - 对符合规则的整包退款发起退款；
   - 处理支付异常并选择结论；
   - 安排下次复核；
   - 对支付对账案件指派负责人、记录修复动作、解决或忽略；
   - 申请 Provider 或商品恢复。
5. 涉及资金的动作通常先进入审批中心；不要重复提交相同请求键。

订单明细提示“账务操作失败”时，先确认当前版本已包含只读详情修复，然后用订单号重新查询；不要为了查看详情申请写权限或发起财务修复。只有明细中的真实状态/金额与渠道证据不一致时，才进入异常或审批流程。

### 4.7 定价与商品

#### 当前在售目录

1. 打开“定价与商品”。
2. 主页面“当前在售充值包”只显示生命周期为 `ON_SALE` 的商品；支付渠道临时暂停不改变商品生命周期，渠道状态在支付控制中查看。
3. 查看计量单位、模型定价、商品积分、售价、渠道和展示顺序。
4. 选择“管理草稿与历史商品”查看 `DRAFT`、`ON_SALE`、`OFF_SALE` 和 `DELETED` 全生命周期记录，并按状态筛选。

#### 添加商品

1. 选择独立按钮“添加商品”，在弹窗中填写商品代码、简体中文/英文/日文名称、展示顺序、基础积分、赠送积分、有效期、SKU/BOM、价格和原因。
2. Provider、Adapter 版本、支付渠道和已有发票品名必须从服务端下发的选项中选择；没有可选值时先修复配置，不能把任意文本当成生产配置。
3. 页面只录入积分，不录入 `microcredit`。系统按 `总积分 × 10,000` 生成内部账本单位；OpenAPI 中的旧 `credit_microcredits` 仅为兼容字段，传入时必须与积分换算完全一致。
4. 选择准入类型：正式商品使用 `FORMAL`；测试商品只在隔离环境使用 `TEST_ONLY`。
5. 保存后商品为草稿。具有 `platform.products.publish` 的运营人员只能对当前草稿版本发起验证，不能自行录入或提交“已通过”证据；内部 verifier 会冻结目标快照、现场执行商品/支付/履约校验，并把不可变证据绑定到该版本。等待状态变为 `VERIFIED` 后才能上架；`FAILED`、`EXPIRED` 或 `REVOKED` 时查看脱敏原因并发起新的验证轮次，不能改写原证据。

#### 编辑、替换和生命周期

1. 从“管理草稿与历史商品”打开商品。
2. 从未发布的 `DRAFT` 可原位编辑；保存使用目录版本和映射草稿版本双重并发控制，编辑后旧准入证据失效，必须重新验证。
3. 已在售商品和曾发布后下架的商品不可直接改写历史。选择编辑时系统创建新的替代草稿和新商品 ID，并保留与原商品的关联。
4. 替代草稿不会自动上架，也不会自动下架旧商品。先验证并上架新商品，再根据切换计划下架旧商品。
5. 生命周期为 `DRAFT → ON_SALE → OFF_SALE → ON_SALE`；草稿或已下架商品可以逻辑删除。删除对操作员不可恢复，但历史订单和审计仍保留。
6. 上架、下架、删除和影响已有售卖关系的操作要求近期认证、原因、幂等键和预期版本；结果未知时按原键查询。

价格公式、计量单位和商品是不同版本域。商品调整不能改写已创建订单；模型价格变更前应核对历史公式版本，避免影响进行中的 Hold 和结算。

### 4.8 模型与 Token

当前环境可能只显示旧版 `Token Gateway`，也可能在“模型与 Token”分组下显示“模型管理”“Token 资源”“运行与用量”。具体形态由已部署制品、会话能力 Gate 和读取权限共同决定；代码中存在新版页面不代表目标环境已经部署或开启。命令按钮还受独立动作 Gate 和服务端命令 readiness 约束，不能从页面可见性推断命令已激活。

#### 模型目录

1. 打开“模型管理 > 模型目录”。
2. 搜索模型，查看状态、生命周期、协议、来源、上下文长度和健康摘要。
3. 保存模型草稿、发布模型、停用或移除模型。
4. 对需要影响的模型执行生命周期变更前，先查看影响预检。
5. 需要回滚目录时，选择来源目录版本并确认影响。

#### 协议、公式和价格

1. 在模型管理打开协议/公式区域。
2. 查看协议版本、计量单位和公式。
3. 创建协议或公式草稿。
4. 预览公式结果后发布。
5. 使用价格投影验证模型价格。

#### Token Account

1. 打开“Token 资源”。
2. 查询 Token Account、状态、健康、凭据和路由摘要。
3. 创建 Token Account 时先搜索所有者，不允许手输内部 UUID。
4. 配置稳定路由时先选择已发布模型和协议版本，再保存路由。
5. 查看路由健康、凭据摘要和审计。
6. 凭据验证或吊销按权限执行；吊销涉及高危审批时进入审批中心。

Token Account 列表根据服务端 readiness 使用以下三种模式：

- `SNAPSHOT`：授权版本有效且分页快照可用，显示完整的稳定快照分页，并开放筛选和翻页。
- `LEGACY_BOUNDED`：授权版本有效但分页快照未启用，最多只显示最近更新的 100 个 Token Account，不提供筛选和翻页；这不是完整清单。
- `BLOCKED`：授权版本无效，或分页控制状态读取失败，列表安全关闭并显示原因。

“账户创建待处理”比列表要求更严格：必须处于 `SNAPSHOT`、授权版本有效，并且服务端返回合法的命令治理状态。合法状态包括 epoch 为 0 的 `PRE_ACTIVATION`，以及 epoch 大于 0 的 `ACTIVE` 或 `SAFE_ROLLBACK`；治理状态读取失败或 state/epoch 组合非法时队列关闭。`PRE_ACTIVATION`/`SAFE_ROLLBACK` 允许读取和受控恢复队列，不等同于所有 Token 写命令均可执行；每个动作仍要遵守自身 Gate 和治理策略。

#### 账号创建恢复队列

1. 打开 Token 资源中的恢复队列。
2. 输入完整命令引用，筛选状态为 `MANUAL_REVIEW`、结果仍为 `PENDING` 的 `TOKEN_ACCOUNT_CREATE` 任务。
3. 列表和处理弹窗只展示命令引用、人工复核状态、恢复代次、更新时间和动作，不展示创建者、Billing receipt 或内部阻塞原因；这些事实由服务端在提交恢复动作时重新校验，并写入创建者/操作员审计。
4. 队列可见还要求模型与 Token 动作 Gate 已开启，操作者同时拥有 `platform.tokens.manage` 和 `platform.tokens.owner-candidates.read`；仅有 Token 读取权限不能处理恢复。
5. 只能选择“重新入队”或“取消创建”；重新入队会创建新的恢复轮次，服务端重新校验当前权限、所有者状态和 Billing receipt，不能跳过这些校验。
6. 提交后重新刷新状态；结果不明时以原命令引用为准，不要重复创建。

#### 运行与用量

1. 打开“运行与用量”。
2. 按权限查看“Provisioning”“用量请求”“异常核对”等页卡；单个数据源失败不影响其他视图。
3. Provisioning 中可查看尝试次数、SLA、失败阶段、路由/凭据证据和修复动作。只有失败或 `REPAIR_REQUIRED` 状态可执行人工修复；修复会创建新轮次，不会跳过安全校验。
4. 用量详情显示请求号、模型和版本、执行/交付/结算状态、Hold、Token Account、协议、Adapter、上游尝试、实际/最大积分、Token 统计、错误、时间和脱敏证据。
5. “重新核对现有证据”只在以下条件同时满足时出现：记录为 `SETTLEMENT_PENDING` 或 `REVIEW`；拥有 `platform.usage.reconcile.retry`；治理命令已启用且状态为 `ACTIVE`。
6. 填写 1–500 字原因后提交。该操作只重新读取已有用量、Hold 和结算证据，固定禁止再次调用模型，不会产生第二次模型费用。
7. 结果未知时保留原幂等键并刷新原记录，不要新建重试。记录不满足重新核对条件时等待自动核对；只有已经形成独立异常案件且对应财务修复命令已激活、冻结事实完整时，才从该案件或“审批中心 > 发起财务修复”进入相应流程。系统没有把任意用量记录“一键转审批”的通用入口，不得改数据库强行变更状态。

### 4.9 运维配置

#### 新注册用户赠送积分

1. 打开“运维配置 > 新注册用户赠送积分”。只读权限可查看；修改需要 `platform.registration-bonus.manage` 和近期认证。
2. 查看资格 readiness。只有 `READY` 才能启用：`PENDING` 表示历史资格仍可恢复，应等待或执行已批准的历史回填任务；`BLOCKED` 表示存在无法安全恢复的匿名历史注册，必须进入数据治理并明确处置，不能继续声称仅需回填；`UNAVAILABLE` 表示 Account readiness 服务、服务身份或网络不可用，应先恢复依赖，不能把它当作回填未完成。页面不能强制绕过任一状态。
3. 设置是否启用、赠送整数积分、有效天数（1–3650）和 10–500 字变更原因。
4. 保存使用配置修订号进行并发控制；提示冲突时刷新配置、核对他人修改后再保存。
5. 策略只影响保存后首次完成注册的手机号。手机号第一次完成注册时即消耗终身资格，即使当时策略关闭或赠送为 0；后续启用不会追赠，同一手机号注销后重新注册也不会再次赠送。
6. 赠送成功后，在用户权益中查看来源为 `REGISTRATION_BONUS` 的权益包和账本事实。

#### 策略验收建议

在隔离验收环境准备三个从未注册过的测试手机号：一个验证启用时首次赠送；一个在策略关闭或积分为 0 时完成首次注册，再启用后验证不追赠；一个先领取、按正常流程注销并重新注册，验证不重复领取。不得为验证策略而反复注册真实用户手机号。

### 4.10 审批中心

审批中心视图可能包括：我的申请、待我审批、执行与失败、审批策略目录、发起财务修复。具体视图和动作取决于已部署构建、会话 Gate、权限、授权版本及命令激活状态；当前实现状态中部分新审批/财务修复链仍可能为 `NOT_DEPLOYED` 或 `INACTIVE`。只读目录出现不代表可以发起或执行修复，未取得目标环境激活证据时不得按下面步骤提交。

#### 查询和处理申请

1. 打开“审批中心”。
2. 使用命令类型、目标、状态过滤。
3. 选择“查看”打开申请详情。
4. 按身份执行：
   - 申请人可提交草稿或撤回申请；
   - 审批人可批准或拒绝申请。
5. 提交动作必须填写至少 3 字理由。
6. 确认后系统不会自动重试。若返回结果不明，先刷新申请详情；不要重复提交。
7. 执行失败会显示失败阶段和原因；可在执行与失败视图跟踪。

#### 发起财务修复

1. 打开“审批中心 > 发起财务修复”。
2. 选择修复命令：
   - `LEDGER_REPAIR`：账本修复；
   - `RECEIVABLE_WRITE_OFF`：应收核销；
   - `PAYMENT_FINANCIAL_REPAIR`：支付财务修复；
   - `REFUND_EXCEPTION_REPAIR`：退款异常修复；
   - `CHARGEBACK_FINANCIAL_REPAIR`：拒付财务修复；
   - `RECONCILIATION_FINANCIAL_REPAIR`：对账财务修复；
   - `USAGE_SETTLEMENT_REPAIR`：用量结算修复。
3. 填写目标引用和命令所需字段。页面不会推算金额或账务事实。
4. 选择“读取冻结事实”。系统返回服务端冻结投影、临界版本和财务快照。
5. 核对投影中的目标、金额、版本和原因码。
6. 填写申请理由，长度 10–2000 字。
7. 填写请求键。同一目标修复应复用同一请求键，避免重复创建。
8. 提交审批草稿。之后在“我的申请”跟踪，或由审批人在“待我审批”处理。

常见失败：

- 无法读取冻结事实：命令未激活、目标不存在、版本不匹配或事实不满足前置条件。
- 控制已变化：重新读取冻结事实后再提交。
- 幂等冲突：查询原申请，不要更换随机请求键重试。

### 4.11 审计与导出

1. 打开“审计与导出”。
2. 按时间、动作、主体、对象或事件类型筛选审计事实。
3. 查看脱敏后的审计摘要和关联对象。
4. 需要导出时创建异步导出任务。
5. 填写导出原因；涉及敏感数据时必须完成近期认证并设置有效期。
6. 导出完成后下载并核对记录数。导出文件不得转发到非授权渠道。

### 4.12 系统与安全

1. 打开“系统与安全”。
2. 查看服务健康、事件转发、安全状态和运行摘要。
3. 有权限时可处理身份安全修复。
4. 高风险恢复只提供受控边界；必须核对当前状态、原因和审批链。
5. 系统异常时先保存截图/请求 ID，再联系平台运维，不要直接修改数据库。

### 4.13 偏好设置与短信服务

#### 页面偏好

1. 打开“偏好设置”。
2. 选择界面语言：简体中文、English 或日本語。
3. 语言偏好保存在当前浏览器。
4. 退出登录会结束后台会话；语言等浏览器偏好可能保留。

#### 短信发送配置

1. 需要 `platform.sms-config.read` 查看，`platform.sms-config.manage` 修改；修改还要求近期认证。
2. 先由运维在部署 Secret 中配置供应商访问密钥、端点和凭据 Profile。后台只管理非敏感配置，永远不显示或保存密钥、Token 和自定义秘密端点。
3. 页面用两个选择框分别选择短信 Provider 和凭据 Profile。Provider ID 为 `aliyun-managed`（托管阿里云）或 `http-generated`（通用 HTTP 生成式适配）；选择 Provider 后，再从该 Provider 的环境下发列表选择凭据 Profile，默认标识分别为 `aliyun-default` 或 `http-default`。Provider ID 不是凭据 Profile，实际可选项和配置状态均以环境下发为准。
4. 阿里云配置填写签名，以及注册、登录、修改手机号、重置密码四种用途的模板 ID。
5. 填写 10–500 字变更原因，启用并保存。没有可用 Profile 时禁止启用；修订冲突时刷新后重新核对。
6. 就绪状态为 `READY`、`DISABLED` 或 `PROFILE_UNAVAILABLE`。变更只影响之后新建的短信挑战；已经发出的验证码继续按创建时冻结的配置验证。
7. 在隔离验收环境用测试手机号分别触发注册、短信登录、修改手机号和重置密码，核对四种模板、发送结果和验证码校验。不要在后台填写真实密钥，也不要把生产短信 Profile 复制到开发环境。

## 5. 审核与高风险操作通则

### 5.1 标准审核流程

1. **定位对象**：使用永久对象编码、订单号、用量请求号或命令引用，不以用户名、展示名称或金额作为唯一依据。
2. **读取冻结事实**：页面提供“读取冻结事实”或影响预检时必须先执行，核对版本、金额、状态、证据来源和原因码。
3. **确认前置条件**：对象必须处于命令允许的状态；不满足时解决真实阻断项，不能改状态绕过。
4. **发起申请**：填写真实原因和稳定请求键。对同一对象重试时沿用原键。
5. **独立审批**：审批人核对业务申请、冻结事实和审计记录；申请人不能审批本人申请。
6. **跟踪执行**：批准不等于执行成功。在“执行与失败”查看最终阶段、结果和失败原因。
7. **结果未知**：停止新提交，使用原申请 ID、命令引用或幂等键恢复结果。

### 5.2 哪些操作通常需要审批

以当前审批策略目录为准，典型高风险动作包括账本修复、应收核销、支付/退款/拒付/对账财务修复、用量结算修复、部分凭据吊销和身份安全修复。普通只读查询、重新读取已有用量证据、未发布草稿编辑通常不进入财务审批，但仍可能要求近期认证和审计原因。

### 5.3 审核记录必须包含

- 环境、操作者、申请人和审批人；
- 目标永久编码、当前版本和原始请求/订单/用量引用；
- 触发异常的时间线和用户影响；
- 上游、账本、Hold、支付或身份侧的可验证证据；
- 选择该结论的理由、预期修复结果和回滚/补偿方式；
- 最终执行结果及审计事件引用。

不得把截图中的手机号、密钥、Cookie 或完整凭据复制到工单；必要的个人信息必须脱敏。

## 6. 异常前置条件、触发方法与审核入口

本章回答“页面为什么没有审核按钮”和“怎样得到可审核样本”。除明确写为正式操作外，触发步骤只能在隔离验收环境执行。

### 6.1 用量结算待核对

**页面前置条件**

- 用量状态为 `SETTLEMENT_PENDING` 或 `REVIEW`；
- 当前角色拥有 `platform.usage.reconcile.retry`；
- 用量核对命令开关已启用，治理状态为 `ACTIVE`；
- 记录保留了可重新读取的请求、Hold、结算或上游证据。

**隔离验收触发方法**

当前仓库没有面向运营人员的上游故障开关，也没有可按本手册启动的 UAT Stub；不得虚构 Stub 地址、通过代理截断真实请求或关闭 Provider 来造样本。确定性触发只存在于自动化测试夹具：

1. 在开发测试机进入 `account-platform/`，运行 `go test ./internal/token -run 'TestProxyStreamWithholdsDoneWhenUsageEvidenceIsMissing|TestProxyStreamMarksMissingTerminalForReconciliation|TestNonStreamingMissingUsagePersistsProviderEvidenceRecoveryState|TestProxyStreamReportsSettlementPendingWhenCommitFails'`。
2. 测试分别在进程内构造缺少 usage、缺少流终止事件、非流式缺少用量以及结算提交失败，并断言进入待核对/人工复核状态；它们不会生成可供共享 UAT 后台人工处理的持久数据。
3. 如需端到端人工验收，只能使用目标环境负责人已经提供并记录在该环境发布材料中的专用测试 Provider/Profile；当前仓库没有通用操作 Runbook。在没有该环境能力时，只审核生产或 UAT 自然产生的 `SETTLEMENT_PENDING`/`REVIEW` 记录。
4. 对已有记录，在后台打开“运行与用量 > 用量请求/异常核对”，保存请求 ID，确认已有证据可读后再执行“重新核对现有证据”。该命令不会再次调用模型。

自动核对会按策略重试；最长核对窗口达到 24 小时后会停止继续等待，并按已有事实结算或释放 Hold。生产环境只能处理自然产生的记录，不得断开生产上游或删除证据来造样本。

### 6.2 Token Account 创建待处理

**页面前置条件**

- 创建命令类型为 `TOKEN_ACCOUNT_CREATE`；
- Saga 状态为 `MANUAL_REVIEW`，命令结果仍为 `PENDING`；
- Token Account readiness 为 `SNAPSHOT`、授权版本有效，治理 state/epoch 是服务端接受的 `PRE_ACTIVATION`、`ACTIVE` 或 `SAFE_ROLLBACK` 组合；
- 模型与 Token 动作 Gate 已开启，操作者同时拥有 `platform.tokens.manage` 和 `platform.tokens.owner-candidates.read`。

**隔离验收触发方法**

当前仓库没有用于暂停 Billing receipt 的运营故障开关，也没有支持从页面主动制造 `MANUAL_REVIEW` 的工具。确定性触发属于自动化集成测试：

1. 准备仓库测试说明要求的隔离 PostgreSQL 环境，进入 `account-platform/`，运行 `go test ./internal/token -run TestTokenAccountProvisioningThreeServicePostgresIntegration`。
2. 测试夹具在隔离事务中覆盖 Token 预留、Billing 不可用/回执、重试、人工复核和不同操作员恢复语义；测试数据不应被当作 UAT 业务数据，也不能复制到生产。
3. 共享 UAT 没有已批准的依赖故障注入 profile 时，只处理系统自然形成的记录。记录进入 `MANUAL_REVIEW` 的服务端边界是最多 8 次尝试或 30 分钟 SLA，而不是运营人员手工改状态。
4. 先恢复真实依赖，再在“Token 资源 > 账户创建待处理”用完整命令引用查询；页面只核对引用与恢复代次，服务端在提交时重新校验当前权限、所有者和 Billing receipt。仅在确认不再创建时选择“取消”。

生产环境出现同类记录时先恢复真实依赖，再重新入队。直接把数据库状态改成 `MANUAL_REVIEW` 不会形成完整证据，不能用于验收。

### 6.3 Provisioning 失败或需要修复

**页面前置条件**：Provisioning 已处于失败或 `REPAIR_REQUIRED`，且当前用户有管理权限、操作开关开启并完成近期认证。

**隔离验收触发方法**

当前仓库没有用于强制凭据验证或路由探测失败的运营开关。状态机及人工修复请求边界可在开发测试机进入 `account-platform/` 后运行 `go test ./internal/token -run 'TestProvisioningBackoffIsBoundedAndDeterministic|TestProvisioningStatusUsesStableAdmissionErrors|TestAdminRepairProvisioningValidatesIdempotencyKeyAndUnicodeReason'` 验证；这些测试不生成共享 UAT 页面数据。人工页面验收只能使用目标环境已有的专用测试 Provider/Profile 产生的自然失败记录；恢复依赖后执行人工修复，确认新轮次成功且旧轮次仍可审计。

不要把无效生产凭据写入后台，也不要关闭真实 Provider 来制造修复任务。

### 6.4 支付、退款与对账异常

生产构建没有支付模拟器；以下场景只在开发/UAT Payment Simulator 中存在：

| 模拟场景 | 可形成的前置状态 | 审核重点 |
|---|---|---|
| `SUCCESS` | 正常支付完成 | 订单、交易和权益一致 |
| `FAIL` / `CANCEL` | 支付失败或取消 | 不发权益、不入成功账 |
| `TIMEOUT` | 长时间待支付/查询未决 | 查询恢复、超时关闭和重复提交 |
| `LATE_SUCCESS` | 订单过期后渠道成功 | 迟付复核、退款或受控履约结论 |
| `DROP_NOTIFY` | 渠道成功但回调丢失 | 主动查询最终收敛 |
| `DUPLICATE_NOTIFY` | 重复支付通知 | 幂等，不重复发权益 |
| `BAD_AMOUNT` / `BAD_CURRENCY` / `BAD_MERCHANT` / `BAD_SIGNATURE` | 渠道事实与订单不匹配 | 隔离异常、不得自动入账 |
| `REFUND_FAIL` | 退款失败 | 退款异常和后续修复证据 |

**隔离验收触发方法**

1. 按 [`ADR-007`](adr/ADR-007-payment-simulator.md) 和 [`deployment.md`](deployment.md) 确认环境明确部署了 Payment Simulator，商户、渠道和数据库均为测试配置；生产构建和生产 Helm 不提供该服务。
2. `SUCCESS` 可从桌面或 Web 正常创建小额测试订单完成。异常场景没有面向用户的页面选择器，也没有仓库通用 CLI；支付集成测试夹具必须以具备 `internal.payment-simulator.order.create` 的专用服务身份调用 Simulator 的 `POST /internal/v1/orders`，并在请求体传入受支持的 `scenario`。接口及权限定义以 `internal/paymentsim/service.go` 为准，不要用浏览器开发者工具修改请求。
3. 测试夹具必须同时走 Billing 的测试订单、签名回调和查询链路，不能只在 Simulator 数据库中单独造一条渠道订单，否则后台不会得到完整审核事实。
4. 保存订单号、渠道交易号、通知/查询时间线和请求 ID。
5. 在“支付与对账”打开订单明细，确认异常进入相应的迟付复核、退款异常、支付异常或对账案件。
6. 按页面读取冻结事实、选择结论；需要财务事实变更时从审批中心发起对应修复，而不是直接改订单状态。

生产部署会拒绝启用 Simulator。Simulator 支持上表中的支付、通知、金额/签名和退款场景，但没有拒付 API 或 `CHARGEBACK` 场景。拒付只能由支持该事实的真实 Provider 回传，或由专用自动化集成测试夹具验证；当前后台和共享 UAT 没有面向运营人员的拒付造数入口。生产异常类型可能包括 `CHARGEBACK`、`FORCED_REFUND`、`DUPLICATE_PAYMENT`、`LATE_PAYMENT_CONFLICT`、`REFUND_FAILURE`、`PAYMENT_FACT_CONFLICT` 和 `ILLEGAL_TRANSITION`，只能按各自真实渠道事实形成。

### 6.5 账号注销阻断

注销页面和后台详情会根据事实显示阻断项。可在隔离环境通过正常业务流程得到下列样本：

| 阻断 | 安全触发方法 | 解除方法 |
|---|---|---|
| `UNSETTLED_HOLD` | 发起一个保持中的测试模型请求，使其处于活动或核对中 | 等待正常结算；无结算可能时走受控 Hold 释放/用量修复 |
| `PAYMENT_PROCESSING` | 创建测试订单并保持 `CREATED`、`PENDING`、人工复核或关注状态 | 完成、关闭或按真实渠道事实复核订单 |
| `REFUND_UNRESOLVED` | 对测试订单发起退款并用 `REFUND_FAIL` 形成未成功退款 | 恢复渠道后重试或审批修复 |
| 对账/支付异常未解决 | 使用 Payment Simulator 支持的金额、币种、商户、签名、通知或晚到场景形成对应案件 | 审核案件并记录结论 |
| 拒付未解决 | 无运营造数入口；仅处理真实 Provider 事实，确定性验证使用专用自动化集成测试夹具 | 审核拒付案件并按冻结事实处理 |
| 组织所有者 | 使用测试用户创建组织并保持其为所有者 | 先转移所有者或按组织注销流程处理 |
| 最后一个超级管理员 | 在隔离环境仅保留该账号为最后一个有效超级管理员 | 先授予并验证另一个合格管理员，再处理原账号 |

提交 `CLOSE_MY_ACCOUNT` 后应看到当前阶段、SLA 和阻断原因。不要为了让注销通过而删除账本、订单、组织或审计事实。

### 6.6 商品准入待验证

1. 在隔离环境新增 `DRAFT` 商品，选择测试 Provider、Adapter、渠道和 `TEST_ONLY` 准入。
2. 不发起验证时尝试上架，页面应明确阻止并显示待验证状态。
3. 具有 `platform.products.publish` 的运营人员对当前版本发起 verify。运营人员不上传或编写“已通过”证据；内部 verifier 冻结目标快照，现场核验价格、渠道、支付、权益发放和退款闭环，并生成绑定该版本的不可变证据。
4. 等待后台显示 `VERIFIED`；若为 `FAILED`、`EXPIRED` 或 `REVOKED`，查看脱敏失败原因，修正配置后发起新验证轮次，不能编辑旧证据。
5. 再次上架并确认成功；随后编辑从未发布的草稿关键字段，确认旧验证因指纹变化而不可用并要求重新验证。

生产正式商品必须使用 `FORMAL` 证据；`TEST_ONLY` 不能作为生产上架凭证。

### 6.7 注册赠送资格和短信配置异常

- 注册赠送 readiness 为 `PENDING`：历史手机号资格仍可恢复，等待或执行已批准的历史回填任务，完成后重新读取 readiness。
- 注册赠送 readiness 为 `BLOCKED`：存在无法安全恢复的匿名历史注册；进入数据治理并形成明确处置结论，不能把它描述为普通回填等待，也不能通过后台忽略。
- 注册赠送 readiness 为 `UNAVAILABLE`：Account readiness 服务、服务身份、响应合同或网络不可用；先恢复服务和身份链路，再判断是否需要回填。
- 短信 `PROFILE_UNAVAILABLE`：部署 Secret 没有配置所选 Profile，或该环境未声明可用。由运维修复 Secret 并滚动服务后再启用。
- 已发验证码在配置变更后仍使用旧模板版本是正常行为；新建挑战才采用新配置。

### 6.8 “页面没有操作按钮”的排查顺序

1. 核对当前环境、账号和个人/组织上下文。
2. 核对读取权限和动作权限是否分别具备。
3. 完成近期认证并刷新页面。
4. 核对目标生命周期和版本是否满足命令前置条件。
5. 核对功能开关、命令开关、分页能力和治理状态是否激活。
6. 查看服务端返回的 readiness/blocked reason；不要把按钮缺失一律当作前端问题。

## 7. 通用规则与故障处理

### 7.1 权限不足

页面显示“权限不足”、按钮置灰或菜单缺失时，确认当前上下文正确后联系组织管理员或平台管理员。不要尝试直接调用接口绕过 UI。

### 7.2 重新认证

修改资料、敏感授权、PII 导出和部分高危操作要求近期认证。系统跳转重新登录后，会尽量返回原页面；完成认证后重新执行原操作。

### 7.3 结果未知

支付、审批、修复、注销等命令可能遇到网络或服务端结果未知。正确做法是：

1. 保存请求 ID、审批 ID 或幂等键。
2. 刷新详情或订单状态。
3. 等待短时间后再次查询。
4. 不要立即使用新幂等键重复提交。

### 7.4 分页快照过期

后台列表使用稳定游标。出现“快照过期”时，从第一页重新查询，不要重复点击下一页。

### 7.5 常见提示

| 提示 | 处理 |
|---|---|
| 钱包 `PROVISIONING` | 等待钱包初始化完成并刷新 |
| 钱包 `REPAIR_REQUIRED` | 联系平台运营处理 |
| 预占不足 | 充值、减少请求范围或等待既有 Hold 结算 |
| 权限不足 | 联系管理员授权 |
| 幂等键已存在 | 查询原命令结果，不要重放 |
| 审批控制已变化 | 重新读取冻结事实或刷新详情 |
| 导出需要近期认证 | 重新认证后再创建导出 |

## 8. 发布、更新与回滚

本手册不复制服务器地址、账号、密钥或临时命令。发布时以仓库内 Runbook 为唯一可执行来源：

- 全量部署：[`../deploy/runbooks/full-redeployment.md`](../deploy/runbooks/full-redeployment.md)
- Runbook 索引：[`../deploy/runbooks/README.md`](../deploy/runbooks/README.md)
- 部署架构与通用要求：[`deployment.md`](deployment.md)
- 备份恢复、切换回滚、事件投递、模型 Token 发布、New API 和 Keycloak 操作：从 Runbook 索引选择对应专题。

### 8.1 发布前

1. 确认代码提交、镜像或桌面制品版本和目标环境，禁止部署工作区未提交文件。
2. 阅读目标版本数据库迁移、配置新增项和兼容说明；先备份数据库与必要的配置事实。
3. 校验服务 Secret、短信 Profile、支付渠道、模型 Provider、OIDC 回调和外部域名，但不要把值写入文档、命令历史或日志。
4. 执行仓库规定的单元、契约、架构和前端构建检查。
5. 对需要历史回填的功能（例如手机号赠送资格）确认回填完成且 readiness 为 `READY`。
6. 明确回滚边界：数据库迁移是否可逆、旧服务是否兼容新 Schema、异步任务是否需要暂停。

### 8.2 发布中

1. 严格按全量部署 Runbook 的服务顺序执行迁移、后端、Portal/边缘和客户端发布。
2. 每一步记录版本、开始/结束时间、健康检查和操作者，不跳过迁移或就绪检查。
3. 遇到失败先停止后续步骤并保存日志；不要在未知状态下重复执行非幂等命令。
4. 桌面 OTA 只有在已生成、签名、发布并验证对应制品时才能声明完成；仅仓库版本号变化不代表 OTA 已上线。

### 8.3 发布后验收

至少完成：登录/注册/重置密码、桌面到 Web 账号交接、余额和两位小数用量显示、个人与组织模型调用、余额不足充值入口、充值支付、订单/权益名称多语言、组织额度消费、商品目录与编辑、用户详情下钻、Token 资源、用量核对权限、短信四用途、注册赠送、审批只读/写入分离、Windows 托盘和无模型欢迎页。

异常流程使用第 6 章的隔离触发方法验收；生产发布后只验证已有自然异常或只读 readiness，不主动造故障。

### 8.4 回滚

1. 达到 Runbook 回滚条件时停止写入扩散，保留审计、订单、账本和事件证据。
2. 按迁移兼容性选择应用回滚、配置回滚或数据库恢复，不能只回滚某个服务而忽略 Schema/事件版本。
3. 回滚后重新执行健康检查和关键业务冒烟，并核对在发布窗口内创建的订单、Hold、审批和异步任务。
4. 记录根因、影响范围和补偿事项；禁止通过删除异常记录制造“恢复成功”。

## 9. 安全要求

- 不要共享账号、密码、短信验证码、Cookie、令牌或导出文件。
- 资金、修复、删除、导出和授权操作必须填写真实业务原因。
- 管理页面不会显示完整凭据；不要尝试通过浏览器工具读取敏感数据。
- 导出文件包含业务事实和个人信息时，只能在授权设备和授权期限内使用。
- 发现账号异常、越权访问或数据泄露时，立即退出登录并联系平台管理员。

## 10. 版本验收清单

| 角色/模块 | 必验项 |
|---|---|
| 普通用户 | 注册字段保留、单一密码眼睛、登录/重置、用户名/手机号修改、Web 退出、桌面交接 |
| 桌面 | 无模型全屏入口、平台/本地模型、最后一个用户模型删除、余额不足充值链接、Windows 托盘 |
| 额度与用量 | 整数余额、两位小数用量、turn ID 前 6 位、执行/结算/消费状态一致、取消反馈 |
| 组织 | 组织树/成员分行、模型策略卡片间距、邀请、节点、组织额度分配与成员消费 |
| 商品 | 在售主列表、独立新增、权威选项、无微额度输入、草稿原位编辑、已发布替代草稿、准入验证 |
| 用户/导航 | 分组导航和面包屑、用户名下钻页、刷新/返回、权限隐藏和只读状态 |
| Token/用量 | Token Account 列表、创建恢复队列 readiness、Provisioning 修复、已有证据重新核对 |
| 运维配置 | 新用户赠送一次性资格、历史回填 readiness、短信非敏感配置与四用途验证 |
| 财务治理 | 订单详情只读、支付异常、冻结事实、双人审批、结果未知恢复、审计导出 |
| 发布运维 | 备份、迁移、健康检查、制品签名、发布后冒烟、回滚证据 |

验收记录必须写明环境、版本、账号角色、测试对象编码、预期/实际结果和证据链接；“页面能打开”不等于业务闭环通过。
