# 首次 Create 与已观察支付期限

PAY-18 的用户 `expires_at` 继续使用首次已验证 Create 的精确期限；没有期限时保留既有能力窗口和字段优先级。

同键恢复 Get 或 Sync 可以在首次 Create 外部调用返回前提交真实期限。首次 Create 在原钱包、订单锁内合并已接受、身份完整匹配的不可变 QUERY 证据中的期限，保留已观察外部支付与 PAY-39 归档上界；初始估计、无期限响应和未验证证据不能冒充真实期限。

恢复查询的 PENDING/CREATED 事实使用既有 QUERY/RECORDED 证据和去重接口，不增加状态转换。Sync 的 SUCCESS 期限观察与后续资金归并属于两个事务，前一事务用独立 `|deadline` 证据键记录期限；其 RECORDED 结果不代表已入账，原资金归并键和 MERGED 证据保留。若资金事务失败，完整匹配的该 SUCCESS 期限证据继续阻止未支付归档，不能因没有生成资金流水而忽略已观察的成功事实；不匹配的历史快照不能取得这一阻断权限。

旧证据缺少规范化身份或期限时不猜测、不补写。该修复不重建历史已丢失的上界，不改变回执、权限、支付或归档准入规则；真实支付仍只按原流水幂等归并。
