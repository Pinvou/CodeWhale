# 桌面草稿的模型确认

普通桌面草稿显式选择 Account Platform 或本地模型后，首次实质操作仍只创建一次会话；模型绑定确认前不公布活动会话，也不消费草稿。确认期间的其他发送等待同一个创建结果，不绕过指定模型使用默认模型。

确认成功后才迁移草稿、工作区及已有模式意图。模型拒绝时保留当前草稿、模型选择和重试归属；多个等待发送的文本累计回填，避免同批界面更新只显示最后一条。空会话清理仍是尽力执行，不新增自动重试、资金恢复或模型替换策略。

真正的新导航或新的草稿模型选择使旧确认结果失去公布权限；已选择模型且等待确认期间改选工作区、项目或目录链时，也中止已按旧绑定创建的结果，保留新选择供下一次明确操作使用，不自动重建。旧结果不覆盖新选择，也不删除已被新导航接管的会话。未公布会话的失败不创建新草稿 epoch。定向测试执行真实 sessions/settings/chat 桥接工厂并控制 IPC 时序；它不是完整 Tauri、真实模型或支付验收。

## Web 宿主的处理范围

Web 的分步物化路径等待绑定确认再公布活动会话。并发发送共用一次创建，并按顺序发出。模型拒绝时保留选择，累计回填同一草稿的文本。历史会话记录可能已被其他客户端接管，因此该路径保留已创建的空记录。新导航、模型改选或工作区模式变更会使旧结果失去公布权限。

已协商原子首轮的 Web 草稿在成功回包后公布活动会话，并迁移当前输入。显式选择本地模型时，宿主通过独立的协商命令持久化指定模型，再受理首轮。无效模型在建会话前拒绝。模型已绑定而首轮受理失败时，保留历史记录，避免误删可能已被接管的会话。较旧的原子宿主会提示升级并保留草稿。传输结果未知时保留发送状态。浏览器或宿主超时后的重试沿用原请求 ID 和选型。Account Platform 的模型绑定仍由既有宿主权限控制。

已协商原子首轮的 Web 新对话选择 Account Platform 模型时，界面明确提示当前选型限制，并保留草稿和附件。已明确拒绝的首轮可在重新选型后以新请求 ID 重试，并重新绑定当前模型及导航归属。结果尚未确定的重放继续使用原命令、全部参数和请求 ID。
