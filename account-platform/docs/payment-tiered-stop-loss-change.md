# 支付分级止损需求变更

> 状态：第三轮独立业务与安全审核通过
>
> 变更范围：支付异常隔离、商品级止损、Provider 临时熔断与持久止损、分层受控恢复
>
> 不变边界：商品目录生命周期、历史订单/资金/权益事实、双人恢复和 Break-glass 禁用边界

## 1. 变更背景

当前实现会在任一关联支付订单的 P0/P1 人工案件超过止损 SLA 后，同时关闭关联商品和整个 Provider 的新单开关。该策略会让一笔孤立订单异常扩大为全渠道不可售，无法区分订单、商品和 Provider 三种影响范围。

本次变更把止损判定调整为分级升级：单订单异常先隔离订单；证据表明异常已扩散到单一商品时暂停该商品；只有连续异常、跨商品共同异常、Provider 不可查询或达到失败率阈值时，才暂停 Provider 全部新单。

## 2. 不变原则与信任边界

1. 止损只影响新订单，不删除或改写商品目录、订单、回调、支付流水、权益、账本及审计事实。
2. 已创建订单继续接受查询、回调、对账、人工复核和幂等履约。
3. 任何止损事实都必须可归因、可审计、可幂等重放；商品和 Provider 恢复分别申请、分别审批，且仍须不同稳定用户完成双人审批。
4. Provider 业务拒绝、用户取消、参数校验失败及单笔商城原始 `FAILED` 不计入 Provider 可用性序列；未知资金状态仍按订单级人工复核处理。
5. 止损策略使用冻结的版本化快照。阈值任意方向调整，以及分类规则、分区键、业务拒绝白名单、故障签名、多样性/权重、主动探测信任或适用范围的新增、修改和停用，均须独立原子权限、近期认证、`expected_version`、幂等键和双人审批；修改只影响新评估，不改写既有评估事实。
6. 结果分类只能由版本化 Provider Adapter 和领域规则根据受信原始响应、网络错误或服务端探测生成。用户输入、申诉、人工自由标签和 Provider 可控描述字段不得直接成为计数样本；无法确定时归为 `UNCERTAIN_RESULT`。观察保存分类规则版本和脱敏原始证据摘要。
7. 自动止损只由持有精确工作负载权限的 Billing Worker 通过分层数据库安全定义函数执行；运行身份不得直接更新控制表，商品级命令在数据库层不得写 Provider 控制。

## 3. 分级止损模型

### 3.1 L1：订单隔离

出现支付事实冲突、非法状态跃迁、晚到支付冲突、重复支付、退款/拒付异常或对账差异时，系统立即把对应订单、支付流水或退款事实置于既有 `MANUAL_REVIEW/REVIEW_REQUIRED` 状态，并停止该订单自动履约或高风险推进。

单一订单案件本身不得修改 Provider 或商品的新单控制。案件是否被认领不改变订单隔离；案件解决后仅收敛该订单及其资金/权益事实，不自动恢复任何更高层控制。

### 3.2 L2：商品暂停

案件只有同时满足以下准入条件才可参与商品止损聚合：由受信领域规则标记 `stop_loss_scope_candidate=true` 和 `affects_new_orders=true`；能够绑定同一 Provider 版本、商品映射版本和稳定故障签名；且异常属于新单配置/准入/映射完整性、创建支付或查询支付状态的商品可归因故障。退款、拒付、用户争议、单用户资料问题及仅影响历史订单的异常默认不参与，除非受信证据证明其同样危及该商品的新订单。

满足准入条件后，出现任一情形时仅暂停对应 Provider 版本下的目标商品：

1. 滚动 10 分钟内，同一商品出现至少 2 个不同订单的开放 P0/P1 案件；
2. 单个 P0 案件的受信证据明确指向商品配置、SKU/BOM、金额、准入证据或映射完整性；
3. 关联商品的开放 P0/P1 案件超过止损 SLA；不满足准入条件的超时案件保持 L1 隔离，不因 SLA 超时扩大范围；
4. 商品当前准入证据过期或被追加式撤销。

商品暂停只写 `payment_product_controls`，目录仍保持 `ON_SALE`，列表返回 `PRODUCT_PAUSED`。单商品暂停不得顺带关闭 Provider；其他满足三层可售门禁的商品继续可购买。

### 3.3 临时分区熔断与 L3 Provider 持久暂停

既有 NFR-44 熔断器是按 `Provider/版本/能力动作/支付渠道/路由` 分区的短时调用保护，可半开探测并自动闭合；L3 是持久业务控制，只能双人恢复。熔断器拒绝的调用不形成健康样本，熔断器自动闭合不得打开 L3 或任何商品控制。

健康序列也必须按上述五元组分区。只有 `ORDER_CREATE`、`ORDER_QUERY/PAYMENT_STATUS_QUERY` 等新单关键能力可升级到 Provider 新单止损；退款、账单下载或其他非新单动作的故障只影响自身分区。单路由异常先触发该路由熔断；只有该路由是 Provider 唯一关键路径，或至少两个独立关键动作/路由出现共同故障证据时，才可升级到 L3。

在满足上述边界后，以下任一条件触发 Provider 持久暂停：

1. **连续基础设施异常**：滚动 5 分钟内同一关键分区最近 5 个可计数观察均为 `INFRASTRUCTURE_FAILURE` 或 `UNCERTAIN_RESULT`，中间没有 `SUCCESS`；5 个观察须覆盖至少 3 个不同逻辑订单，或来自至少 3 次受信主动探测；
2. **跨商品共同异常**：滚动 15 分钟内至少 2 个不同商品因案件驱动进入 L2，覆盖至少 3 个不同订单和 2 个不同付款主体，且受信证据具有相同 Provider 故障签名或存在独立 Provider 基础设施证据；
3. **Provider 不可查询**：进入既有 `PROVIDER_BLIND`，或 Provider 声明支持查询但查询关键分区连续 5 个可计数观察失败并满足第 1 项的多样性和路径条件；
4. **失败率阈值**：滚动 1 分钟内，同一关键分区至少有 20 个可用性样本，其中 `INFRASTRUCTURE_FAILURE` 与 `UNCERTAIN_RESULT` 合计占比不低于 50%，并覆盖至少 5 个不同逻辑订单或受信探测。单分区命中仍须满足唯一关键路径或跨独立关键路径条件。

每个外部逻辑尝试由 Billing 服务端生成稳定 `provider_attempt_id`；同一订单、动作和逻辑尝试的传输重试、查询重放、回调重放只产生一个健康样本。受信主动探测只能由不可被终端用户触发、持有 `internal.billing.provider-health.probe` 精确权限的专用工作负载创建，签发短时单用途探测意图并绑定 Provider、版本、分区、nonce、过期时间及 `provider_attempt_id`；消费后不可重放，普通服务身份和用户请求均不得伪装探测。用户触发查询必须合并和限频；同一订单或付款主体在任一窗口中的贡献设上限，不能单独满足多样性要求。`BUSINESS_REJECTION` 作为观察事实保存，但既不进入失败分子，也不进入可用性分母，且不重置连续失败；只有 `SUCCESS` 重置所在分区的连续失败序列。

Provider 暂停只写 `payment_provider_controls`，列表中的全部相关商品返回 `PROVIDER_PAUSED`。同一阈值穿越事实只能产生一次不可变评估；重复 Worker、并发异常和重复回调不得重复增加控制版本。

## 4. 评估、持久化与并发

1. Provider 调用采用两阶段本地事务，禁止持有数据库事务或锁等待网络：调用前事务先提交 `provider_attempt_id`、调用意图和 Outbox；提交后才调用 Provider；调用后第二个事务原子追加脱敏结果证据、健康观察和 Outbox。观察至少保存 Provider/版本、能力动作、渠道/路由、分类及规则版本、可选订单/商品/主体不可逆摘要、Billing `received_at`、稳定 `provider_attempt_id` 和原始证据摘要，不保存密钥、Token、完整供应商载荷或用户敏感字段。调用前崩溃可安全恢复意图；Provider 已受理但第二事务未提交形成 `OBSERVATION_GAP`，只能用原幂等键和只读查询收敛，高风险原请求不得自动重发；第二事务重复执行按 `provider_attempt_id` 幂等归并。
2. 新增版本化分级止损评估事实，保存评估级别、触发类型、半开窗口 `(window_start, window_end]`、冻结观察高水位、完整 observation/case ID 成员或不可变成员清单引用、样本数、失败数、连续失败数、多样性指标、故障签名、策略版本和控制动作快照。
3. 聚合只使用 Billing 数据库可信 `received_at`；Provider 时间仅作证据。评估唯一键至少绑定作用域、触发类型、策略版本、控制前版本和阈值穿越事实 ID。并发控制采用 Provider→商品→订单的固定加锁顺序和 `expected_version` CAS。
4. 人工案件通知仍可按一小时节流，但止损聚合是独立评估器：案件创建、严重级别/状态/归因变化及健康观察写入时触发，分钟 Worker 负责补偿扫描；不得依赖 `last_escalated_at`、`mitigation_at` 或 `stop_loss_evaluated_at` 才继续评估。
5. 订单隔离、商品暂停和 Provider 暂停分别使用稳定幂等键；控制状态已关闭时重复评估只复用或追加证据，不无意义递增控制版本。
6. 若观察 Outbox 或分区事实出现缺口，系统维护该五元组的 `OBSERVATION_GAP` 高水位，只失败关闭无法证明安全的对应动作和路由；若缺口覆盖唯一新单关键路径，则阻断该 Provider 新单。缺失样本不得作为成功、不得参与恢复，也不得把一次已成功的外部资金调用伪装成失败。

## 5. 分层恢复策略

1. 订单隔离只通过既有案件命令收敛，不需要 Provider 双人恢复。
2. 商品与 Provider 使用独立恢复命令和独立审批。Provider 恢复只写 Provider 控制，绝不修改商品控制；商品恢复只写明确目标商品，绝不修改 Provider 或其他商品控制。
3. Provider/商品恢复均冻结控制版本、当前开放阻断案件、策略版本、观察高水位、映射/准入版本和健康探测事实；执行前任何变化使审批失效。
4. Provider 恢复要求触发持久暂停的窗口已经结束、没有新的同类阈值命中、所有观察缺口关闭、只读现场探测成功，并由不同稳定用户申请和批准。临时熔断器自动恢复不满足或替代这些条件。
5. 商品恢复要求目标商品不存在开放阻断案件、准入和映射有效、没有新的 L2 阈值命中、相关 `OBSERVATION_GAP` 已关闭且最新受信现场探测成功；审批冻结并在执行时复核上述事实及版本。如果 Provider 仍暂停，商品恢复命令直接拒绝，不生成可在未来自动生效的恢复意图。Provider 恢复后必须重新提交并完成一次新的商品双人审批，成功后才打开商品。

## 6. 上线迁移

1. 上线前已经关闭、但缺少新分级评估证据的 Provider/商品控制保持失败关闭并标记 `LEGACY_UNCLASSIFIED`，不得由迁移或新聚合器自动重算、降级或开放。
2. 每个历史控制生成唯一迁移复核案件，冻结原控制版本和上线观察高水位；运营按新的 L1/L2/L3 准入与归因规则补证。确认只属订单或商品范围时，多余的 Provider 控制仍必须通过 Provider 双人恢复命令解除；独立商品控制继续保持关闭，直到其自身双人恢复完成。
3. 新聚合器只消费冻结上线高水位之后产生的新观察和案件变化；旧样本保留审计但不得重复触发新控制。

## 7. 用户与运营表现

1. 个人中心继续显示业务已上架商品：商品级暂停只禁用目标商品；Provider 暂停禁用该 Provider 下全部商品。
2. 用户只看到稳定本地化原因，不暴露案件、阈值、供应商原始错误或内部拓扑。
3. 后台控制页展示当前暂停层级、分区、触发类型、策略版本、窗口指标、多样性和来源证据摘要、观察缺口及控制版本，并分别提供商品恢复与 Provider 恢复申请。
4. 阈值策略页只对拥有独立权限的角色开放；弱化策略必须显示影响范围并走近期认证和双人审批，所有变更保留不可变审计事实。

## 8. 验收标准

1. 单笔订单 `FAILED/REVIEW_REQUIRED` 只隔离订单；案件超过 P1 止损 SLA 时，只有满足 L2 准入矩阵才暂停其商品，绝不直接关闭 Provider。
2. 同一商品两个不同订单在 10 分钟内形成符合准入条件的开放 P0/P1 时暂停该商品，其他商品仍可下单；退款、拒付或用户争议案件不因数量直接暂停新单。
3. 两个商品、三个订单和两个付款主体在 15 分钟内分别进入案件驱动 L2，但故障签名不同或无法归因 Provider 时不暂停 Provider；存在共同 Provider 故障证据时才暂停。
4. 同一关键分区 5 个去重失败且覆盖 3 个不同订单或受信探测时命中连续阈值；中间一次 `SUCCESS` 重置该分区，其他分区成功不重置，业务拒绝不进入序列。
5. 同一关键分区 1 分钟内 20 个可用性样本中至少 10 个失败且满足多样性时命中失败率阈值；19 个样本、低于 50%、重复尝试或业务拒绝填充分母均不触发。
6. 单个非唯一路由或退款动作故障只打开对应临时熔断；唯一关键路径、两个独立关键路径共同故障或 `PROVIDER_BLIND` 才触发 Provider 持久暂停。
7. SLA 通知刚升级不足一小时也不延迟止损评估；案件/观察变更实时触发，分钟补偿 Worker 在一个周期内收敛漏评。
8. 重复回调、重试、查询重放、并发案件和重复 Worker 不会扩大样本或重复递增控制版本；目录生命周期和既有订单收敛不受影响。
9. 分别在调用前提交前、Provider 已受理但结果事务未提交、结果事务重复执行时注入崩溃；不得持锁网络调用、不得生成第二个外部请求，gap 最终以原尝试查询收敛且观察最多一条。
10. 观察缺口只阻断受影响分区，缺失样本不能证明健康；外部成功事实不因本地观察写入失败被改写为失败。
11. Provider 暂停时商品恢复直接拒绝；Provider 恢复不打开任何商品，之后商品必须重新申请双人审批，并在 gap、现场探测、案件或版本变化时拒绝。
12. 自动工作负载、运营人员和策略修改者越权直写控制表均被拒绝；任一策略字段变更缺近期认证、双人审批、CAS 或幂等键时拒绝；普通用户不能生成或重放受信探测。
13. 历史关闭控制迁移为 `LEGACY_UNCLASSIFIED` 且保持关闭、各生成一次复核案件；新聚合器不消费上线高水位前旧样本，任何层级恢复仍须对应双人命令。
14. 当前云环境回归验证单订单异常不再导致全部充值套餐显示“支付渠道维护中”。
