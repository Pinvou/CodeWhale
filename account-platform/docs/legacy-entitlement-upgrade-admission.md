# Billing 016 前数据库升级准入

当前版本暂不支持从尚未应用原 `000016_entitlement_components` 的既存 Billing 数据库升级。迁移命令明确拒绝，保留原数据库、迁移账本、余额、预占和全部财务分录；不会自动修改期限、补账、退款或释放预占。应保留备份和原服务版本，等待明确支持的升级方案，不能删除迁移账本或改校验值绕过准入。

完整交付必须包含精确原016。只有原001–015前缀及其在006之后安装的精确原900001 outbox fence可以不携带016；任何017或后续交付漏掉016，都在任何数据库写入之前作为交付不完整明确拒绝，不能借“本次不含016”绕过存量准入。

真正空库可正常一次初始化到当前版本。仅有空迁移账本且无业务对象的空库也可初始化；已有业务对象但没有有效账本、已有任意历史迁移但尚无016，都属于不支持的存量。是否存在余额、余额是否为零以及最大迁移版本，都不能用于把存量库判为新库。

已应用原016的数据库继续现有升级流程，仅接受原名称和精确LF/CRLF SQL身份；迁移不会重跑016，不会推测或回改已记录的期限。曾修改原016、使旧权益可以没有到期时间的历史版本（包括已知旧修复分支）目前同样不受支持，明确拒绝而非兼容其数据模型。未知名称或校验值也拒绝。此策略不是恢复旧无期限权益语义。

准入在通用迁移准备和任何迁移写入之前持有同一迁移互斥锁，只读识别已装历史。拒绝时不会创建迁移账本、补装低版本迁移或改变任何业务表；额外锁只释放自身持有的一层。应用原16之后的数据仍按当前付款、权益、成员额度和未知用量合同处理，新PLAN和充值期限不变。

自动化验证使用真实隔离PostgreSQL和受限部署/业务角色。`TestLegacyEntitlementUpgradeAdmissionPostgres` 验证空库、原016两种换行、016前空余额/已消费/退款/REVIEW预占、无账本旧表、完整交付缺失016、已知旧改写016与未知身份，并完整比较拒绝前后的schema、ledger和业务事实；同时检验迁移锁在成功、拒绝、失败、取消和等待中的归属。原first-delivery升级回归改为从受支持的原016出发，016之前的拒绝由该专项用例覆盖。
