# 手机号验证码登录与首次建号

桌面端和 Web 普通登录默认展示短信入口。选择同意首次创建个人账号后，发送请求携带 `signup_consent_version=mobile-signup-v1`。Account 将同意版本绑定到本次 `LOGIN` 挑战，并使用现有滑块、发送和核验限流、短信模板和统一发送响应。未勾选时继续使用原有短信登录。近期认证页面沿用原有登录方式。

验证码正确后，Account 原子消费指定手机号的挑战，并重查发码时的身份绑定及代次。手机号换绑后需重新取码。已绑定的身份进入原登录授权流程。未绑定的手机号在检查资料变更及注册占用后建立独立持久预约，生成随机用户名。Account 在登记首次身份创建许可前先检查 Identity Adapter 对无密码建号的支持。账号提交继续使用注册 Saga，账务及赠送由原钱包任务处理。已有身份和业务用户必须匹配授权结果后才能建立会话。Provider 或数据库不可用时提示服务暂时不可用。Identity 结果待确认时不重复派发创建，用户可沿原注册流程操作或稍后使用新验证码，运营可通过注册修复队列核对。

同意版短信挑战要求 Keycloak 声明支持新的核验协议。最终会话授权在 Account 的同一读取快照中再次核对挑战、身份和安全代次。支持新协议的普通短信登录在验证前遇到供应商故障或超时时，沿用统一的验证码无效响应。旧 Keycloak 不会消费同意版挑战，现存普通短信挑战继续按旧协议核验。

Identity Adapter 明确证明创建未派发时，Account 在有界窗口内重试持久化证明并释放注册预约。证明未能保存或派发结果未得到确认时，恢复任务继续核对关联身份。运营通过现有注册核查流程处理持续未决的预约。

部署先应用 Account 迁移 `900027`。升级全部 Identity Adapter 副本并退流旧副本后再升级 Account。启用新流量前停止所有旧版 Account 注册恢复写入者，最后升级 Keycloak SPI、主题和桌面应用。迁移先于新应用，旧桌面应用发起的普通短信登录仍被接受。回退时暂停新建号并确认新增注册操作已收敛。应用回退保留 schema。数据库回退发现同意记录时明确拒绝。

发布验证覆盖真实 Keycloak 浏览器和桌面会话、首次注册及已有账号登录、未同意及错误验证码、两次并发提交、未就绪钱包限制、注册恢复、注销和换绑冲突、短信服务限流。真实环境使用受控测试号码和短信配额。
