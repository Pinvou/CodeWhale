# 公开手机号入口的持久准入

注册预检查和滑块生成先执行 Account PostgreSQL 持久准入，数据库不可用时失败关闭。两个入口共享全局 300 次/分钟、可信来源 30 次/10分钟；每个入口每手机号 10 次/10分钟。非法手机号合并至同一拒绝维度，客户端 device ID 不影响限额，手机号前缀和空白规范化不形成不同维度。来源由受信 peer 适配层提供，缺失来源使用共同 unknown 桶。

全部计数用数据库时钟、事务及共同 advisory lock 串行更新，多实例和进程重启不能重置额度。目标或来源超过限额仍消耗全局准入额度；全局用尽不新建任意来源或目标桶。429 复用既有 SMS 限流错误和 Retry-After。注册发送路径的内部预检查不重复消耗公开预检查配额，其短信发送准入继续生效。

迁移 000089 新增无业务引用的计数桶。全局分钟开始时清理过期桶，仅删除 quota counters，不删除验证码、短信、注册或审计数据。每次请求最多新增两个短期维度，10分钟 TTL 与全局额度把活跃桶保守限制至 6601 行；空闲期间桶不继续增长，下一次准入清除过期行。共享 NAT 来源和全局流量到达安全限额会收到冷却响应，发布前应以真实容量验收调整后续策略，不能静默取消保护。

滑块图采用独立随机底纹、独立遮挡像素与轻微变化的拼图像素，取消旧版 piece/3 与 hole 的确定对应，亦不再把 x 坐标编码在确定性渐变内。图片尺寸、透明掩码、拖动 offset 容差和两分钟单次使用合同保持。正常操作者可按可见缺口拖动，正确 offset 仍按服务端持久目标验证。

此措施降低直接像素反解能力；公开图片仍可被高级视觉识别程序求解，不能将滑块视为账号授权或完整反机器人边界。防滥用同时依赖持久准入、SMS 配额和验证码单次使用。测试包括旧直接颜色反解失效、接口在业务工作前拒绝、隔离 PostgreSQL 并发边界、重启和换来源、TTL 清理、随机 key 基数和正常滑块验证。数据库测试显式 opt-in，跳过不构成实际集成验证。
