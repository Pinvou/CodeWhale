# Billing F02 迁移的首装身份

#1632 中的 900004 `refund_dispatch_fencing` 与 900005 `payment_notification_provenance`，在传入载体包含这些迁移时，必须符合编译期登记的版本、名称、元数据 checksum 和规范化 Up/Down SQL 摘要。重算载体 checksum 不能替代登记身份；已登记的名称、摘要或 Up 原文不能移到其他版本。重复版本同样拒绝。

`billingschema.Ordered`（由 Up/DownOne 调用）及 `VerifyApplied` 在访问数据库前检查上述身份。CLI 的受保护域识别登记这两项名称和摘要，目录改名不会使原身份落入通用迁移路径。CLI 仍先连接并识别现有账本；这里的“访问数据库前”指领域 Go 入口，不宣称 CLI 不建立连接。

历史 SQL、执行顺序、已应用账本及其既有 SHA 校验保持原样，900004/900005 的 Down 继续明确拒绝回退。没有新增数据库迁移，不重写历史。规范化 LF/CRLF 的原文兼容性保留；这两个可选钉定自身不要求早期载体补齐尚未携带的迁移，也不承诺任意不完整 SQL 组合可执行。

该检查约束迁移载体和受信任编译产物的一致性，不替代发布产物签名、发布授权或数据库角色隔离；拥有修改并重编整个二进制权限的人仍处于其原信任边界。该修复不关闭整个 #1632。
