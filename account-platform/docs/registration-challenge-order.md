# Registration challenge and availability checks

Registration uses the existing SMS request as its availability gate: consume the one-time mobile/purpose-bound slider challenge, apply the existing PRECHECK source/target/global quota once, validate the opaque password reference and username/mobile availability, reserve the registration operation under the existing final uniqueness rules, then deliver SMS. A failed captcha cannot reach availability reads; any failed precheck or final reservation sends no SMS. The public development-only `/v1/auth/registration/precheck` route is removed from Account, Portal and the published signup contract.

The Identity password-policy endpoint remains necessary to prepare an opaque password handle without retaining raw passwords in Account or Keycloak session notes. That preparation does not query account availability. Account still performs authoritative reference and policy validation after consuming the slider, and repeats the original operation-bound validation before its registration reservation.

Creating a slider image applies the existing CAPTCHA quota but does not query registration availability. The unchanged captcha store binds the mobile, purpose, deadline and one-time status; it does not claim a source/device binding it never stored. Trusted source attribution still controls existing quotas and is recorded with the original device in the SMS challenge. Portal strips untrusted forwarding/authority and preserves only the existing exact proof/risk routes.

Keycloak and the native Account login clear the attempted slider proof after every SMS request outcome, including a duplicate identity, a rate rejection or an uncertain dependency response. Retry requires a new challenge. Valid opaque password references and non-secret fields remain available; an explicitly invalid/conflicting reference is discarded so the user must prepare a new reference before confirming again. The native password preparation command accepts only a password and returns only the opaque handle, policy version and optional expiry; username normalization and availability remain authoritative in Account Send/Register. Old native page generations cannot apply late completion/error state. Existing duplicate/password/rate error messages and final registration recovery semantics remain unchanged. This change does not add a captcha-proof protocol, alter quotas or migration identity, or claim real Keycloak/IdP deployment acceptance.
