# 回放留存清理

Token 的 `ReplayRetentionWorker` 在原周期内分别执行未知派发恢复和内容清理。清理失败报告固定代码 `REPLAY_RETENTION_CLEANUP_RETRY_PENDING`，不输出原始数据库错误、响应内容或客户标识；随后周期继续重试。该代码表示清理尚未完成，不能据此判断财务结果。

一次清理按未结算帧、已结算帧、未结算结果、已结算结果、幂等墓碑、留存案件六类推进。每类最多处理 100 条记录，使用独立事务或单条原子语句及 2 秒上下文预算。前序已提交类别不会因后续失败回滚；失败类别保留原事实，下一次调用继续。成功提交满批后，生产 worker 每隔 1 秒继续一个清理批次，至没有满批进度为止；未知派发恢复仍仅按原配置周期执行，旧自定义 repository 沿用原周期接口。清理失败后回到原周期重试，避免持续故障忙重试。每个案件最多级联删除一个独立 payload 行，但其 JSON 大小不受行数限制。

候选在 LIMIT 前排除有效留存案件，跳过其他事务锁定的 usage；随后在所持 usage 行锁下用新语句再次核对期限、状态及案件。创建留存案件也先锁定同一 usage，再复制加密内容。清理对用户匿名化锁采用非阻塞的共享尝试，避免持 usage 行锁反向等待匿名化的排他用户锁。事务预算同时限制内容行锁等后续等待。

未结算内容仍按各自首次持久化时钟清除，保留序号、身份及不可变事实；不会续期或复活响应。已结算流帧原 24 小时、结果原 30 天、墓碑原 90 天，以及未结算内容原 30 天和受控案件的到期/解除期限均不改变。墓碑删除与 usage 幂等键清空在同一事务内完成。清理不删除财务账本，不新增扣款、派发或未知结果终态。

`TestReplayRetentionBoundedCleanupPublicPostgres` 使用公开迁移、Token 运行角色及现有隔离数据库夹具。usage 初始状态由既有受控夹具建立，加密帧经真实 `AppendReplayEvent` 写入；这不代表真实上游请求或 Billing 扣款。测试覆盖单 usage 超批次、锁竞争后续进度、案件复制串行化、墓碑原子清除、案件与 payload 级联、事务等待失败后恢复。既有 `TestF05UnsettledContentRetention` 保留精确期限及不复活断言。

容量样本为单 usage 的 10,000 条 62 字节明文帧，记录自然规划器的 `EXPLAIN (ANALYZE, BUFFERS)` 与真实单周期耗时，不关闭顺序扫描或强制索引。行数上限不保证只扫描 100 行，排序和过滤仍可能读取更多数据；现有索引保持不变。该样本不代表生产分布、最大响应、长期积压、磁盘冷缓存或部署容量验收。正常周期和持续满批时的追赶能力应结合实际到达速率、积压与错误日志评估，不能据测试耗时宣称生产 SLA 已达标。
