# Billing 历史目录回退边界

公共 Billing `DownOne` 和迁移 CLI 对最高已安装版本为 035、036、037、042、046 或 051 的数据库，继续保留数据库并拒绝对应回退。应用版本回退不表示数据库可以执行这些 Down。

035、036、037、042 的原始 Down 发布固定商品映射或价格，无法证明恢复任意升级前的目录配置。046 和 051 的原始 Down 仅保留已修复事实；移除其迁移账本也不能证明完成逆变换。原迁移文件、名称和校验身份保持不变，公共守卫在执行 Down 和删除账本的同一事务内先拒绝，拒绝后数据、结构及账本均保留。

需要回退时，先核实实际最高版本、备份及应用兼容性，再采用经确认的保留数据库或向前恢复方案。不要删高版本账本伪造历史阶段，也不要绕过公共入口运行原始 Down。

定向回归 `TestBillingHistoricalCatalogRollbackPostgres` 使用独立 PostgreSQL、原始数值迁移及受限迁移角色，覆盖 035、036、037、051 的默认与自定义历史事实，并构建当前迁移 CLI 验证公共入口拒绝。它检查拒绝前后全部 public 表数据、结构和原账本一致；051 另检查真实修复的 pricing-space ETag。CI 的财务 schema 阶段强制命中该根及各历史版本、CLI 子例，缺失或跳过失败。这是隔离回归，不能代替留存业务数据库和部署恢复验收。
