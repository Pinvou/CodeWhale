# Billing 历史目录回退边界

公共 Billing `DownOne` 和迁移 CLI 对最高已安装版本为 035、036、037、042、046 或 051 的数据库，继续保留数据库并拒绝对应回退。应用版本回退不表示数据库可以执行这些 Down。

035、036、037、042 的原始 Down 发布固定商品映射或价格，无法证明恢复任意升级前的目录配置。046 和 051 的原始 Down 仅保留已修复事实；移除其迁移账本也不能证明完成逆变换。原迁移文件、名称和校验身份保持不变，公共守卫在执行 Down 和删除账本的同一事务内先拒绝，拒绝后数据、结构及账本均保留。

需要回退时，先核实实际最高版本、备份及应用兼容性，再采用经确认的保留数据库或向前恢复方案。不要删高版本账本伪造历史阶段，也不要绕过公共入口运行原始 Down。

定向回归 `TestBillingHistoricalCatalogRollbackPostgres` 使用独立 PostgreSQL、原始数值迁移及受限迁移角色，覆盖 035、036、037、051 的默认与自定义历史事实，并构建当前迁移 CLI 验证公共入口拒绝。它检查拒绝前后全部 public 表数据、结构和原账本一致；051 另检查真实修复的 pricing-space ETag。CI 的财务 schema 阶段强制命中该根及各历史版本、CLI 子例，缺失或跳过失败。这是隔离回归，不能代替留存业务数据库和部署恢复验收。

## 010、014、027 和 049 的状态保真

这些保护在对应版本为最高已安装迁移时生效。公共 `DownOne` 和迁移 CLI 先在原事务中核对状态。拒绝时保留原始迁移身份、账本、结构和数据。

| 版本 | 何时拒绝 |
| --- | --- |
| 010 | Up 覆盖了四个旧商品的启停事实，Down 固定启用。安装后的状态无法区分原默认配置与自定义停用，公共入口拒绝。 |
| 014 | 仍有 `MANUAL_REVIEW` 通知或修复记录。原 Down 会折叠通知结果并删除修复表。没有这些事实时可执行原回退。 |
| 027 | 存在可能承载旧退款状态的付款、已撤销权益、退款和保留记录、强制退款证据或退款暂停状态。原 Up 把旧退款终态折叠为支付成功，原 Down 会把撤销变成冻结并移除退款细节。没有这些事实时可执行原回退。 |
| 049 | 库中仍有支付订单。原 Up 清除受影响订单的付款指令，后续状态推进也可能隐藏其曾到期。只有订单表为空时才允许原回退。 |

`TestBillingHistoricalStateRollbackPostgres` 使用原数值迁移和受限角色，执行公共入口、当前 CLI 和原始回退对照，验证默认状态、自定义事实、拒绝无副作用及可保真空历史。财务 schema 门禁要求全部子例实际执行。现场恢复仍按站点备份及兼容性审批执行。

迁移 CLI 通过原迁移身份识别 Billing，目录别名也受同一入口约束。执行受支持的回退须使用完整官方迁移包。仅保留早期数值 SQL 的归档包会被现有 Billing 前置校验拒绝，归档包测试验证了该入口和数据保全边界。
