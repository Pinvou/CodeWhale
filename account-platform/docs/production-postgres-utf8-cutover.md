# 正式 PostgreSQL UTF8 保全迁移与切换

状态：需求、设计与三项任务拆分已独立审核通过；R1 实现与验证已完成，尚未修改生产数据库或启动影子集群。

R1 验证记录：两次全量合同测试均为 532 项、530 通过、0 失败、2 项按设计跳过；隔离 Linux 初始化 fixture
覆盖全新 UTF8 初始化、旧标记拒绝、错误 system identifier 拒绝、单库编码漂移拒绝及修复后恢复。首次隔离备份
恢复验证因辅助恢复容器不继承 `POSTGRES_USER` 而在健康检查失败，随后将编码检查改为由初始化和健康调用方
分别显式传入探测角色；同一备份 fixture 重跑后，加密全量与增量备份、WAL、PITR、错误密钥拒绝、恢复后
UTF8 健康检查均通过。独立审核确认随机 fixture 容器、网络和运行目录无残留，原九个正式依赖保持健康。

## 背景与决策

C4C3c2 初始化 Token Account 所有者上限时，原生函数因服务端编码不是 UTF8 返回 SQLSTATE `42601`。
现场确认当前正式集群的 `postgres`、五个业务数据库及两个模板库均为 `SQL_ASCII`、locale 为 `C`。
生产入口脚本继承 `LC_ALL=C`，同时 `POSTGRES_INITDB_ARGS` 只指定认证方式，导致初始化未明确选择 UTF8；
既有健康检查也没有验证数据库编码。

负责人批准采用“同版本并行 UTF8 影子集群 → 全量逻辑迁移 → 独立验证 → 受控切换 → 旧集群冷回退”方案。
不得直接修改 `pg_database`、绕过 Unicode/NFC 校验、覆盖原数据目录、把正式身份数据当测试数据丢弃，
也不得在结果未知时重跑失败的 cap 初始化请求。

## 需求

- 目标集群继续使用已冻结的 PostgreSQL 17.11 镜像，数据库编码固定为 `UTF8`，`LC_COLLATE=C`、
  `LC_CTYPE=C`，避免在修正编码时同时改变现有排序和比较语义。
- 初始化参数必须显式包含 `--encoding=UTF8 --locale=C`；入口、健康检查、初始化完成标记和部署检查器
均验证集群及全部数据库为 UTF8。模板库不是例外，发现 `SQL_ASCII` 或其他编码必须失败关闭。
- 保全现有正式 Account、Billing、Token、Keycloak、New API 和 postgres 数据库；保全全局角色、SCRAM
  verifier、角色属性/成员关系、数据库与对象所有者、ACL、函数、触发器、扩展、序列及 schema migration 账本。
  不重新生成 KMS、数据库、Keycloak 或工作负载身份材料。
- 迁移前验证所有现存文本值可由目标 UTF8 数据库接受。`SQL_ASCII` 不声明高位字节的真实编码，
  因此不能只检查 ASCII；目标恢复本身必须作为强制的全量编码验证，任一非法字节立即停止切换。
- 逻辑内容不得以明文普通文件写入宿主磁盘。现有加密 pgBackRest 备份用于恢复保障；逻辑迁移通过
  受控进程管道直接从旧集群导入影子集群，输出仅记录摘要、计数、退出状态和脱敏错误分类。
- 最终迁移前停止并核实所有 PostgreSQL 写入方，至少包括 Keycloak 及其工作负载身份组件；当前尚未启动的
  Account Platform/New API 业务容器保持未启动。停写后确认全部目标库不存在非迁移会话，再导出全局对象
  与各数据库。不同数据库快照不得在仍有写入者时被冒充为集群一致快照。
- 影子集群使用新的私有数据目录、容器身份、内部迁移网络和独立备份 stanza/repository，不发布宿主端口、
  不占用正式 `postgres` 网络别名、不覆盖旧数据目录和旧备份仓库。TLS 私钥和管理员材料只读挂载到准确消费者。
- 切换前必须证明源/目标逐库 schema、表与行摘要、序列、函数定义、扩展、所有者和 ACL 一致；全局角色、
  成员关系及排除明确引导角色后的密码摘要一致；Keycloak Realm、Client、用户、角色和工作负载身份均完整。
- 切换通过“等待在途备份完成并暂停旧备份任务/监控 → 停止旧 PostgreSQL → 将新集群接入原内部 data
  network 的 `postgres` 别名 → 使用原 HBA/TLS 与正式身份做只读连接 → 冷回退演练 → 再切回新集群 →
  恢复身份组件”的受控步骤完成。任一步结果不确定时先读实际容器、网络和数据库状态。
- 新集群首次正式写入前完成新的加密全量备份和实际恢复演练。旧集群容器停止、数据目录保持原样且不再写入，
  在业务总验收完成前作为冷回退保留；清理旧集群或旧备份必须另行审批。
- 切换验收期间不开放公网业务、不创建首个业务管理员、不启用 Token runtime。冷回退演练结束前只允许数据库
  只读探针；失败时停止新集群、恢复旧集群原网络身份并验证数据库健康。启动 Keycloak 或工作负载身份组件
  即视为新集群开始写入，此后回退须先冻结新写并单独决定数据保全策略；不得合并新旧集群的部分写入。

## 设计

### 初始化与门禁

生产 Compose 显式传入 `POSTGRES_INITDB_ARGS=--encoding=UTF8 --locale=C --auth-local=scram-sha-256
--auth-host=scram-sha-256`。`postgres-common.sh` 保留脚本执行所需的确定性 `LC_ALL=C`，编码不再依赖环境推导。
公共检查器静态核对初始化参数。一次性初始化脚本在写完成标记前核验 `postgres/template0/template1` 和
所有业务数据库编码均为 UTF8，并写入绑定 system identifier 的新 `v2-utf8` 完成标记；entrypoint 对已有
`PG_VERSION` 只接受这个新标记，不能把旧 `v1` 标记解释为合规。healthcheck 在服务启动后查询 `pg_database`
逐库验证编码，形成第二道运行门禁。迁移期间的旧源集群继续使用其已冻结旧配置运行，不能提前套用新入口。

### 数据保全与流式恢复

迁移工具固定源/目标容器 ID、镜像 ID、system identifier、数据目录 inode、网络 ID、TLS/管理员材料摘要和
实际数据库清单。先保存源集群新鲜加密备份，再创建全新的目标目录并启动隔离目标；目标必须为全新 UTF8
集群，system identifier 与源不同。工具通过内核管道执行以下内容，不在宿主保存明文 dump：

1. 从源输出受审的全局角色定义，导入目标；引导管理员已存在的预期冲突必须在执行器中精确识别，其他错误拒绝。
2. 目标数据库只从目标 `template0` 创建，显式 UTF8/locale C；不复制源 `template0/template1`。
3. 对 Account、Billing、Token、Keycloak、New API 和 postgres 逐库执行逻辑导出/恢复。源已全局停写，
   所以逐库快照共同代表同一静止业务状态；恢复通道的双方退出码均必须为 0。
4. 恢复后执行 `ANALYZE`，但统计信息不纳入业务事实等价摘要；所有可变统计值只作运行证据。

迁移执行器禁止 shell tracing、core dump、Docker Socket/数据库数据目录挂载到工具、明文命令行密码、宽泛网络、
自动删除源数据或 `--clean` 覆盖目标。错误只写固定码与 stderr 摘要；原始诊断在内存中按受审白名单分类。

### 等价验证与切换

源和目标均在零业务写入下生成两个层级的证据。等价比较按数据库、schema、对象和角色的逻辑名称归一化；
不把 OID、relfilenode、数据目录、system identifier、容器/mount/PID 及统计信息等预期不同的物理标识
误作相等条件。数据库编码从 SQL_ASCII 变为 UTF8、模板标记升级和新集群物理身份是明确且唯一允许的基础差异：

- 业务事实：逐表行数与规范行摘要、schema migration、序列当前位置、函数/触发器定义、扩展、所有者及 ACL；
- 集群身份：全角色属性/成员关系、SCRAM verifier 摘要、数据库属性、HBA/TLS及最小权限正反向连接结果。

任何源对象不能被目标 UTF8 接受、摘要不一致、额外/缺失对象、权限扩大、角色 LOGIN 状态变化、Keycloak
身份数量或引用不一致，均不得切换。目标独立加密备份恢复成功后才进入网络切换。冷回退演练完成前只允许
数据库健康、TLS/HBA、数据库身份和只读 SQL 探针；OIDC 获取/校验必须等新集群再次成为正式目标并明确越过
新写入边界后执行。其间不执行 cap、治理激活或其他正式业务写入。

旧数据目录、源容器 inspect、迁移前备份、目标恢复证据与网络切换回执完整保留。回退演练验证旧集群可重新接入
准确 `postgres` 别名且数据摘要仍等于迁移前；演练后再恢复新集群作为当前正式目标。不得同时让两个集群持有
相同正式网络别名或同时接受正式写入。

## 快速实施原则

当前业务容器和公网入口尚未启动。只读盘点确认六个可连接数据库合计约 65 MB，磁盘可用约 9.36 GB；
现有业务会话仅 Keycloak 4 条，另有盘点自身 1 条 postgres 会话，写入方仅限现有身份基础设施。
为缩短上线时间，不建立“试迁数据目标”和“最终数据目标”两套流程：fixture 只在临时非正式数据库验证迁移器，
服务器上只创建一个全新、唯一的最终 UTF8 影子集群；其空库身份经审核后，在一次停写窗口完成一次逻辑迁移。
不省略前后备份、UTF8 强校验、全量等价、独立审核、冷回退演练和真实身份验证。

## 任务拆分

### C4C3c2-R1：UTF8 初始化合同与运行门禁

- 更新 Compose、入口/初始化/健康脚本和部署检查器，显式 UTF8 + locale C。
- 增加全新初始化成功、SQL_ASCII 旧目录启动拒绝、任一业务库编码漂移 health 拒绝、参数缺失/重复/非法值测试。
- 此任务只修改仓库代码和文档，不接触现有正式集群；独立审核通过后单独提交。

### C4C3c2-R2：最终影子集群、流式迁移与受控切换

- 先只读盘点正式库对象、数据量、潜在非 UTF8 字节、写入方、磁盘与内存水位，确定流式管道和超时预算。
- 创建私有执行器：固定身份、前置加密备份、隔离 UTF8 最终目标、零明文落盘的全局/逐库迁移、精确状态回执。
- 使用非正式临时 fixture 覆盖非法 UTF8、导出失败、恢复失败、对象/ACL/密码摘要漂移及未知结果；独立代码审核。
- 审核通过后在 47 服务器只创建一个全新且空的最终影子集群；独立核验其 UTF8、唯一 system identifier、
  私有目录/网络、零业务对象及未占正式别名，再进入停写窗口。不得向已恢复对象重复导入或使用 `--clean`。
- 停止并固定所有实际写入方，确认源零会话；执行唯一一次正式流式迁移和完整源/目标等价核验。
- 等待旧集群在途备份完成后受控暂停其 backup job、定时器和监控，保留旧配置、仓库与回执供冷回退。
  为目标配置独立加密备份仓库，重新绑定新 container/system identifier/data directory 的 job、stanza、定时器
  和监控，完成首次全量备份与实际恢复验证；不覆盖或清理源备份。
- 独立现场审核通过后执行网络切换，只使用不产生业务写入的数据库 TLS/HBA/只读身份探针；随后在身份组件
  尚未启动时完成一次冷回退演练，再切回新集群并复核。确认新集群为正式目标后才启动 Keycloak 与工作负载
  身份并验证 OIDC。首次启动身份组件即视为目标已开始新写入；此后不得声称旧库可无损直接回退，若需回退必须
  先冻结新写入并单独决定反向保全或明确接受丢弃本窗口新事实。
- 本任务不启动 Account Platform/New API 业务，不执行 cap 或治理写入；证据审核通过后单独提交。

### C4C3c2-R3：恢复 cap=100 与后续治理

- 在 UTF8 正式集群重新执行 C4C3c2：新备份、quiescence、短暂 operator LOGIN、固定幂等语义的 cap=100、
  立即 NOLOGIN、readiness、三表精确差异、后置备份与独立审核。
- 原 SQL_ASCII 失败尝试没有业务提交；保留其回执，新的执行窗口使用新的唯一目录和清晰关联，不重写旧回执。
- R2 新基线中的容器 ID、system identifier、PID、数据目录/mount、网络、完成标记、角色 OID、HBA、TLS
  及备份设施绑定必须由新回执继承；所有旧集群绑定只保留为历史。cap/governance 执行器必须从新角色清单
  绑定实际 OID，不能继续使用旧集群硬编码 OID 或直接复用旧窗口完成回执。
- C4C3c2 完成并独立提交后，按既定 c3、c4 继续治理 ACTIVE 与运行身份启用。

每个任务均由原实施者实现、独立审核者复核，问题修复后重复审核，审核通过后独立签名提交。
全部部署任务完成后统一推送。当前总进度按新增关键路径重估为约 82%，不代表业务已上线。
