# F05 回放内容清理与轮换库存边界

未结算响应从首次持久化起保留 30 天，重复保存不续期；既有终态期限和受控案件留存继续采用各自原有规则。公开流式/响应内容清理后，空 `encrypted_payload` 行仍保留首次创建时钟、序号、原密钥标签、完整性摘要和财务元数据。这些字段是历史事实，轮换不能把空行重新加密为可回放内容，也不能用新摘要覆盖原证据。

普通轮换计数、扫描高水位和待处理查询使用一致的密文准入：流式事件及响应要求密文非空；已交接的 dispatch intent 没有 envelope 时不计密文库存。真实非空旧密文仍须轮换，暂不可解或损坏的真实密文仍计剩余，严格就绪门禁保持。内容清理与轮换并发时沿用原密文和关键字段 CAS，清理成功的内容不得被轮换复活。

受控案件将真实加密副本保存在 `usage_replay_case_payloads` 的 JSON 中，副本及原 key ID、AAD 所需字段和摘要按原案件期限、释放及清理规则保留。本轮不改这些规则、不搬迁或销毁案件副本。

`SecretRotationRemaining=0` 只说明普通五张表的待轮换密文库存归零，不证明整个数据库没有旧密文，也不授权停用或销毁案件所需的旧密钥。既有 Transit 运维工具要求 `min_decryption_version=1`、禁止删除数据密钥；授权 Token 轮换与数据密钥销毁不同。此处不新增数据密钥退役入口，不以轮换统计替代案件及密钥保管核查。

本地验证分别记录实际普通轮换、真实回放清理及受控案件保存的结果。使用当前 schema 的受控输入和测试密钥，不冒称外部 KMS、留存生产数据库、完整 E2E 或发布验收。
