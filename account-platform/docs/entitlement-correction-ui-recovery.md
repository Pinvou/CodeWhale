# Entitlement correction approval recovery

The administration page reads the owner projection through `POST /admin/v2/approval-command-prechecks`. It copies the closed policy v2 / snapshot v2 proof into an approval request; the browser does not derive amounts, component identities or wallet versions. The current `platform.billing.repairs.request` permission and recent authentication remain authoritative on the server. Activation remains a separate server prerequisite.

The page uses the established governed approval create/edit/submit protocol. A confirmed approval request is not evidence that the financial command executed. Subsequent review and execution belong to the approval center.

Recovery evidence lives in session storage, scoped to the authenticated actor and this operation. It contains the frozen proof, operator reason and original logical key, plus the original approval request ID and edit version when editing a draft. It contains no credentials. The local logical key is at most 111 ASCII characters because the existing draft builder adds `approval:` (9 characters); the public approval key limit remains 120. Exactly 120 public characters are accepted and 121 are rejected.

Persistence and readback must succeed before any write. An edit additionally saves its original CAS before the first PUT. A new client after authentication or a full page reload reuses that original CAS and input, even if the current request version increased. GET results alone are never a write acknowledgement. Unknown results survive subsequent 401, 403 and 409 responses; users must explicitly retry with current permission. Evidence from another actor is retained without replaying it. Corrupt, unwritable or inconsistent storage prevents sending; failure to clear evidence after a receipt blocks further commands. A late receipt cannot clear a newer key.

Use `npm run test:account-platform-entitlement-correction` for codec/storage contracts and `npm run test:account-platform-entitlement-correction-ui` for the production compiled browser path. Browser tests serve the actual Portal assets with controlled HTTP authorities; they do not constitute production deployment, real recent-authentication-provider or PostgreSQL financial execution evidence. The default closure operation contract is separately exercised by `npm run test:account-platform-closure-ui`.
