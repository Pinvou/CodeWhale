# 商品人工准入

本功能只为 `FORMAL` 商品提供两人核验闭环，并复用原件保管前置能力。上传原件或创建申请都不算投票；提交者可以明确投第一张 `APPROVE`，第二张 `APPROVE` 必须来自不同的实际用户。相同用户不能用不同会话或密钥计两票。

每次申请冻结商品完整发布快照、部署环境、原件摘要、原件版本和明确到期时间。投票前重新检查当前商品发布权限、近期认证、商品版本、摘要、原件未清理、到期时间和撤销状态；任何一项不一致都拒绝签发。`REJECT` 只终止本次申请并保留原件到既定留存期限，不产生正式准入证据。

第二张有效 `APPROVE` 在同一数据库事务中写入正式证据、核验状态、审计和回执。重复请求必须复用原幂等键和原事实；结果未知时先查询原回执，回执不存在不代表请求未执行。已完成的原请求不得通过改变商品版本、投票理由或请求 ID 再次改写。

现有自报告的 `FORMAL` 完成接口不再单独签发正式证据；只有实际保存两张不同用户的明确批准后，内部事务终结器才可完成签发。既有 `TEST_ONLY` 能力和历史导入证据仍按原契约运行。未提交或未完成的申请在其上传时声明的到期时间到达后标记失败并释放待处理槽位，不自动重发或延长期限。

新申请返回 `usable_for_publish`，表示当前摘要、期限和撤销检查均通过；它不要求已有当前绑定。首次发布仍由原商品发布入口执行完整版本、权限、支付渠道和撤销检查，不新增绕过门禁的接口。更新或续证不会自动解除既有安全暂停。

Portal 只转发这三个精确入口：创建申请、读取申请、提交决定。所有入口要求当前商品发布权限、15 分钟内重新认证、CSRF 和当前会话；响应不包含原始文件字节。原件上传和下载的 10 MiB 边界、`no-store`/`nosniff`、摘要校验和保留策略由前置 PR 负责。
