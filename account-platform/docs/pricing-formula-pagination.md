# Pricing formula selection across current Token response modes

The pricing lifecycle editor consumes published formula versions, not protocol IDs. The currently delivered pagination-disabled Token server still returns the `/admin/v1/protocols` aggregate; that capability remains supported. In snapshot mode, the client reads one `/admin/v1/formulas` page (`status=PUBLISHED`, limit50), without scanning protocol or formula continuations automatically.

In snapshot mode, operators explicitly request another page or filter by the existing exact protocol-code/formula-UUID `q` contract. The UI identifies the current result filter and continuation. Viewing another page retains the selected formula. Page errors retain displayed facts without declaring the failed result complete; retry keeps the same cursor/filter, and cursor expiry requires explicit restart. The PRE aggregate keeps its original complete data and selector; it does not acquire a client-side search/filter contract. No quota, TTL, deadline or backend endpoint changes are introduced.

Existing drafts outside the current page use exact UUID `q` lookup. Because a new same-resource snapshot replaces the previous cursor, a successful lookup becomes the displayed filter/page; a rejected lookup that already replaced that snapshot requires an explicit restart before further paging. All page loads, cached draft selection and exact draft lookup share one formula-resource generation and cancellation boundary. Only its latest intent may commit a page, editor authority, error or loading completion; writes and unknown-result recovery keep their existing invocation boundary. Editing requires one published matching ID/protocol, positive version and real unit-version UUIDs. Missing or incompatible authority fails closed. Permission denial invalidates selected authority and closes an ordinary editor. A current denial synchronously retires an undispatched draft preparation waiting on a price-space read; a subsequent successful catalogue refresh does not revive that preparation. This fence does not cancel a dispatched command or change its recovery credentials; unknown writes retain their frozen input/key. Parent components key the workspace by owner/session epoch. Contextual model pricing uses its supplied formula/model without catalogue requests.

The permanent Node contracts use real-handler DTO fixtures and controlled HTTP page/rate semantics. They cover bounded3001-formula selection under the existing60-per-subject/resource/minute policy, continuation/retry, PRE mode, lookup, errors, cancellation and session retirement. This is not execution of PostgreSQL rate SQL. Original v1 full-scan61st-query429 evidence remains preserved privately; the new contract does not call a partial page a complete catalogue.

The existing `test:account-platform-management-ui` npm task retains its management smoke and also compiles the production pricing workspace/client for real-browser regressions. Controlled delayed HTTP responses cover page-to-lookup and lookup-to-filter/restart/refresh, late success/403/410, and cached selection, including completions that ignore cancellation. Ready/MergeQueue frontend smoke selection already includes this task; the existing Draft browser-skip policy is unchanged. Private real-component/browser evidence additionally exercises selection, old drafts, exact integers, unknown-key recovery, permissions and page errors against controlled APIs. It is not real IdP/PG/Billing-effects or deployment E2E. The normal npm account-portal build regenerates necessary HTML/chunks; shared i18n changes also change its importing entry hashes. No unrelated source behavior is changed.
