# 注册补偿的 outbox 事实查询索引

对应 #1644 的注册事实检查。`compensationProof` 在持有注册操作行锁时，检查用户、身份、钱包创建任务和**任意事件类型**的 `outbox_events.aggregate_id` 引用。审批授权事件的部分唯一索引不能支持这个无 `event_type` 谓词的查询。

本片仅处理 #1644 的这一索引条目，其余条目继续跟踪，不据此关闭整单。

900020 增加非唯一 B-tree `outbox_events_aggregate_idx(aggregate_id)`，保留原查询、错误语义、所有旧索引、事件行及授权来源。不按超时、空分页或某一事件类型推断没有业务事实。

## 迁移与权限

沿用完整 Account 迁移载体、专用 `account_migrator` 登录及 `MIGRATION_ROLE=account_service`。新 SQL 校验既有 outbox 所有者，通过同一迁移事务临时授予该独立所有者 schema CREATE，建索引后立即收回；不增加运行服务的角色成员关系，不留持久 CREATE 权限。新 Up/Down 名称及 SQL 身份在 Account 公开迁移入口和域识别中钉定，既有 SQL 与账本摘要不变。

从源码 `account-platform` 目录，沿用受控 `DATABASE_URL` 和既有生产备份证据配置运行：

```powershell
$env:MIGRATION_ROLE = 'account_service'
go run ./cmd/migrate --dir ./migrations/account --direction up
```

普通 CREATE INDEX 在构建期间会阻塞 outbox 写入，应在维护窗口执行并核对可用空间和业务积压；它不是并发建索引或生产时延承诺。本片没有更改 relay 的至少一次投递及 generation 围栏。

仅当实际待回滚头确认为本 900020、载体及索引身份匹配时，公开 `--direction down` 才会移除本索引和对应账本行。Down 不删除事件，不修改 ACL。历史 900015 等保护仍保持原拒绝语义；测试明确选取其目标版本，不能用索引删除成功替代历史回滚验收。旧应用/旧迁移载体与后续其他补充版本的站点组合应按实际安装记录另行核验。

索引往返验收使用保留原 SQL 字节的 900020 版本切片；随后通过公开入口升级到主线 900022，校验索引与新增清单合同并存、900022 的前向限制仍拒绝回退，再校验完整当前载体。后续迁移已安装时，不删除其账本或绕过守卫来制造 900020 为最高版本。

## 验证口径

隔离 PostgreSQL 使用真实公开迁移及运行/迁移/审批写方角色。分别覆盖首次安装、非空前一载体升级、实际 migrate CLI 的运行账号拒绝与专用迁移账号 Up/Down、旧事件/账本/所有者/ACL/触发器保全。运行账号安装失败时临时授权必须一起回滚。

历史负载为十万条受控合成的已发布记录，形状来自原注册写方样本；注册和受保护审批样本分别由原 Bootstrap/审批授权写方产生。外部身份、Token 激活和快照来源为已有受控夹具，不能当作真实供应商或完整现场端到端。

在同一数据集上以真实 Down/Up 仅切换新索引，保存匹配注册、匹配审批、不匹配、晚写入历史引用四种查询的 EXPLAIN/BUFFERS。实际 `compensationProof` 在 SERIALIZABLE 事务中执行：用 outbox 表锁固定其已取得注册行锁的位置，观察第二事务确实等待同一行，再释放屏障，记录后续完成/等待时间。时间包含数据库往返、屏障释放和调度，不能解释为完整注销/身份清理 SLA，也不承诺每个单样本都更快。

本文描述本片机制与验收范围，不代表 v3、远端 CI、合并或现场发布已经通过。
