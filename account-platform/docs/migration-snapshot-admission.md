# 迁移准入与快照识别

本说明记录当前迁移命令的实际校验和已知拒绝条件，不是全部历史版本的支持矩阵，也不新增“所有开发中间快照均已退役”的政策。已经承诺支持的历史库仍须完成对应兼容和验证，不能用本文代替。

## 交付包与已应用账本

通用运行器按版本读取已应用 Up 的 SHA-256；仅接受与当前 SQL 内容相同的 LF 或 CRLF 表示。文件名中的版本与名称冲突由包加载器拒绝。通用账本校验并非普遍逐行比较历史名称；领域包装器还会对特定身份、安装集合、角色和数据前置条件另行检查。

修改清单不能使旧库兼容。不得删除、改号或手改迁移账本来绕过拒绝，也不得重写已执行的 SQL。一次升级按版本提交事务；后面拒绝不表示此前版本全部自动回滚。受限回滚与前向升级须分别判断，不能把 Down 的限制当成 Up 校验失败。

## 部署核验与证据边界

升级前应固定目标服务和迁移包，使用已有受控只读方式取得实际账本和必要 schema 事实，按版本、摘要和领域准入逐项核对，并保留备份及原服务版本。发现未识别或未排演的保留历史时，先保全数据、制品与证据，完成其支持边界和隔离升级验证；不要直接执行回滚、清库或改账本。

迁移清单守卫只证明当前包的文件和摘要一致，不证明所有 SQL 语义、旧库升级、新装角色、备份、部署或回滚均通过。某次只读核查中的一条 87 记录，也不能证明同库其他版本、其他部署或备份的身份。以上拒绝条件是源码可核查事实；本文没有执行实际部署升级，不把当前拒绝自动解释为允许撤销已有支持承诺。
