# 配对注册的公平准入

`PairingStore` 在生成连接码、派生摘要和密封回包前校验注册专属预算，并在同一状态
所有者内串行执行分配及持久化。CAS 冲突后重新读取并校验预算，不以旧快照发布结果。
默认生产拒绝启动门禁、认证、通用 WebSocket 入站限制及 claim 侧三层保护均保持。

默认限制：

| 资源 | 限制 |
| --- | --- |
| 同端点保留的注册回执 | 32 |
| 全局注册回执或配对墓碑 | 各 4096 |
| 同端点每分钟新注册 | 8 |
| 全局每分钟新注册 | 256 |
| 新注册准入时的配对命名空间 JSON | 4 MiB，预留一次分配的 16 KiB 余量 |
| 等待或执行中的不同注册 | 全局64、同端点2 |

字节预算可先于记录数上限触发，不承诺一定能容纳4096条记录。共享状态所有者仍执行
其原有默认16 MiB总上限。认证端点不能独占等待队列，队列错误和正常完成均释放其名额。
预算拒绝只返回既有 `controller_busy`，不返回剩余配额、密钥或内部错误详情。
这是准入拒绝，不分配连接码或创建终态回执；预算释放后可显式重试原ID。
生命周期撤销、终态收口和安全回收继续按原状态所有者规则执行，不用注册配额阻止清理。

稳定 `registration_request_id` 的已确认同参数重投直接读取原结果，不生成新码、不
续期、不扣新名额；仅变更 transport `request_id` 时回包关联新ID。相同在途请求合并，
不同参数或 Relay epoch 继续执行原有冲突/过期拒绝。入队时冻结请求副本，等待期间
调用者不能改变端点或材料。构造参数 `registrationBudget` 仅是可信所有者配置/测试
接口，不从客户端消息读取；它校验整数、端点/全局公平关系和硬字节上限。

配额来自既有持久化回执和墓碑，不新增状态格式或清除旧数据。成功和确定生成失败
均计入既有隔离保留窗口（至少10分钟，终态保留按原规则处理）；5分钟码有效期到期
并不释放隔离名额。生成失败和不可密封
的包装公钥产生既有有界 `pairing_code_generation_failed` 回执，重投不再反复执行
密封，也不保存原始异常或明文码。重启重新读取相同记录计数；保留记录的未来时间
在时钟回拨时仍占窗口。受 reservation 所有者保护的墓碑继续占用全局记录和字节
预算，其生命周期和端点交互槽规则不变。

分配已经执行但未确认发布的持久化失败，也占当前进程的有界频率窗口，防止在存储
故障下反复执行密封。已发布结果仍只计一次，已确认重投仍直接读取。未发布尝试不
占持久化记录名额；其内存计数仅在当前进程有效，窗口到期释放，进程重启后不保留。
已持久化回执的计数则继续跨重启有效；生产状态所有者自己的故障停机规则不被绕过。

验证应区分内存CAS/JSON重载模型、真实文件/锁/CAS重开与完整Relay进程。Windows
路由文件测试沿用既有ACL替身边界，不证明原生ACL。小配额故障注入能验证公平性与
拒绝前零分配，不能宣称已经完成攻击规模压测。
