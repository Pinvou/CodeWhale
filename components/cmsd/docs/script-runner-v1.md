# 首次启用脚本的进度与进程边界

本机脚本运行器仅用于容器卡的首次`enable.sh`。标准安装仍委托既有模型商店，
这里没有新增模型安装器或扩大脚本权限。已运行的幂等启用和systemd原生模型执行方式保持。

## 实际问题与修复

旧运行器复用HTTP的LF读行器，tqdm一类CR刷新进度累计超过8KiB就会被当作超长行。
原脚本并没有单条超长记录，失败来自错误的记录边界。

现在脚本专用读取器分别识别CR、LF和CRLF，跨缓冲区保留UTF8，EOF前没有换行的尾段也保留。
每条记录仍不超过8KiB；真正无限长记录或非法UTF8明确失败，128条有界泵通道和有界任务历史
保持。HTTP协议解析没有改为接受CR进度。中英日文/混合分隔符由2字节缓冲测试验证。

旧代码还把两根输出管道关闭当成子进程已经退出，直接`child.wait()`，从而绕过监督循环。
真实OS子进程单元基线中，标记内部取消后仍等2.897秒自然退出；修后EOF只是输出通道状态，
尚活跃的子进程每100ms轮询，继续应用取消检查、10分钟无输出与6小时绝对期限，不忙循环。
私有测试使用200ms预算证明关闭管道仍受总期限约束，生产默认期限没有缩短。

根脚本已退出、孙进程继承管道时，发现退出后最多给5秒读取余量，之后清理**该脚本独立进程组**，
避免泵线程/FD和未登记辅助进程永久遗留；root/sleep真实子进程测试验证回收。不会按名称杀模型
或其他任务，已注册的Docker/systemd模型由原生命周期控制。

公开v1取消接口目前仍只接受install。上述内部取消测试不等于新增了enable取消入口，也不代表
可以取消已执行的默认选择/换胎。商店取消/部分文件保留与模型管理授权语义没有改变。

## 验证

Rust 测试覆盖混合分隔符、分段 UTF-8、超长记录、关闭输出后的内部取消与总期限，以及继承管道的孙进程回收。
这些 OS 进程测试验证脚本监督边界；真实引擎首次创建、推理和长期运行仍需单独验收。
