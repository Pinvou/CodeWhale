# 统一预算恢复与有界执行（2026-10-18）

本批修复两个单机风险：后端自行重启绕过资源预算，以及慢连接/畸形输入/CLI挂起耗尽管理进程。
保留 v1 API，未提供 v2 组事务或平台写授权。

## 恢复由 cmsd 准入

明确托管对象的恢复意图保存在私有 `recovery/{card}.json`。显式 enable 登记意图，
disable/purge 在对外执行停止前先持久撤意图。默认切换由已有持久任务与补偿流程推进，
LLM 在换胎期间可以缺席。关闭 Pinvou 不撤掉已接受的任务或意图。

- 容器使用 `restart=no`；原生实例使用独立 drop-in `Restart=no` 并撤开机自动拉起。
  共享模板与外部对象的原策略不因发现而改变。`linked` 单元不等于开机启用，保留安装链接。
- 旧明确托管记录启动时核实真实策略再迁移。后端查询失败留下待核实迁移记录，不将未知当未安装。
- cmsd 守护每10秒核对恢复对象。异常退出、主机重启后的恢复复用同一生命周期排他、
  组件门、卸载门、内存预算、就绪检查和任务结果。后端失联不回退脚本。
- 自动尝试5分钟内最多3次，按5/10/20秒退避。超限持久熔断，核查后显式 enable 恢复。
  重启 daemon 不清尝试或熔断记录。运行时实体消失时给出商店修复入口，不自动重跑安装。
- 同次启动期间检测到管理面外的正常停止，撤恢复意图；异常退出保持意图。
  恢复查询前后校验生命周期代次，用户操作发生后舍弃旧查询结果。

`/v1/models` 明确托管行的 `boot_enabled` 表示 cmsd 恢复意图；`restart_policy` 仍是
Docker事实，另返回 `recovery_owner=cmsd` 和恢复记录。前端不能将 `restart=no` 等同于
未启用 cmsd 恢复。仅发现资源仍报告其原后端事实。

首次容器创建的可信商店脚本通过任务私有 CLI 适配器执行：run/create 出生即无独立重启，
start/restart 先撤后端自启；核对声明容器，单服务 compose 校验展开配置并覆盖 restart。
不支持的动作/多服务配方明确失败。适配器不是任意脚本沙箱；不接受跳过它的自定义首装方式。
原持有 daemon 的 boot/PID/启动时钟失效后，延迟脚本不能再通过适配器执行 Docker。

## 预算依据

启动、恢复、切换预检共用权重加运行时保守下限。全机可用内存差会混入其他进程变化，
实测值只能提高下限。容器静态预留还取该下限的较大值，拒绝非有限或越界比例。
原生卡的已支持 W4A4 环境字面量传入 systemd，避免丢失卡片运行档。

GB10 的主预算继续使用 `/proc/meminfo` 的 MemAvailable，并保留安全边际。
实机观测中 CUDA空闲量与系统可用量差异很大；NVIDIA官方说明 UMA 的 CUDA读数可能低估
可分配内存，建议结合系统可回收情况，不能只凭 CUDA 空闲量判定。
来源：[DGX Spark统一内存指引](https://docs.nvidia.com/dgx/dgx-spark/known-issues.html)。
不将 SwapFree 直接加入可用量。本批未更改系统缓存或内核参数。

权重与固定开销仍是保守估计，特定上下文、KV、vision、并行配方须按对应 RuntimeProfile
单独标定。单机通过不证明任意模型/任意参数均有准确峰值预算；多机 Reservation 仍待实现。

## 资源上限与故障行为

| 项目 | 本批行为 |
|---|---|
| 管理连接 | 64，超额503；内核SO_PEERCRED认证 |
| 推理网关连接 | 独立64，超额503；SSE管理流最多16 |
| 接收管理/网关请求 | 单次读3秒，总接收10秒；网关转发仍保留流式长响应 |
| HTTP | 先限制行长再分配；拒绝重复/冲突长度、异常chunk、过长trailer |
| HTTP正文 | 管理入口64KiB；网关/客户端读取单次16MiB。全进程小正文池4MiB、大正文池16MiB，分配前准入、chunk增量计费、离开请求/响应释放；大上传不耗小请求配额 |
| JSON | 最多64层；网关最多65,536个值；一般解析1,000,000个值以兼容有界持久历史。严格数字、控制字符、代理对、重复键/UTF-8校验 |
| Docker/systemd查询 | 10秒，变更150秒；stdout8MiB、stderr256KiB；超时清理CLI进程组 |
| 首装脚本输出 | 同步有界队列128，单行8KiB，持续输出也受绝对时限约束 |
| 持久历史 | 最多100终态任务、每任务500事件；事件文本512字节、结果4KiB，省略有标记 |
| 状态库 | 私有文件、fsync+原子替换，64MiB上限；损坏/不可读拒绝启动并保留原文件 |

CLI超时仅证明本地CLI已终止，外部后端的动作结果须重新核实。查询错误保留事实，不改判为停止。
组件/模型维护、恢复意图和逻辑开机偏好的控制收据使用 no-follow、nonblocking 的有界文件读取，
检查文件描述符对应的普通文件及账号归属；目录链接或读取异常不能投影为空状态。
原生恢复的 owned drop-in 由两条既有 fence 路径共用文件助手，保留两种已知完整 `Restart=no`
内容及现存合法读取权限；外来内容、特殊文件和链接需先核查，不能因读取失败自动改写。
缺失时以独立临时文件原子发布，不复用可能指向其他文件的固定临时名。

正文超限返回 413，共享正文池繁忙返回 503；不以失败或半个请求创建模型任务。
JSON 网关在转发前检查 UTF-8 与结构数量，单次解析复用模型名和别名改写结果。
二进制 multipart 仍按原代理路径透传。

## 验证

Rust 单元测试覆盖预算、恢复持久化、后端查询错误、请求和正文池上限、JSON 边界及进程超时。
`tests/real_startup_boundaries.py` 和 `tests/real_gateway_listener.py` 使用独立状态及端口验证真实进程边界。
`tests/real_store_adoption.py` 需要现有 CPU 镜像和权重，验证收编前后推理、幂等启用、重启和短时运行。
这些结果需绑定本次制品摘要；历史开发制品的性能记录不能替代当前代码验收。
