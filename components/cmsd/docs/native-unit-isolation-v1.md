# 原生模型服务的实例隔离

2026-10-19 多安装方式实测发现：不同 cmsd 状态目录原先共用并覆盖用户的 `megacube-model@.service`，导致已有服务后续启停可能读取另一实例的 env。独立 PID、socket 和网关不足以隔离这一风险。测试发现后已备份现场并恢复原服务模板的配置绑定，没有停止原模型；此前制品不作为本轮最终验收件。

新安装显式写入 `native_unit_namespace = "state"`。模板和模型单位分别为 `megacube-model-<状态路径摘要>@.service` 与 `megacube-model-<摘要>@<card>.service`。摘要由最终 env 绝对路径的 SHA256 前16位产生。发现、日志、启停、维护预留和重启恢复均使用同一前缀，只对账本实例单位。Pinvou 新装组件使用此配置；模板必须写入真实 systemd 用户搜索目录，不能仅写入组件私有 units 子目录。

既有未声明配置默认 legacy，保留名称及兼容性；不自动迁移正在运行的服务。模板采用原子无覆盖创建：存在且完整内容匹配才复用，外来、损坏或软链均保留并拒绝原生控制。只读设备/容器管理可继续，错误通过任务和服务日志展示。不会用启动 cmsd 重新写入其他实例的模板。

首次正常启动原子持久化 `state/native-unit-namespace-v1`。完整状态备份必须包含此文件；配置命名空间变化、摘要不匹配、损坏或已有原生管理记录却缺少 scoped 锚点时，启动拒绝。不得删除锚点解锁、手工改 state_dir 或将旧原生记录复制进新命名空间；已有服务迁移须单独安排停止、完整备份及核验。故障文件保留供恢复。

`cmsd --component-info` 声明 `native_unit_namespace: 1`。Pinvou 对 scoped 配置选用的组件在停止旧服务前核查此能力；旧包被拒绝。新配置也使不支持此键的旧解析器在打开状态前失败，不能通过组件回退悄悄绑定回共享模板。清单格式和 /v1 协议保持兼容；此字段是二进制能力声明，不是发布签名。

回退程序版本时保持当前身份、权限、任务、恢复意图和命名空间锚点，使用支持当前配置的匹配候选。不能回滚权威状态来迁就旧程序。无模型管理记录的全新环境可重新初始化；已激活环境使用正常组件维护，不使用工厂回退。

单元回归覆盖两个状态目录同一卡名不同单位、同实例名称稳定、legacy 模板完整保留、冲突和链接拒绝、锚点缺失/损坏/配置变化拒绝。实际二进制、用户 systemd 和推理验证需绑定对应源码及制品。
