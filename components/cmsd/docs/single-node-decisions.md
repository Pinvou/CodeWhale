# Cube Manage Software 单机领域决策

本说明记录后台设计理由、状态所有权与故障边界。[单机部署与恢复](single-node.md) 提供操作步骤，本文不复制完整 API 字段。跨仓闭环见 Pinvou 仓库的 `docs/megacube-single-node-decisions.md`；各主题合同仍是具体协议依据。

## 支持范围与名称

可读名称为 **Cube Manage Software**，后台技术标识为 `cmsd`（c = Cube、m = Manage、s = Software、d = daemon）。本单机版本尚未发布，不添加旧品牌兼容别名。Pinvou 联动限定同一非 root Linux 账号的用户级服务；独立 standalone system 模式保留，不能将 root 后台与桌面用户商店的跨账号访问称为已支持。用户服务不自动配置 linger，关闭桌面与退出登录/整机启动是不同运行条件。

只提供本机 Unix `/v1` 管理与回环推理网关。设备 ID 标识本地状态，不是远程可信身份。本批没有远程配对、Plan/Grant/Operation、组执行或平台授权；发现不支持的远程/计划状态格式时保留原件并拒绝启动，不以删除授权或回滚状态完成软件降级。

## 决策及替代方案

| 决策 | 正向依据与理由 | 未采用方案及其代价 |
|---|---|---|
| 标准安装委托独立 Pinvou 商店 host | 复用原下载/部署语义、目录与幂等记录，关闭 UI 不丢执行者 | daemon 内第二套安装器会产生重复任务、两套 current 与难以恢复的副作用 |
| 商店 current 是普通操作唯一选择 | logical/physical、版本、部署修订来自同一权威清单，支持完整手动回退 | 扫描最新目录、选最大版本号或回落旧权重会绕过商店的发布与验证 |
| 发现与管理权分离 | 原生/容器实际身份和明确启用构成托管证明 | 健康、同名或“看见进程即接管”会把外部服务变成可停止对象 |
| cmsd 持久恢复意图统一准入 | 自动恢复复用生命周期、维护门、预算与身份检查 | Docker/systemd 独立自启会绕过同一可用内存预算；外部对象仍保留原策略 |
| 逻辑开机偏好独立于物理部署 | 用户对逻辑模型的选择跨版本保留，旧版本撤下自启 | 复制旧物理实例运行意图可能复活归档；简单丢偏好会使手动回退失去自启设置 |
| 先持久受理，后发送副作用 | 断线后按原任务/商店 run 查询，可区分未核实与失败 | 超时即重装、not_found 即重发不能证明旧请求未受理 |
| 维护以持久门和私有 owner 贯穿双方 | 保护停服务、卸载脚本、注销和清理全过程 | 查一次“无任务”再操作存在接单竞态；PID 退出即解门会丢掉未完成文件操作 |
| 软件回退只替换兼容程序和登记 | 当前权限、任务、恢复意图、生命周期版本和命名空间继续有效 | 覆盖旧状态快照会回放旧权威；删除新标记会使旧程序绕过新合同 |
| 有界输入、查询和历史 | 管理连接、正文池、CLI、脚本输出和日志均有预算，错误可观察 | 无界扫描、慢后端持 Store 锁、截断后当空结果会拖住控制面或制造假事实 |

## 对象身份与当前部署

`managed` 是已取得的生命周期权限；`can_adopt` 是声明卡可以经明确 enable 接管；`can_reserve_uninstall` 是清理预留能力，三者不能互换。仅观察、实验登记、健康、预算足够均不授予停止、默认或自动恢复权。旧状态仅在存在明确启用证据时保留管理关系。

普通 enable、set-default、switch、恢复与网关路由按商店权威 current 核实同一部署修订。历史、ready、失败下载及归档目录退出普通候选；保存墓碑防止历史记录删除后重新发现。用户在商店完整恢复目标卡片、脚本、附属资源、权重路径和部署配置并原子发布 current 后，cmsd 接受新的 current。另一张当前有效模型可以是换模失败的程序恢复目标，归档历史不能自动充当回滚候选。见[当前部署与历史归档](latest-installed-model-v1.md)。

容器证明采用同次 inspect 的镜像、权重挂载 source、已知配置和回环端口可达声明；原生证明组合引擎 inode、UID、权重、真实 unit/收编 Binding、PID 代际、监听者、准确 model ID 及完整受管档位参数。相同 HTTP 名称、端口或容器 ID 不能单独证明部署。停止保留原有托管对象证明，卡片删除不妨碍安全停止，外来同名对象继续拒绝。任意脚本中未建模参数仍需人工核对。

已知商店容器缺失而需首次运行 enable.sh 时，使用 current 固定的 `models_root`；不从默认设置、旧副本或权重子路径猜根。未知或变化时在脚本前拒绝、保留资源，恢复原路径/挂载或匹配完整商店记录后重试。已有容器和原生启动不重跑首建。current_not_deployed 只保留一致的清理身份，不能启用或设默认。

新安装使用 state 命名空间，模板与实际单元按最终状态/env 路径生成稳定摘要，避免两个隔离实例覆盖同一模板。已有 legacy 配置不自动迁移运行实例；模板采用无覆盖创建、完整内容复用和持久命名空间锚点。原生日志沿实际 Binding 的真实 unit，停止后可保存私有诊断来源；该来源不授予生命周期权限。详见[实例隔离](native-unit-isolation-v1.md)。

## 资源与恢复意图

明确托管对象撤后端独立 restart/开机策略，由 cmsd 的持久 recovery 与逻辑 boot 偏好控制。显式停止在执行后端动作前先撤意图；按生命周期代次对账，用户操作后舍弃旧查询。外部正常停止、异常退出与后端失联分别处理；不能把查询错误当停止，也不能把 restart=no 当 cmsd 未开启恢复。重启 daemon 不清除退避/熔断历史，运行实体缺失提供修复入口，不自动重跑安装。

容量、显式启动、换模预检、恢复与降级复核使用同一预算函数。需求取声明预留、有效实测与权重加运行时下限的较大值，另留系统边际。无效预留明确拒绝，较小测量不降低声明；配方或档位变化后旧标定不直接沿用。统一内存以 MemAvailable 为主要依据，不加入 SwapFree，不单用 CUDA 空闲量保证分配。静态预算是保守准入，不能等同满上下文/并发峰值保证。见[预算恢复](recovery-and-robustness-v1.md)和[原生预算](native-profile-budget-v1.md)。

网关管理可达、监听成功、上游健康与真实推理是四个事实。绑定失败保留本机管理，重试相同配置地址，不停止占用方或暗换端口。转发保留长响应/SSE；上游发送和接收采用各自空闲超时，不声明整个推理绝对墙钟期限。请求正文预算持有到响应结束，用于资源上限，不承诺大请求等待时间。Pinvou 状态卡尚未完整展示新增监听事实，详见[网关可用性](gateway-availability-v1.md)。

## 任务、取消与维护清理

任务准入在同一 Store 锁下检查冲突、维护门与持久生命周期版本；成功受理前先写版本、任务和必要关联，再创建 worker/发商店请求。版本可能有空隙，不是成功任务数，也不是硬件防回滚。标记损坏、缺失或设备不符时围栏新变更，事实读取和组件救援保留，原任务可按合同收尾。身份读取锁竞争仅使当前请求返回可重试的 `identity_busy`，不持久围栏或消耗版本；启动初始化竞争则在恢复和接单前退出，沿既有启动失败合同重试。见[生命周期版本](lifecycle-revision-v1.md)。

商店标准重试固定原 run、原 download/install_local 类型、存储上下文及审阅摘要。连接失败、回执不匹配、临时 GET404 与 unknown 都保留原关联和排他；只有具备持久幂等关联的重试可退避重投。旧普通安装不因恢复自动重发。取消先持久化，恢复时继续转发原 run，真正终态由匹配回执决定。download 成功不表示已部署，install_local 成功也不表示已启用。见[安装重试](install-retry-v1.md)。

列表和事件有界，索引遗漏不能证明任务不存在。消费端应按已受理 ID 继续查询；Pinvou 对最近 20 条外的原 switch 使用有限串行轮转，并保留未知。单任务详情、商店查询状态及有界事件分页分别反映来源；不能把失败列表改为空列表或把接单当完成。

组件维护与模型生命周期互斥，普通停止/更新不自动取消现有任务。模型维护覆盖 daemon、商店脚本和文件清理，私有 owner 绑定真实 peer UID，不作为普通 MCP 参数或日志输出。清理预留只允许已核实停止/不存在且无独立自启的资源；带 owner 的 purge 只撤登记，不删除权重。普通无 owner 的旧 purge 语义不能冒充“保留权重卸载”。

后端慢查询在全局锁外执行，回锁后核对完整持久前置条件，变化则拒绝并要求重查。解除门前检查原任务、真实运行时、独立自启和商店脚本已终结。超时、进程退出或 daemon 重启不自动解除持久门；脚本中断不自动重跑删除。路径、共享引用、权限或归属未知时保留数据和错误。见[模型维护](model-maintenance-v1.md)与[组件维护](component-maintenance-v1.md)。

## 组件、配置与故障证据

Pinvou 维护当前用户服务前核实 unit/配置摘要、文件归属、OS peer 和真实进程绑定；登记替换有原件与耐久回执。失败时先恢复精确登记，外来修改继续拒绝。组件包摘要只校验内容，能力声明只说明兼容性，两者均不是发行签名。兼容检查必须在停止原服务前完成，包含 store_selection、native_profile_from_card、native_profile_budget、实例命名空间与 local-v1 权威范围。

配置严格解析未知键、重复键、错误类型和非法路径；显式坏配置在打开状态前拒绝，不落到另一套默认目录。require_store_selection 与 require_native_profile_budget 哨兵阻止旧程序忽略策略启动。check-config 不证明运行权限或后端可达；diagnose 读取同一实例的有限事实，不写入修复，不证明推理。见[配置](configuration-v1.md)、[启动与 socket](startup-and-socket-v1.md)及[诊断](diagnostics-v1.md)。

同状态和同 socket 的锁持续持有。活动监听、满队列、拒绝访问和超时都保留原端点；只有充分核实的 stale socket 可以清理，不以任意连接失败判不存在。控制收据有界、no-follow/nonblocking 读取，损坏和未知不能解释为无维护/无意图。

CLI/脚本执行有输出与时间预算，只清理本任务进程组；CLI 超时不能证明外部动作被撤销，需要重新核实。脚本 CR/LF 进度、输出 EOF、子进程退出和继承管道分别处理；内部取消监督不等于公开 enable 取消能力。日志和网络观测保留错误、采样时间与 partial/unknown，网络接口/RDMA 枚举不证明物理拓扑、RoCE 或集合通信。详见[脚本监督](script-runner-v1.md)与[网络事实](network-observation-v1.md)。

## 验证、限制与维护

从仓库根目录运行 `cargo test --locked -- --test-threads=1`、`cargo clippy --locked --all-targets -- -D warnings` 和 `cargo fmt --all -- --check`。真实边界用 `tests/real_startup_boundaries.py`、`real_gateway_listener.py`、`real_lifecycle_revision.py`、`real_install_retry.py`、`real_install_retry_pending.py` 等显式传入受测二进制与新证据目录的驱动。`real_store_adoption.py` 及 CPU 服务需要真实权重和相应运行环境；不是 GPU 性能验收。

测试夹具、OS 多进程、用户 systemd、真实下载/CPU 推理、已有 GPU 调用和物理多机分别记录。每份结果绑定实际源码及制品摘要，旧失败与修复后成功并列保留；不能将历史制品改标为最终版本。最终计数和门禁进度由当次 PR/本地验收记录说明，本文不宣称最终三轮审核或发布已经完成。

明确限制包括：同 UID 不是恶意本地进程之间的安全隔离；包无签名发行链或跨发行版 ABI 认证；任意脚本并非沙箱/完整配置证明；部分未知需要人工恢复匹配记录；回退只能使用具备当前必要能力的程序；完整发布包、跨账号联动、其他平台、物理重启/断电、GPU 满长上下文、多机与长期负载需要另行实现或验收。
