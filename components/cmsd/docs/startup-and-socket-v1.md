# 启动排他、socket 占用与恢复

cmsd 已有状态目录生命周期锁。此批修复的是启动探测阻塞和错误删除活动 socket，
并为不同状态目录竞争同一 socket 增加生命周期声明锁；保留本机 v1 接口。

## 启动条件与兼容

状态目录必须属于当前运行 UID，路径不能包含符号链接，服务将其收紧为 0700。
`state_dir/daemon.lock` 与 `socket_path` 同目录的 `<socket文件名>.lock` 都必须是
当前 UID 的单链接普通文件，锁持续持有至进程退出。锁文件用 0600 创建，禁止跟随符号链接；
旧 0644 状态锁在获得排他锁后原位收紧为 0600，保留 inode 和内容，不替换现有实例的锁。

socket 父目录因此需要允许服务账号创建声明锁。系统级安装应由安装器预建运行目录、
配置服务账号所有权；不要用删除锁文件解决占用。停止或崩溃后保留的小锁文件正常，
操作系统会释放已退出进程的锁。Pinvou 组件维护仍使用既有状态目录锁检查服务已退出。

探测已有 Unix socket 的连接期限为 200 毫秒。活动监听、满队列、权限拒绝、超时和
无法判定的失败都明确拒绝启动，保留原路径；不会把“连接失败”解释为“服务不存在”。
只有当前 UID、单链接的真实 socket 连续两次明确 ConnectionRefused（相隔 20 毫秒），
且末次核验仍是同一设备号/inode 时，才清除已退出实例留下的端点并重新绑定。
普通文件、符号链接、硬链接或其他 UID 的端点不清理。旧版没有 socket 声明锁，
新版仍以有限探测保留旧版活动端点。相同 UID 任意进程篡改文件不属于独立安全隔离边界。

## 失败恢复与回退

失败信息写入 stderr/systemd 日志，进程非零退出；不会代替原实例接管监听或执行旧脚本。
先核对实际服务 PID、状态目录与 socket 配置是否指向同一实例，再用 Pinvou 组件入口
或对应独立 systemd unit 停止/恢复。不要在原服务运行时移走状态目录、socket 或锁文件。
无法核实的权限、路径和状态应保留现场，修正账号/目录配置后重试。

本批没有新增需要回滚的数据格式。停止受测实例后，可使用匹配配置的旧制品回退；
保留当前身份、吊销、生命周期版本、任务和操作台账，不以旧快照覆盖权威状态。
旧制品不具有新增的 socket 保护，不应继续用于暴露的故障场景。

## 真实进程验收

`tests/real_startup_boundaries.py --binary /absolute/cmsd --evidence /new/private/path`
使用真实监听、满接受队列、000 权限、链接/哨兵、SIGKILL 和 16 并发实例。
必须由非 root 账号运行。只操作新状态目录和 `/run/user/<uid>/cmsd-start-*`，退出回收
自己的进程和临时运行目录；不停止原 cmsd、不操作模型，不冒充推理或多机验收。
