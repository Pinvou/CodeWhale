# 商店当前部署与历史归档（v1）

2026-10-20。当前版本指模型商店成功提交的已安装、已部署版本；不按目录名称、修改时间或远程版本猜测，也不自动下载远程最新版。

Pinvou 商店提供 `latest-installed-v1` 权威选择：逻辑卡 ID → 当前物理卡、版本 ID、部署修订。部署修订覆盖有效配方、引擎、配置及启动参数。当前指针缺失、文件校验失败、商店查询失联时拒绝启动，不回落旧目录。非当前的历史目录、保留权重和失败暂存不作为普通启用、默认、自动恢复或换模失败回滚候选。已成功下载但部署失败、或保留权重卸载后的权威 current 保留选择身份，仅供私有 owner 申请清理 reservation；没有完整部署条目仍不能启用、设默认或启用开机策略；原已托管的当前实例仍可经既有归属核查安全停止，未托管实例不能借清理身份取得停止权。历史、deleting 或版本绑定不一致不取得该清理身份。用户可以在商店手动完整回退本地卡片、脚本、权重路径及部署配置；商店原子发布回切后的当前指针，cmsd 随之接受该部署，并恢复逻辑模型的开机偏好，不直接重放历史运行意图。另一张当前有效模型仍可作为换模失败的程序恢复目标。

cmsd 保存 `store-selection.json` 与 `store-selection-v1`，跨重启保留归档墓碑，商店清理历史记录不会重新发现旧目录。归档信息不授予停止权限；只有原已授权托管实例可由显式启用/换模任务停止。状态查询只围栏旧版自动恢复，不暗中停机。逻辑开机偏好保存在 `logical-model-boot.json`，迁移到新版本；旧版本撤下自启。独占商店发布/清理锁与 cmsd 任务共享锁覆盖读选择、校验、停止旧实例和新实例就绪。

同账号 `POST /v1/store-enrollment` 的 `registered=true` 表示读取器绑定已确认，首份选择清单仍由后台发布。发布前状态和模型查询可返回 `503/store_selection_unavailable`，调用方应有界等待新事实；未知状态不授予执行权限。重复登记相同绑定仍会唤醒读取器，且不重写未改变的绑定文件，以便恢复首次清单尚未发布的情况。

模型操作任务固定记录 requested_card、实际 card、logical_card、selected_version 和 deployment_revision。MCP 换胎仍由程序完成，LLM 离线期间不影响执行；Pinvou 根据固定任务身份接回原有逻辑模型注册或创建新选项，不能将旧任务接到之后的新部署。

原生模型就绪必须同时符合当前引擎 inode、权重路径、账号、systemd/收编实例、监听 socket 所属 PID、模型 ID 和完整受管运行参数。HTTP 同名或端口相同不足以证明身份。卡片声明 262144 上下文时按声明启动，不能被 cmsd 的历史 32768 默认值覆盖。配置修订变化后不沿用旧模型内存标定；首启没有显式预留时仍使用权重加开销预算，需以真实负载测量，不保证所有长上下文并发能同时满载。

`--component-info` 新能力为 `store_selection=1`、`native_profile_from_card=1`。配置 `require_store_selection="v1"` 阻止旧程序忽略新策略启动。组件维护必须在停止当前服务之前预检候选；只允许同等或更新能力的软件回退。不要删除状态标记强制降级。

## 首建脚本的固定下载根目录

商店清单条目的 `models_root` 来自当前数据库记录，已参与配方/部署修订。仅当前 selection 的容器不存在而需执行 `enable.sh` 时，将其用于 `LMM_MODELS_DIR`；先复核当前配方和规范目录，不读取过期的 `store-installed` 副本，不从 `MODEL_DIR` 推测父级。已有容器和原生启动不重放该脚本；独立外部卡保留显式 daemon 配置语义。

已知商店条目缺字段或格式不合法时以 `store_models_root_unknown` 拒绝首建；已登记根路径缺失、变成链接或无法核实时以 `store_models_root_changed` 拒绝。保留卡片、权重和原部署，不猜后来设置的默认目录，也不下载。目录/挂载故障先恢复原登记路径后重试；字段缺失则恢复包含固定 root 和匹配配方的完整商店记录备份，或由商店明确选择已有完整目录记录的已验证版本并重新发布 current。不能证明匹配关系时继续拒绝首建并人工核查，不提供自动回填或重新下载代替身份恢复。

## 验证层次

自动测试覆盖逻辑/物理映射、历史拒绝、损坏/缺失当前、部署漂移、任务持久化、读写互斥、历史清理后墓碑、进程/监听身份和参数解析。实际升级、推理和重启需要对应制品另行联调，单元测试不能代替满上下文或物理多设备验收。

## 迁移与身份

同账号、同状态路径的完整已知旧 unit 模板可原子迁移，先保留原件；异归属、链接和未知内容继续拒绝。归档恢复记录支持 archiving/archived 往返，仍要求运行和开机意图为 false；中断后保留原开机偏好。旧进程观测不覆盖当前实例探测，原生 PID/监听身份和健康缓存会在 cmsd 重启后重新建立。

当前配方可含有界的附属源文件，安全相对路径逐字校验、每文件256 KiB、最多1041项（1024源资产加固定文件）、全清单1 MiB；不执行清单中的脚本。声明源码恢复与生成依赖扫描分别处理，不将依赖环境缓存纳入普通实例身份。普通停止、跨模型切换和回滚恢复同步逻辑开机偏好；历史换代停止不清除新版本继承的偏好，定期对账不能重新启用用户已停用的模型。普通日志查询也将逻辑ID解析到当前物理卡；保留运行的原生实例沿用已核实 Binding 的真实单元名，模型和引擎清单展示相同日志来源，不将新 namespace 推导名误报为旧实例。没有 systemd 单元的独立进程明确返回日志不可用，不能以新空单元冒充引擎日志。显式停止在退休生命周期 Binding 前保留私有日志来源，因此 PID 退出或停止完成后仍可读原 unit journal；CMS 新建当前单元前切换日志来源，注销/卸载模型时清理。此诊断来源不授予启动、停止或恢复权，损坏时明确未核实，不扫描猜测其他单元。

## 停止模型的告警对账

停止态和故障独立表达。确认归属、后端和恢复记录一致后，清理已经解决的围栏/后端错误；运行时仍缺失、崩溃或熔断的诊断继续保留。清除已解决的告警不启动模型、不重跑安装，也不改变开机偏好。

日志来源读取仍有4096字节上限，格式、卡片或unit不符时明确未知。来源只是诊断信息：可信私有普通文件的旧JSON损坏、超限或旧unit/card内容不阻止已独立核实的停止和注销；受信生命周期路径可原子替换或退役该固定文件，不读取旧大内容。链接、异归属、非普通文件或非私有目录/权限仍拒绝并保留现场。真正身份记录的原有内容限额和错误行为不变。
