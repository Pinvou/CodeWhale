# 标准安装的原语义重试

商店仍是标准模型安装的唯一执行者。失败或取消发生在模型库首次落库前时，
Pinvou 的未完成安装入口可以重新预览包和原存储上下文，再向 cmsd 申请重试。
不能把下载任务重解释成本地部署，也不能从残留目录获得管理权。

## 协议与准入

设备能力 `model.install_retry.v1` 对应独立入口：

```
POST /v1/models/{card}/install/retry
{"retry_store_run_id":"原商店 run_id","expected_preview_sha256":"64位小写SHA256"}
```

拒绝多余字段、重复 JSON 键、路径标识符和无效摘要。预先读取商店原任务，要求
相同卡片、原类型为 download/install_local、状态为 failed/cancelled。
原任务成功不属于未完成安装恢复；需新发明确安装请求。
随后在 Store 锁内再次检查组件维护、模型维护、全局安装并发、同卡任务及持久版本，
原子保存 cmsd 任务、完整 `cmsd-<task_id>` 商店关联、原类型和重试来源/摘要，才发送请求。
持久受理后立即返回任务编号，由后台发送、镜像和对账；不让商店五秒超时拖过 UI 调用期限。
锁内不执行商店网络查询。商店再次核实最新回执、无模型库记录、原执行者状态和包完整性。

内部商店入口固定为：

```
POST /v1/retry_install
{"original_run_id":"原run_id","expected_preview_sha256":"完整预览摘要","run_id":"cmsd-<task_id>"}
```

仅此三个字段；200 回执为 `{run_id,kind,card}`，三者必须匹配持久上下文。
接收方先按完整 run_id 查幂等关联，再校验 latest/DB 等新操作条件；相同关联返回原回执，
不同原任务或摘要返回 409。第一份私有持久回执在 worker/联网验包之前保存。
旧服务的新路径 404 直接暴露，不回退普通 install；不能向旧 install 路径添加可被忽略的参数。
有 cmsd 管理关系而失联/缺能力时，UI 不直接改走商店或脚本。

## 后台、超时和取消

Unix 商店连接包含 backlog 满时的非阻塞连接；连接、写入和读取合用五秒绝对期限。
应答有界，严格 UTF-8/JSON；未知任务类型不补成 download，无效列表不静默丢项。
`GET /v1/tasks` 的 `store_query` 明确商店查询是否成功；本机持久任务仍可读。
单个任务查询不把商店离线映射为“无此任务”。

发送后断开、回执不匹配、协议异常或临时 GET404，均不能证明未受理。
cmsd 保留原任务及互斥，关闭 UI 不取消；重启按原关联继续核实。
仅新重试的持久三字段关联可在 GET404 时退避重投，间隔最多30秒；不会创建新run，
不会重放旧普通 install，也不会因后来核实请求被拒绝而擅自宣告首次请求不存在。
商店长期失联时保持待核实并报告原因；匹配备份/真实后台恢复后继续查询。
存储不可写不发送安装请求；损坏任务/重试上下文不能在加载时被丢弃从而释放排他。

取消意图先保存，再转发原 run；恢复轮询发现仍运行会再次转发取消。
暂时查不到时仅返回 cancelling，不假报取消完成。最终 succeeded/failed/cancelled
以正确关联的商店回执为准；完成与取消竞态可能仍以成功结束。

- download 成功：引擎检查、权重下载及校验；尚未部署和启用。
- install_local 成功：原本地安装链和部署；尚未启用。
- 启用、默认切换、LLM 程序化换胎仍由现有明确操作控制。

## 验收分层

Rust 测试覆盖严格正文、原子上下文、取消意图持久化、损坏上下文拒绝加载、
Unix backlog 满时连接超时及既有安装/任务契约。跨进程商店、故障代理、真实模型
与 Pinvou 界面证据按对应二进制摘要记录；夹具脚本不称为模型推理或多机验收。
长期失联且原商店回执已被破坏时，仍需人工恢复对应后台状态；不得自动清围栏后重新安装。

可复现驱动为 `tests/real_install_retry.py` 和 `tests/real_install_retry_pending.py`。
驱动只操作临时 profile、测试 socket、测试脚本及测试模型；真实推理需要另行提供权重和运行环境。
